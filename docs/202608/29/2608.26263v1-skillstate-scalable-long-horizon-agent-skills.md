## 摘要
大语言模型（LLMs）越来越多地充当自主智能体，执行复杂、长期运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理轨迹追加到不断增长的对话历史中来维持执行，这会导致延迟退化，并在长期运行中出现上下文污染故障。我们提出了SKILL.state，一种运行时架构，用显式的、可变的执行状态替代仅追加的对话历史。在每个执行步骤中，模型仅接收不可变的技能规范、当前的结构化执行状态以及最新的观察。中间推理在生成经过验证的状态更新后立即被丢弃，从而防止提示词随执行历史增长。在多种数据集、模型和执行环境中，SKILL.state 提高了任务准确性，同时大幅减少了累计令牌消耗。我们的结果表明，显式执行状态是一种有效且与架构无关的抽象，适用于可扩展的长期智能体技能。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL.state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

大语言模型（LLM）正在从被动语言接口演变为可执行复杂程序性技能的自主智能体。然而，现有的智能体运行时普遍采用**对话式执行模型**：每一步都将之前的推理、动作、观察和工具输出不断追加到对话历史中。

这种设计在长时程任务中带来两个根本性缺陷：
- **Prompt 大小随执行长度线性增长**，导致 token 消耗和推理成本大幅上升（累计复杂度达 O(T²)）；
- **历史信息污染**——过时观察和无关推理长期存留在上下文中，模型需要不断从文稿历史中重建当前世界状态，而非直接基于当前事实决策，导致“上下文中毒”（context-poisoning）。

**整体含义：**
论文提出将“执行”本身视为一个系统问题而非纯推理问题，主张用**显式、可变的结构化执行状态**替代追加式对话历史。该方法不依赖压缩或检索等手段缓解历史膨胀，而是从根源上消除历史累积，使 prompt 大小与已执行步骤数无关。

## 2. 论文提出的方法论

**核心思想：**
SKILL.state 将程序性技能执行重构为**显式状态转换过程**，而不是对话历史的累积。每一步模型仅接收三部分输入：

At = (P, Σt, Ot)

- **P**：不可变的程序性技能规范（skill specification）；
- **Σt**：第 t 步的结构化执行状态（structured execution state）；
- **Ot**：最新的环境观察（latest observation）。

**关键技术细节：**

1. **状态 Schema 定义**：每个领域定义一个结构化 schema（如 InterCode CTF 中跨 100 个任务共用一个 5 字段 schema：`discovered_flags`, `tested_hypotheses`, `active_files`, `working_dir`, `cmd_summary`），schema 按领域一次性编写，而非按任务逐个编写。

2. **推理与状态更新分离**：LLM 在每步生成三元组：
   (Rt, ΔΣt, at)
   - Rt：多步 Chain-of-Thought 推理轨迹（生成完成后立即丢弃）；
   - ΔΣt：结构化状态更新（JSON 字典，包含键的修改与删除）；
   - at：要执行的动作。

3. **状态合并机制**：Σt+1 = Σt ⊕ ΔΣt，其中 ⊕ 为运行时实现的字典合并操作符，支持空值删除语义。

4. **确定性验证**：运行时对 LLM 提出的状态补丁进行确定性验证，非法补丁不会污染持久状态，而是触发回滚-重试循环。

**算法流程（Algorithm 1）：**
```
for t = 0 ... T:
    接收最新观察 Ot
    构建 prompt (P, Σt, Ot)
    LLM 生成 (Rt, ΔΣt, at)
    验证 ΔΣt
    应用状态更新 Σt+1 ← Σt ⊕ ΔΣt
    执行动作 at
```

**复杂度分析：**
- 传统对话式运行时：|Ct| = O(t)，累计 token 复杂度为 O(T²)；
- SKILL.state：|Pt| = O(|P| + |Σ| + |O|)，与已执行步数 t 无关，累计复杂度降为 O(T)。

## 6. 论文的主要结论与发现

1. **显式状态优于历史累积**：SKILL.state 在所有基准和模型上匹配或超过基于历史的基线，同时 prompt 大小保持 O(1) 平坦。

2. **Token 消耗大幅降低**：在 Warehouse T=100 时，SKILL.state 消耗 65k tokens，相比 Stateful 基线（1,062k）降低 16.2 倍；在 T=200 时仅需 122k tokens，而 Memory 基线膨胀至 6.1M。

3. **噪声鲁棒性显著提高**：50 事件/步的高噪声下，ReAct 准确率降至 0.53，SKILL.state 保持 0.98，因为干扰在状态补丁生成阶段即被过滤。

4. **状态恢复能力突出**：环境静默改变世界状态时，历史基线产生 5-14 步的幻觉滞后，SKILL.state 需要 0 步恢复。

5. **结构化状态优于统计压缩**：预算匹配下，滑动窗口（0.18）和 LLMLingua（0.22）严重失效，而 SKILL.state 保持 0.94，说明统计压缩会破坏精确关系依赖。

6. **小模型主要瓶颈是结构化输出遵循度**而非推理能力：68% 的错误为过早状态覆盖/删除，20% 为 schema 理解问题，12% 为 JSON 格式错误。

## 7. 优点

### 方法论亮点
- **釜底抽薪式的方案**：不是改进历史压缩，而是从架构上消除历史累积，O(T²) → O(T) 的复杂度改进是严格的理论保证；
- **架构无关性**：方法不依赖特定模型或特定推理范式，适用于任何可生成结构化输出的 LLM；
- **状态作为充足统计量**：将“什么信息需要在跨步间存活”显式建模，推理只作为瞬态中间计算；
- **确定性验证机制**：状态更新由运行时验证，模型错误不会污染持久状态，有回滚-重试保障；
- **Schema 复用**：跨 100 个 CTF 任务只需一个静态 5 字段 schema，表明设计开销可控。

### 实验设计亮点
- **预算匹配对照**：精准回答“性能提升来自短 prompt 还是结构化状态”的关键混淆问题；
- **状态恢复实验**：创造性模拟真实世界中的静默环境漂移，揭示历史基线的幻觉问题；
- **小模型错误分类学**：为后续改进（如约束解码）提供了明确方向。

## 8. 不足与局限

### 作者自述的局限
1. **充足统计量假设**：SKILL.state 假设执行状态可以完全捕捉影响未来决策的所有信息，但在以下情况失效：
   - 动态执行中需发现新状态结构时；
   - 早期观察的重要性在后续才被意识到且未被提交到状态时；
   - 任务目标本身定义在历史轨迹上（如审计、调试溯源）时。

2. **多智能体扩展未验证**：虽然显式状态可自然扩展为多智能体协调基板，但并发写入的冲突解决语义未实现和测试。

3. **小模型结构化输出能力**：Gemma/Qwen 等模型状态更新时易遗漏键或产生格式错误，需要约束解码辅助。

### 其他潜在不足
- **状态 schema 的领域依赖**：schema 设计本身需要人工参与，“每领域一次”的成本未量化，对开放式探索任务可能构成瓶颈；
- **丢失轨迹信息**：丢弃推理轨迹意味着无法事后分析模型决策过程，对可解释性有负面影响；
- **历史任务不可用**：如作者所言，任何需要追溯历史动作序列的任务（如生成执行日志、解释过去行为）在 SKILL.state 框架下无法直接支持；
- **实验覆盖局限**：未评估 SKILL.state 在视觉、具身等非文本观测环境中的适用性；公开基准上的统计报告不够完整（缺乏多次运行方差）；
- **算力信息缺失**：未披露任何硬件/推理延迟数据，无法评估实际运行时开销（如 JSON 验证、回滚重试的成本）。
