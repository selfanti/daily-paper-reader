## 摘要
智能体技能将专业知识和流程打包为可复用资源，从而扩展AI智能体的能力。近期工作从智能体经验中自动发现此类技能，使智能体能够通过交互逐步适应。然而，指导技能开发的洞察通常分散在优化历史中，限制了其在迭代中的系统复用。我们提出WikiSkill，一个将智能体技能与持久知识库（wiki）共同进化的框架。从高层次看，WikiSkill将原始执行经验、积累的知识和可执行技能分离，同时持续将经验整合到wiki中，后续技能更新可在此基础上构建。在多种基准和模型上，WikiSkill持续优于最先进的技能进化方法，并在大多数模型-基准设置中优于无技能基线。我们发现技能进化与模型缩放互补：较大的模型通常从进化技能中获益更多，而具备技能的较小模型可以超越没有技能的显著更大的模型。我们还发现进化技能在模型和模型家族之间有效迁移，并且由其他模型进化的技能可以优于自我进化的技能。最后，我们的消融研究证实，wiki中的持久知识积累对于有效的技能进化至关重要。这些结果证明了系统积累和提炼智能体经验对于开发可复用和可迁移技能的好处。

## Abstract
Agent skills package specialized knowledge and workflows into reusable resources that extend AI agent capabilities. Recent work automatically discovers such skills from agent experience, which enables agents to progressively adapt through interaction. However, the insights that guide skill development typically remain scattered across optimization histories, limiting their systematic reuse across iterations. We introduce WikiSkill, a framework that co-evolves agent skills with a persistent knowledge base (wiki). At a high level, WikiSkill separates raw execution experience, accumulated knowledge, and executable skills, while continuously consolidating experience into the wiki, which subsequent skill updates can build on. Across diverse benchmarks and models, WikiSkill consistently outperforms state-of-the-art skill-evolution methods and improves over no-skill baselines in most model-benchmark settings. We find that skill evolution complements model scaling: larger models generally benefit more from evolved skills, while smaller models with skills can outperform substantially larger models without them. We also find that evolved skills transfer effectively across models and model families, and skills evolved by other models can outperform self-evolved skills. Finally, our ablation studies confirm that persistent knowledge accumulation in the wiki is critical for effective skill evolution. These results demonstrate the benefits of systematically accumulating and refining agent experience for developing reusable and transferable skills.

- **背景**：通用 AI 智能体（LLM Agent）在复杂任务上能力不断增强，但真实世界任务往往需要领域特定的专业知识和流程（程序性知识）。智能体技能（Agent Skills）以轻量、开放的文件系统格式（如 SKILL.md）封装这类知识，无需更新模型参数即可复用和审计。
- **核心问题**：现有技能自动进化方法（如 EvoSkill、Trace2Skill、SkillOpt）虽然能从智能体的成功/失败轨迹中提炼并改进技能，但指导技能开发的洞察（patterns、经验教训）通常**分散在优化历史中**，缺乏一个独立、持久的、不断累积的知识表示，导致经验难以跨迭代系统复用。
- **论文主张**：受 Karpathy “LLM Wiki” 观点启发，提出 **WikiSkill** 框架，将智能体经验“编译”为持久、复合增长的知识库（wiki），使技能开发能建立在持续整合、不断完善的知识之上，而不是零散的进化产物之上。该工作系统研究了经验沉淀、知识积累与技能进化之间的协同关系。

### 2. 方法论：WikiSkill 框架

- **三层知识架构（核心思想）**：将智能体工作区分为三个层次，实现“原始经验—结构知识—可执行技能”的分离：
  - **Raw Layer（raw/）**：存放每次迭代的不可变执行轨迹（完整步骤、工具调用、最终答案），用于后续分析。
  - **Wiki Layer（wiki/）**：持久知识库，包含 `patterns/` 目录（记录具体失败模式、成功策略和可行解决方案）、`index.md`（模式索引）、`logs.md`（进化日志）和 `skill-impact.md`（技能影响追踪器，记录每次提案的 diff、验证分数和接受/拒绝结果）。该层**跨迭代持续累积，永不重置**。
  - **Skill Layer（skills/）**：当前活跃的可执行技能集合，每个技能目录包含 `SKILL.md`（完整程序性指令）和 `PURPOSE.md`（记录该技能来源和所针对的 wiki 模式）。
- **进化循环（四组件协同）**：
  1. **Inference Agent（推断智能体）**：使用当前活跃技能在训练集上执行 rollout，生成轨迹。在训练期间**禁止访问 Wiki 层**（消融证明允许访问会降低技能质量）。
  2. **Wiki Maintainer（Wiki 维护者）**：对采样轨迹（最多 8 条，5 失败 + 3 成功）进行深度根因分析，提取成功策略；以增量 patch 方式新建/更新模式页面，并更新索引和进化日志。
  3. **Skill Proposer（技能提案器）**：以 ReAct（推理+行动）方式自主读取 wiki 索引、技能影响追踪器和轨迹，诊断失败根因，提出原子化技能提案（创建新技能或对现有技能进行增量 patch 编辑）。
  4. **Gating & Rollback（门控与回滚）**：在验证集上评估候选技能集，若验证分数 $R(\mathcal{T}_{\text{val},k}) > R_{\text{best}}$ 则接受，否则回滚技能集。**但 wiki 永不回滚**，以保证知识长期积累。
- **算法流程（伪代码要点）**：初始化技能集 $S_0=\emptyset$、wiki $W_0=\emptyset$，评估无技能基线验证分数 $R_{\text{best}}$；每一轮 （1）训练集 rollout → （2）采样轨迹 → （3）Wiki 维护 → （4）技能提案 → （5）应用提案 → （6）验证集评估 → （7）接受/拒绝门控 → （8）更新 skill-impact 日志。若验证分数达到 1.0 则提前终止。
- **优化器 API 调用复杂度**：WikiSkill 使用全批量模式（$B=N_{\text{train}}$），每轮迭代仅需 $1 + T_{\text{ReAct}}$ 次优化器调用（$T_{\text{ReAct}} \approx 10$–$20$），复杂度为 $O(1)$（与训练集规模无关）；对比 EvoSkill 为 $O(N_{\text{train}}/B)$，SkillOpt 为 $O(N_{\text{train}}/B)$，Trace2Skill 至少为 $O(N_{\text{train}})$。

  - **SkillOpt**：六阶段 ReflACT 流程（Rollout, Reflect, Aggregate, Select, Update, Evaluate）。

  4. 定性分析：统计技能/wiki 模式创建、编辑、长度等；分析接受技能更新的时间分布；提供 ALFWorld 案例研究。

### 6. 主要结论与发现

- **WikiSkill 一致优于现有方法**：在 5 个模型上，平均性能比最强竞争方法高 3.3–12.0 个百分点；相比无技能基线，在大多数模型-基准组合中均有提升。例如 Gemini-3.5-Flash 在 LiveMath 上从 33.0% 提升到 72.6%，在 SpreadSheet 上从 50.5% 提升到 76.6%。
- **技能进化与模型缩放互补**：Qwen 家族内，WikiSkill 带来的提升随模型规模增大而增加（4B: +12.3，9B: +17.5，27B: +23.9），尤其在 SpreadSheet 上 Qwen-3.6-27B 提升达 +40.9。同时，小模型 + 技能可超越大模型无技能：Qwen-3.5-9B + WikiSkill（47.4%）> Qwen-3.6-27B 无技能（39.4%）。
- **技能可跨模型迁移，甚至超过自进化技能**：例如 Qwen-3.6-27B 进化的技能使 Qwen-3.5-9B 在 SpreadSheet 上达到 50.5%（自进化仅 33.6%，无技能 24.3%）；Qwen-3.5-4B 技能可将 Gemma-4-31B 在 LiveMath 上提升至 73.1%。
- **迁移效果取决于技能是否捕获通用程序 vs. 模型特定工作区**：LiveMath 技能迁移性强；SpreadSheet 上 Qwen-3.5-4B 的低级 workaround 技能导致 Gemini-3.5-Flash 性能从 50.5% 降至 18.1%（负面迁移）。
- **持久知识是关键**：消融显示，Skill Proposer 可访问持久 wiki 使平均性能从 48.7% 提升到 63.7%（+15.0%）；而 Inference Agent 在训练期间访问 wiki 反而使性能从 63.7% 降至 60.9%。wiki 的持续积累（模式、拒绝历史、技能影响追踪）使技能提炼能持续到中后期迭代（如 SealQA 上 33% 接受发生在中期，28% 在后期）。
- **技能发现与技能执行是两种不同能力**：一个模型进化出的技能可能对另一个模型更有用（如 Qwen-3.5-4B 技能降低自身 OfficeQA 性能但大幅提升 Qwen-3.6-27B）。

### 7. 优点

- **概念清晰、架构优雅**：三层分离（raw / wiki / skills）将“经验—知识—程序”解耦，wiki 作为持久知识层解决了既有方法知识分散的问题；wiki 永不回滚 + 技能可回滚的设计，保证长期知识积累与短期质量控制的平衡。
- **实验规范且全面**：5 基准 × 5 模型 × 3 次重复 + 统计检验 + 跨模型迁移 + 消融，结论稳健；并且公开了完整的系统提示词、算法伪代码和优化器 API 复杂度分析，可复现性强。
- **洞察深刻**：揭示了技能进化与模型缩放互补、技能迁移性差异（通用程序 vs. 模型特定 workaround）、技能发现与执行解耦等现象，对后续研究有重要启发。
- **效率优势**：在 full-batch 模式下，WikiSkill 的优化器调用复杂度为 $O(1)$（相对于训练集规模），相比 Trace2Skill 的 $O(N_{\text{train}})$ 有明显扩展潜力。

### 8. 不足与局限

- **未涉及技能检索/触发**：实验中直接注入全部技能内容，规避了技能选择问题；当技能数量增大时，如何检索和触发将变得关键，论文未研究这一点。
- **严格的门控标准**：仅接受验证分数严格提升的提案，排除了中性但有潜力的更新（可能为后续迭代铺路），可能限制进化空间。
- **wiki 无限增长**：wiki 持续累积模式页面、日志和 diff，论文明确承认缺少自动剪枝机制，长期运行可能面临上下文/存储膨胀问题。
- **任务时域有限**：未覆盖需要数百步或数小时执行的超长时域任务，在线技能自适应（单次长 rollout 内的技能精炼）仍是空白。
- **“未来”性质与可验证性**：论文引用和日期设定在 2026 年（如 Qwen3.5/3.6、Gemma 4、Gemini 3.5 等），基于当前公开信息，部分模型和基准的细节难以独立验证；且未披露算力细节，复现成本可能较高。
- **OfficeQA 使用 oracle 页面**作为初始证据，降低了真实检索难度，可能高估技能在该任务上的效果。
