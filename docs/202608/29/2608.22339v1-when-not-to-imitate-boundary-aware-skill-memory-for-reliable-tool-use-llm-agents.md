## 摘要
从过去的成功中提取技能对于大型语言模型（LLM）代理的高效进化至关重要。主流的代理自我进化范式通常依赖一个核心假设：用从成功轨迹中提取的技能记忆装备LLM将单调地提升其问题解决能力。然而，探测分析揭示，仅从成功轨迹中提取技能会使模型陷入“技能模仿陷阱”。对于与过去成功相似但需要不同工具的任务，检索更多技能反而会增加模型对错误工具调用的置信度——程序技能将错误工具边际比无记忆基线提高了47%。为克服这一局限，我们提出边界感知技能记忆（BASM），为每项技能附加显式的边界字段——适用条件、风险线索、规避规则和恢复说明。这些字段将每个检索到的技能从无条件动作模板转化为状态条件化指导：当条件成立时代理应用该技能，当条件不成立时抑制不适用的工具调用，并在执行失败时发出定向修复。在三个代理基准和四个模型规模上，BASM持续优于成功蒸馏技能记忆基线：在AppWorld上任务成功率最高提升23.8%，在BFCL上准确率最高提升5.0%，在AgentDojo上攻击成功率降低4.6%，同时相对于无记忆基线，平均AppWorld步数最高减少6.6%。

## Abstract
Extracting skills from past successes is critical for the efficient evolution of Large Language Model (LLM) agents. Prevailing agent self-evolution paradigms typically rely on a core assumption: equipping LLMs with skill memories derived from successful trajectories will monotonically improve their problem-solving capabilities. However, probe analyses reveal that extracting skills solely from successful trajectories traps the model in a \textbf{Skill Imitation Trap}. For tasks that resemble past successes but require different tools, retrieving more skills paradoxically increases the model's confidence in wrong tool calls---procedure skills raise the wrong-tool margin by $47\%$ over a memory-free baseline. To overcome this limitation, we propose \textbf{Boundary-Aware Skill Memory} (BASM), which augments each skill with explicit boundary fields---applicability conditions, risk cues, avoidance rules, and recovery notes. These fields transform each retrieved skill from an unconditional action template into state-conditioned guidance: the agent applies the skill when its conditions hold, suppresses inapplicable tool calls when they do not, and issues targeted repairs when execution fails. Across three agent benchmarks and four model scales, BASM consistently outperforms success-distilled skill-memory baselines: it improves task success rate by up to $23.8\%$ on AppWorld, accuracy by up to $5.0\%$ on BFCL, and reduces attack success rate by $4.6\%$ on AgentDojo, while simultaneously reducing average AppWorld steps by up to $6.6\%$ relative to the memory-free baseline.

- **整体含义**：这项工作质疑了代理自我进化领域中“技能记忆越多越好”的隐含前提，揭示出**技能记忆必须携带其有效边界**才能实现可靠性，对代理安全的经验复用范式具有重要指导意义。

### 2. 方法论：核心思想、关键技术细节、公式与算法流程

#### 2.1 核心思想

提出**Boundary-Aware Skill Memory（BASM）**，为每项技能附加显式边界字段，将检索到的技能从**无条件的动作模板**转化为**状态条件化指导**：条件成立时应用技能、条件不成立时抑制调用、执行失败时定向修复。

#### 2.2 七槽技能模式（核心公式）

每项技能表示为七字段结构化记录：

```
s = (g, π, T, A, R, N, F)
```

- **程序性组件（Procedural Core）**：`g`（目标）、`π`（程序规范）、`T`（工具集）
- **边界组件（Boundary Component）**：`A`（适用条件）、`R`（风险线索）、`N`（规避规则）、`F`（恢复说明）
- 边界文本组合：`B(s) = A(s) ⊕ R(s) ⊕ N(s) ⊕ F(s)`

#### 2.3 离线技能库构建

- 从成功轨迹 `K+` 和失败/部分失败轨迹 `K−` 中提取技能。提取在两种粒度进行：**步骤级**（从计划步骤提取功能技能）和**工具级**（从具体工具调用及观察结果提取原子技能）。
- 候选技能经过确定性验证算子 `ψ`（JSON解析、必填字段校验、边界槽列表化、非空风险线索与规避规则、工具模式合法性），失败即丢弃，保证库中每项技能都携带可操作的边界证据。

#### 2.4 检索与提示格式化

- **多视图检索分数**：结合语义相似度、工具重叠（Jaccard）和步骤/目标重叠：

```
score(xt, s) = λsem·cos(e(xt), e(vs)) + λtool·J(Txt, Ts) + λstep·overlap(xt, gs, πs)
```

- **预算化提示组装**：程序性内容（g, π, T）始终包含；边界字段仅在边界相关分数 `rB(xt, s)` 超过阈值 γ 时选择性暴露，且受最大边界token预算 β 限制。这一设计源于探测发现：无差别检索会放大而非缓解错误工具偏好。

#### 2.5 执行期控制与修复

- **边界检查器**：对照检索到的边界字段检查提议的工具调用 `at`，阻止或修改违反适用条件、匹配规避规则或重复已知失败模式的动作。计算公式中的门控函数 `G` 使用确定性字符串/模式检查优先、LLM辅助判断处理歧义自然语言条件。
- **局部失败修复**：在有状态环境中，当观察 `ot+1` 指示局部失败时，修复模块检索定向提示 `ht` 并注入下一决策步骤，而非重新进行完整的技能重检索。

#### 2.6 机制公式

- **错误工具边际（诊断指标）**：

```
mwrong(xt) = max_{y∈Ywrong} ℓt(y) − max_{y∈Yctrl} ℓt(y)
```

正值表示模型在当前决策点局部偏向不正确的工具。
- **边界/程序注意力比**：

```
η(l,h)(xt) = α(l,h)_B(xt) / (α(l,h)_P(xt) + ε)
```

衡量决策token对边界证据相对于程序内容的注意力强度。

4. **组件互补**：边界提示主要提升函数选择精度（BFCL），运行时修复在有状态多步恢复中发挥关键作用（AppWorld）。两者结合方能最大化效果：Prompt-BASM在AppWorld上反而低于Base，Repair-Only在BFCL上无增益。

### 8. 不足与局限

- **模型覆盖面有限**：所有实验仅在Qwen模型家族（Qwen3系列）上进行，未验证其他主流模型（如GPT、Claude、Llama、Mistral等）上的表现，结论的跨架构泛化性存疑。
- **评估规模较小**：AppWorld仅168个测试任务，BFCL仅800实例，对许多需长尾覆盖的真实场景代表性有限；且未提供多次运行的方差/置信区间。
- **资源信息不透明**：未报告GPU配置、计算成本、推理耗时等关键信息，影响可复现性和实用性判断。
- **边界表示依赖自然语言**：当前实现用显式自然语言字段表示边界条件，虽可解释性强，但在更紧的上下文预算下可能不够紧凑，且提取质量依赖LLM抽取器的可靠性。
- **场景局限于文本工具使用代理**：未涵盖多模态代理、动态变化的工具API、延迟反馈的长时运行工作流等更丰富的交互场景。
- **BFCL上的效果差异有限**：在Qwen3-32B和Qwen3.5-397B上，BASM与Proc. Skill的BFCL差距仅1.38和0.37个百分点，增益绝对值并不大，主要优势集中在AppWorld等有状态场景。
- **安全性提升的机制未充分解释**：AgentDojo上ASR的降低究竟来自哪个边界字段的哪种具体机制（如何阻断注入指令），文中仅通过消融间接推断，缺少对安全性改进的深入机制分析。
- **存在误抑制风险**：严格的边界检查可能在适用性判断模糊时错误抑制有效工具调用，论文未深入探讨这种“过度保守”代价及其边界条件。
