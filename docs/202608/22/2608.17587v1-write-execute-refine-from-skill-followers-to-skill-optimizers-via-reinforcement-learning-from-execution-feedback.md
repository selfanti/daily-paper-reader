## 摘要
专家编写的自然语言技能可以提高使用工具的智能体，然而智能体自身编写的技能比不使用技能表现差8-11个百分点。这一差距表明，遵循程序性指导与根据执行证据改进它，是两种不同的能力。推理时间循环可以修复技能，但不能改进编写下一个技能的模型。我们研究如何将中间技能的执行经验组织成优化器的训练状态。我们提出了WER（写、执行、改进）框架，这是一个多阶段框架，在冻结的执行器之外训练技能优化器。优化器提出技能，冻结的智能体重复执行每个技能，程序化验证器对结果进行评分。评分提供相对信用并选择混合结果记录。来自这些记录中匹配的成功和失败轨迹构成下一阶段的改进状态，因此优化器从先前输出的结果中学习。在BFCL v4多轮和tau2-bench上，WER相对于无技能基线平均Pass@1分别提高了7.80和3.85个百分点。在相同的改进流程下，它比没有优化器训练的同一骨干模型高出9.35和10.29个百分点。训练后的4B优化器在BFCL v4上达到76.63%的准确率，平均优于所有评估的现成通用模型作为技能优化器。

## Abstract
Expert-written natural language skills can improve tool-using agents, yet agent-authored skills perform 8-11 points worse than using no skill. This gap suggests that following procedural guidance and improving it from execution evidence are distinct capabilities. Inference time loops can repair skills but do not improve the model that writes the next one. We study how to organize execution experience from intermediate skills into training states for an optimizer. We introduce WER (Write, Execute, and Refine), a multi-phase framework that trains a Skill Optimizer outside a frozen executor. The optimizer proposes skills, a frozen agent executes each repeatedly, and a programmatic verifier scores the outcomes. The scores provide relative credit and select mixed-outcome records. Matched successful and failed trajectories from these records form the next phase's refinement states, so the optimizer learns from the consequences of its earlier outputs. On BFCL v4 multi-turn and tau2-bench, WER improves average Pass@1 over the no-skill baseline by 7.80 and 3.85 points, respectively. Under an identical refinement workflow, it outperforms the same backbone without optimizer training by 9.35 and 10.29 points. The trained 4B optimizer reaches 76.63 percent on BFCL v4, outperforming all evaluated off-the-shelf general-purpose models used as skill optimizers on average.

- **背景**：工具使用智能体需要程序性知识（何时调用哪个工具、如何校验参数、合适重试），而技能（skill）是这类知识的重要载体。已有研究表明，专家编写的技能能将通过率从33.9%提升至50.5%。

- **本文研究问题**：如何将中间技能产生的执行经验组织成训练状态，以训练一个专门的技能优化器（Skill Optimizer）？本文将这一问题拆解为rollout机制、信用分配（credit assignment）与跨阶段经验构造三个子问题。

## 2. 提出的方法论（WER框架）

### 2.1 核心思想

- 将技能优化建模为一个**独立于执行器的学习策略**：技能优化器πθ仅与文本交互，处于环境之外充当观察者，永不直接发出工具动作。
- 训练/推理流程（“Write-Execute-Refine”循环）：优化器"写"出候选技能 → 冻结的执行器"执行"验证 → 根据程序化验证器的评分"改进"技能。执行器在训练中完全冻结，实现**信用归因的隔离**。

### 2.2 关键技术细节

- **技能表示**：每个技能为一段简短的Markdown文档，固定包含四个部分——名称、适用任务族的一句话描述、编号工作流、记录假设/边界情况/已知失败模式的Notes。技能被注入系统提示词开头，且必须描述程序而非具体解的答案（不包含具体参数值或实体标识符）。
- **改进状态（refinement state）**：定义为 x = (q, C, h, s, e)——用户查询、工具定义与环境描述、交互历史、当前技能、上次执行证据。优化器的生成规则为 s′ ~ πθ(·|x)，这是框架中唯一的生成规则。
- **执行反馈的双渠道设计**：
  - **通道一（上下文）**：完整轨迹原样传递给优化器（不摘要化），让模型看到具体工具选择、参数、环境返回和失败后的行为。
  - **通道二（奖励）**：完全由程序化验证器决定——BFCL v4比较最终环境对象状态与参考解的差异，τ2-bench比较终端数据库与参考库及必需的已执行动作，二者都是确定性验证，杜绝模型自评。
- **奖励设计**（式4）：R(s′) = (Rfmt + Rtask + Rlen)/3。Rfmt要求生成格式可解析且推理与技能体分离；Rtask为n次rollout的验证器结果汇总；Rlen约束推理块长度（空推理或超预算受罚）。Rfmt在训练中逐步退火（annealed downward），因为格式能力早期习得后不应与任务信号竞争。
- **组相对优势**（式5）：Âk = Rk − μ(R)，K个候选技能在同一状态下互比，消除任务难度差异，用GRPO裁剪代理目标优化（式6），**无KL项、无参考策略**——目标输出是基础模型不具备的文档格式与修改风格，锚定初始化会阻碍学习。
- **跨阶段自举**（Phase-Wise Self-Bootstrapping）：
  - 每个被评分的候选作为元组(x, s′, {τ1..τn}, R)写入经验缓冲区；
  - **保留策略**：n=2时只保留恰好1次成功1次失败的中等结果样本，形成同技能同任务的"匹配成败对"——因为技能与任务固定，配对轨迹的差异恰好暴露技能未能约束的分支点，单一轨迹无法实现这种定位；
  - 下一代改进状态由拼接组成（成功轨迹放入<success>块，失败轨迹放入<failure>块），不做摘要或压缩；
  - 阶段迭代使输入分布向"技能几乎但不完全够用"的状态偏移，形成修正树（revision tree）而非每阶段从初始草稿重启。

## 6. 主要结论与发现

- **WER显著提升智能体的技能使用效果**：BFCL v4上相对于No Skill基线提升7.80个百分点（68.83%→76.63%），τ2-bench上提升3.85个百分点（46.87%→50.72%）。
- **专门训练是必要的**：相同的改进工作流下，未训练的Qwen3-4B优化器在两个基准上均低于No Skill基线；经WER训练后，同一骨干分别提升9.35（BFCL v4）和10.29（τ2-bench）个百分点。
- **小模型可以超越大模型的通用推理**：训练后的4B优化器（76.63%）在BFCL v4上超过所有现成通用模型（最佳为GPT-5.5的74.75%），说明技能改进能力可被专门训练压缩进入小模型。
- **多阶段训练有增量收益**：平均Pass@1随训练阶段单调上升（69.35→71.29→76.63），证实跨阶段自举的独特价值。
- **推理时改进深度收益饱和**：两轮改进几乎带来全部增益（67.28→76.63），第三轮反而轻微下降（75.33），说明早期改进最有效、后续逐渐饱和——改进链深度是推理时的自由选择。
- **逐轮改进针对不同失败模式**（定性）：种子技能两轮rollout全失败（0/2）→ 第一轮修复文件创建→ 仍有一个rollout聚合出错（1/2）→ 第二轮修复聚合逻辑（2/2全通过），直观展示了执行暴露的渐进修正。

## 7. 优点

- **问题定义精准**：明确区分"写技能"与"改进技能"两种能力，把技能优化定义为独立于执行器的可学习策略，并设计了完整的状态表示（x = q, C, h, s, e）。
- **严格的信用归因隔离**：执行器完全冻结意味着候选技能之间的结果差异只能归因于文档文本差异，排除了行动者变化的混淆；程序化验证器杜绝了"模型自评"的自我确认陷阱。
- **精细的训练数据构造**："只保留混合结果样本"（success/fail匹配对）的设计十分巧妙——在固定技能与任务下，成败轨迹的差异精确地局部化了技能欠约束的行为分支，为下一轮改进提供了最可操作的学习信号；原始轨迹不压缩地拼接，保留完整诊断信息。
- **方法适配性好**：优化器仅操作文本，动作空间不依赖工具环境接口，可以合并多个benchmark的训练数据联合训练，支持跨benchmark泛化。
- **无KL/参考策略的GRPO设计**具有合理性——技能优化器需要学习基础模型没有的输出分布（特定格式与修改风格），锚定到初始化反而有害。

## 8. 不足与局限

- **基准覆盖偏窄**：目前仅在BFCL v4 multi-turn和τ2-bench两个**具备程序化验证器**的基准上评估，未验证在开放式评估、未见工具接口、不同执行器模型上的迁移能力。
- **状态可扩展性瓶颈**：构造下一阶段状态时原样保留匹配成败轨迹，随着任务交互变长、轨迹变复杂，状态尺寸线性增长，尚未验证在更长周期任务、多模态轨迹或大型技能库上的可扩展性。
- **测试集规模有限**：BFCL v4测试集仅150例、每个域约37例，结果方差较大；虽然3次平均缓解了部分波动，但依据小样本的域级结论仍需谨慎。
- **计算成本未透明化**：未报告训练时长、总NPU时数及GPT-5.1/GPT-5.5辅助模型的使用成本，不利于复现和产业落地评估。
- **部分设计选择的依据可更充分**：例如保留"恰好中间结果"的标准（n=2下恰好1/2成功）在实际训练中可能过滤掉大量信息（全成功样本中的成功经验也无法利用）；Rfmt退火策略的具体调节方式没有完整报告；超参数（K、n、阶段数P=3）的敏感性分析缺失。
- **推理时合并阶段引入新变量**：GPT-5.5将WER优化器输出的多个技能合并为领域技能这一环节本身可能引入性能损失或增益，而论文未隔离这一合并器的独立影响。
