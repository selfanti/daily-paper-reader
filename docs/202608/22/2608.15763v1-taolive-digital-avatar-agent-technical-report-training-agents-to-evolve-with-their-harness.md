## 摘要
在直播电商中，基于AI的数字虚拟主播必须实时回答产品问题、吸引观众并执行不断变化的商业策略。这要求低延迟、事实准确且有效的回复，并快速适应更新的活动、合规和风格要求。我们开发了一个可演进的配套系统（Harness），将技能、钩子、系统提示和工具与模型权重解耦，允许在不重新训练的情况下改变运行时行为。然而，配套系统的演进创造了一个动态的执行环境：在单一配置上微调的紧凑模型可能记住名称、模式和提示模板，而不是遵循当前提供的配套系统，而更强的零样本模型对于实时使用来说太慢。我们通过配套系统感知训练（HAT）来解决这一矛盾，该方法将配套系统状态纳入训练分布。HAT对技能、工具模式、提示结构和交互约束应用保留任务的配套系统状态增强（HSA），并包括三个阶段：基于HSA的监督微调、恢复通用能力的通用策略蒸馏，以及在生产信息模拟的直播间环境中进行基于HSA的智能体强化学习。在超过4,500个案例的四个评估集上，我们的紧凑型35B模型在真实世界直播问答中得分为94.8，而基础模型为80.3，最强的评估通用大语言模型为93.0，同时在配套系统变体问答中得分为94.6，并在IFEval上保留83.5分。相比之下，固定配套系统的SFT使IFEval降低了7.7分。在一次启用MTP的受控完整智能体重放中，系统在单块NVIDIA H20 GPU上实现了3.407秒的P50和8.114秒的P95延迟。这些结果表明，HAT产生了一个延迟可行的紧凑智能体，在评估的配套系统变化下保持有效，而不牺牲通用指令跟随能力。

## Abstract
AI-powered digital-avatar streamers in live e-commerce must answer product questions, engage viewers, and execute changing business strategies in real time. This requires low latency, factual and effective replies, and rapid adaptation to updated campaign, compliance, and style requirements. We develop an evolvable Harness that decouples Skills, Hooks, system prompts, and tools from model weights, allowing runtime behavior to change without retraining. However, Harness evolution creates a moving execution environment: compact models fine-tuned on one configuration may memorize names, schemas, and prompt templates rather than follow the Harness currently provided, while stronger zero-shot models are too slow for real-time use. We address this tension with Harness-Aware Training (HAT), which makes Harness states part of the training distribution. HAT applies task-preserving Harness-State Augmentation (HSA) to Skills, tool schemas, prompt structures, and interaction constraints, and comprises three stages: HSA-based supervised fine-tuning, general on-policy distillation to recover general capabilities, and HSA-based agentic reinforcement learning in a production-informed live-room simulator. Across four evaluation sets with more than 4,500 cases, our compact 35B model scores 94.8 on real-world Live-Stream QA, versus 80.3 for the base model and 93.0 for the strongest evaluated general LLM, while scoring 94.6 on Harness-Variant QA and retaining 83.5 on IFEval. By contrast, fixed-Harness SFT reduces IFEval by 7.7 points. In a controlled complete-agent replay on one NVIDIA H20 GPU with MTP enabled, the system achieves 3.407 s P50 and 8.114 s P95 latency. These results show that HAT produces a latency-feasible compact agent that remains effective under evaluated Harness changes without sacrificing general instruction following.

## 1. 核心问题与研究动机

- 论文面向**直播电商中的 AI 数字虚拟主播**场景：数字人需实时回答观众问题、调用商品/促销/售后工具，并在严格延迟约束下执行不断变化的营销策略。
- 实际部署面临三个矛盾需求：
  - **超低延迟**：回复面向整个直播间，等待时间过长会严重损害体验；
  - **高频适应**：运营团队和商家频繁修改活动规则、合规要求、回复风格；
  - **准确且有效**：回复必须事实有据、避免幻觉，同时真正满足观众意图。
- 已有的 ReAct 式智能体或中心化提示词修改无法支撑快速迭代；重新训练模型周期过长。
- 作者提出可演化 **Harness**：将 Skill（技能）、Hook（钩子）、Prompt Pipeline（提示词流水线）、Tool Registry（工具注册表）与模型权重解耦，使业务行为可以在不重训模型的情况下快速更新。
- 但 Harness 演化带来新问题：模型面对的执行环境从“固定配置”变成“不断移动的目标”。强零样本大模型适应能力强但延迟过高；紧凑模型若只在单一 Harness 配置上做 SFT，则容易记住技能名、工具名、提示模板，而不是真正理解当前 Harness。
- 核心贡献是提出 **Harness-Aware Training (HAT)**，让紧凑模型在训练时暴露于多样的 Harness 状态，从而既能跟上 Harness 变化，又满足低延迟要求。

## 2. 方法论

### 2.1 总体思想

- 将 Harness 状态显式建模为：
  - \(h = (S, T, P, K)\)
  - \(S\)：活跃技能集合；
  - \(T\)：工具注册表（schema、参数、描述）；
  - \(P\)：系统提示词流水线；
  - \(K\)：Hook 集合。
- 训练目标不是拟合单一配置 \(h_t\)，而是让模型学会**以当前 Harness 为条件**进行决策，从而适应部署后出现的 \(h_{t+1}, h_{t+2}, \dots\)。

### 2.2 Harness-State Augmentation (HSA)

- HSA 对 Harness 施加保持任务语义的扰动，沿五个维度：
  1. **Skill 标识**：重命名技能、重写描述、增加干扰技能、随机遮蔽技能；
  2. **Skill 内容**：改写规则、随机遮蔽、调整规则顺序；
  3. **工具定义**：重命名工具、重写描述，使名称匹配不可靠；
  4. **系统提示词**：重排指令块、在有效范围内扰动数值约束；
  5. **Hook 行为**：改变重试逻辑、消息结构、Hook 触发方式。
- 目的：削弱模型对“固定名称/模板”的捷径依赖，迫使其利用 Harness 的语义功能信息。

### 2.3 模拟在线环境

- 构建生产信息驱动的直播间模拟器，包含：
  - 直播间输入模拟：商品咨询、闲聊、购买意图、售后、混合意图弹幕；
  - Harness 调度：加载 Skill、触发 Hook、多轮交互；
  - 工具执行模拟：基于生产目录快照，并注入超时、错误、权限拒绝等失败情形；
  - 增强 Harness 配置：模拟器使用 HSA 生成的状态，使离线与在线阶段处于同一变化包络内。
- 该环境使模型能获得“自身错误轨迹”的反馈，而不仅仅模仿教师轨迹。

### 2.4 强化学习目标

- 采用 GRPO 家族优化，奖励分为四维：
  - Accuracy（事实准确性）；
  - Effectiveness（意图满足度）；
  - Tool Rationality（工具调用链合理性）；
  - Skill Selection（技能选择正确性）。
- 使用 GDPO 进行分组奖励归一化，并加入**CoT 长度惩罚**：
  - 低于阈值 \(L_{low}\) 不惩罚，高于 \(L_{high}\) 饱和惩罚；默认 100/200 token；
  - 工具段和回复段分别计算，避免互相占用长度预算。
- 采用 GSPO 的序列级重要性采样，并用 PPO clip 目标稳定 MoE 训练；零优势样本在优化前丢弃。

### 2.5 三阶段训练流程

1. **HSA-SFT**：
   - 从真实直播间数据构造样本；
   - 使用原始 Harness 和多种 HSA 增强 Harness 生成教师轨迹；
   - 按 Accuracy/Effectiveness 过滤；
   - 对多数含 Hook 重试的轨迹只保留最终正确行为，但保留少量完整重试轨迹，以学习失败恢复。
2. **一般领域在线策略蒸馏（General OPD）**：
   - 以训练前 base 模型为教师，在 Tulu3 通用指令数据上做 on-policy distillation；
   - 最小化学生与 base 模型之间的 KL 散度，恢复域内 SFT 损失的通用指令跟随能力。
3. **HSA-RL**：
   - 在模拟直播间环境中进行 Agentic RL；
   - 每条 rollout 随机使用原始 Harness 或增强 Harness；
   - 使用上述 GDPO/GSPO/CoT 惩罚的强化学习目标；
   - 完整流程见 Algorithm 1：采样 → 切分工具/回复段 → 多维奖励 → 分组归一化 → 序列级重要性采样 → clip 更新。

## 6. 主要结论与发现

- HAT 训练的紧凑 35B 模型在 T1 Live-Stream QA 上达到 **94.8 AVG**，超过基础模型 80.3 和最强通用大模型 93.0；

- 避免了 Fixed-Harness SFT 带来的 IFEval 下降（后者下降 7.7/5.3 分），HAT 模型 IFE-P 为 83.5，仍高于 base 的 81.5；

- 消融显示：
  - General OPD 主要恢复通用指令跟随能力；
  - HSA 的主要收益来自 SFT 阶段（IFE-P +9.4），RL 阶段贡献相对较小（+1.0）；
  - HSA-RL 相比不加 HSA 的 Agentic RL 有更好平衡；
- Harness Evolution 本身显著提升了开发集指标（Accuracy 从 82.40 到 92.55，Effectiveness 从 87.16 到 92.75），但过程非单调，需要人工早停；
- 人工盲测中，35/36 个有效偏好样本偏向 Harness 系统；
- 线上 A/B 初步快照显示 Harness 系统相对 ReAct 的 GMV/用户提升 5.54%，订单/用户提升 0.80%。

## 7. 优点

- **问题定义清晰**：首次把“可演化 Harness”带来的环境漂移作为训练分布设计问题来处理，而不是简单归因于 prompt 或模型能力；
-

- **方法论系统且可操作**：HSA 的五维扰动设计覆盖了 Harness 的核心可变组件（技能、工具、提示词、Hook），不是零散的 data augmentation，而是对“模型应忽略什么、应依赖什么”的显式归纳偏置；三阶段流程（HSA-SFT → General OPD → HSA-RL）顺序合理，每个阶段都有明确的功能定位。
- **评测框架全面**：从真实业务（T1、部署重放）到合成鲁棒性（T2、T3），再到通用能力（T4）与线上指标（A/B），形成了“离线→回放→人工→线上”的完整证据链；多维度奖励函数（Accuracy/Effectiveness/Tool Rationality/Skill Selection）与延迟指标并重，避免了单一指标导向。
- **工程落地意识强**：论文不仅报告质量提升，还关注推理吞吐、延迟分位数、并发扩展、MTP 投机解码影响、15 秒到达率等工程指标，这些往往在学术论文中被忽略，但对生产系统至关重要。
- **写作结构清晰、信息密度高**：大量细节（数据规模、超参数、延迟分位数、Ablation 设计）以表格和算法伪代码形式给出，读者可以直接复现或借鉴。

## 8. 不足与局限性

- **训练资源信息不完整**：论文未报告训练阶段的总 GPU 数量、卡时、训练时长与集群配置，只说明推理使用单块 H20；读者无法评估该方法的性价比与可复现成本。
- **统计严谨性有限**：
  - 主表与多数消融结果为单次运行的 point estimate，未报告重训练方差或置信区间；
  - 额外的独立 bootstrap 检验使用另一组生成结果，不能完全替代对主表结果的直接推断；
  - Agentic RL vs Agentic OPD、HSA 阶段隔离等关键对比被明确标注为“描述性单次运行对比”，结论强度受限。
- **Judge 依赖风险**：T1/T2 的 Accuracy/Effectiveness 由 Harness-based Agent-as-a-Judge 评分，而该 Judge 本身也依赖 Harness 配置；若 Judge 对 Harness 变化的偏差未被完全校准（Cjudge 仅 482 条），主指标可能系统性偏移。
- **模拟环境与真实部署的差距**：在线 RL 依赖模拟直播间与模拟工具执行器，虽然基于生产数据快照构建，但观众行为多样性、工具失败模式、长尾交互（如仲裁、投诉、多轮砍价）可能被低估。
- **线上验证仍然初步**：A/B 为 7 天快照，未报告显著性检验、置信区间、样本量、以及 Harness 系统相对 ReAct 的成本对比；GMV/用户提升 5.54%、订单/用户提升 0.80% 是否稳健尚待更长周期验证。
- **人工评测规模有限**：人工盲测仅 100 例（有效 36 例），虽然比例占优（35/36），但样本量小，无法支撑细粒度错误分析。
- **缺少对失败模式的深入分析**：论文未系统分析 HAT 模型在哪些类型的观众问题（如反事实推理、复杂售后、跨工具长链任务）上仍会失败，也未报告 T1/T2 中具体错误分布。

## 9. 启示与借鉴意义

- **“环境即分布”是可行的范式**：本文将 Harness 演化类比为数据分布漂移，用训练期分布设计来应对部署期环境变化，这一思想可推广到任何“提示词/工具/技能频繁更新”的 LLM 系统（客服、编程助手、企业 Copilot）。
- **轻量模型 + 高质训练优于重模型 + 强推理**：35B-A3B 紧凑模型通过 HSA-SFT + RL 达到并超过 DeepSeek-V4-pro 等强通用模型在领域内的表现，说明在交互型业务中，针对环境变化的训练可能比模型规模扩展更经济。
- **SFT 阶段的数据多样性比 RL 阶段更关键**：消融显示 HSA 的主要收益（+9.4 IFE-P）来自 SFT 阶段，这提示若要成本优先，可先强化 SFT 阶段的 Harness 扰动，RL 作为精细调节。
- **通用能力需要主动保护**：Fixed-Harness SFT 导致 IFEval 明显下降（-7.7/-5.3），而 General OPD 作为训练后恢复步骤有效解决了该问题；任何领域 SFT/RL 都应将通用指令跟随能力作为显式约束，而非默认保留。
- **延迟是智能体训练的真正约束**：论文将 CoT 长度、MTP、15 秒到达率纳入训练与评测，说明在直播这类实时场景中，模型不仅要“回答对”，还要“回答快”；这为未来智能体训练目标设计提供了参考。
- **模拟器是数据飞轮的催化剂**：生产信息驱动的模拟器使离线 RL 能在无真实交互成本的情况下提供自身错误轨迹反馈，这一思路可复用于其他难以在线上探索的智能体系统。

## 10. 总结

该论文系统解决了实时数字人直播场景中“可演化 Harness + 紧凑模型”的适配问题，通过 HSA 将 Harness 状态多样性注入 SFT 与 RL，结合顺序分段的 GRPO 优化与 CoT 长度惩罚，在降低延迟的同时达到乃至超越强通用模型的业务质量，并保持了通用指令跟随能力。尽管存在训练资源信息不完整、统计检验与线上验证仍较初步等不足，但其方法论完整、评测全面、工程可落地性强，为 LLM 智能体在动态生产环境中的训练范式提供了有价值的参考。
