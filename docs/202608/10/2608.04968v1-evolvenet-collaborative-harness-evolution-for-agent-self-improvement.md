## 摘要
LLM智能体的能力不仅取决于其模型，还取决于其工具链：即构建上下文、调用工具、验证结果并从失败中恢复的可执行程序。近期研究表明，在不更新模型权重的情况下进化工具链可带来持续改进。然而，现有方法假设所有执行经验都可以路由到单一优化器，该优化器沿顺序轨迹进化一个工具链。真实的智能体生态系统违背了这一假设：用户、组织和环境产生孤立的经验流，无法合并，因此最值得学习的经验恰恰是无法直接集中的经验。我们提出EvolveNet，一种协作式工具链进化范式，将经验提取移至数据端。共享工具链被广播到数据本地的智能体部署中，每个部署在其自身工作负载上进化该工具链。只有最终的程序适配被组合成更新后的共享工具链并重新分发，从而每个参与的智能体都能继承其他智能体发现的操作经验。通过将聚合边界从原始工作负载转移到学习到的适配，EvolveNet保持工作负载本地化，并允许多个进化搜索并发进行，同时减少串行深度。由于独立修改的程序无法像模型参数那样平均，并且在组合时可能冲突，EvolveNet引入了作用域类型化、证据引导的程序聚合。在涵盖文本到SQL、数据科学编程、竞争性编程、软件工程和智能体工作流的五个设置中，EvolveNet在所有五个设置中均改进了共享工具链，在异构工作负载下收益最大，消融实验将改进归因于来自不同智能体的适配组合，而非从中选择。

## Abstract
The capabilities of an LLM agent depend not only on its model but on the harness: the executable program that constructs context, invokes tools, verifies results, and recovers from failure. Recent work shows that evolving the harness yields persistent improvements without updating model weights. Existing approaches, however, assume that all execution experience can be routed to a single optimizer, which evolves one harness along a sequential trajectory. Real agent ecosystems violate that assumption: users, organizations, and environments generate isolated streams of experience that cannot be pooled, so the experience most worth learning from is exactly the experience that cannot be directly centralized. We introduce EvolveNet, a paradigm of collaborative harness evolution that moves experience extraction to the data. A shared harness is broadcast to data-local agent deployments, each of which evolves it on its own workload. Only the resulting program adaptations are composed into an updated shared harness and redistributed, so that every participating agent inherits operational experience discovered by the others. By shifting the aggregation boundary from raw workloads to learned adaptations, EvolveNet keeps workloads local and allows multiple evolutionary searches to proceed concurrently with reduced serial depth. Because independently modified programs cannot be averaged like model parameters and may conflict when composed, EvolveNet introduces scope-typed, evidence-guided program aggregation. Across five settings spanning text-to-SQL, data-science coding, competitive programming, software engineering, and agentic workflows, EvolveNet improves the shared harness in all five, with the largest gains under heterogeneous workloads, and ablations attribute the improvement to composition of adaptations from different agents rather than to selecting among them.

# EvolveNet 论文详细中文总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题**：LLM 智能体的能力不仅取决于其底层模型，还取决于其"工具链"（harness）——即构建上下文、调用工具、验证中间结果、从失败中恢复的可执行程序。已有研究证明，在不更新模型权重的情况下进化工具链可以获得持久的性能提升，但这些方法大多遵循**集中式范式**：所有工作负载、执行轨迹和行为反馈必须汇聚到单一优化器中，沿单条顺序轨迹进化一个工具链。

**现实矛盾**：真实智能体生态是天然分布式的——用户、组织、数据库、代码仓库和工具环境各自产生**彼此隔离的经验流**，无法被集中汇总。最有价值的经验恰恰是那些无法直接集中的经验。作者由此提出范式反转：与其先把包含经验的工作负载集中起来再学习，不如让每个部署先在本地把执行经验转化为改进后的工具链，再把程序适配（adaptations）进行聚合。

**整体含义**：通过将跨系统边界传输的对象从"经验负载"变为"经验的可执行表示"，EvolveNet 实现了真正的协作式工具链进化——多个部署并行探索不同的进化轨迹，各自发现的经验通过共享工具链的再分发被所有智能体继承。论文本质上是研究"许多智能体发现的改进如何在一个共享的可进化工件中累积"，而不是单个智能体如何自我改进。

## 2. 论文提出的方法论

### 核心思想
EvolveNet 将传统的"汇聚数据→集中进化"流水线替换为"本地进化→聚合程序"的循环（SPECIALIZE → AGGREGATE → REDISTRIBUTE）。每个客户端从不共享的 h(t) 出发，在自己的本地工作负载上独立进化出专家程序，服务器仅聚合返回的程序增量，通过行为验证后作为下一轮共享起点重新分发。

### 关键技术细节

**（1）公共基线的程序增量（Common-base program deltas）**：所有客户端从同一 h(t) 出发，贡献表示为 `Δ(t)_k = diff(h(t), h(t)_k)`。服务器在 h(t) 的逐字节副本上编辑，而不是从 K 个完整文件合成新程序。增量被分解为"机制"（mechanisms）——语义上连贯的适应行为（如执行重试规则、模式探测、输出格式约束）。

**（2）行为证据（Behavioral evidence）**：客户端比较 h(t)_k 与 h(t) 在本地工作负载上的逐项判定，报告：
- `F(t)_k`：由错转对的项（新获得的能力）
- `B(t)_k`：由对转错的项（丧失的能力）

**（3）作用域类型化组合（Scope-typed composition）**：每个候选机制 m 被分配作用域 `τ(m) ∈ {GLOBAL} ∪ {HOME(d_k)}`，规则为：
- **GLOBAL**：证据跨两个及以上领域，或属于无法本地化的领域无关失败模式（如输出格式错误、执行失败）；
- **HOME(d_k)**：证据仅来自某一客户端领域，以条件分支形式仅在该领域激活；
- **⊥（拒绝）**：证据仅来自单个数据项（属于单题怪癖而非一类问题）。

**（4）两条理论性质**：
- **命题 1（作用域隔离）**：若 HOME(d) 机制的语句仅在 `κ(x)=d` 守卫下可达，且不写守卫外读取的状态、不改守卫外应用的提示文本，则在非 d 领域的输入上，组合后的程序与不组合时行为完全一致。
- **命题 2（不相交作用域下的冲突消解）**：两个证据位于不同领域的客户端即使对同一行为做了相反修改，也无需二选一仲裁——双方在对方领域内均不可达。这是参数空间聚合无法实现的：坐标式组合无法让更新依赖未来的输入。

**（5）行为承诺与回滚（Behavioral commitment and rollback）**：候选共享工具链需在独立验证切片 Dval 上通过与上一轮 h(t) 的逐项对比，满足 `|Fval| ≥ |Bval|` 才被提交；失败时允许聚合器修订一次，再失败则回滚到 h(t)。门控只看翻转项而非总分差，保证提交轨迹在门控标准上单调不降。

**（6）算法流程（Algorithm 1）**：
1. 服务器广播 h(t) 至 K 个客户端；
2. 客户端并行执行本地进化（h(t)_k ← LOCAL EVOLVE）、计算增量 Δ(t)_k 与行为证据 e(t)_k；
3. 服务器执行作用域聚合得到候选 eh(t+1)；
4. 在 Dval 上与 h(t) 逐项比较；
5. 若 |Bval| > |Fval| 则修订一次并重新比较；
6. 通过则提交为 h(t+1)，否则回滚至 h(t)。

**（7）串行深度优势**：集中式串行执行 K 个本地搜索需 `Σ C(t)_k + C(t)_A + C(t)_val`，而 EvolveNet 的串行深度为 `max_k C(t)_k + C(t)_A + C(t)_val`——由最慢客户端而非客户端数量总和决定。

## 6. 论文的主要结论与发现

1. **共享工具链在全部五个设置上均获改进**：BIRD +13.4 点（57.3→70.7%）、DS-1000 +13.0（55.5→68.5%）、LiveCodeBench +33.4（33.3→66.7%）、SWE-bench +20.0（37.5→57.5%）、ClawEval +8.3（65.8→74.1%）；所有改进均通过配对显著性检验并经 Holm 校正。
2. **组合优于选择**：EvolveNet（68.5%）> GLOBAL-only（66.5%）> Delegation（64.0%）> Select-best（59.5%）> Unevolved（55.5%）；消融证明增益主要来自机制被提升为全局共享行为，领域条件化额外贡献 2.0 点。
3. **经验确实跨智能体累积**：90%（18/20）的客户端独有增益被合并工具链保留；合并程序产生了无任何单一客户端达到的行为（2 项）；在无客户端训练的 Pytorch 库上 EvolveNet 仍超过所有基线（10/15 vs 8/15），证明存在跨领域迁移。
4. **优于集中式进化**：等预算下 EvolveNet 达 70.7%，集中式种群仅 67.3%；集中式基线出现停滞和回滚，而协作式分解使五个专业机制族并发发展。
5. **模型无关**：换用 MiMo-V2.5 后定性行为完全复现（最终 72.7% vs 未进化 62.7%）。
6. **异构负载
