## 摘要
Macaron-V1 是一个面向体验智能的开放智能体-模型家族：从真实环境中的经验中学习，并在部署后持续学习。它围绕两个系统目标组织。适应性通过版本化模型-测试工具对的递归改进来实现，其中来自一种配置的经验在外部契约下进行评估，并用于构建其后续版本。协作则通过冻结基础模型、组合专家LoRA适配器并在每次用户交互时选择一个LoRA的混合LoRA（Mixture-of-LoRA, MoL）架构来实现。旗舰模型 Macaron-V1-Venti 将744B的GLM-5.2基础模型与四个分别用于聊天、智能体、编程和GenUI的LoRA相结合；基于Qwen3.6的Macaron-V1-Tall（50B）采用相同设计用于本地部署。本报告将Macaron-V1呈现为一个涵盖架构、算法和基础设施的协同设计系统。MoL架构通过可扩展的LoRA专家支持持续学习。该算法结合了模型-测试工具协同设计（Model-Harness Co-design）与递归自我改进循环，包括UI4A组件原生GenUI测试工具、有状态动作基底、带版本控制的HCP契约，以及智能体强化学习框架MindForge。支持性基础设施包括后训练平台MinT、长上下文强化学习方法LongStraw，以及针对稀疏MoE和DSA基础模型的稳定性技术。我们在个人智能、GenUI和通用能力基准上，与前沿基线对比评估了Macaron-V1。我们的结果验证了当前系统，而持续学习和集体智能带来的复合增益仍是待解决的问题。

## Abstract
Macaron-V1 is an open agent-model family for experiential intelligence: learning from experience in real environments and continuing to learn after deployment. It is organized around two system goals. Adaptation is pursued through recursive improvement of versioned model-harness pairs, where experience from one configuration is evaluated under an external contract and used to construct its successor. Collaboration is pursued via the Mixture-of-LoRA (MoL) architecture that freezes a base model, composes specialist LoRA adapters, and selects one LoRA per user turn. The flagship Macaron-V1-Venti combines a 744B GLM-5.2 base with four LoRAs for chat, agent, coding, and GenUI; the Qwen3.6-based Macaron-V1-Tall (50B) uses the same design for local deployment. This report presents Macaron-V1 as a co-designed system spanning architecture, algorithms, and infrastructure. The MoL architecture supports continual learning through extensible LoRA specialists. The algorithm combines Model-Harness Co-design and recursive self-improvement loop, including the UI4A component-native GenUI harness, a stateful action substrate, versioned HCP contract, and the agentic RL framework MindForge. The supporting infrastructure includes the post-training platform MinT, the long-context RL method LongStraw, and stability techniques for sparse MoE and DSA base models. We evaluate Macaron-V1 on Personal Intelligence, GenUI, and general capability benchmarks against frontier baselines. Our results validate the current system, while compounding gains from continual learning and collective intelligence remain open questions.

## 二、方法论：核心思想、关键技术细节与流程

### 2.1 总体设计原则
- 主张“模型能力靠单一检查点扩展”不是全部路径；MoL 将能力扩展分解为：基础模型规模、模型外部的工具/脚手架、以及可插拔 LoRA 专家的组合。
- 核心规则：**将技能和思维模式相近的任务聚类到同一个 LoRA；将差异较大的任务分到不同 LoRA**，以减少共享参数中的跨任务干扰。

### 2.2 MoL 架构（Mixture-of-LoRA）
- 冻结大基座（如 Venti 的 GLM-5.2 744B），在其上挂载 4 个 LoRA 专家：
  - L0：Chat（对话/指令遵循/身份，兼作路由入口）；
  - L1：Agent（长程工具使用、个人代理工作流）；
  - L2：Coding（代码生成、SWE、终端）；
  - L3：GenUI（UI4A 渲染与 UI 驱动动作）。
- 没有单独训练路由模型，而是由入口适配器 L0 在每轮用户请求时，通过受限解码（24 token 预算）输出唯一路由标签（L0–L3），称为 **路由环**：Route → Answer → Summary。
- 路由环还包含 tool-result 短路锁定、事务回滚（引擎故障时恢复对话状态）等机制。
- 每个适配器有独立的“own-view”对话视图：自己的历史轮次完整保留，其他适配器的轮次压缩为 192 token 摘要；确定性重建保证 KV 缓存前缀复用，降低路由切换成本。
- KV 缓存复用分两层：
  - 第一层（生产路径）：基于稳定 own-view 的原生前缀缓存命中；
  - 第二层（实验性）：同一请求内 L0 router 前缀与目标适配器解码前缀共享的 overlay。
- MoL 部署相比“复制四份基座”的方案，在逻辑存储参数上约减少 74%（MoL 约 774.8B 逻辑参数 vs 复制基座约 2.976T）。

### 2.3 模型–测试工具协同设计（Model–Harness Co-design）
- 将 harness（测试工具/运行环境）视为一等训练目标，强调训练与部署共享显式运行契约。
- 三个组成部分：
  1. **UI4A**：组件原生的生成式 UI harness。模型编写常规前端代码（import + component + state + Action），由运行时强制边界；相比 HTML-native 更可控，相比 schema-native 表达力更高。输出 token 数平均减少约 45%（1,224→672 token），配合非推理 LoRA 可达约 6× 更快的首屏渲染。
  2. **REPL Agent Harness**：有状态 Python 命名空间的“读-求值-打印循环”作为工具执行基底。支持“可执行组合”（中间值保留在运行时，不必每步回到模型）与“验证后复用”（save_tool / promote_tool 需通过私有验证集测试）。
  3. **Harness Context Protocol (HCP)**：版本化 TOML 契约，将运行时、模型、工具白名单、提示、技能、钩子、会话/工作区状态等序列化为可移植、可审计的配置。HCP 本身不承载梯度，但模型可以在语言空间内改写它所描述的 harness 配置。

### 2.4 递归自我改进（RSI）与 MindForge
- RSI 循环作为持续学习的主算法，分为三个阶段：
  1. **发现（Discovery）**：由当前模型在种子任务库基础上提出更难任务变体（提升约束、隐藏偏好、链式子目标、嵌入矛盾），并要求带可验证答案或评估准则；保留满足“质量”和“学习价值”（当前模型不能稳定解决）的任务。
  2. **扩展（Expansion）**：在固定模型–HCP 对下运行任务，评估器既评分任务结果也评分过程行为，形成轨迹（trajectories）；审计将失败定位到模型、任务或 harness 配置，并对 HCP 承载的资源（提示、技能、工具暴露、钩子）做候选修改，用受影响切片重跑验证。
  3. **更新（Update）**：对轨迹过滤（无效/重复/不具信息量的剔除），用 GRPO 更新 LoRA（基座冻结）；同时将接受的 HCP 注册为下一代的运行配置，由 MindForge 记录模型–配置–数据–评估之间的谱系。
- 公式化表示：策略 πϕ(a_t | o_{≤t}; θ, c)，其中 θ 冻结基座参数、ϕ 可训练 LoRA 参数、c 版本化 harness 配置；轨迹 τ = (o0, a0, …, oT, aT, y)。模型优化只改变 ϕ，配置搜索则选择新的 c。
- 基础设施配套：
  - **MinT**：模型状态谱系管理，提供不可变 adapter revision 导出、百万级 adapter 编目（实测 10^6 条目）等；
  - **LongStraw**：response-only 长上下文 RL 执行栈，可在大约固定 GPU 下完成 2M 甚至 4.25M token 的操作；
  - **稀疏基座错配控制**：R3（rollout 路由重放）、DSA 集成对齐、IcePop 式 token 级残差过滤。

### 2.5 关键扩展实验（Expansion 阶段）
- 在 122 个被冻结 GLM-5.2-FP8 基座全部失败的 TerminalBench 2.1 模拟任务上，仅修改 HCP 承载配置、不更新任何权重：
  - 自适应配置搜索最终达到 122/122 任务的累计覆盖；而两个“用单一配置扫描全集”的作业最多只通过 11/122（9.0%）。
  - 论文明确说明这是“配置搜索覆盖”，而非完整 RSI 训练循环带来的能力提升。

## 三、实验设计：数据集 / 场景 / 基准与对比
