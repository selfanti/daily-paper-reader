## 摘要
基于记忆的自我改进代理——那些从在线任务流中学习并通过维护文本记忆库随时间改进的代理——在最近的文献中显示出巨大潜力。然而，这些方法的可靠性方面被严重忽视。在这项工作中，我们对两种基于记忆的方法进行了全面重新评估，沿两个维度扩展了评估范围：（1）包含多次运行以量化方差，（2）随机打乱任务顺序以研究任务顺序的影响。通过这些实验，我们得出两个揭示当前方法脆弱性的观察结果：首先，在复杂环境和多步骤任务中，代理评估固有地存在噪声，而在其上叠加自我改进循环会进一步放大这种噪声。其次，代理的改进高度依赖于任务顺序。先前的工作通常采用默认顺序，这施加了隐式的课程，成为成功的隐藏先决条件。为了更好地理解这种脆弱性，我们手动检查代理的记忆，并假设任务和环境欠规格化导致了这种脆弱性。我们通过在记忆构建过程中纳入能够实现更好规格化的信息（如详细评分标准和环境反馈）来验证这一假设。虽然这些添加的信息部分弥补了先前实验中的性能下降，但显著差距仍然存在，这表明其他未表征的因素也导致了这种脆弱性。展望未来，我们的工作倡导对自我改进代理采用更严格的评估协议，报告多次运行的结果并在具有挑战性的条件下进行压力测试。此外，我们关于欠规格化的发现呼吁建立能够实现有效人类监督的系统和接口，防止代理以不可预见的方式失败。

## Abstract
Memory-based self-improving agents--those that learn from an online stream of tasks and improve over time by maintaining a textual memory bank--have shown great promise in recent literature. However, the reliability aspects of these methods have been critically overlooked. In this work, we conduct a comprehensive re-evaluation of two memory-based methods, broadening the scope of evaluation along two axes: (1) including multiple runs to quantify variance, and (2) randomly shuffling the tasks to investigate the effect of task order. Through these experiments, we make two observations that expose the fragility of current methods: First, agent evaluation is inherently noisy in complex environments and on multi-step tasks, and stacking a self-improving loop on top can further amplify this noise. Second, the agent's improvement is highly dependent on task order. Prior works often adopt default orderings that impose an implicit curriculum, acting as a hidden prerequisite for success.   To better understand this fragility, we manually examine the agents' memory and hypothesize that task and environment underspecification contribute to this fragility. We validate this hypothesis by incorporating information that enables better specification, such as detailed rubrics and environment feedback, into the memory construction process. While this added information partially closes the performance degradation in previous experiments, significant gaps still remain, suggesting that other uncharacterized factors contribute to this fragility. Looking ahead, our work advocates for more rigorous evaluation protocols for self-improving agents by reporting results across multiple runs and stress-testing them under challenging conditions. Moreover, our findings on underspecification call for systems and interfaces that enable effective human oversight, preventing agents from failing in unforeseeable ways.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：记忆型（memory-based）自我改进智能体是近年来的热门方向，这类系统通过在线任务流中积累文本记忆，随时间推移自主提升性能，在自动化工作流、经济价值创造和开放式研究探索方面展现出巨大潜力。代表性方法包括 Agent Workflow Memory (AWM) 和 ReasoningBank (RBank)。
- **核心问题**：现有文献对这类方法的**可靠性**关注严重不足。在实际部署场景（如企业应用）中，系统对错误的容忍度极低：初期失败可能失去用户信任，且初始错误可能在长期运行中静默级联，造成不可逆或高代价的影响。
- **本文动机**：在部署前，必须在真实、富有挑战性的条件下批判性评估这些系统的可靠性。本文针对 WebArena、VisualWebArena 和 SCUBA 三个基准对两种代表性方法进行重评估，并沿**多次运行（量化方差）**和**任务随机化（考察顺序效应）**两个维度扩展评估范围。
- **整体含义**：研究揭示当前自我改进智能体方法存在严重的脆弱性——评估噪声被放大、性能依赖任务顺序、任务与环境欠规格化导致错误记忆的传播。论文呼吁建立更严格的评估协议并开发支持人类监督的系统。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **研究对象**：两种记忆型自我改进方法——
  - **Agent Workflow Memory (AWM)**：任务结束后从成功轨迹中总结可复用的工作流，存入记忆库，去重后全部纳入后续任务的上下文。
  - **ReasoningBank (RBank)**：从成功和失败轨迹中均生成通用推理痕迹和见解（不限于结构化工作流），通过检索器选取最相关的历史记忆进行条件化。
- **评估框架**：在更强基线（GPT-5-mini 模型 + 更新 agent harness）之上，对上述方法进行两个维度的扩展评估：
  - **多次运行**（每次实验 3 次相同运行），量化 run-level 统计量（均值和标准差、最好-最差差距）。
  - **随机任务顺序**（默认顺序 + 2 种打乱顺序），研究任务到达顺序的影响。

  1. **Rubrics and Scores (+Rub)**：提供评估函数（must_include、exact_match、fuzzy_match 等）和得分，澄清任务意图。
  2. **Environment Feedback (+Env)**：加入动作执行是否成功等环境反馈，避免重复 UI 交互错误。
  3. **Prompt Modification (+PMod)**：明确禁止生成不支持的行为（API 调用、请求人类确认等），鼓励生成程序性知识和站点导航结构。

### 6. 论文的主要结论与发现

1. **自我改进方法放大评估方差**：在 24 个案例中有 17 个（≈71%）观察到叠加自我改进循环后方差增加，其中 11 个案例相对增幅超过 50%。标准差最高达 3.9%，最好-最差运行的差距在 Map 域达到 8.2%、GitLab 域达到 7.8%。
2. **任务顺序是隐藏的"成功先决条件"**：默认顺序（按任务 ID 排序）呈现隐式易到难课程。在默认顺序下 RBank 平均提升 1.5%，而在随机打乱顺序下变为下降 4.5%（WebArena）。8 个案例中有 6 个在打乱顺序下显著恶化。
3. **强基线下的效果递减**：GPT-5-mini 无记忆基线（WebArena 54.8%）已超过先前使用更强模型（Gemini-2.5-Pro）配合 RBank 的记忆增强结果（53.9%）。在此背景下 AWM/RBank 均未产生统计显著的提升（p=0.23）。
4. **欠规格化是脆弱性的潜在驱动因素**：
   - 环境欠规格化导致代理反复记忆并检索对"API 调用""请求用户确认"等环境不支持的动作（WebArena 3 次运行中出现 26 次"user confirmation"提及）。
   - 任务欠规格化导致误解、过度思考和错误记忆的跨任务传播（如"下颌磨牙症"任务和 evaluator bug 示例）。
   - "记忆传染"现象：Haversine 公式作为网站的 fallback 策略被偶然奖励后，在记忆中被反复放大，加剧运行间方差。
5. **补充信息仅部分缓解**：+All 设置（+Rub、+Env、+PMod）在 Shuffle-1 下将 RBank 从 49.8% 提升至 52.7%（恢复了 31% 的性能下降），对 Default 顺序无负面扰动。但仍有 69% 的差距未得到解释，说明存在其他未表征的脆弱性因素。

- **研究问题重要且及时**：定位到自我改进智能体可靠性这一被忽视但关键的问题，与社区对评估科学和可靠性的关注高度呼应。

### 8. 不足与局限

- **方法覆盖不足**：仅评估两种方法（AWM 和 RBank），且未包含最新的记忆管理技术（如 MemGPT、A-Mem 等），结论的普适性有限。

- **任务顺序的"公平性"问题**：打乱顺序实验中未说明这些随机顺序本身的难度分布特性，无法排除特定打乱顺序的偶然性带来的偏差。
