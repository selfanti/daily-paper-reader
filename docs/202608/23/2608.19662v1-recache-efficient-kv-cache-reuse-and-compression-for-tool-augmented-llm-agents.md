## 摘要
智能体语言模型会反复对工具和技能模式进行编码，这些模式以不同组合和顺序跨请求重复出现，这阻碍了标准前缀缓存对其键值（KV）状态的重用。我们引入了ReCache，一个独立缓存资源表示并降低其推理时计算与内存开销的框架。资源级注意力消除了跨资源交互，并分配资源局部位置，从而生成组合不变的KV块。然后，ReCache将资源可见性限制在基于贡献度选择的层-KV头组路径上，并通过结构和语义剪枝仅保留调用关键字段。我们在由七个公共工具和技能使用数据集（包括资源不相交测试）组成的基准上评估ReCache。资源级注意力与稠密调用性能相当（82.3%对82.4%的Inv-F1），同时提供了3.655倍的首令牌时间加速。完整框架将分配的KV张量内存减少了92.43%，并将注意力加速了1.423倍。这些结果表明，将可重用的模式编码与选择性资源访问分离，可以在有限的效果损失下大幅降低智能体推理成本。代码可在 https://github.com/EIT-NLP/ReCache 获取。

## Abstract
Agentic language models repeatedly encode tool and skill schemas that recur across requests in different combinations and orders, preventing standard prefix caching from reusing their key--value (KV) states. We introduce \textbf{ReCache}, a framework for independently caching resource representations while reducing their inference-time computational and memory overhead. Resource-wise attention removes cross-resource interactions and assigns resource-local positions, producing composition-invariant KV blocks. ReCache then restricts resource visibility to contribution-selected layer--KV-head-group routes and retains only invocation-critical fields through structural and semantic pruning. We evaluate ReCache on a benchmark assembled from seven public tool- and skill-use datasets, including resource-disjoint tests. Resource-wise attention matches dense invocation performance (82.3\% versus 82.4\% Inv-F1) while providing a 3.655$\times$ time-to-first-token speedup. The complete framework reduces allocated KV-tensor memory by 92.43\% and accelerates attention by 1.423$\times$. These results show that separating reusable schema encoding from selective resource access substantially reduces agentic inference costs with limited effectiveness loss. The code is available at https://github.com/EIT-NLP/ReCache.

## 1. 核心问题与研究动机

- **背景**：工具增强的智能体语言模型（Agentic LLM）在运行时需要动态调用外部工具（tools）和技能（skills），通常先检索与当前请求相关的模式（schema），再拼接到上下文中。这类“资源”（resource）模式会在不同请求中反复出现，但组合方式和顺序各不相同。
- **核心问题**：
  - 标准前缀缓存（prefix caching）要求重复内容形成完全相同的上下文前缀，因此无法对动态组合、顺序可变的资源块实现KV（键值）状态复用，导致大量重复prefill计算和推理开销。
  - 即使独立缓存了资源，完整存储和访问所有资源KV状态仍会带来较高的内存与注意力计算成本。
- **核心洞察**：
  - 实验显示（Qwen3-4B），注意力主要集中在单一资源内部，跨资源注意力显著较弱；
  - 后续对话token对资源的注意力主要集中在其尾部token，说明资源内部语义比全局顺序更重要；
  - 工具/技能调用失败通常源于名称或参数错误，因此压缩时需保留关键接口字段，而不能像通用文本压缩那样只保留粗略语义。

## 2. 方法论：ReCache框架

ReCache由三个递进阶段组成，整体思路是**在编码阶段保持信息完整并生成可复用KV块，在推理阶段通过选择性访问和压缩来降低开销**。

### 2.1 资源级注意力（Resource-Wise Attention）

- 消除不同资源块之间的注意力交互，使每个资源在编码时只关注共享前缀及其自身内部token。
- 对每个资源重置位置索引为局部相对位置（`pos(t_{i,j}) = j`），使KV块与资源在提示中的全局顺序和组合方式无关。
- 效果：
  - 注意力复杂度从 \(O(D_R^2)\) 降为 \(O(\sum D_i^2)\)；
  - 每个资源可被独立构造、缓存和复用，实现“组合不变”的KV块；
  - 通过轻量微调使模型适应这种注意力与位置模式，保持调用质量。

### 2.2 结构剪枝（Structural Pruning）

- **核心思想**：并非所有Transformer层和KV头组都对资源调用有同等贡献，只保留少数关键“层–KV头组”路径上的资源可见性。
- **路由定义**：设 \((l,g) \in \Omega \subseteq [L] \times [G]\) 为具有资源访问权限的层–KV头组路径。\(\Omega\) 之外的路径使用\(M_{\text{context}}\)，完全屏蔽资源token；\(\Omega\) 内的路径使用\(M_{\text{resource}}\)，允许访问保留的资源KV状态。
- **贡献度选择**：采用“leave-one-in”分析，从空配置Ω=∅开始，分别激活某一层或某一KV头组，衡量对invocation loss的边际降低：
  - 针对目标响应 span \(T(Y)\) 计算损失；
  - 定义层贡献 \(s_l\) 和头组贡献 \(s_g\)；
  - 归一化为权重 \(w_i = \frac{\max(s_i,0)}{\sum_j \max(s_j,0)}\)；
  - 按权重选取 Top-K 层和 Top-K 头组，最终路由为 \( \Omega^\star = L^\star \times G^\star\)。

### 2.3 语义剪枝（Semantic Pruning）

- **保留字段**：对每个资源，保留三类关键信息：
  - 资源名称（resource name）：用于资源识别；
  - 参数名称（argument names）：用于参数接口对齐；
  - 参数描述（argument descriptions）：用于参数值约束；
  - 额外保留资源末尾的suffix token，作为语义聚合锚点（其因果状态已覆盖所有前序字段）。
- **删除字段**：资源描述、格式性字符及其他冗余内容；字段消融实验表明资源描述对调用的额外收益可忽略。

最终所有策略结合形成完整的ReCache掩码，使`Y`（目标调用）在解码时只能通过Ω\*路径访问保留后的资源字段。

## 6. 主要结论与发现

- 资源级注意力与稠密调用性能几乎无差距：Inv-F1 分别为 82.3% 与 82.4%，ID-F1 均为96.0%，同时TTFT加速3.655×。
- 去除跨资源注意力和全局位置信息不会损害工具调用有效性，说明对这些任务而言，资源内部语义比跨资源关系和顺序更重要。
- 结构剪枝效果：
  - 贡献度选择优于注意力质量选择：在层预算20时，Ω_{20,G}比Ω_full+SPEED在TIND高出3.2%Inv-F1，在TOOD高出10.0%；
  - 联合剪枝Ω_{20,3}比SA_{20,3}在TIND和TOOD分别高出3.0%和5.0%；
  - OOD幻觉率从SPEED的13.4%和SA的5.1%降至0.5%，说明贡献度路由在资源变化时更具鲁棒性。
- 语义剪枝效果：
  - 通用压缩方法（Gist/Beacon）无法保留工具调用所需的细粒度接口信息，Inv-F1显著下降；
  - 字段级语义剪枝（保留资源名、参数名、参数描述和suffix token）几乎不影响有效性，而资源描述贡献极低。
- 完整ReCache：
  - KV-tensor内存减少92.43%；
  - 注意力延迟加速1.423×；
  - TIND上保留Dense性能的97.5%（Inv-F1 80.3%），TOOD上保留91.8%（60.8%）。
- 随资源长度增长（最高≥10K token），ReCache的TTFT、TPOT、注意力和KV内存均保持近恒定，尤其是KV内存被限制在0.03 GiB，远低于Dense的约8 GiB，表明其适合动态、大规模资源池场景。
- 结构预算对模型规模敏感：Qwen3-4B只需3个KV头组，Qwen3-1.7B则需要7个；贡献度分布说明了不同尺寸模型对并行KV头组冗余度的差异。

## 7. 优点

1. **问题定义清晰且有针对性**：精准命中了工具增强智能体中“重复编码 + 动态组合 + 前缀缓存不可用”的关键痛点。
2. **方法设计简单高效**：用“资源级注意力 + 位置重置”一个机制同时解决组合变化和顺序变化，不依赖复杂的额外位置补偿或选择性重算，工程实现和推理集成都相对容易。
3. **多维压缩结合自然**：结构维（层/头组路由）与语义维（关键字段保留）正交组合，后量化剪枝对KV内存和注意力计算的影响可以叠加，形成较大的总体压缩率。
4. **选择标准具有可解释性和稳定性**：以预测损失的边际贡献作为路由依据，比常见的注意力质量选择更可靠，且在OOD上表现出明显更低的幻觉率。
5. **关注资源语义特殊性**：针对工具调用的结构字段特征设计压缩方案，优于将资源视作普通文本的通用压缩方法；suffix token作为“天然summary”的设计也很巧妙，无需额外训练新token。
6. **实验设计审慎**：包括资源级OOD池、多样性优先采样、配置签名去重、完整结构/语义消融，以及效率随资源长度的鲁棒性分析，提升了结论的可信度。
7. **开放型良好**：代码开源，便于复现与后续扩展。

5. **数据预处理可能引入偏差**：
   - 构建统一benchmark时进行了大量过滤和重平衡，剔除了相当比例原始数据，可能改变数据分布和难度特征；
   - OOD池只保留低频率资源，可能使OOD评估偏向“稀有工具”而非“随机新工具”。
6. **效率指标的测量粒度**：
   - TTFT和TPOT包含其他计算环节（如投影、FFN），结构/语义剪枝的单独贡献主要靠Attn.指标量化；
   - 注意力延迟与KV内存的对比以Dense为基准，但未对CPU/GPU内存带宽、batch调度、并发场景等真实服务因素做系统分析。
7. **对语义剪枝的抽象依赖**：
   - 保留字段的假设（“资源名、参数名、参数描述足够”）基于当前测试集；若资源描述中包含实际执行所需的重要约束（如权限、错误码语义），该方法可能失效；
   - 这提示其可能不适用于所有工具模式，需针对新数据重新验证保留字段配置。

## 结语

ReCache是一种面向工具增强型智能体的高效KV缓存重用与压缩框架，其核心贡献在于将资源模式的编码与运行时访问解耦，通过资源级注意力实现组合无关的KV复用，再结合贡献度结构剪枝和字段级语义剪枝大幅降低内存与计算开销。实验在覆盖分布内与资源不相交OOD的七个数据集基准上显示，该方法在几乎不损失调用性能的前提下获得了显著的TTFT加速和KV内存压缩。尽管存在模型覆盖、可训练性依赖与应用场景限制等不足，ReCache仍为动态工具调用场景的推理优化提供了一个兼具效率和可靠性的实用方案。
