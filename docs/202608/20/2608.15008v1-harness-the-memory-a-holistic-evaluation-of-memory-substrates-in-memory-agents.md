## 摘要
记忆正在成为长时程LLM代理的核心基础设施，然而现有评估对于在不同操作机制下应使用哪种记忆底物（即记忆表示和存储的底层介质）提供的指导有限。我们提出了一种对记忆增强代理的记忆底物进行受控测试评估的方法，涵盖密集和稀疏索引、文本记录、结构存储、层次存储、基于精炼的记忆、参数更新以及兼容激活的上下文机制。在三个主干模型和四个涵盖以用户为中心的问答和以代理为中心的决策的基准套件中，我们在统一测试框架下测量了26个性能和效率指标。结果表明，没有单一底物始终占优：广泛检索有利于长上下文事实问答，而过度检索可能通过将注意力从行动关键上下文转移而损害顺序决策。可扩展性引入了进一步的路径选择维度，因为在中等问题历史长度下表现良好的底物在更长时程下可能变得昂贵或脆弱。这些发现促使底物路径选择成为自适应代理记忆系统的必要组成部分，并为设计高效、可靠且具有机制意识的长时程LLM代理记忆提供了经验指导。代码将在接受后提供。

## Abstract
Memory is becoming core infrastructure for long-horizon LLM agents, yet existing evaluations offer limited guidance on which memory substrate, namely the underlying medium in which memory is represented and stored, should be used under different operating regimes. We present a controlled harness evaluation of memory substrates for memory-augmented agents, covering dense and sparse indices, text records, structural stores, hierarchical stores, refinement-based memories, parametric updates, and activation-compatible context mechanisms. Across three backbone models and four benchmark suites spanning user-centric question answering and agent-centric decision-making, we instrument 26 performance and efficiency metrics under a unified harness. Our results show that no single substrate consistently dominates: broad retrieval benefits long-context factual QA, while excessive retrieval can harm sequential decision-making by shifting attention away from action-critical context. Scalability introduces a further routing axis, as substrates that perform well at moderate history lengths can become costly or brittle at longer horizons. These findings motivate substrate routing as a necessary component of adaptive agent memory systems and provide empirical guidance for designing efficient, reliable, and regime-aware long-term memory for LLM agents. ### 2.1 整体框架：受控 harness 评估

- **核心思想**：将**记忆底物作为唯一实验变量**，在统一 harness（模型、提示词、辅助 LLM 设置）下隔离评测，以回答两个问题：
  1. 代理行为在多大程度上可归因于底物本身？
  2. 这种归因在不同操作机制间是否稳定？
- 采用 [19] 的外部/内部记忆分类法：
  - **外部记忆**：信息存储在模型外部数据结构（向量、文本记录、图、树、蒸馏抽象），通过显式读写操作访问。
  - **内部记忆**：信息编码在模型权重或 KV-cache 激活中，生成时隐式访问，无独立检索步骤。

## 6. 主要结论与发现

1. **没有单一底物在所有机制下占优**：
   - 在对话 QA 中，结构化图（M5）通常最优（如在 Qwen3-32B 上 P4=0.683），但在代理任务上被支配。
   - 精炼型记忆（M7）在具身规划（ALFWorld TSR=32.1% 为最高值）领先，但在 QA 上落后。
   - 这直接否定了"单一底物通用记忆"的设计思路。

2. **检索广度（retrieval breadth）在不同机制下效果相反**：
   - 长上下文事实问答中，检索深度 k 增加 → P4 单调上升（越多证据越好）。
   - 顺序决策中，k 增加 → 任务成功率下降（M7 从 k=1 的 32.1% 降至 k=5 的约 25%），步数增加（"游荡"现象）。
   - 注意力探针揭示机制：两种任务中增大 k 都会把注意力从任务上下文转移到检索块——但 QA 中答案在检索块里（有益），ALFWorld 中决策需要关注当前观察与合法动作（有害）。**问题不在"检索"，而在"答案住在哪里"。**

3. **可扩展性是第三条路由轴**：
   - 精炼型底物（M7、M8）质量随输入规模提升且延迟增长温和（固定大小技能束，读取成本与输入长度无关）。
   - 结构化底物（M4、M5）在 262K token 时图重建与实体抽取成本急剧上升，侵蚀其中等规模下的质量优势。
   - 内部激活底物（M10）质量随长度提升但读取延迟线性增长；权重底物（M9）缺乏选择性时间更新机制，在冲突消解上表现持续不佳。

4. **设计规则："用写深度换读广度"（trade read breadth for write depth）**——每次查询少检索条目，在写时投入更多进行提炼和结构化。

5. **成本是重尾分布且经常无回报**：复杂底物的高延迟（如 M5 在 BCB-Hard 上 28–46 秒/查询）经常不带来质量提升，高价机制只在机制与任务瓶颈匹配时才值得。

6. **通用记忆系统的路径**：不是设计更好的单一底物，而是**多底物/多代理系统**，按角色组合——精炼底物负责策展抽象、结构/文本底物负责保存事实、激活/平面底物负责保留原始体验——由 harness 按查询路由到与其负载区域对齐的底物。

## 7. 优点

- **受控实验的严谨性**：首次将记忆底物作为唯一实验变量进行隔离评测，统一模板、统一辅助 LLM、统一推理栈，这在记忆系统评估领域是显著的进步。
- **全景式覆盖**：11 种方法覆盖 7 个底物家族、3 个骨干模型、4 个基准、26 个指标，首次将部署关键成本（写成本、管理成本、压缩比、各阶段调用数）系统呈现。
- **跨机制对比的设计**：用户中心（问答）与代理中心（决策）的对比揭示了"同一操作在不同机制下效果相反"的深层规律，而非简单的好/坏排序。
- **诊断深度**：检索广度扫描 + 注意力探针的组合，提供了机制层面的解释（"注意力稀释但后果取决于答案所在区域"），而非仅停留在表面对比。
- **可扩展性分析**：将历史长度作为明确变量，识别出"中等长度表现好→长历史失效"的底物类型。
- **诚实的方法论披露**：明确标注对 M8、M11 的实现改动、排除 MemGPT/Mem0/Zep 的原因、离线池与评测池的语义对齐验证，增强了结果可信度。

## 8. 不足与局限

- **实验覆盖**：
  - M10 完全缺失于两个代理中心基准（上下文超窗），M9 与 Gemma 的 MoE 不兼容，M7 不适用于对话输入——因此部分底物 × 基准的组合从未被评测，"全景"仍有盲区。
  - 骨干模型全部是开源模型（Qwen、Gemma），而 81% 的既有系统使用 GPT 家族，结论对闭源前沿模型的推广性未知。
  - 辅助 LLM 固定为 GPT-4O-MINI，不同辅助模型下底物排序是否稳定未验证。
- **实现偏差风险**：
  - M8 用零样本 LLM 替代 PPO 控制器（作者声明是为了避免训练成本混淆比较，但改变了该方法的实际行为）。
  - M11 用逐话语重预填充替代 EpiCache 的原位 KV 编辑（受限于 Qwen3 混合注意力内核兼容性），可能低估原方法优势。
- **排除生产级系统**：MemGPT、Mem0、Zep 因辅助成本过高被排除在主比较之外，其核心思想仅由近似实现（M3、M5）代表，生产级管道中的具体优化不一定被捕捉。
- **评估的时间范围**：对话/任务历史虽长（最大 262K tokens），但论文未讨论真正的"终身学习"（跨数月/数年、跨任务类别漂移）场景。
- **注意力探针的普适性**：探针仅基于 Qwen3-8B 的一个模型、单头求和、上层注意力，结论在不同架构（如 Gemma 的 MoE）中可能有所不同。
- **潜在偏差**：LLM 裁判使用 GPT-4O-MINI 评估所有模型，不同骨干的答案格式/风格差异可能引入裁判偏差（论文附录提到但未做系统性裁判偏差校正）。
