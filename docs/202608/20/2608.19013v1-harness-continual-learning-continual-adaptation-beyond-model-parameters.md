## 摘要
持续学习在很大程度上以模型为中心，将模型参数视为随顺序经验变化的状态。现代智能体还可以通过由提示、记忆、工具、技能和路由规则组成的外部配置进行适应。由于这些内容共同塑造后续执行，即使模型被冻结，外部配置的更新也可能破坏先前可靠的行为。这引出了一个新问题：智能体如何在保留先前获得的行为的同时，持续改进模型外部的状态？我们提出了外部配置持续学习（HCL），这是一种新的持续学习范式，其中外部配置围绕冻结的基础模型演化，并将由此导致的先前行为丢失定义为外部配置级遗忘。我们通过四个面向执行的组件实例化HCL：任务接口、经验记忆、能力图和自适应路由器。我们进一步引入受保护的外部配置演化，将更新生成与状态提交分离。持续优化器基于执行后反馈提出候选外部配置，持续评估器仅在检查当前改进、历史保留和有效性之后，才提交最终的候选外部配置。在文本推理、多模态感知和开放世界交互上的实验展示了能力积累和故障恢复，在多个设置下相对基线取得了超过10%的相对增益。组件消融评估了每个配置组件的贡献，而受控的保留扫描揭示了可测量的外部配置级遗忘，并表明稳定性-可塑性权衡可以被明确调整。

## Abstract
Continual learning has largely been model-centric, treating model parameters as the state that changes with sequential experience. Modern agents can also adapt through a harness of prompts, memories, tools, skills, and routing rules. Because these contents jointly shape later execution, a harness update can disrupt previously reliable behavior even when the model is frozen. This raises a new question: how can an agent continually improve its state outside the model while retaining behavior acquired earlier? We formulate Harness Continual Learning (HCL), a new continual learning paradigm in which the harness evolves around a frozen foundation model, and define the resulting loss of earlier behavior as harness-level forgetting. We instantiate HCL with four execution-facing components: the Task Interface, Experience Memory, Capability Map, and Adaptive Router. We further introduce guarded harness evolution to separate update generation from state commitment. A Continual Optimizer proposes candidate harnesses from post-execution feedback, and a Continual Evaluator commits the resulting candidate harness only after checking current improvement, historical retention, and validity. Experiments on textual reasoning, multimodal perception, and open-world interaction demonstrate capability accumulation and failure recovery, with relative gains exceeding 10% over corresponding baselines in multiple settings. Component ablations assess the contribution of each harness component, while controlled retention sweeps reveal measurable harness-level forgetting and show that the stability--plasticity trade-off can be explicitly adjusted.

## 1. 核心问题与研究动机

- 传统持续学习（Continual Learning）以模型为中心，关注如何更新模型参数、表示或结构，以适应顺序到来的任务并缓解灾难性遗忘。
- 现代智能体（agent）不仅依赖模型参数，还依赖一个外部“harness”（外部配置层），包括提示词、记忆、工具与技能描述、路由规则等。即使基础模型被冻结，这些 harness 内容也会随交互经验演化，并直接影响后续行为。
- 论文指出一个被忽视的问题：**harness 更新可能破坏之前已可靠的行为**，例如记忆变化改变检索证据、技能修订改变工具调用、路由调整破坏已有成功工作流。这种在模型参数不变的情况下、由 harness 变化导致的行为丢失，被定义为 **harness-level forgetting（harness 级遗忘）**。
- 由此提出新的持续学习范式 **Harness Continual Learning（HCL）**：围绕冻结的基础模型，通过顺序更新 harness 状态来获取和保留能力，将持续学习的研究对象从模型参数扩展到模型外部的执行配置。

## 2. 方法论：核心思想与关键技术

### 2.1 总体框架

- HCL 将部署的 harness 状态形式化为四元组：
  \[
  H_n = (I_n, M_n, C_n, R_n)
  \]
  分别代表任务接口、经验记忆、能力图和自适应路由器。
- 交互过程：原始输入 \(u_n\) 经任务接口转换为结构化表示 \(i_n\)，再经路由器结合记忆与能力生成执行上下文 \(z_n\)，最终产生结果 \(y_n\) 与反馈 \(f_n\)。
- 更新过程分离为“生成—评估—提交”三阶段，只有通过评估的候选 harness 才会替换当前部署状态。

### 2.2 四个 harness 组件

| 组件 | 执行功能 | 可更新内容 |
|---|---|---|
| 任务接口（Task Interface） | 将原始交互转换为结构化输入（输入、目标、约束） | 提示词、任务模板、解析与规范化规则 |
| 经验记忆（Experience Memory） | 存储与复用交互经验 | 原始记忆（Raw Memory）和抽象记忆（Abstract Memory） |
| 能力图（Capability Map） | 提供外部操作与内部可复用技能 | 外部能力（API等）与从经验中提炼的内部技能 |
| 自适应路由器（Adaptive Router） | 检索记忆、选择能力、组织执行流程 | 路由提示、选择标准、工作流模板 |

### 2.3 受保护的 harness 演化（Guarded Harness Evolution）

- **持续优化器（Continual Optimizer）**：使用冻结的基础模型，根据部署的 harness 和交互反馈生成候选 harness。可同时修改多个组件，但采用固定顺序、逐组件生成最多 \(K\) 个备选，替换单个组件并评估，保留最高分可接受方案。
- **持续评估器（Continual Evaluator）**：根据三个标准决定是否提交候选：
  - **当前改进**：候选在当前任务验证集上的性能提升 \(\Delta_n \ge \delta_n\)；
  - **历史保留**：候选导致历史锚点（anchor）失败的数量 \(D_n \le B_n\)，其中 \(B_n\) 是历史损失容忍度；
  - **有效性**：候选通过语法、输出格式、工具使用等有效性检查。
- 提交决策：
  \[
  G_n^{(k)} = \mathbf{1}\left[(\Delta_n^{(k)} \ge \delta_n) \wedge (D_n^{(k)} \le B_n) \wedge (\forall \ell, v_{n,\ell}(\tilde{H}_{n+1}^{(k)}) = 1)\right]
  \]
  多个通过门控的候选按综合分数排序，最优者被部署；否则保持现有 harness。
- 通过调节历史损失容忍度 \(B_n\)，可实现不同稳定性—塑性平衡（如 \(B_n=0\) 为强稳定，\(B_n=\infty\) 为强塑性）。

### 2.4 与模型中心持续学习的联系

- 经验记忆对应基于回放的方法；能力图对应表示/模块化方法；路由器对应架构选择；优化器+评估器则类似优化/正则化思想，将“适应”与“保护”统一到同一演化过程中，而非相互分离的解决方案族。

## 3. 实验设计

### 3.3 评估指标

- 最终平均性能 \(Avg_T\) 和平均旧任务遗忘 \(Fgt_T\)：
  \[
  Avg_T = \frac{1}{T}\sum_{j=1}^T R_{T,j},\quad Fgt_T = \frac{1}{T-1}\sum_{j=1}^{T-1}\left(\max_{r\in\{j,\ldots,T\}} R_{r,j} - R_{T,j}\right)
  \]
- 遗忘仅在顺序更新的方法中计算；Zero-shot 和静态 harness 不计算遗忘。

## 6. 主要结论与发现

- HCL 能在冻结模型的情况下，通过 harness 演化实现**能力积累和故障恢复**：ALFWorld 上 Stability-HCL 和 Plasticity-HCL 分别达到 61.74% 和 62.98% 的平均成功率，明显高于静态 harness 的 47.12%；Minecraft 中 HCL 完成全部 50 个任务，静态 harness 只能完成 15 个。
- 存在可测量的 *harness 级遗忘*：如 Plasticity-HCL 在 ALFWorld 上平均遗忘达 10.94，而 Stability-HCL 仅为 2.64；文本流中 Plasticity-HCL 遗忘 0.07，Stability-HCL 为零。
- **稳定性—塑性权衡可显式调节**：只改变历史损失容忍度 \(B_n\) 即可在不同运行间切换适应与保留的强度；受控扫描显示，过度放宽保留约束（\(b=\infty\)）反而使最终性能下降（60.13% vs. 最优 63.46%），说明无约束的本地改进可能破坏后续可用的 harness 内容。
- 多模态流中，HCL 显著超越零样本和 DGG，尤其在检测与视觉定位上提升明显；VQAv2 是唯一零样本仍占优的任务，但 HCL 仍远高于 DGG。
- 消融显示任务接口和记忆更新贡献最大；能力图更新在纯多模态流中贡献相对较小，但在 Minecraft 这类技能密集型环境中可能更重要。

## 7. 优点与亮点

- **概念创新**：将持续学习的研究对象从模型参数扩展到模型之外的“harness”，提出新范式 HCL 和“harness 级遗忘”这一新问题，有理论贡献。
- **框架统一**：将记忆、技能、提示、路由等原有分散机制统一到一个连续演化的状态中，并借鉴模型中心 CL 的回放、表示、架构、优化/正则化思想，形成系统级方案。
- **机制可解释**：通过“候选生成—评估—提交”将历史保留显式纳入提交条件，并通过 \(B_n\) 定量控制稳定性和塑性，比隐式正则化更直观。
- **实验设计较全面**：涵盖开放世界交互和受控任务流，跨多种基础模型，且有基线对比、消融和参数扫描。
- **有效性验证**：结果展示了相对基线超过 10% 的增益；Minecraft 中的动作效率分析也支持“减少冗余执行”的直觉。

## 8. 不足与局限

### 8.1 实验覆盖方面

- 任务流长度有限（文本/多模态各 4 个任务），与真实智能体长期部署的规模有差距。
- 缺少对数百/数千个交互的长程评估；Minecraft 虽有 50 个任务，但也没有系统重放所有已完成任务。
- 不同场景使用了不同基础模型，导致跨场景结果不能直接可比，削弱了结论的通用性。

### 8.2 方法与机制方面

- 历史锚点集 \(A_n\) 规模有限，满足 \(D_n \le B_n\) 并不能保证测试集上无遗忘（实验中的残余遗忘正源于此）。
- 锚点选择和更新策略有一定人为设计，锚点组成比例、数量等超参未系统扫描。
- 当前改进阈值 \(\delta_n\)、有效性合规阈值为启发式设定，缺乏理论依据或敏感性分析。
- 候选生成依赖 LLM 逐组件搜索，评估需要重复运行历史和当前任务验证集，**评估成本高**，在复杂环境中可能限制可扩展性。
- 有效性检查依赖人工定义的规则；部分场景（如开放世界）很难全面覆盖“有效性”含义。

### 8.3 应用限制

- 该方法假设 harness 内容可解析、可版本化、可被 LLM 修改；无法适应那些难以用文本描述和验证的隐式技能/知识。
- 对历史保留的严格约束（\(B_n=0\)）可能使更新过于保守，降低在新任务上的塑性；用户需要根据任务需求手动调节权衡。
- 论文未讨论失败日志、候选方案被拒绝后的学习、以及多次拒绝是否会导致优化器偏离目标等问题。
