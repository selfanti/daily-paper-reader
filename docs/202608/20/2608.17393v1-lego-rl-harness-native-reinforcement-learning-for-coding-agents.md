## 摘要
针对编码智能体的强化学习日益依赖长时运行的智能体框架来管理工具集成、仓库上下文和执行反馈。然而，这些框架的原生执行环境与策略梯度训练天然不匹配：环境崩溃和奖励黑客行为会破坏结果信号，而训练-推理差异使回滚行为与策略更新脱节。为解决这一问题，我们提出了LEGO-RL，一个在不修改原生编码智能体框架内部控制流的前提下，将原生框架与可扩展策略梯度优化桥接起来的框架。LEGO-RL基于三大支柱：（1）通过进程内LLM代理实现忠实优化，捕获原始生成流以进行token级对齐，并在框架端压缩或重新序列化情况下进行稳健的训练端对数概率重计算；（2）通过可扩展沙箱编排实现可靠执行，具备镜像缓存和分阶段防御以缓解奖励黑客行为；（3）通过集成插件实现可观测训练，自动化验证与监控，并配以实时用户界面进行细粒度轨迹诊断。我们通过使用GSPO在三个原生编码智能体框架上训练稀疏MoE模型Qwen3.5-35B-A3B来评估LEGO-RL。在SWE-bench Verified上，LEGO-RL将Qwen3.5-35B-A3B在OpenHands SDK（64.0%提升至70.4%）、Claude Code（62.4%提升至68.2%）和OpenCode（57.2%提升至66.6%）上的表现均有提升，同时保持回滚-训练概率相关性高于0.99。

## Abstract
Reinforcement learning for coding agents increasingly relies on long-running agent harnesses to manage tool integration, repository contexts, and execution feedback. However, the native execution environments of these harnesses are inherently misaligned with policy-gradient training: environmental crashes and reward hacking corrupt outcome signals, while train-inference discrepancies decouple rollout behavior from policy updates. To address this, we present LEGO-RL, a framework that bridges native coding-agent harnesses with scalable policy-gradient optimization without modifying their internal control flow. LEGO-RL is built upon three pillars: (1) faithful optimization via in-process LLM proxying that captures raw generation streams for token-level alignment and robust trainer-side log-probability recomputation, even under harness-side compaction or re-serialization; (2) reliable execution via scalable sandbox orchestration featuring image caching and stage-wise defenses to mitigate reward hacking; and (3) observable training through an integrated plugin that automates validation and monitoring, paired with a Live UI for granular trajectory diagnostics. We evaluate LEGO-RL by training the sparse MoE model Qwen3.5-35B-A3B with GSPO across three native coding-agent harnesses. LEGO-RL improves Qwen3.5-35B-A3B across OpenHands SDK (64.0% to 70.4%), Claude Code (62.4% to 68.2%), and OpenCode (57.2% to 66.6%) on SWE-bench Verified, while maintaining a rollout-training probability correlation above 0.99.

# LEGO-RL：面向编码智能体的原生 Harness 强化学习框架

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：编码智能体（coding agents）的强化学习训练需要处理长时间跨度的轨迹，涉及工具调用、仓库浏览、代码修改、依赖安装和测试执行。这类训练依赖原生 agent harness（如 OpenHands SDK、Claude Code、OpenCode 等）来管理提示词、工具、上下文和执行状态。
- **核心挑战**：harness 的原生执行环境与策略梯度训练存在**根本错位**，具体表现为：
  - **环境崩溃与奖励黑客**：沙箱失败、依赖错误、验证器误配置、超时等问题会丢弃代价高昂的轨迹或污染奖励信号；
  - **训练-推理不一致**：harness 侧的提示词构建、上下文压缩、历史重写等操作，导致重建的轨迹与实际采样到的 token 序列不一致，使训练端无法忠实重算对数概率；
  - **稀疏 MoE 模型的路由不一致**：rollout 时的专家路由在训练时无法复现，进一步加剧偏差；
  - **异步管线中的诊断困难**：故障跨阶段传播、诊断信号分散，难以定位问题。
- **总体意义**：LEGO-RL 的目标是在**不修改 harness 内部流程**的前提下，将现有编码 agent harness 连接到可扩展的策略梯度优化，同时保证**忠实性（faithfulness）**、**可靠性（reliability）** 和**可观测性（observability）**。

## 2. 方法论：核心思想、关键技术细节

LEGO-RL 基于三个核心支柱，外加一个闭环运营工作流：

### 2.1 忠实优化（Faithful Optimization）
- **进程内 LLM 代理（In-Process Proxy）**：与 rollout 引擎共存，在模型服务边界捕获每次模型调用的 token ID、对数概率、响应掩码和生成元数据，而非事后从最终轨迹中重建。
- **历史重写对齐**：harness 可能在模型调用间压缩、重写或丢弃历史。LEGO-RL 在消息粒度上对齐前后上下文，工具调用通过稳定 ID 和函数名关联，匹配的 policy 生成 token 保留原始信息；重写/截断的内容仅作为条件上下文，不进入训练掩码。
- **MoE 路由重放（R3）**：记录 rollout 时的专家路由决策并在训练时重放，确保训练端的概率计算与行为策略使用相同的专家路由。实验显示开启 R3 后 rollout-训练相关性从 0.9946 提升到 0.9993。

### 2.2 可靠执行（Reliable Execution）
- **沙箱编排**：支持 Docker、Kubernetes 等多种后端，使用 Nydus 懒加载快照器减少镜像启动开销，组件以只读方式挂载而非每轮重装。
- **分阶段防御奖励黑客**：通过特权 sidecar 控制网络（agent 无法修改）、隐藏仓库 git 历史、延迟注入测试文件等方式保证奖励的真实性。
- **终止感知的轨迹准入**：基础设施故障导致的轨迹被排除出优化（掩码置零），而有效但未完成的政策轨迹则保留。
- **异步调度**：完全异步的 rollout 生成，避免慢轨迹阻塞整批；配置上限限制异常长会话。

### 2.3 可观测训练（Observable Training）
- **Agent 插件**：提供可复用的技能，覆盖运行验证、训练执行和实时监控，自动化实验生命周期。
- **Live UI**：提供终止原因分布、逐实例任务网格、轨迹查看器、一致性面板、批内奖励分布、AI 辅助分析等视图，将训练指标的变化与任务级、轨迹级证据关联起来。

### 2.4 优化目标
- 使用 GSPO（Group Sequence Policy Optimization）的序列级代理目标：
  - σᵢ(θ) = (π_θ(τᵢ) / π_θk′(τᵢ))^(1/|M(τᵢ)|)，其中 M(τ) 是策略生成的 token 位置集合；

## 6. 主要结论与发现

- **端到端有效性**：LEGO-RL 在三个 harness 上均带来显著提升（+5.8 至 +9.4 个百分点），且 policy 熵稳定无崩溃。
- **忠实性达标**：rollout-训练概率相关性中位数 ≥ 0.998，p99 每轨迹平均对数概率差异 < 3×10⁻³；MoE 路由重放将相关性提升到 0.9993。
- **任务可靠性**：约 2.5% 的任务存在错误的验证器逻辑；7.1%（Claude Code）、2.4%（OpenHands）、6.4%（OpenCode）的轨迹因基础设施故障被排除。
- **奖励信息量**：难度筛选至关重要——不筛选的池中 72.7% 任务永远解不出、13.4% 总能解出，组内无方差则无学习信号。
- **行为变化**：训练后 agent 更多地进行自我检查（编辑后重读文件比例从 73.6% 升至 98.1%），交互轮次显著增加（+78%），而错误恢复能力变化有限。
- **效率**：agent 执行占平均耗时的 91.3%；异步调度相对同步在相同时间内完成 2.5 倍步数。

## 7. 优点（亮点）

- **架构清晰、贡献集中**：将"harness-native fidelity"作为核心设计原则，用进程内代理 + 路由重放 + 生成时捕获三位一体地解决训练-推理偏差问题，切中 agentic RL 的关键痛点。
- **工程完整性高**：从沙箱、镜像、验证器到训练器、监控 UI 形成闭环，且开源全部框架、模型和数据集。
- **可观测性叙事出色**：Live UI 将训练指标变化落到具体轨迹证据上，三个故障诊断案例展示了区分策略退化与外因故障的能力。
- **奖励完整性防御系统化**：六种失败模式各有对应防御措施，且有实测发生率数据。
- **关键的否定性发现**：KAT-Coder 在 Claude Code 上 +3.4 分却在 OpenHands 上 −0.4 分，有力支持了"harness 是优化问题的一部分"的核心论点。
- **诚实的方法论态度**：多处明确标记观测性结论（如推理比例上升不意味着推理能力提升，任务级变化受采样噪声影响），避免过度声称。

- **实验覆盖有限**：
