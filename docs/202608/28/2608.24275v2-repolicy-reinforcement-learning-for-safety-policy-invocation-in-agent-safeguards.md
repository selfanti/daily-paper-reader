## 摘要
保护语言模型智能体需要根据上下文相关的安全策略评估完整的执行轨迹。现有的策略感知防护主要依赖于提示或监督微调，限制了它们适应未见轨迹和变化策略上下文的能力。我们提出RePolicy，一种通过强化学习学习安全策略调用的智能体防护。给定智能体轨迹和动态策略库，RePolicy调用适用的策略，并利用其内容生成基于策略的推理和安全判断。我们构建PolicyTraj-20K以支持监督初始化，随后使用带有可验证奖励和策略上下文扰动的GRPO。在六个智能体安全基准上的实验表明，RePolicy在变化策略上下文下实现了强大的整体安全检测性能和稳健的策略调用。

## Abstract
Safeguarding language model agents requires assessing complete execution trajectories under context-dependent safety policies. Existing policy-aware safeguards mainly rely on prompting or supervised fine-tuning, limiting their ability to adapt to unseen trajectories and changing policy contexts. We propose RePolicy, an agent safeguard that learns safety-policy invocation through reinforcement learning. Given an agent trajectory and a dynamic policy library, RePolicy invokes the applicable policy and uses its content to produce a policy-grounded rationale and safety judgment. We construct PolicyTraj-20K to support supervised initialization, followed by GRPO with verifiable rewards and policy-context perturbation. Experiments across six agent safety benchmarks show that RePolicy achieves strong overall safety-detection performance and robust policy invocation under varying policy contexts.

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）智能体从文本生成工具演化为可规划、调用工具、在外部环境中行动的自主系统，其安全风险从单次交互的有害内容扩展为完整执行轨迹上的行为危害。
- **问题**：现有防护机制大多在预定义风险分类或固定安全策略下决策，但真实部署中不存在放之四海而皆准的固定策略集；同一行为可能受不同用户权限、组织要求和监管辖区约束，且安全策略本身会随时间演化。
- **已有方法的不足**：策略感知型防护主要依赖提示（prompting）或监督微调（SFT），提示不直接优化模型对策略的使用方式，SFT受限于训练数据中的轨迹-策略分布，面对未见轨迹或新的策略组合时难以判断应调用哪个策略及其条款如何应用。
- **核心命题**：将安全策略从被动上下文视为可调用的能力（capability），把“策略调用”转化为一个智能体强化学习任务，通过防护结果直接优化调用决策，从而提升适应性和可解释性。

## 2. 方法论

论文提出 **RePolicy**，其核心流程为：**策略调用 → 策略内容返回 → 基于策略的推理 → 安全判断**。

### 2.1 任务形式化
- 输入：完整智能体轨迹 τ，候选策略库 P = {p₁, ..., p_K}，每个策略含范围描述和详细内容 c(p)。
- 过程：
  - 先调用策略：$\hat{p} \sim \pi_\theta(\cdot \mid \tau, P)$
  - 再基于调用策略生成推理和安全标签：$(\hat{r}, \hat{y}) \sim \pi_\theta(\cdot \mid \tau, P, \hat{p}, c(\hat{p}))$
- 策略调用以结构化工具调用实现，最终输出 JSON 格式的判断。

### 2.2 数据构建（PolicyTraj-20K）
- **轨迹合成**：从多种安全资源收集交互模式，使用 API 模型对任务内容重采样，保留轨迹结构、工具使用模式和安全机制；生成安全/不安全样本，过滤不一致样本。
- **策略初始化**：以“操作场景”为中心组织安全策略（而非最终风险类别），每个场景对应一个策略（标题、范围、详细安全要求）；审计全部轨迹，构建带策略标注的数据集 D = {(τᵢ, pᵢ*, rᵢ, yᵢ)}。
- 最终数据集含 **20,000+ 条策略标注轨迹**，覆盖多种工具、环境和任务场景。

### 2.3 冷启动监督微调（SFT）
- 为每条轨迹构造局部策略库：$\tilde{P}_i = \{p_i^*\} \cup P_i^-$，其中 P_i⁻ 为干扰策略（其他场景策略或合成诱饵）。
- 优化目标为两步对数似然之和：
  $$L_{SFT} = -\frac{1}{N}\sum_i \left[ \log \pi_\theta(p_i^* | \tau_i, \tilde{P}_i) + \log \pi_\theta(r_i, y_i | \tau_i, \tilde{P}_i, p_i^*, c(p_i^*)) \right]$$
- 作用：初始化完整调用-推理序列，学习格式和基本策略理解。

### 2.4 强化学习（GRPO）
- 使用 **GRPO**（Group Relative Policy Optimization）优化完整防护 rollout，每个提示采样多个 rollout 进行比较。
- 两个关键设计：
  1. **策略上下文扰动（Policy-Context Perturbation）**：重采样干扰策略、打乱策略库顺序、注入合成诱饵策略，防止模型记忆固定轨迹-策略关联，迫使其从当前轨迹和策略范围判断适用性。
  2. **基于规则的可验证奖励**：
     $$R = \lambda_{fmt} R_{fmt} + \lambda_{pol} R_{pol} + \lambda_{acc} R_{acc}$$
     - R_fmt：格式奖励（合法策略调用 + 格式正确的最终响应）
     - R_pol：策略调用奖励 I[ŷ_p = p*]
     - R_acc：安全判断准确率奖励 I[ŷ_y = y]
     - 默认权重：0.1 / 0.3 / 0.6

## 6. 主要结论

- RePolicy 以 4B 模型规模达到 88.15 的平均 Unsafe F1，超过所有闭源大模型和专用防护模型，验证了强化学习可直接优化“策略调用 + 安全判断”的完整决策过程。
- GRPO 显著提升正确策略调用率（从约 94.4% 到 98.5%），同时将诱饵策略选择率保持在 1% 以下，说明模型学到了“何时调用哪个策略”而非盲选。
- 显式策略调用是 RL 收益的主要来源，在全部六个基准上优于无调用的 GRPO 变体（平均提升 2.32 点），尤其体现在 AgentHazard (+5.9) 和 OpenAgentSafety (+4.4)。

- 策略上下文扰动防止模型依赖固定策略库或诱饵关联，是稳健调用的关键。

## 8. 不足与局限

- **假设与适用范围**：要求候选策略库中存在适用且足够精确的策略；对策略覆盖不全、范围模糊、要求过时或策略冲突的情形鲁棒性未知。
- **单策略约束**：当前将每条轨迹关联到一个主策略，但实际部署可能需要同时应用多个层级（操作、组织、法规）的策略。
- **推理开销**：显式策略调用增加一次工具调用和上下文注入，比单遍防护更耗时；但论文未给出明确的延迟/吞吐量化指标。
- **评估规模与多样性**：仅使用 4B 骨干，缺少跨规模（8B/32B 等）验证；基准轨迹均为离线记录、二元标签，未覆盖多语言部署、在线干预、连续环境变化和“何时中断智能体”的实时防护场景。
- **奖励的可信度边界**：奖励仅验证策略调用和最终标签，不保证生成的每条 rationale 都忠实于被调用策略内容，即“理由可解释但未必逐句可验证”。
- **数据伦理双面性**：PolicyTraj-20K 包含不安全行为轨迹与策略标注，虽未重新执行危险操作，仍具潜在的 offensive 双用风险；论文建议勿作为高价值场景的独立执行机制。
