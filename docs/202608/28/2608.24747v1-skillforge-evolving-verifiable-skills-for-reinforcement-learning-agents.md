## 摘要
大型语言模型（LLM）智能体通过强化学习（RL）训练以完成复杂的决策任务。然而，大多数经过RL训练的智能体仍然是 episodic 的，无法跨回合积累可重用的知识。最近的基于技能的方法，如SkillRL，试图通过从原始轨迹中提取技能来解决这个问题，但将技能库视为仅追加的存储库，而不验证存储的技能是否仍然有效。在本文中，我们提出了SkillForge，一个用于持续技能进化的框架，通过环境交互使技能得以验证和精炼。通过在智能体交互过程中显式地使用技能，RL可以直接优化环境动作和技能调用决策。SkillForge进一步引入了基于证据的技能验证和多路径技能归纳，使技能库在保持质量的同时持续增长。在ALFWorld、WebShop和AppWorld上的大量实验表明，SkillForge始终优于SkillRL，证明了持续验证的技能在训练更强的LLM智能体方面的有效性。

## Abstract
Large language model (LLM) agents are trained with reinforcement learning (RL) for complex decision-making tasks. However, most RL-trained agents remain episodic and cannot accumulate reusable knowledge across episodes. Recent skill-based approaches, such as SkillRL, attempt to address this issue by extracting skills from raw trajectories, but treat the skill bank as an append-only repository without verifying whether stored skills remain effective. In this paper, we propose SkillForge, a framework for continuous skill evolution that enables skills to be verified and refined through environment interaction. By making skill usage explicit during agent interaction, RL can directly optimize both environment actions and skill invocation decisions. SkillForge further introduces evidence-based skill verification and multi-pathway skill induction, allowing the skill bank to continuously grow while maintaining its quality. Extensive experiments on ALFWorld, WebShop, and AppWorld show that SkillForge consistently outperforms SkillRL, demonstrating the effectiveness of continuously verified skills in training stronger LLM agents.

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：大多数经过强化学习（RL）训练的LLM智能体仍然是 **episodic（回合制）** 的，每个回合从零开始，无法跨回合积累和复用知识。这导致智能体反复重新发现有效行为，学习效率低下。
- **现有方案的不足**：虽然已有基于记忆的方法（存储轨迹）和基于技能的方法（如SkillRL，将轨迹蒸馏为技能注入策略提示），但存在三个关键缺陷：
  - **技能使用不可观测**：技能被批量注入提示，无法判断智能体是否真正依赖某个技能做决策。
  - **技能效果难以归因**：缺乏显式使用信号，难以判断成功轨迹是由特定技能导致还是巧合。
  - **技能质量不受控**：错误或过时的技能可能永久留在技能库中，逐步污染知识库。
- **整体含义**：本文提出 **SkillForge** 框架，使技能库能够通过环境交互持续验证和精化，实现"技能进化"，从而让LLM智能体在开放环境中训练得更强。

### 2. 方法论：核心思想与技术细节

#### 2.1 核心思想

- 使技能使用**显式化**：将技能作为可调用的结构化单元，智能体通过 `<skill_call>` 标签按需调用，使技能调用成为轨迹中的离散可追踪事件。
- 通过RL**联合优化**环境动作和技能调用决策。
- 引入**证据验证**与**多路径归纳**，让技能库在持续增长的同时保持质量。

#### 2.2 技能表示与检索（Stage 1）

- **技能结构**：每个技能定义为六元组 `s = (title, intent, principle, applicability, category, status)`：
  - `title`：可调用的唯一标识符；
  - `intent`：一句话用途描述，显示在目录中；
  - `principle`：核心决策策略（调用后返回）；
  - `applicability`：可应用的触发条件；
  - `category`：通用技能或任务特定技能；
  - `status`：活跃/审查中/弃用。
- **初始技能库**：用初始指令微调策略在目标环境中 rollout，由教师LLM将成功轨迹蒸馏为策略模式、失败轨迹合成为纠错教训。
- **检索与目录注入**：使用嵌入相似度（式2）从技能库中检索Top-K技能，仅向提示中注入紧凑目录（技能名称+一行触发描述），完整内容在技能被调用时返回。这保持了提示的紧凑性。

#### 2.3 显式技能调用与策略优化（Stage 2）

- **显式调用**：每步智能体输出由环境动作 $a^{env}_t$ 和可选技能调用 $c_t$ 组成（式3）。调用后，完整技能内容作为反馈拼接到下一观测中（式4）。
- **GRPO策略优化**：使用组相对优势 $\hat{A}_i = (R_i - \bar{R})/\sigma_R$ 和GRPO目标函数（式5）更新策略，同时优化环境动作和技能调用决策。
- **轨迹抽象**：每条轨迹由LLM压缩为结构化摘要，按成功/失败存入对应任务类型的缓冲区，作为技能归纳的输入。

#### 2.4 技能进化（Stage 3）

- **多路径技能归纳**（每I=5步触发一次）：
  - **提取（Extraction）**：从成功轨迹中提取可泛化策略；
  - **精化（Refinement）**：从失败轨迹中识别重复失败模式并提出纠正策略；
  - **对比分析（Contrastive）**：配对成功与失败轨迹，识别关键行为差异。
  - 新技能通过词法和语义双重去重后加入技能库。
- **证据验证**：
  - 为每个技能跟踪EMA成功率（式7）和使用次数；
  - 计算低表现置信度分数（式8）：$\text{conf}(s) = (1 - \hat{p}_s) \cdot (1 - 0.5^{n_s/h})$，分数越高表示越需要审查；
  - 高置信度分数（低成功率+高使用量）的技能被送交LLM反思，决定保留（keep）或修订（revise）。

#### 2.5 训练流程（Algorithm 1）

- 每步：检索技能目录 → 采样G条轨迹 → GRPO更新策略 → LLM抽象轨迹并更新逐技能统计。
- 每5步：技能归纳+去重 → 计算置信度分数 → 对标记技能做LLM反思（保留/修订）。
- 更新后的技能库立即用于后续rollout，形成"生成→测试→精化"的持续循环。

### 7. 优点（亮点）

- **显式技能调用设计**：将技能调用作为token序列的一部分，使RL能直接优化技能使用，同时使技能使用可观测、可归因，这是与SkillRL的本质区别。
- **证据驱动的技能验证**：EMA成功率和置信度分数的设计使得技能质量可以用环境交互数据持续衡量，有效防止知识库污染。
- **多路径技能归纳**：综合利用成功、失败和对比轨迹，比仅从成功轨迹提取更全面。
- **实用的工程权衡**：紧凑目录+按需调用机制平衡了提示长度和技能覆盖范围；无需SFT冷启动，简化了训练流程。
- **完善的分析体系**：技能库演化可视化、迁移实验、教师敏感性分析、效率分解，使论文的论证链完整且令人信服。

### 8. 不足与局限

- **依赖外部教师LLM**：技能归纳和验证的质量取决于教师模型（Qwen3-Max）的能力，自教师设置下性能有所下降（AppWorld：44.6→39.3），这限制了框架在无强大教师模型时的适用性。
- **技能库持续增长可能导致检索开销**：虽然当前实验显示增长率受控，但超长训练运行中技能库规模仍可能成为瓶颈，论文提出的应对机制只是初步的。
- **显式调用增加推理成本**：额外的 `<skill_call>` 标记和技能内容返回会增加交互的token数，在超大规模部署中可能带来显著推理开销。
- **实验有限性**：
  - 消融实验仅在单一模型和部分基准上进行；
  - 未报告多次运行的标准差，统计显著性不明确；
  - 未做超参数敏感性分析（如EMA系数α、使用半衰期h、检索数量k等）；
  - 未在更复杂/更开放的基准（如长时域家庭助手、真实浏览器环境）上验证。
- **奖励信号简单**：所有任务仅使用二值奖励（成功/失败），未探索更细粒度的奖励设计。
- **仅验证文本环境**：未在视觉或多模态环境中测试，泛化性有待验证。
