## 摘要
在AI智能体的上下文中，安全规则和情景日志争夺相同的令牌。当预算溢出时，两者以相同的速率被摘要；只有规则需要精确措辞才能保持可执行性。在20个生产代理配置中，在Sonnet 4.6上使用Claude Code的/compact提示，一次压缩后保留了53%的安全规则，五次后仅剩10%。我们将此称为“压缩悬崖”。我们通过“知识分诊”来解决这个问题，这是一个框架，它按类型对智能体知识库的每一行进行分类，并让每种类型通过各自的保留策略进行路由。三个确定性操作符在三个上下文管理操作中实现了这种分诊：TypeCompact在按类型保真度下就地重写条目；TypeDecompose将过于庞大而无法安全压缩的主题分区，并在分区中复制范围内安全规则；TypeRetrieve从外部存储获取条目，并将范围内规则固定优先于相关性。在五个公共语料库上，TypeCompact在每种比例下比最强的一次性LLM压缩器多保留2-4倍的安全规则，五轮后召回率达到96%。TypeDecompose实现了0%的局部性违规，而均匀分区则有93%的违规。TypeRetrieve实现了100%的召回率@50，而最佳一次性LLM检索器为73%。在三个下游行为基准上，我们在医疗合规性上优于生产Sonnet压缩器（保留性的配对McNemar检验 $p < 10^{-8}$，$N = 200$），在零售任务通过率上优于完整策略和分层基线（$p < 0.01$，$N = 115$），在航空领域上优于分层压缩（$p = 0.024$）。我们发布了AgentArtifactCorpus（来自54,628个公共GitHub仓库的396,934个智能体配置）、分类器以及参考实现。

## Abstract
A safety rule and an episodic log compete for the same tokens in an AI agent's context. When the budget overflows, both are summarized at the same rate; only the rule needs exact wording to remain enforceable. On 20 production agent configurations, Claude Code's /compact prompt on Sonnet 4.6 preserves 53\% of safety rules after one compaction round and 10\% after five. We name this the Compaction Cliff. We address it with Knowledge Triage, a framework that classifies each line of an agent's knowledge base by type and routes each type through its own retention policy. Three deterministic operators implement this triage across the three context-management operations: TypeCompact rewrites items in place under per-type fidelity, TypeDecompose partitions a topic too large to compact safely, replicating in-scope safety rules across partitions, and TypeRetrieve fetches items from external storage with in-scope rules pinned ahead of relevance. On five public corpora, TypeCompact preserves 2--4$\times$ more safety rules than the strongest single-shot LLM compactor at every ratio, with 96\% recall over five rounds. TypeDecompose reaches 0\% locality violations against 93\% under uniform partitioning. TypeRetrieve reaches 100\% recall@50 against 73\% for the best single-shot LLM retriever. On three downstream behavioral benchmarks, we outperform the production Sonnet compactor on medical compliance (paired McNemar $p < 10^{-8}$ on preservation, $N = 200$), the full-policy and hierarchical baselines on retail task pass rate ($p < 0.01$, $N = 115$), and the hierarchical compaction on the airline domain ($p = 0.024$). We release AgentArtifactCorpus (396{,}934 agent configurations from 54{,}628 public GitHub repositories), the classifier, and the reference implementation.

## 二、方法论：Knowledge Triage（知识分诊）框架

### 1. 核心思想
类比医院按红/黄/绿对伤员分诊，智能体在令牌预算约束下按**对失真的容忍度**对知识条目分诊：安全约束必须完整存活，程序性指令可在行为等价的前提下改写，情景日志可丢弃。该框架由三部分组成：类型化知识模型、分类器 𝜏、三个确定性操作符。

### 2. 五类知识模型（§3.1）
- 知识库定义为元组 𝐾 = (𝐼, 𝜏, 𝑇, 𝜋, 𝜎)：有限条目集 𝐼、类型分配 𝜏、主题树 𝑇、叶子映射 𝜋、作用域函数 𝜎（约束适用的叶子主题集合）。
- 五种类型及失真容忍度：
  - **约束（Constraint, C）**：限制智能体行为的规则，违反即安全失效；失真容忍度为**零**（二进制失真：完整或丢失）。
  - **程序性指令（Procedural, P）**：逐步操作说明；仅当执行结果一致时才允许改写。
  - **信念（Belief, B）**：视为真的事实断言；允许有界语义距离（1 − cos 嵌入距离）。
  - **偏好（Preference, F）**：软性指导；可被摘要或合并。
  - **情景（Episodic, E）**：过去事件或观察；可自由丢弃（gist 距离）。
- 该五类模型经验证覆盖了真实智能体知识的 **97%**。

### 3. 分类器 𝜏（§3.2）
- **SafetyMargin（默认）**：通过反事实安全估计判断条目是否为约束——计算 `margin(i) = max_a [P(unsafe | a, K\{i}) − P(unsafe | a, K)]`，即“删除该条目后是否会让某行动变得不安全”，得分 > 0.5 标记为约束。该方法能捕获陈述式规则（如“患者对X过敏”），而基于语法形式的分类器会漏掉这类规则。
- **替代方案**：多阶段选择性级联（正则 → 编码器 → gpt-5.4-mini → 强制归为约束）、单次 LLM 调用、纯表面启发式（正则/编码器/蒸馏 MiniLM）。分类器仅在索引时运行一次，成本恒定。
- **权威加权**：按来源（系统/开发者/用户/工具/检索）对置信度加权（权重 1.5/1.25/1.0/0.75/0.6），风险分 = P(𝜏=约束) × 权威权重。

### 4. 三个确定性操作符（§3.3）
- **TypeCompact（压缩）**：安全要求是每个约束在压缩后仍以零失真存在（∀𝑖∈𝐼_𝐶, ∃𝑖′∈𝐶(𝐾): 𝑑_𝐶(𝑖,𝑖′)=0）。算法将条目路由到三条保真通道：约束和程序性指令全量保留，信念/偏好压缩，情景条目降级为占位符。确定性验证器提取每条约束的规范化形式（否定词+宾语短语），检查其出现在输出中，缺失则恢复原文或升级为 Unsafe。
- **TypeDecompose（分解）**：安全要求是**约束局部性**——任何包含某约束作用域内条目的分区，必须同时包含该约束本身。算法按主题分组、按预算分块，然后将每条约束复制到其作用域覆盖的所有分区（全局约束开销最大，局部约束零开销）。
- **TypeRetrieve（检索）**：安全要求是**优先级**——凡查询主题与约束作用域相交（in-scope），该约束必须出现在结果集中，无论相似度分数如何。算法先固定所有 in-scope 约束，再用相关性分数填充剩余预算。
- 三者可组合为完整周期：先尝试压缩，低于最小安全预算 𝑩_min 时转分解，部分推入外部存储供 TypeRetrieve 按需拉回。

## 六、主要结论与发现

1. **压缩悬崖是类型盲策略的结构性失效模式**：在所有 LLM 家族和结构基线中呈相同衰减形态；最好的类型盲策略单轮保留率仅 0.53（50% 压缩比），五轮后降至 0.10。
2. **类型化保留显著提升安全约束存续**：
   - TypeCompact 在 50/25/10% 压缩比下约束保留率达 **1.00/0.95/0.80**（最强基线为 0.53/0.39/0.24），多轮后稳定在 **0.96**，即比最强单次 LLM 压缩器高 **2–4 倍**。
   - TypeDecompose 局部性违规 **0%**（最差基线 93%），平均令牌开销 14.5%（中位数 0%）。
   - TypeRetrieve 召回率@50 达 **100%**（最强 LLM 检索器 73%），且每查询零 LLM token。
3. **下游行为验证**：SafetyMed 上通过率领先 Sonnet 压缩器（p=0.022）、保留率领先 14.5 个百分点（p<10⁻⁸）；零售

零售基准上 TypeCompact 在行为通过率上保持领先（p<0.05 水平显著），航空基准上在保留令牌数少于基线（647 vs 718）的条件下仍领先 11.1 个百分点，说明优势并非单纯来自更大的上下文预算。人工验证实验（Cohen's 𝜅 达成高一致性）确认了 100 个单元格中类型标注与安全规则恢复均可靠。

## 七、局限性与未决问题

1. **分类器误差的传导效应**：SafetyMargin 以反事实估计为核心，但若分类器将约束误判为信念/偏好，该条目即失去全部保真保护——安全保证的上限取决于 𝜏 的精度。论文报告了分类器在基准上的 F1，但未充分讨论误判在真实医疗/法律场景中的级联后果。
2. **五类知识模型的粒度争议**：信念与偏好之间的界限（有界语义距离 vs 可摘要）在实施中需要阈值调参；程序性指令的“行为等价”判定依赖验证器能力，而验证器对非文本行为的覆盖有限。
3. **作用域函数 𝜎 的人工依赖**：TypeDecompose 与 TypeRetrieve 的局部性/优先级保证均依赖叶子映射与作用域函数，目前需要配置者事先定义——论文未给出 𝜎 的自动推断方法，这限制了开箱即用性。
4. **单语文本语料限制**：全部评估基于英文文本数据；中文、日文等多字节语言中 token 预算、嵌入距离与占位符策略的适配未经验证。
5. **多智能体与动态知识场景缺失**：知识库 𝐾 被假定为静态快照；当约束在运行中新增、撤销或局部更新（如“本周禁用某药”）时，类型化操作符的增量维护成本未建模。
6. **与长期记忆系统的关系未厘清**：论文聚焦压缩/分解/检索三种操作，但与外部长期记忆、向量库写回、衰退机制等工作如何协同，未形成统一运行时架构。

## 八、研究贡献总结

- **问题发现层**：首次以系统性实证揭示“压缩悬崖”结构——统一压缩策略对安全约束存在不可接受的流失速率，并将该问题归因于失真容忍度未参与分诊决策。
- **理论框架层**：提出 Knowledge Triage 与五类知识模型（约束/程序/信念/偏好/情景），提供了从“上下文管理”到“知识保真管理”的概念迁移。
- **工程机制层**：给出三个确定性操作符（TypeCompact/TypeDecompose/TypeRetrieve）及其形式化安全保证（零失真、约束局部性、in-scope 优先级），每个操作符均配套可运行的验证器与恢复机制——这使安全保证不止于设计意图，而是可在工程上被检验。
- **证据链条层**：从 6 个语料库到 4 个研究问题、从孤立指标（保留率）到下游行为（医疗/零售/航空），形成了“机制 → 指标 → 行为”的三级验证体系，对生产级智能体运行时设计有直接参考价值。

## 九、批判性评价

- **优势**：论文将 AI 安全议题从模型层下沉到系统层，视角新颖且工程可落地；实验矩阵宽广，尤其包含多轮迭代与下游行为回放，避免了“指标提升但行为退化”的常见陷阱；确定性验证器的设计理念与可审计性契合生产合规需求。
- **不足**：安全保证与分类器精度强耦合，而对分类器在对抗性措辞下的失效模式分析仍偏弱；基准集中于英文、单轮交互为主，缺乏长时跨会话的持续学习场景；与现有 Agent 框架（如 LangGraph、AutoGen）的集成方式未给出接口说明，工程迁移成本未知；论文未报告任何基于真实患者/客户数据的合规性审查结果，SafetyMed 作为自建基准仍需外部效度验证。

总体而言，论文贡献了一个“分类—操作—验证”的闭环框架，指出了一个真实且紧迫的部署风险，并以充分实验证明了类型化保留的可行性与必要性。其局限主要在分类器依赖与生态集成，可在后续工作中通过引入自适应分诊策略与标准 Agent 运行时插件规范来弥合。
