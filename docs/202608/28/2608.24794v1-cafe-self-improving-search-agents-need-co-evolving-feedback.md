## 摘要
结果监督的搜索智能体学习何时以及如何检索证据，但终局奖励既不能定位中间错误，也不能在错误累积之前重定向进行中的轨迹。将纠正性反馈视为一种学习的轨迹内干预，将两个角色耦合：智能体必须决定何时请求和使用反馈，而批评者必须从结果混淆的轨迹中推断有用的纠正，这些轨迹的失败模式会随着智能体的改进而变化。我们提出了CAFE（耦合智能体-反馈演化）框架，其中共享参数模型在搜索智能体和批评者角色之间交替。CAFE从围绕基础智能体自身失败构建的轨迹中初始化反馈条件下的恢复，然后耦合在线和离线优化。在线强化学习期间，比较性反馈估计使用提示级别的调用-跳过成功差距来塑造请求回报，而反馈感知的优势塑造在反馈前后重新加权令牌优势。离线时，从轨迹衍生的偏好优化从匹配的成功和不成功轨迹中学习反馈。在七个智能体搜索基准上，CAFE平均优于所评估的基于强化学习的搜索智能体，在所有六个域外基准上保持其收益，并减少答案级幻觉。单侧消融表明，仅改进智能体或仅改进批评者最终会达到平台期，而交替两种更新则持续提高性能。这些发现表明，自我改进的搜索智能体需要与其所引导的策略共同演化的反馈。

## Abstract
Outcome-supervised search agents learn when and how to retrieve evidence, but terminal rewards neither localize intermediate errors nor redirect an ongoing trajectory before those errors compound. Treating corrective feedback as a learned in-trajectory intervention couples the two roles: the agent must decide when to request and use feedback, while the critic must infer useful corrections from outcome-confounded rollouts whose failure patterns shift as the agent improves. We introduce CAFE (Coupled Agent--Feedback Evolution), a framework in which a shared-parameter model alternates between search-agent and critic roles. CAFE initializes feedback-conditioned recovery from trajectories built around the base agent's own failures, then couples online and offline optimization. During online RL, a comparative feedback estimate uses a prompt-level call--skip success gap to shape request returns, while feedback-aware advantage shaping reweights token advantages before and after feedback. Offline, rollout-derived preference optimization learns feedback from matched successful and unsuccessful trajectories. On seven agentic search benchmarks, CAFE outperforms the evaluated RL-based search agents on average, retains its gains across all six out-of-domain benchmarks, and reduces answer-level hallucinations. One-sided ablations show that improving only the agent or only the critic eventually plateaus, whereas alternating the two updates continues to improve performance. These findings suggest that a self-improving search agent needs feedback that co-evolves with the policy it guides.

## 1. 核心问题与研究动机

- **结果监督的局限**：现有搜索智能体（Search Agent）主要依赖终局奖励（outcome reward）来学习何时检索、如何检索。但在长视野（long-horizon）搜索中，早期方向性错误往往**无法被终局奖励定位**，错误会持续传播并累积放大，导致整个轨迹最终失败。
- **反馈的引入**：将纠正性反馈（corrective feedback）作为一种轨迹内干预（in-trajectory intervention）具有必要性。但已有的 Reflexion、Self-Refine、CRITIC 等工作多采用提示式、事后的自然语言批评，而非经过训练的、可学习的轨迹内反馈。
- **三方面挑战**：
  1. **智能体侧**：需要学习何时请求反馈；同时，被反馈"救回"的轨迹与无缺陷轨迹共享相同终局奖励，智能体应强化哪一部分行为缺乏明确的信用分配（credit assignment）。
  2. **批评者（critic）侧**：反馈本身没有监督信号，只能从被搜索过程与后续行为共同"混淆"的终局结果中学习，存在严重的结果混杂（outcome confounding）问题。
  3. **二者耦合**：在线更新会持续改变智能体访问的状态和失败分布，静态批评者的反馈会逐渐与演化中的策略失配（misalignment）。
- **论文主张**：自我改进的搜索智能体需要**与其引导的策略共同演化（co-evolving）的反馈**，而非固定不变的监督者。

## 2. 方法论：CAFE 框架

### 2.1 核心思想

**CAFE（Coupled Agent-Feedback Evolution）** 采用一个**共享参数模型**，它随情境切换扮演两种角色：

- **智能体角色（agent role, A）**：执行搜索、制定计划、给出答案。
- **批评者角色（critic role, C）**：在智能体显式发出 `<request_feedback>` 时，根据当前轨迹生成纠正性、可操作的反馈。

二者的行为形式化为：

```
a_i,t ~ πθ^A(· | h_i,t)
f_i,t ~ qθ^C(· | h_i,t)
```

即在推理时两个角色保持分离、共用同一主干网络。训练的总体流程为：**反馈增强的 SFT 初始化 → 交替进行在线智能体强化学习与离线反馈偏好优化**。

### 2.2 阶段 I：反馈增强的 SFT 初始化（Bootstrapping）

- 收集基础智能体自身的失败轨迹，交由教师模型（Kimi-K2.5）标记出**最早出错或停止进展的位置**。
- **保留智能体自己的错误前缀**（而非用理想轨迹替换），在该位置插入 `<request_feedback>`，由教师生成反馈及反馈条件下的成功延续。
- 仅保留最终答案正确的"修复后轨迹"作为 SFT 数据，使模型学会在其策略**真正会访问到的状态**下请求、生成并使用反馈。

### 2.3 阶段 II：在线智能体优化

#### (a) 比较式反馈估计（CFE，Comparative Feedback Estimate）

- 沿用 GRPO 的组采样：对每个提示 x 采样一组轨迹 Gx，按是否请求过反馈分为 **call 组** 和 **skip 组**，定义两组经验成功率的差值：

```
û(x) = mean(r_j for call) − mean(r_k for skip)
```

- 将提示级统计量并入每个轨迹的奖励，构成 CFE 塑造后的回报：

```
R_i^CFE = r_task + β·C_i·û(x_i) − γ·[n_fb,i − 1]+
```

  - 第一项：原始答案正确性奖励；
  - 第二项：反馈效用奖励（仅对请求了反馈的轨迹生效），促使智能体学会"帮助值得请求时才请求"；
  - 第三项：对第一次以后的重复请求施加惩罚；
  - 若提示组内某一路径缺失，采用批次级回退估计（batch-level fallback）。

#### (b) 反馈感知优势重塑（Feedback-Aware Advantage Shaping）

- 标准 GRPO 为轨迹内所有可训练 token 分配同一优势 Ai，这会把"导致搜索偏离的行为"和"修复偏离的后续行为"同等强化，恰好奖励了应当放弃的行为。
- 因此，对每个**请求过反馈**的轨迹，将可训练 token 划分为三部分：
  - **T_pre**：首次请求前的 token——由于 SFT 初始化保留自身错误前缀，这些 token 多为导致错误的低质量行为；由优势中减去 `λ·g_i`。
  - **T_call**：请求动作本身的 token——保持原优势。
  - **T_post**：反馈之后的延续 token——加上 `λ·g_i`，强化成功修复行为。

```
Â_i,t = max(A_i − λg_i, 0)   for t ∈ T_pre
Â_i,t = A_i                  for t ∈ T_call
Â_i,t = A_i + λg_i           for t ∈ T_post
```

其中 `g_i = clip(û(x_i), 0, b)`，且仅在 `A_i > 0`、`g_i > 0` 时生效。观察与反馈 token 不参与策略损失。

### 2.4 阶段 III：离线反馈优化与迭代共演化

#### (a) 滚动导出偏好优化（RDPO，Rollout-Derived Preference Optimization）

- 在每轮在线 RL 后，从最新 on-policy rollout 中按提示分组，**前缀匹配**（token-set Jaccard 相似度 ≥ 0.7，辅以 LLM 审查）成功/失败的反馈请求轨迹。
- 以成功轨迹的历史前缀为共享上下文，其反馈 f+ 为 chosen，失败轨迹的反馈 f− 为 rejected，构造 DPO 偏好对进行离线更新。

#### (b) 交替调度

- 一轮完整的 CAFE 迭代为：`H` 步在线 RL → 1 次 RDPO 更新，重复 K 轮；默认配置 `H=100，K=5`，即共 500 在线 RL 步。
- 由于参数共享，在线更新会改变 RDPO 的数据分布，而 RDPO 又会影响下一轮在线采样，从而形成**双向耦合的共同演化循环**。
- 论文还给出了算法定理（Theorem 1）：在扰动上界 `Δ_CAFE < ‖G_task‖` 时，CAFE 更新与纯任务更新方向保持正对齐，不会反向优化任务目标。

## 6. 主要结论与发现

1. **主结果领先**：7B 主干下，CAFE 平均 EM 52.5、F1 60.7，比最强 RL 基线 IGPO 高 2.1 EM / 1.3 F1；在 7 个基准上均优于朴素 GRPO，且**在全部 6 个域外基准上保持收益**。
2. **阶段性增益明确**：Base → SFT → GRPO → CAFE 逐级提升，证明反馈的迭代优化带来的增益超越单纯更强的搜索策略。
3. **在线组件必要性**：CFE 单独提升请求回报建模，优势重塑单独提升前后 token 信用分配，二者联合最优；CFE 与优势重塑均不对齐时效果最差。
4. **离线 RDPO 优于正例 SFT（RSFT）**：RDPO 通过成败配对的相对偏好学习，能缓解正例轨迹中"搜索成功但反馈无用"的噪声，且始终锚定最新在线 checkpoint。
5. **共同演化优于单侧改进**：只有智能体或只有批评者被更新的对照最终都会进入平台期；交替更新的 CAFE 持续上升（2Wiki 上最终 86.6 vs. agent-only 的 83.6）。跨代交叉实验表明，晚期各代智能体均与本代批评者配对效果最佳，说明收益源于对齐而非批评者本身的绝对强度。
6. **反馈内容随训练演化**：早期以检索与接地错误为主，中期转向证据验证，晚期针对残余的重复查询、冗余工具调用与逻辑错误，表明批评者自适应地追踪智能体演化的失败画像。
7. **幻觉显著下降**：答案级幻觉率由 Base 的 29.9% → GRPO 的 17.6% → CAFE 的 12.6%，在 NQ、MuSiQue 上降幅最大，且在所有基准上均优于 GRPO。
8. **训练动态健康**：CAFE 在保持高测试精度的同时维持更高熵的反馈路由策略（0.496 bits vs. GRPO 的 0.221 bits），避免了路由坍缩。

## 7. 主要优点

- **问题界定清晰、动机强**：明确区分了"评估性信号"与"指导性反馈"，以三问（RQ1–RQ3）驱动方法设计，逻辑链条完整。
- **共享参数双角色设计优雅**：避免维护独立的批评者模型，复用已有 RL 基建，降低开销；角色分工在推理时解耦、训练时耦合。
- **信用分配精细且可解释**：对比式反馈估计（CFE）解决"何时请求"的跨轨迹问题，优势重塑解决"成功归因于谁"的轨迹内问题，二者互补；公式化和定理保证（task-update direction preservation）增强了理论可信度。
- **RDPO 的数据构造具有针对性**：前缀匹配 + 结构过滤 + LLM 审查，有效缓解反馈学习的终局奖励混杂问题；保留自身失败前缀的 SFT 构造方法也明显优于教师理想轨迹。
- **验证体系深刻**：cross-play 矩阵、共演化控制组和反馈内容演化分析提供了纯性能指标之外的机制性证据，对"共同演化"假说的支持比较有力。
- **泛化与鲁棒性证据充分**：7B/3B 双规模、7 个标准基准 + 1 个长视野基准、全离线域外覆盖，综合置信度较高。

## 8. 不足与局限

- **域内数据集单一**：仅用 2WikiMultihopQA 一个域内基准进行训练与 SFT 数据构建，域内分布的代表性有限，可能影响反馈机制在其他类型任务（代码、对话、具身等）上的可迁移结论。
- **依赖教师模型的引导质量**：SFT 初始化依赖 Kimi-K2.5 做最早错误定位与成功延续生成，教师模型本身的质量和偏差会直接注入训练数据，而论文没有分析教师模型不同选择对最终效果的影响。
- **基线协议不完全统一**：部分基线使用原文报告数字、部分为官方 checkpoint 在本协议下复测、部分为本文复现，环境、检索器和评估代码的差异无法完全排除，跨论文比较需谨慎。
- **评估规模与检索环境有限**：每数据集仅 500 例（Bamboogle 125 例），固定本地语料库的 E5 检索器与真实生产环境（在线搜索、动态网页）仍有差距；30 次工具调用上限可能不足以覆盖超长深研任务。
- **训练信号仍以答案匹配为唯一硬标签**：幻觉评估是论文自建的启发式标准（人工/规则判断是否被检索证据支持），没有报告评估者一致性或误差分析，幻觉率数字的可靠性存在一定不确定性。
- **RDPO 的偏好对依赖阈值与 LLM 审查**：Jaccard 阈值（0.7）、审查语义匹配等环节可能引入选择偏差，论文没有给出保留率、有效对比例等统计。
- **无负面案例分析**：除了一个成功的案例研究外，没有系统分析 CAFE 何时失效、错误类型如何分布，未回答"哪类失败模式是反馈机制仍然无法挽救的"。
- **迭代调度结论可能欠稳健**：调度消融显示 100×5 最优，但没有探讨 RDPO 更新次数（epochs）与在线 RL 步数的交互；理论定理的条件（扰动上界小于任务更新范数）在实验中也未验证是否始终成立。
