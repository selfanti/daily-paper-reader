## 摘要
递归自我改进（RSI）在长时程任务中仍然困难，因为不断增长的历史记录会模糊任务状态并导致技能调用错位。我们提出了Recuris，一种面向长时程智能体框架的递归经验-工作记忆架构，其中工作记忆跟踪任务进度并引导从经验记忆中选择技能，将技能使用锚定于当前需求而非完整历史。这种耦合还将执行过程转化为结构化证据，将失败定位到特定的记忆组件。跨任务中，一个固定的元智能体将这些证据转化为针对技能记忆的、经过验证门控的局部更新，从而重塑执行并产生新证据，形成有界的递归记忆演化循环。在四个长时程基准和十个模型上，Recuris在37个完成的模型-基准配对中提升了35个的任务成功率，将前沿模型推至SOTA级任务成功率：在tau-bench上，它为GPT-5.6 Sol增加了+17.8个百分点，为Claude Opus 5增加了+15.6个百分点，使Opus 5达到87.9%；在SkillFlow上，为Qwen3.6-27B/35B分别增加了+16.6/+13.5个百分点。随着交互时程的增长，优势进一步扩大，在最长任务上达到+32.2个百分点，常见的长时程失败率下降高达80%。这些结果将递归演化记忆定位为RSI的可扩展基础，使智能体能够持续将累积经验转化为日益有效的长时程行为。代码：https://github.com/Gen-Verse/Recuris

## Abstract
Recursive self-improvement (RSI) remains hard in long-horizon tasks, where growing histories obscure the task state and misalign skill invocation. We introduce Recuris, a recursive Experiential-Working Memory architecture for long-horizon agent harnesses, in which Working Memory tracks task progress and guides skill selection from Experiential Memory, grounding skill use in current needs rather than the full history. This coupling also turns execution into structured evidence that localizes failures to specific memory components. Across tasks, a fixed Meta-Agent turns that evidence into localized, validation-gated updates to Skill Memory that reshape execution and yield new evidence, forming a bounded recursive memory-evolution loop. Across four long-horizon benchmarks and ten models, Recuris improves task success in 35 of the 37 completed model-benchmark pairs, carrying frontier models to SOTA-level task success: on tau-bench it adds +17.8 points to GPT-5.6 Sol and +15.6 to Claude Opus 5, taking Opus 5 to 87.9%, and +16.6/+13.5 points on Qwen3.6-27B/35B on SkillFlow. The advantage widens as the interaction horizon grows, to +32.2 points on the longest tasks, and common long-horizon failures fall by up to 80%. These results position recursively evolving memory as a scalable foundation for RSI, enabling agents to continuously transform accumulated experience into increasingly effective long-horizon behavior. ## 一、论文的核心问题与整体含义（研究动机与背景）

长时程（long-horizon）任务是 LLM 智能体面临的核心挑战之一。随着交互历史的持续增长，智能体容易丢失对未完成目标的跟踪，检索到的技能也与当前任务状态逐渐脱节，导致**递归自我改进（Recursive Self-Improvement, RSI）**难以实现。现有经验记忆方法（如从初始指令或完整对话历史中检索技能）存在两个关键缺陷：

1. **初始指令可能已无法反映当前问题**——任务状态在执行中持续演化；
2. **完整历史混合了过时信息、已完成步骤、未解决需求与执行噪声**——检索不可靠。

论文的核心洞见是：**存在一个紧凑且可靠的任务状态表示（工作记忆），持续将存储的经验与智能体当前的执行需求对齐**，是解决长时程任务中 RSI 问题的关键。Recuris 将这一思想落实为“经验记忆-工作记忆耦合 + 结构化证据驱动的递归演化”架构，使记忆系统本身成为可改进的、可训练的“外化表面”。

## 二、论文提出的方法论

### 核心思想

Recuris 构建了一个**有界的递归记忆演化循环**：

> **EM–WM 耦合 → 结构化证据 → 失败定位 → 定向记忆演化**

整个循环分为任务级执行循环与跨任务演化循环两个层次。底层 LLM 与外部改进流程完全冻结，递归仅发生在外部化的记忆控制层中。

### 关键技术细节

**1. 技能记忆架构**

演化进行到第 k 轮时，技能记忆表示为四元组：

> **Mₖ = (Eₖ, Wₖ, ρₖ, Cₖ)**

- **Eₖ**：经验记忆，存储可复用技能（采用 Agent Skills 格式）；
- **Wₖ**：工作记忆规范，定义状态模式与状态更新提案；
- **ρₖ**：调用策略，决定在哪些执行事件上检索技能；
- **Cₖ**：检查器集合，检验观测是否支持状态变更。

每个候选补丁只修订诊断识别到的组件，保持补丁空间可解释且组件级限定。

**2. 任务内验证式 EM–WM 耦合**

- **结构化工作状态 wₜ**：每个目标条目记录内容、状态（pending/done/blocked）、支撑证据与可选阻碍项；
- **状态锚定技能调用**：`Eₜ = ρₖ(x, wₜ, eₜ, Eₖ)`，在特定执行事件（如起草状态更改工具调用时、回合边界时）触发检索，检索键为当前工具或状态谓词；
- **证据锚定状态更新**：通过 `ŵₜ₊₁ = U_{Wₖ}(wₜ, aₜ, oₜ)` 提出状态变更，`Cₖ` 检查器基于环境返回的观测结果（而非模型自身声明）决定是否接受变更，`K` 为固定提交规则。目标只有在检查器确认环境证据支持时才能从 pending 变为 done。

**3. 跨任务有界技能记忆演化**

- **基于轨迹的失败定位**：固定定位阶段产生 `Dₖ = {(fⱼ, zⱼ)}`，将每个失败归因到四个组件之一（E=技能缺失/缺陷，W=状态规范问题，ρ=调用时机/键问题，C=检查器问题）；
- **组件专属补丁**：`Δm_z = P_fixed(...)`，只修改被归因的组件；
- **验证门控补丁准入**：固定门控 G_fixed 要求候选补丁必须修复源失败任务且不使保留开发集（含锚定任务）发生回归，才被采纳；
- **测试时适应模式**：缩小证据池与补丁空间至单个任务，用隐藏验证器返回的 1 bit 反馈驱动更新。

### 核心公式（文字表述）

任务级执行回路为：当前工作状态 → 调用策略选择技能 → LLM+工具产生动作与观测 → 工作记忆规范+检查器+固定提交规则更新状态。跨任务演化回路为：当前记忆 → 结构化执行轨迹 → 固定定位分析 → 固定补丁生成 → 验证门控决策 → 下一轮记忆。

## 六、论文的主要结论与发现

1. **Recuris 在 37 个模型-基准配对中提升 35 个**，增益跨 3B 到前沿模型普遍存在：
   - τ²-Retail：GPT-5.6 Sol +17.8 pts（58.3→76.1）、Claude Opus 5 +15.6 pts（72.4→87.9）、部署模型 +23.3 pts（58.1→81.4）；
   - SkillFlow：Qwen3.6-27B +16.6 pts、Qwen3.6-35B +13.5 pts。

2. **优势随时间程增长而扩大**：最长任务上达 +32.2 pts，无衰减趋势；常见长时程失败率下降 20–86%（如幻觉式完成 ↓86%、零写入回合 ↓80%）。

3. **长时程失败是执行问题而非检索问题**：读取动作召回率在所有变体中均高（88.0–97.9%），差距完全在写入路径。基础智能体 42% 的需写入 episode 未执行任何写入（Recuris 仅为 16%）。

4. **工作状态比技能内容更重要**：WM only +23.9 pts vs EM only +2.0 pts；模型控制注入全部技能比不带技能还差（65.6 vs 82.0），证明“何时调用”比“调用什么”更关键。

5. **关键机制因域而异（双分离）**：写审查（write review）在 τ²-Airline 至关重要（移除 −13.5 pts），在 τ²-Retail 近乎惰性；状态板（status board）则正好相反（τ²-Retail −17.3 pts）。

6. **结构化轨迹使故障可定位**：故障注入条件下，宏观准确率从仅结果的 13.0% 提升到结构化轨迹的 64.8%。

7. **递归演化产生一致的保留集增益**：三条演化线收敛至约 +10 pts 增益；两套独立 Meta-Agent 实现（Claude Code 与 DeepSeek Harness）统计上不可区分。

8. **演化记忆跨任务和跨模型迁移**：基于 16 个失败任务的训练，在 86 个未见任务上提升 +9.01 至 +17.44 pts；记忆迁移到未见模型（GPT-5.6 Sol、Claude Opus 5 等）。

9. **测试时适应（单任务模式）**：预算匹配后（4 次尝试），adaption 相比纯重试仅 +2.3 pts（区间含零），但每尝试成功率在需要学习技能的任务上 +4.5 pts；显示学习效应集中在单任务可靠性与个别困难任务上。

## 七、优点与亮点

1. **概念框架清晰且优雅**：将 RSI 从“改写模型/完整智能体”收敛为“只演化外部化记忆控制层”，在有限但可操作的表面内实现自我改进，概念上有界性明确。

2. **双重分离的实验设计**：状态板 vs 写审查在两个域上的相反重要性，强有力地证明“关键组件无法通过架构先验确定”，为演化动机提供了直接实证支持。

3. **结构化轨迹作为诊断基础设施**：将每一步的（状态、调用技能、动作、观测、检查器决定）记录为生态学证据，使失败可归因到具体组件，解决了 RSI 中“该修哪里”这一核心难题。

4. **严格的验证门控**：要求候选补丁修复源任务且不使保留开发集回归（锚定任务）；门控宁可保守（拒绝在保留集上实际有效的补丁），也不冒险破坏既有能力。

5. **统计纪律严格**：使用配对任务聚簇 bootstrap、A/A 重跑校准分辨率、McNemar 精确检验、明确的“区间含零即无效应”标准，避免了选择性报告。

6. **消融设计系统全面**：从“有没有记忆层”（harness term）到“演化有无增益”（evolution term）再到“机制是否关键”（mechanism ablation），逐层剥离归因，最终效果定位在演化项而非工程项。

7. **跨模型迁移设计凸显鲁棒性**：一个记忆包在中间规模模型上演化后直接迁移到 6 个未见模型，证明学到的是模型间共享的程序/纪律而非特定模型缺陷。

## 八、不足与局限

1. **算力信息缺失**：未报告 GPU 型号、数量、演化循环总计算成本、Meta-Agent 的推理开销等关键资源数据，难以评估实际部署成本。

2. **τ²-Airline 统计功效不足且效应弱**：50 任务的小样本使所有消融区间均含零，只能读出方向；且回忆该域保留集已无可改进任务，跨任务迁移无法验证。

3. **SkillFlow 缺乏真正的 held-out 泛化测试**：技能模板是在家族内选择的（in-sample），只能衡量跨目标模型迁移，无法衡量对未见任务的泛化——这是基准结构决定的，但仍是能力边界。

4. **单一来源记忆存在潜在偏置**：记忆只在 Doubao-2.0-Pro 上演化；论文有意选择这一设计，但也承认如果针对每个模型单独演化，结果可能不同。记忆迁移的公平性虽好，但并非最优适配。

5. **测试时适应的学习效应较弱**：预算匹配后 +2.3 pts（区间含零）且 McNemar p=0.774 不显著；只有 56 个任务的 avg@4 变化方向一致（+4.5 pts），但所有区间仍含零。深度案例（单任务 16 次 rollout）是唯一显著证据，样本代表性有限。

6. **验证门控在现实应用中的保守性代价**：门控在大约 30 点宽的置信区间上拒绝了许多在 held-out 集上实际有效的补丁（图 9b 中 3 个被拒候选在保留集上转正），保守性可能导致有效改进被长期延迟。

7. **退化/遗忘风险监测有限**：论文报告接纳的补丁在 42 个锚定任务上只破坏 4 个（9.5%），但演化只增不减、未采用剪枝操作，技能记忆持续扩张带来的长期维护成本（冗余技能、冲突技能）未被充分探讨。

8. **基座模型/工具/环境受限**：所有实验使用特定的工具集与参考代理，结论对更多样的工具生态与更复杂环境的普适性需要进一步验证；τ²-Airline 基线上限较高（>75%），增量空间有限，限制了增益解读。

9. **因果识别仍是启发式的**：论文明确承认失败定位是“修复决策”而非“因果识别”，多机制共同导致失败时，归因到单组件的选择可能遗漏更优的联合修复方案。
