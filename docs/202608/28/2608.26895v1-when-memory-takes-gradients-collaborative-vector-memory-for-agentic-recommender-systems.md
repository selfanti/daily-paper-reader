## 摘要
智能体推荐系统将大语言模型（LLM）的每个决策基于用户的持久记忆，在现有智能体中，这种记忆是文本：由进一步的LLM调用编写和维护的叙述。文本以两种方式限制这种记忆。它一次只重写一个部分，因此利用完整交互历史的成本过高；而且协作证据——整个目录上的分级相似性——无法在翻译成句子后保留。我们提出CoVeMem（协作向量记忆），它将智能体记忆的协作核心向量化。冻结的LightGCN用户和物品状态构成记忆库；在每次决策时，候选集本身检索最相关的历史状态，这些状态以软令牌形式连同简洁的文本画像进入LLM的上下文。与物品语义锚点的对比对齐，随后与掩码候选进行列表式协同训练，教会模型阅读这些状态并通过它们进行排序；逐点的是/否读出对每个候选进行评分。在四个基于指令的推荐基准上，CoVeMem在20个指标单元中的19个上匹配或超过最强的协作文本记忆智能体，同时除了共享的静态画像外，记忆维护无需额外LLM调用，而文本记忆需要每次交互调用。记忆现在获取梯度：文本无法企及的完整交互历史，成为智能体记住什么以及如何阅读所记住内容的训练数据。

## Abstract
Agentic recommender systems ground each decision of a large language model (LLM) in a persistent memory of the user, and in existing agents that memory is text: a narrative written and maintained by further LLM calls. Text limits this memory in two ways. It is updated one rewrite at a time, so exploiting the full interaction history is prohibitively expensive; and collaborative evidence, graded similarity over an entire catalog, does not survive translation into sentences. We propose CoVeMem (Collaborative Vector Memory), which vectorizes the collaborative core of the agent's memory. Frozen LightGCN user and item states form the memory bank; at each decision, the candidate set itself retrieves the most relevant historical states, which enter the LLM's context as soft tokens alongside a light textual profile. Contrastive alignment to item-semantic anchors, followed by listwise co-training with masked candidates, teaches the model to read these states and to rank through them; a pointwise yes/no readout scores each candidate. Across four instruction-grounded recommendation benchmarks, CoVeMem matches or exceeds the strongest collaborative text-memory agent on 19 of 20 metric cells while requiring zero additional LLM calls for memory maintenance beyond the shared static profile, against per-interaction calls for text memory. The memory now takes gradients: the full interaction history, out of reach for text, becomes available as training data for what the agent remembers and for how it reads what it remembers.

## 1. 核心问题与整体含义

- **研究动机**：智能体推荐系统（Agentic Recommender Systems）依赖 LLM 维护用户的持久记忆以完成推荐决策。现有系统普遍使用**文本记忆**（textual memory），即通过 LLM 反复改写用户叙述来记录偏好。
- **文本记忆的两大根本限制**：
  - **维护成本高**：文本记忆一次只能进行一次 LLM rewrite，吸收完整交互历史需要逐条反复调用 LLM，代价高昂且无法并行利用全部历史。
  - **协作结构丢失**：推荐的核心协同信号是**跨整个目录的分级相似性**（graded similarity over an entire catalog），这本质上是一种几何结构，无法在序列化为句子后完整保留——文本只能表达它命名的内容，大量邻居/维度在序化过程中被丢弃。
- **核心问题**：能否构建一种持久智能体记忆，保留目录级协作结构、可用完整交互历史进行训练，同时无需反复文本重写、直接为 LLM 所用？
- **整体含义**：作者提出将记忆从“待书写的文本工件”转变为“可训练的组件”——通过向量化协作记忆并使其接受排序梯度的训练，完整的交互历史首次可成为记忆内容与记忆读取方式的训练数据。

## 2. 方法论：CoVeMem 的核心思想与关键技术

### 2.1 总体框架
- **混合记忆架构**：CoVeMem 将智能体记忆分为两部分——**协作向量记忆**（存储证据）+ **参数化记忆读取器**（学习如何使用证据）。
- 记忆库（Memory Bank）：用 LightGCN 在训练交互二部图上学习每个用户和每个物品的 d=64 维状态向量，训练后**冻结**。
- 同时保留一个简洁的**文本画像**（一次性离线蒸馏自训练评论），承载显式用户信息。

### 2.2 目标感知检索（Target-Aware Retrieval）
- 对每个决策，用候选集的**质心**（centroid）查询用户历史：  
  \(\bar{c} = \frac{1}{|C_u|} \sum_{c \in C_u} v_c\)，返回与质心最相似的 K=5 个历史物品状态。
- 这是**候选条件化检索**（candidate-conditioned retrieval），而非简单取最近历史——只涉及点积，不消耗 LLM 调用。
- 训练时历史严格取事件之前的因果前缀，确保检索永远不会暴露目标项。

### 2.3 记忆注入
- **门控投影器**（gated projector，两模块门控 MLP）将状态向量映射到 LLM 输入嵌入空间，占据单个 token 位置成为**软令牌（soft tokens）**。
- 提示词中形成固定**记忆模式**：用户画像 + K 个 token 历史槽 + 同名标题行 + 用户软令牌 + 候选行（每个候选含标题与物品软令牌）。

### 2.4 参数化记忆读取器（Parametric Memory Reader）
- 由**门控投影器**与**rank-r LoRA 适配器**（r=4，作用于注意力投影，约 6.8M 参数，占模型不足 0.1%）组成。
- 关键设计：记忆库与画像冻结，**反向传播的梯度只训练读取器**（投影器+LoRA），即“记忆获取梯度”体现在读取方式的训练上。

### 2.5 两阶段训练

**阶段一：语义锚点对齐（Semantic-Anchor Alignment）**
- 为每个物品构造语义锚点 \(y_i\)（LLM 输入嵌入空间中标题与类别的平均）。
- 对称批内对比损失：
  \[
  \mathcal{L}_{align} = \frac{1}{2} \left[ CE\left(\frac{\hat{\phi}(v)\hat{y}^\top}{\tau}\right) + CE\left(\frac{\hat{y}\hat{\phi}(v)^\top}{\tau}\right) \right]
  \]
  其中 \(\hat{\cdot}\) 表示 ℓ2 归一化，\(\tau\) 为温度，目标为对角。
- 作用：为投影器提供免费的跨模态桥接初始化，使每个投影状态在语言空间中获得有意义的语义位置。

**阶段二：掩码列表式协同训练（Masked Listwise Co-Training）**
- 每次交互（具有足够前缀）构成一个排序事件：前缀为历史，交互物品为正样本，N−1 个负样本从用户完整序列之外均匀采样。
- **列表式损失**（竞争池 P 上的边际排序损失）：
  \[
  \mathcal{L}_{rank} = \frac{1}{|P|-1} \sum_{j \in P, j \neq y} \max(0, m - (z_y - z_j))
  \]
- **防文本捷径的关键设计**：以概率 p=0.5 掩码每个候选标题。当正样本被掩码时，竞争池 P 仅包含被掩码的候选——这些选项无法通过标题文字区分，模型**只能**借助协作软令牌完成排序，从而被迫学会读取记忆。
- **稳定性措施**：门控缩放从 0 退火到 1（前 \(T_g=60\) 步）、对用户令牌与历史槽做轻量 dropout。
- 注意：指令在训练阶段被刻意省略（InstructRec 的指令由留出目标项推导而来，属目标条件信息），仅推理时加入。

### 2.6 推理：记忆感知裁决
- 逐候选进行**点式 yes/no 读出**（pointwise yes/no readout），而非列表式生成：
  \[
  s_c = M[T_u \|_\pi M^{text}_u \| \Phi(\tilde{H}_u) \| t(\tilde{H}_u) \| \phi(s_u) \| (c, \phi(v_c)) \| P_{judge}][\text{Yes}]
  \]
- 分数为“Yes”令牌的 logit，各候选并行打分，最终对分数排序。无文本生成，避免生成式排序的解析失败。
- 指令位置（早/中/晚）由**零样本规则卡**基于训练集统计（交互密度与集中度）预测选择，非搜索调参。

- 指标：Hit@K（K=1,3,5）与 NDCG@K（K=3,5）。

### 3.2 对比方法

- 所有智能体基线使用相同 LLM 栈（Qwen2.5-7B-Instruct）复现。

### 3.3 消融与附加研究
- **记忆消融**（RQ2）：Text-Recent（仅标题按时间最近，无向量记忆）与 Text-TA（标题按目标感知选取，无向量记忆）对比完整 CoVeMem；以及 w/o LoRA（冻结适配器）。
- **协作骨干研究**（RQ3）：在 Yelp 上用五种不同协作骨干替换记忆库状态——BPR-MF、SVD++、GRU4Rec、SASRec、LightGCN，全程重训流程。
- **记忆维护效率**（RQ4）：测量记忆维护 token 成本与决策时间 token 成本。

## 6. 主要结论与发现

- 在 20 个指标单元中，CoVeMem 对最强文本记忆基线 MemRec **匹配或超越 19 项**，Goodreads 上优势最大，MovieTV 方向一致但幅度较小。
- Goodreads 是流行度主导的数据集（仅按训练集流行度排序 Hit@1 即达 0.6727），文本记忆只能保留有限侧面，而 CoVeMem 的图训练记忆库编码目录级交互结构，**补回 Vanilla LLM 与最强传统推荐器之间 Hit@1 差距的 90% 以上**。
- Books 与 Yelp 每个物品交互较少，文本语义作用更大——CoVeMem 保留 LLM 的语义能力并叠加协作信息作为补充：Yelp 领先，Books 持平。
- **消融证明**：增益主要来自注入的向量状态（而非仅目标感知标题选择）；移除 LoRA 后模型无法读取状态，性能跌至 Vanilla LLM 水平甚至更差，证明 LoRA 适配是向量记忆可用的必要条件。
- **骨干研究证明**：记忆库模块化——任意能产出状态的传统推荐器均可作为骨干，但**记忆质量直接决定收益上限**（最强 SVD++ 超越默认 LightGCN，最弱 SASRec 无优势）。
- **效率**：CoVeMem 记忆维护的 LLM token 成本为**零**（一次性离线构建），决策时间 token 成本为四大系统最低，在 Pareto 前沿上占据高精度端。

## 7. 优点

- **视角创新**：明确提出“记忆载体”（memory carrier）是独立设计维度——文本只保存它命名的内容，载体决定何种证据可触及决策；向量化使记忆从“智能体书写的工件”变为“可训练的组件”。
- **训练机制精心设计**：
  - 候选掩码强制模型离开文本捷径、依赖协作令牌；
  - 列表式损失与掩码竞争池协同作用，使排名只能通过比较协作令牌被降低；
  - 门控退火与 dropout 保障训练稳定性；
  - 语义对齐为跨模态桥提供免费监督初始化。
- **严格因果性**：训练时检索严格取事件前缀、目标不进入检索；测试目标同时从图和画像中剔除，避免信息泄漏。
- **效率显著**：记忆维护零 LLM 调用、检索仅需点积、推理为并行点式评分，体现“高效决策”优势。
- **模块化验证**：用五种协作骨干替换记忆库并重训全部流程，证明方法不依赖特定协同模型，且能清晰刻画骨干质量与最终效果的关系。
- **诚实报告**：对 Goodreads 流行度优势、无 LoRA 时的性能恶化、弱骨干无增益等情况均如实呈现，未文过饰非。

## 8. 不足与局限

- **时间信息缺失**：未报告训练时长、推理延迟对比等计算效率指标（虽然 token 成本已论证，但墙钟时间也是实际部署的关键因素）。
- **外部有效性受限于单一模型栈**：所有实验仅用 Qwen2.5-7B-Instruct 一个 LLM 后端；未见对更大/更小模型或不同模型族的泛化验证。
- **法归一化（transductive）偏差风险**：记忆库与画像在全训练期估计后固定，早期事件的状态可能已反映后续交互；作者承认此点并论证与基线同构，但严格的因果在线模拟并未提供。
- **数据集覆盖有限**：四个 InstructRec 域均为文档型或商户型推荐，未覆盖短视频、新闻、电商等更多模态且交互更稀疏的场景。
- **消融广度受限**：消融仅在 Goodreads 与 Yelp 上进行；未报告候选掩码概率、K 值、批次大小、LoRA rank 等超参数的敏感性分析。
- **协作骨干注入方式未充分探索**：仅用于用户/物品状态注入，未考虑序列级或会话级表示；不同骨干只是“替换状态表”，对骨干自身输出分布差异的适配（除简单缩放）未深入设计。
- **指令位置选择依赖零样本规则卡**：由 LLM 基于训练集统计预测，虽避免测试反馈，但规则本身的鲁棒性未做敏感性检验。
- **规模局限**：单 GPU 设置限制了批次大小与模型规模，大规模生产环境中的可扩展性有待更大规模实验验证。
