## 摘要
工具集成推理（TIR）是大语言模型智能体通过迭代与外部工具交互以解决复杂任务的基本能力。强化学习（RL）已成为实现这种能力的主导范式。然而，现有方法通常分配统一的轨迹级优势，并同等对待所有正确的工具调用，忽略了不同轨迹和推理步骤之间在难度和学习价值上的差异。这可能导致学习信号不精确，无法充分区分琐碎和具有挑战性的工具使用模式。为解决这一局限性，我们提出了HiDiffTIR，一种用于多轮TIR的层次化难度感知策略优化框架。HiDiffTIR在轨迹级和轮次级都执行难度感知的信用分配，使策略能够聚焦于更具信息量的轨迹和更难的推理步骤。值得注意的是，这种细粒度的优化无需额外监督即可实现，仅依赖于从标准RL rollout中获得的组级统计量。在三个工具使用基准上的大量实验表明，HiDiffTIR相较于强RL基线持续提升了多轮TIR性能和工具调用准确性，凸显了难度感知信用分配对于工具集成大语言模型智能体中有效策略优化的必要性。

## Abstract
Tool-Integrated Reasoning (TIR) is a fundamental capability for LLM agents to solve complex tasks by interacting with external tools iteratively. Reinforcement Learning (RL) has become the dominant paradigm for enabling this capability. However, existing approaches typically assign uniform trajectory-level advantages and treat all correct tool calls equally, ignoring the varying difficulty and learning value across trajectories and reasoning steps. This can lead to imprecise learning signals that do not adequately distinguish between trivial and challenging tool-use patterns. To address this limitation, we propose HiDiffTIR, a Hierarchical Difficulty-aware policy optimization framework for multi-turn TIR. HiDiffTIR performs difficulty-aware credit assignment at both trajectory and turn levels, enabling the policy to focus on more informative trajectories and harder reasoning steps. Notably, this fine-grained optimization is achieved without additional supervision, relying solely on group-level statistics derived from standard RL rollouts. Extensive experiments on three tool-using benchmarks demonstrate that HiDiffTIR consistently improves multi-turn TIR performance and tool invocation accuracy over strong RL baselines, highlighting the necessity of difficulty-aware credit assignment for effective policy optimization in tool-integrated LLM agents.

## HiDiffTIR 论文详细总结

### 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：工具集成推理（Tool-Integrated Reasoning, TIR）是 LLM 智能体通过迭代调用外部工具（如 API、搜索引擎、代码解释器等）来解决复杂任务的核心能力。强化学习（RL）已成为训练 LLM 进行 TIR 的主流范式，典型算法如 GRPO（Group Relative Policy Optimization）。
- **核心问题**：现有基于 RL 的 TIR 方法存在**信用分配粗糙**的问题：
  - 早期方法仅依赖结果奖励（outcome-based reward），面临奖励稀疏问题；
  - 近期方法引入轮次级验证（turn-level verification），但仍将所有正确的工具调用**一视同仁**，分配统一的轨迹级优势；
  - 这种做法忽略了不同轨迹和推理步骤在**难度与学习价值**上的差异，导致学习信号不精确，无法充分区分"琐碎"与"具有挑战性"的工具使用模式。
- **核心论点**：并非所有轨迹和工具调用步骤对策略改进的贡献相同——部分轨迹因其相对难度而更具信息量，部分推理步骤本质上更难、更有学习价值。因此，需要一种**难度感知（difficulty-aware）**的细粒度信用分配机制。

### 二、提出的方法论：HiDiffTIR

#### 2.1 核心思想

HiDiffTIR 提出**层次化（Hierarchical）难度感知策略优化框架**，在两个层面进行细粒度信用分配：

- **轨迹级（Trajectory-level）**：根据轨迹中所有工具调用的相对难度区分不同 rollout，使策略优先关注更具信息量的轨迹。
- **轮次级（Turn-level）**：根据各推理步骤的工具选择难度与工具使用难度，将轨迹级优势重新分配到各个轮次。

**关键优势**：整个难度判断**仅依赖标准 RL rollout 产生的组级统计量**（group-level statistics），无需额外监督（如 LLM 判断器、评分标准等）。

#### 2.2 轨迹级难度感知信用分配

1. **原始奖励计算（Raw Reward Computation）**：
   - 对每个轨迹 $τ^{(i)}$，计算预测工具调用与真实工具调用之间的相似度矩阵 $M_i[u,v] = sim(c_{iu}, c^*_{iv})$（综合考虑工具名、参数名、参数值）。
   - 使用匈牙利算法（Hungarian algorithm）求解最大权二分匹配，得到轮次奖励 $r_{i,j}$。

2. **难度感知奖励加权（Difficulty-Aware Reward Reweighting）**：
   - 在同一查询 q 的轨迹组 $G(q)$ 内，计算每个真实工具调用的组内平均奖励 $\bar{r}(c^*)$；
   - 轮次难度定义为 $d_{i,j} = 1 - \bar{r}_{i,j}$；
   - 重新加权原始奖励：$\tilde{r}_{i,j} = d_{i,j} \cdot r_{i,j}$——**强调较难的工具使用决策，削弱持续简单的决策**。

3. **轨迹级分数构建**：
   - 组内 min-max 归一化 + 重新缩放保持总奖励质量；
   - 聚合得到轨迹级分数 $R(τ^{(i)})$；
   - 转换为组内相对优势：$A(τ^{(i)}) = \frac{R(τ^{(i)}) - μ_q}{σ_q}$。

#### 2.3 轮次级难度感知信用分配

1. **组级工具选择成功率（Group-Level Tool Selection Success Rate）**：
   - 计算每个真实工具调用在组内的选择成功率 $s(c^*)$（带平滑常数 λ）；
   - 轮次级统计量取该轮中最难工具调用的成功率：$s_{i,j} = \min_{c^* \in C^*_{i,j}} s(c^*)$。

2. **难度感知优势重加权（Difficulty-Aware Advantage Reweighting）**：
   - 对正优势轨迹：权重 $\tilde{w}_{i,j} = \frac{r_{i,j}}{\sqrt{s_{i,j}}}$，**抑制错误轮次、优先困难正确决策**；
   - 对负优势轨迹：使用均匀权重，保证对失败 rollout 的稳定惩罚；
   - 归一化后，将轨迹级优势按权重分配到各轮次：$A_{i,j} = A(τ^{(i)}) \cdot (α + (1-α)\hat{w}_{i,j})$，其中 $α$ 控制轨迹级与轮次级信用分配的平衡。

#### 2.4 策略优化

- 将轮次级优势分配给对应轮次内所有 token，结合 GRPO 算法进行优化，目标函数为标准 GRPO 形式 + 难度感知层次化信用分配（含重要性采样比率裁剪与 KL 正则化）。

### 六、主要结论与发现

1. **持续最优表现**：HiDiffTIR 在 Qwen3-4B 和 Qwen3-8B 上的平均分均超越所有基线，且在领域内和领域外场景均表现最佳。
2. **跨骨干规模泛化**：改进对 4B 和 8B 模型均有效；较小模型在 FTRL 上获益更明显，说明细粒度难度感知优化可部分弥补较弱的内在推理能力。
3. **工具环境越大，优势越明显**：在工具数较多的 FTRL 和 ToolHop 上改进更显著，难度感知优化在复杂工具环境中的价值更大。
4. **层次化组件缺一不可**：移除任一组件均导致性能下降；轨迹级组件对 FTRL 影响更大。
5. **效率与效果兼具**：完整模型相比仅轨迹级变体，平均响应长度从 2,085 降至 1,893 tokens（减少 ~12.8% 生成延迟），在保持更高准确率的同时实现更紧凑的推理。
6. **α = 0.7 是最优平衡**：较低 α 虽在训练中达到更高工具准确率，但会在测试集上过拟合"刚性正确"模式，抑制必要的试错探索；α = 0.7 兼顾轨迹级探索保护与轮次级瓶颈解决。
7. **组大小越大，ID 表现越好**：G=16 时 ID 性能最佳；OOD 表现存在波动（非严格单调）。
8. **现存局限**：所有 RL-based TIR 方法在缺信息场景（MF/MP）提升有限，HiDiffTIR 的难度加权可能强化"激进调用工具"的偏向。

### 七、优点与亮点

1. **无需额外监督的细粒度优化**：仅依赖标准 RL rollout 的组级统计量即可实现难度感知信用分配，不引入 LLM 判断器、奖励模型或人工标注，成本低、可复现性强。
2. **层次化设计新颖**：同时建模轨迹级与轮次级难度，两个层面互补——轨迹级保住探索价值，轮次级精准定位困难瓶颈。
3. **理论清晰、公式完备**：从原始奖励计算、难度定义、加权策略到 GRPO 目标函数，形成完整自洽的技术路线。
4. **实验设计较全面**：覆盖多模型、多基准、消融、超参敏感性、训练动态、定性案例，验证了方法的有效性、泛化性与效率。
5. **诚实的失败分析**：公开讨论在 BFCL 缺信息场景（MF/MP）上的局限，指出难度加权可能强化激进调用偏向，为后续研究提供了方向。
6. **代码开源**：提供了公开代码仓库，便于复现。

### 八、不足与局限

1. **骨干模型规模有限**：仅验证了 Qwen3-4B 和 Qwen3-8B，未测试更大参数模型（如 70B+）上的行为动态与可扩展性。
2. **依赖初始策略能力**：难度信号基于在线 rollout 统计，若初始策略在极端复杂任务中完全无法产生有效工具调用，会遭遇奖励稀疏问题，可能需要 SFT 热身阶段。
3. **难度估计是启发式的**：反映的是策略在 RL rollout 中的"经验学习难度"（操作瓶颈），而非静态语义复杂度的绝对度量，不同训练阶段难度信号可能不稳定。
4. **OOD 泛化波动**：消融实验显示各组件对 OOD 场景（完全未见过的工具）影响有限；组大小实验也显示 OOD 表现非严格单调。
5. **缺信息场景偏置风险**：难度感知加权放大成功复杂工具序列，可能强化"激进调用"行为，在需要识别信息不足的场景中表现偏弱。
6. **训练时长未报告**：缺少训练时间的具体数据，不利于评估方法的工程成本。
7. **基准工具数差异大**：BFCL 仅 84 个工具，与 FTRL/ToolHop 数千工具的规模差异明显，"工具环境越大优势越明显"的结论证据分布不均。
