## 摘要
生物医学多跳问答（QA）要求模型在疾病、药物、蛋白质和表型等中间实体之间连接证据。现有智能体通常依赖静态检索工作流或粗粒度的提示重写，这可能导致在需要更新推理过程时出现指令漂移。我们提出了SSE-Bio，一种具有智能检索策略的结构化自进化智能体，用于多跳生物医学推理。SSE-Bio不是全局重写智能体指令，而是维护一个结构化状态，通过可训练的代理策略选择性地检索知识三元组和先前模板，并通过细粒度的模板编辑改进其推理记忆。为了优化检索决策，我们引入了一种基于组相对策略优化的代理训练策略，其中代理通过替代检索选择上的决策对比组来改进。在三个生物医学多跳QA基准上的实验表明，SSE-Bio始终优于现有基线，在BioHopR上比最强的自进化基线提高了6.56个绝对百分点。

## Abstract
Biomedical multi-hop question answering (QA) requires models to connect evidence across intermediate entities such as diseases, drugs, proteins, and phenotypes. Existing agents typically rely on static retrieval workflows or coarse-grained prompt rewriting, which can lead to instruction drift when reasoning procedures need to be updated. We propose SSE-Bio, a structured self-evolving agent with an agentic retrieval policy for multi-hop biomedical reasoning. Instead of globally rewriting agent instructions, SSE-Bio maintains a structured state, selectively retrieves knowledge triplets and prior templates through a trainable proxy policy, and improves its reasoning memory through fine-grained template editing. To optimise retrieval decisions, we introduce a proxy-training strategy based on group relative policy optimization, where the proxy is improved through decision-contrastive groups over alternative retrieval choices. Experiments on three biomedical multi-hop QA benchmarks show that SSE-Bio consistently outperforms existing baselines, achieving an improvement of 6.56 absolute points over the strongest self-evolving baseline on BioHopR.

# SSE-Bio 论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

生物医学多跳问答（multi-hop QA）要求模型在疾病、药物、蛋白质、表型等跨实体之间连接证据完成推理，例如先识别与疾病相关的桥梁蛋白，再推断与该蛋白关联的药物。已有方法存在两类关键缺陷：

- **静态检索工作流**：现有 RAG 或多智能体系统大多使用固定检索策略，无法根据当前推理状态动态决定“何时检索、检索什么”，导致证据利用次优。
- **粗粒度记忆更新**：自进化智能体通常通过整体重写提示词来更新推理策略，一次局部失败可能改变整个推理框架，引发“指令漂移”（instruction drift）和幻觉。

本文提出 **SSE-Bio**（Structured Self-Evolving Agent），旨在将 **结构化状态跟踪**、**长期模板记忆** 和 **显式可训练的检索控制** 统一到一个智能体框架中，从而在生物医学多跳推理中实现更可控、可审计的证据利用与记忆演化。

## 2. 方法论

### 2.1 总体框架
SSE-Bio 包含四个组件：
- **Manager**：维护结构化状态（短期记忆），根据状态构造查询相关的推理计划，并在成功时更新长期模板记忆。
- **Proxy**：可训练的检索策略模块，根据当前结构化状态，决定是否检索知识三元组和/或先前模板。
- **Dev Agent**：执行计划，生成中间推理轨迹和答案。
- **Critic**：对推理质量和答案质量进行结构化评估，返回细粒度反馈，用于迭代修正。

### 2.2 结构化记忆
- **短期状态**：包含 Task type、Information gap、Feedback、Retrieval state 四个字段，用于指导检索决策和计划生成。
- **长期模板记忆**：每个模板包含 Task type、Reasoning flow、Verification criteria、Tool-use policy、Failure warning 等字段，作为可复用的推理先验。
- **记忆演化**：当成功轨迹与已有模板对齐时，采用**细粒度编辑**只更新相关字段；若不对齐则蒸馏新模板，从而避免全局重写带来的指令漂移。

### 2.3 智能检索策略（Proxy）
- Proxy 在每个推理轮次输出动作 `a_t ∈ 2^{KG, TPL}`，即四种组合：不检索、仅知识三元组、仅模板、两者都检索。
- 知识三元组检索以信息缺口为查询，使用 BiCA 编码和余弦相似度，经模式过滤后返回 top-K 三元组；模板检索以任务类型为查询，返回 top-1 兼容模板。

### 2.4 Proxy 策略训练
- **SFT 初始化**：通过比较不同检索分支的奖励，生成伪标签，预训练 Proxy。
- **决策对比轨迹生成**：从同一推理状态扩展多个备选检索动作，形成对比轨迹组；通过剪枝（模式不匹配、信息缺口未解决、桥梁实体不受支持等）保留 top-K 分支，避免组合爆炸。
- **奖励塑造**：
  - 结果奖励：`R_out(τ) = 1{corr(τ)}`，判断最终答案是否匹配标准答案。
  - 行为奖励：`R_beh(τ) = (1/|S_τ|) Σ 1{s is evidence-supported}`，衡量关键步骤（桥梁解析、答案验证）是否被检索证据或模板验证标准支持。
  - 综合奖励：`R(τ) = λ_o R_out(τ) + λ_b R_beh(τ)`，实验中取 λ_o=0.8，λ_b=0.2。
- **GRPO 优化**：采用动作级 GRPO，计算组内相对优势 `A_i = (r_i - μ(r)) / (σ(r) + ε)`，使用裁剪的旧-新策略比率 `ρ_i(θ)`，并加入 KL 正则化约束，最大化目标函数 `J_GRPO`。

## 3. 实验设计

### 3.1 数据集与基准
- **BioHopR**：7.63K 配对实例，7:3 划分训练/测试（约 5.34K/2.29K），支持单答案和多答案评估，指标包括 Prec H1、Prec H2、Both cor、Both wr。
- **MedHop**：跨文档生物医学问答数据集，用于零样本迁移评估，报告准确率。
- **Humanity’s Last Exam: Biomedicine（HLE）**：高难度专家级生物医学子集，同样用于零样本评估，报告准确率。

### 3.2 对比基线
涵盖五类：
- 通用 LLM：Llama-3.1-8B/70B、GPT-4o。
- 医学 LLM：HuatuoGPT-o1-70B/8B、UltraMedical-8B。
- RAG 方法：i-MedRAG、AMG-RAG。
- 生物医学智能体：KGARevion、DoctorAgent-RL、MedAgents、Biomni。
- 自进化智能体：STELLA。

为保证公平，所有智能体基线使用与 SSE-Bio 相同的骨干配置：Manager/Critic 用 Gemini-2.5-Pro，Dev 用 Claude-4.5-Sonnet；SSE-Bio 仅 Proxy 为可训练组件。

### 3.3 主要实验类型

- 消融实验：结构化状态 vs 自由文本、细粒度编辑 vs 整体重写、去除 Proxy、去除三元组、去除模板。

## 6. 主要结论与发现

- **主实验结果**：在 BioHopR 上，SSE-Bio 在单答案和多答案设置下均取得最优效果。单答案 Both cor 达到 16.52，较 STELLA（9.96）**提升 6.56 个绝对百分点**；多答案 Both cor 达到 11.73，同样显著优于所有基线。
- **跨基准泛化**：SSE-Bio 零样本迁移到 MedHop 和 HLE 时表现优于或追平最强智能体基线，表现出较强的推理泛化能力。
- **Proxy 价值**：去掉 Proxy 后 Both cor 大幅下降（单答案从 16.52 降至 10.62），且 Learned Proxy 优于任何固定检索策略（固定“两者都检索”的 Both cor 仅为 13.18），说明状态相关的检索控制是关键增益来源。
- **结构化自演化有效**：结构化状态 + 细粒度编辑的组合显著优于自由文本 + 整体重写（Both cor 从 11.72 提升至 16.52），且细粒度编辑比粗粒度重写改动字段更少、产生的不受支持指令和矛盾指令更少。
- **检索有剩余空间**：Oracle 三元组和模板同时使用时，单答案 Both cor 可进一步从 16.52 提升至 18.06，说明当前检索仍有改进空间。
- **关系类型一致性增益**：在全部 12 种生物医学关系模式上，SSE-Bio 均优于 STELLA，尤其在需要强第二跳推理的关系上增益更大。

## 7. 优点

- **统一的框架设计**：将短期状态跟踪、长期模板记忆、显式检索控制整合到单一智能体流程中，避免静态检索和全局重写带来的问题。
- **细粒度、可审计的记忆演化**：通过局部字段编辑（如仅更新验证标准或失败警告）替代整体模板重写，显著降低指令漂移和幻觉风险。
- **可训练的检索策略**：Proxy 是唯一可训练组件，能够根据推理状态自适应决定检索源；SFT 初始化后经 GRPO 优化，训练信号融合了最终答案正确性和证据支撑度，比纯结果奖励更鲁棒。
- **决策对比轨迹生成**：在相同推理状态下扩展备选检索动作，形成匹配的对比分支，使强化学习能够公平比较不同检索决策的相对优劣。
- **实验分析全面**：包含多种消融、边界分析、跨数据集迁移、噪声鲁棒性、提示/API 敏感性等，结论可信度高。
- **开源代码与可控复现**：论文提供了源码仓库，且对训练和推理成本进行了详细披露。

## 8. 不足与局限

- **依赖检索质量**：Oracle 分析表明，更强的三元组和模板检索仍可带来约 1.5 个点的提升，当前检索器并非最优；错误分析中三元组检索失败占失败案例的 24.6%。
- **模板记忆增长问题**：尽管细粒度编辑比整体重写更可控，但长期积累仍可能出现冗余或过时模板，论文未提供自动合并、剪枝或溯源机制。
- **只训练 Proxy**：Manager、Dev、Critic 依赖固定的商业 API（Gemini-2.5-Pro、Claude-4.5-Sonnet），实验结果可能受提示细节和 API 行为影响；论文也承认 SFT 标签和 GRPO 奖励在同一固定代理环境中诱导，检索策略跨骨干迁移的能力未知。
- **训练数据偏置**：SFT 伪标签和 GRPO 轨迹全部来自 BioHopR 训练集，模板记忆也从该数据集中蒸馏，在其他领域或更复杂的生物医学问题上可能存在分布偏移。
- **效率与成本**：SSE-Bio 比 STELLA 和 Biomni 消耗更多 token 和 API 调用，虽然性能提升明显，但实际部署成本更高；论文没有进行更细致的性价比优化。
- **错误来源分布**：Dev 推理错误占 31.2%，说明仅优化检索策略无法完全解决推理质量问题。
- **应用限制**：论文明确指出该系统仅用于研究评估，不应直接用于临床诊断或治疗决策；若在真实生物医学场景使用需额外验证。
