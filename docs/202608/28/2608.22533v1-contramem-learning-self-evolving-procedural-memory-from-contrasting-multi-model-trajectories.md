## 摘要
自主计算机使用智能体日益被应用于需要协调应用程序调用、持续状态跟踪和验证器敏感写入的长时任务，但它们仍然容易出现程序性失败：误读应用程序状态、工具语义或任务进度。程序性记忆有望带来更一致的决策和更少的冗余探索，但在不进行模型训练的情况下构建高质量记忆仍然具有挑战性。我们提出了CONTRAMEM，一个源灵活、免训练的自进化程序性记忆框架，它将同一任务的结果差异视为监督信号：正确性、效率、恢复和失败模式上的差异揭示了与结果相关的程序性区别，并将其提炼为一个紧凑的存储库，包含应用级功能卡和任务级技能卡。该存储库通过局部策展进行演化，而非仅追加式累积或整体重写。在保留的GAIA2/ARE计算机使用任务上，CONTRAMEM使三个源模型目标的成功率提高了一倍以上（从26.2%到55.3%），并且每个模型都有稳定的提升（GPT-5.5：从27.5到61.0；Claude Sonnet 4.6：从28.0到52.5；DeepSeek V4 Pro：从23.0到52.5）。相同的存储库可原样迁移到未见过的Qwen3.7 Plus（从18.5到35.5），这表明程序性知识是可迁移的，而非特定于模型的行为。相同的构建方法也能原样应用于AppWorld，在公开测试集的两个划分上，对所有三个中端智能体均优于无记忆和其自身的单源自记忆变体。在匹配的轨迹预算下，异构多模型轨迹比自模型或同模型多次滚动的记忆产生更强的记忆：这种优势来自对比行为多样性，而非更强的源智能体或更多的采样。

## Abstract
Autonomous computer-use agents are increasingly applied to long-horizon tasks requiring coordinated application calls, persistent state tracking, and verifier-sensitive writes, yet they remain prone to procedural failures: misreading application state, tool semantics, or task progress. Procedural memory promises more consistent decisions and less redundant exploration, but constructing high-quality memory without model training remains challenging. We introduce CONTRAMEM, a source-flexible, training-free framework for self-evolving procedural memory that treats same-task outcome variation as supervision: differences in correctness, efficiency, recovery, and failure modes expose outcome-relevant procedural distinctions, distilled into a compact bank of app-level Function Cards and task-level Skill Cards that evolves through localized curation rather than append-only accumulation or whole-bank rewriting. On held-out GAIA2/ARE computer-use tasks, CONTRAMEM more than doubles the success rate across the three source-model targets (26.2% to 55.3%), with consistent per-model gains (GPT-5.5: 27.5 to 61.0; Claude Sonnet 4.6: 28.0 to 52.5; DeepSeek V4 Pro: 23.0 to 52.5). The same bank transfers unchanged to the unseen Qwen3.7 Plus (18.5 to 35.5), indicating transferable procedural knowledge rather than model-specific behavior. The same construction carries over unchanged to AppWorld, beating both no memory and its own single-source self-memory variant for all three mid-tier agents on both public test splits. Under a matched trajectory budget, heterogeneous multi-model trajectories yield stronger memory than self- or same-model multi-rollout memory: the margin comes from contrastive behavioral diversity, not stronger source agents or more sampling.

# CONTRAMEM: 学习自进化程序性记忆——通过对比多模型轨迹

## 1. 核心问题与整体含义

- **研究动机**：大型语言模型（LLM）被广泛部署为自主计算机使用智能体，需要执行长时任务，包括协调应用调用、持续跟踪状态、执行验证器敏感的写入操作。然而，即便最先进的模型也容易发生程序性失败，例如误读应用状态、工具语义或任务进度。
- **关键挑战**：程序性记忆（procedural memory）可以避免智能体重复探索和重复犯错，但在不更新模型权重的条件下，如何从过往经验中构建高质量、紧凑、可泛化的程序性记忆是结构性的难题：
  - 原始轨迹检索容易迁移脆弱的表面细节，而非可复用的逻辑；
  - 单轨迹摘要忽略“成功—失败”的因果边界；
  - 同模型重采样会继承相同的盲点（blind-spot inheritance）；
  - 仅追加式累积（append-only accumulation）会导致冗余和漂移。
- **核心洞察**：当不同模型尝试同一计算机使用任务时，其行为差异（成功、失败、效率、恢复方式）不是噪声，而是程序性监督信号。这种由多模型实践自然产生的对比信息无需额外标注成本，可离线蒸馏为可复用的记忆。
- **整体含义**：ContraMem 是一种**源灵活、免训练**的自进化程序性记忆框架，将“同一任务的不同结果”视作监督信号，通过异质模型轨迹的对比来提炼和持续精炼可迁移的程序知识，从而显著提升智能体的任务成功率，并实现了良好的跨模型迁移性。

## 2. 方法论

### 2.1 核心思想
- 将同任务、多模型的轨迹对比，类比于对比表示学习（contrastive representation learning）中的多视角思想——不同模型对同一任务的尝试是对其程序性结构的多个“视图”，它们之间的分歧构成了单一模型无法提供的监督信号。
- 注意：该类比是概念层面的，不使用嵌入或对比目标函数；多模型探索仅发生在离线构建阶段，部署时仍由单一目标智能体执行，且不更新任何模型参数。

### 2.2 记忆表示：两类卡片
- **Function Cards（应用级功能卡）**：描述一个可调用应用函数的工具级契约——功能、参数、返回值、副作用、常见错误；跨任务族共享，严格限定于工具语义，不包含任务计划或轨迹摘要。
- **Skill Cards（任务级技能卡）**：编码可迁移的程序性决策规则，例如“在模糊写入前先完成安全分支并请求澄清”；以能力（ability）为单位分库存储，因为同一表面模式在不同能力下意味着不同的任务义务。

### 2.3 构建流程
1. **轨迹归一化**：将原始轨迹映射为统一的事件序列，记录来源、类型、位置以及函数调用、归一化参数和精简观察摘要；并通过占位符策略去除任务特定值，同时保留日期、时序和操作顺序。
2. **对比包（task contrast packet）**：将同一任务的多条源轨迹聚合，暴露运行分歧点，同时保留决定结果的读/写/等待/收尾顺序。
3. **Reflector（反射器）**：基于对比包，定位决策边界，将成功/失败/恢复/效率差异抽象为一条可复用规则（含明确完成条件），每次最多输出 3 条候选 Skill Delta。
4. **Curator（策展器）**：对每条候选 Delta，从现有卡库中检索最相关的卡片，选择最小的有效编辑操作：
   - `ADD`（添加）、`PATCH`（修订）、`MERGE`（合并）、`NARROW`（收窄触发条件）、`NOOP`（不变）；
   - 严格保持语义封闭性：只能组合、压缩、收窄或改写已有证据支持的信息，不得引入新规则、失败模式、示例或函数。
5. **检索与注入**：运行时，由确定性检索器（retriever）根据任务能力标签选择技能卡库，按 BM25 相关性排序并加入软性应用域先验和域不匹配惩罚；功能卡在任务开始时注入，并可在运行时检测到工具调用前进行“即时提醒”（just-in-time）。
6. **三层验证**：模式验证（拒绝无证据支持的卡片/补丁）、隐私验证（去除联系人信息、长标识符、原文评判等）、检索预览（确保不会泄漏同场景信息）。

### 2.4 算法流程（文字描述）
- **离线构建算法**：遍历所有能力和参考任务 → 归一化各源模型轨迹 → 构建函数观察和对比包 → 构建全局 Function Card 库 → 按指定顺序处理每个对比包：检索相关技能卡 → Reflector 生成最多 3 条 Delta → 对每个通过验证的 Delta 检索相关卡片 → Curator 决定最小编辑操作 → 更新技能卡库 → 最终返回 (Function Card 库, 各能力 Skill Card 库)。
- **运行时算法**：给定新任务和冻结的卡片库 → 确定能力标签 → 检索 top-k 技能卡和功能卡 → 注入为软性程序指导 → 若开启预工具交付，则在代理提出工具调用时展示对应功能卡。

## 3. 实验设计

### 3.1 主基准：GAIA2/ARE
- **数据集**：GAIA2 在 Agents Research Environments (ARE) 运行时中执行，动态异步环境，包含状态改变、歧义、时间敏感义务和动作级写入验证。
- **任务划分**：覆盖 5 种能力（Execution、Search、Ambiguity、Adaptability、Time）；每种能力 40 个参考任务 + 40 个保留任务。
- **源模型**：GPT-5.5、Claude Sonnet 4.6、DeepSeek V4 Pro 三个异构前沿模型，各自执行所有参考任务，共 600 条离线轨迹。
- **目标模型**：上述三个源模型 + 未见过的 Qwen3.7 Plus（用于无轨迹迁移测试）。
- **对比方法**：
  - 无记忆（No memory）基线；
  - 自记忆（Self memory）：同一管道但仅使用目标模型自身的参考轨迹；
  - ContraMem 共享跨模型卡库；
  - 先验记忆系统：原始轨迹检索、AWM（Agent Workflow Memory）、ACE（Agentic Context Engineering）——均在相同源池和保留场景下复现。

### 3.2 跨基准验证：AppWorld
- **数据集**：AppWorld——有状态 Python REPL 环境，约 450 个 API、9 个应用，基于状态单元测试评估任务完成（TGC）和场景完成（SGC）。
- **模型**：三个中端目标智能体 DeepSeek-V3.1、Qwen3.6-Flash、GPT-4.1-mini，同时作为源模型共享轨迹。
- **划分**：两个公开测试集划分——Test-Normal（168 任务 / 56 场景）和 Test-Challenge（417 / 139）。
- **对比**：无记忆、目标特定自记忆、ContraMem 共享银行。

### 3.3 消融实验
- **源多样性 vs 样本量**：在相同轨迹预算下，使用同一模型（GPT-5.5）的三次 rollout 作为对比控制。
- **记忆类型**：只使用 Function Cards、只使用 Skill Cards、两者结合。
- **策展器作用**：将全部 Reflector 输出直接追加（append-only）的变体 vs 使用 Curator 局部编辑。
- **检索机制**：固定检索配置，评估各组件贡献。

## 6. 主要结论与发现

- **主结果（GAIA2/ARE）**：
  - ContraMem 使三个源目标模型的平均成功率从 26.2% 提升至 55.3%（超过翻倍）；各目标分别提升 +33.5、+24.5、+29.5 个百分点。
  - 卡库直接迁移到未见过的 Qwen3.7 Plus：18.5% → 35.5%，证明知识是程序性、可迁移的，而非模型特有行为。
  - 在五个能力中，除 Time 外均有大幅提升；平均轨迹长度从 41.1 降至 35.5 个代理事件（−13.6%）。
  - Time 能力仍然最难，文本注入的程序记忆无法解决异步状态跟踪问题。
- **跨基准（AppWorld）**：
  - 在全部目标、划分和指标上，ContraMem 一致优于无记忆和自记忆；Test-Normal TGC 从 54.4% 提升到 75.0%，Test-Challenge TGC 从 42.7% 提升到 57.4%；SGC 提升尤为明显（如 Test-Normal 60.1% vs 自记忆 44.6%）。
- **消融结论**：
  - 异质多模型轨迹的优势来自**对比行为多样性**，而非更强的源模型或更多采样——在相同轨迹数量下，三个不同模型比三个同模型 rollout 产生更强的记忆。
  - Function Cards 与 Skill Cards 互补，结合时达到最佳效果。
  - 局部策展优于 append-only 累积：卡片数量减少 24.9%，同时成功率提升（65.0% → 71.9%）。
  - 相比 AWM、ACE、原始轨迹检索，ContraMem 明显更优（宏均值 77.5% vs 47.5% / 44.2% / 45.8%）。
- **总体结论**：同任务跨模型的失败与成功差异是一种廉价而强大的程序性监督信号；通过紧凑的分层卡片和局部策展，可以将该信号转化为可迁移、持续进化的免训练程序记忆。

## 7. 优点

- **概念新颖且实用**：将多模型“事后对比”系统化，异质轨迹作为自然产生的监督信号，无需额外标注或训练。
- **架构清晰**：应用级 Function Cards 与任务级 Skill Cards 的分层设计，分别对应工具契约和任务决策逻辑，便于检索与复用。
- **紧凑与可进化**：Curator 采用 ADDPATCHMERGENARROWNOOP 的局部最小编辑策略，避免了记忆膨胀、冗余和漂移，保持了卡库的紧凑性。
- **源灵活与可迁移**：框架不要求源模型多样性也能工作，而异质多源可大幅增益；卡库可原样迁移到未见模型和未见基准（AppWorld）。
- **实验严谨**：全面控制了样本量、构建模型能力、检索与注入等变量；对先验方法进行了 matched-evidence 复现；统计检验充分。
- **成本低**：离线构建 token 消耗远低于 ACE，运行时注入 token 少，适配低成本部署场景。

## 8. 不足与局限

- **Time 能力未解决**：跨模型对比证据不足以解决异步通知、模拟时钟窗口等时间敏感失败；文本注入记忆无法替代持久的运行时状态控制和义务跟踪。
- **受限于源证据**：记忆只能防止源轨迹中已编码的失败；超出证据范围的错误无法被记忆覆盖。
- **存在少量回退**：23 个通过→失败的翻转主要源于过度宽泛的澄清卡或对已确定写入的过度谨慎，说明检索阈值和卡片触发的保守性仍有调优空间。
- **基准与模型设定较特殊**：文中的模型名称（GPT-5.5、Claude Sonnet 4.6、DeepSeek V4 Pro、Qwen3.7 Plus）和部分数据集版本属于前沿动态环境，可复现性可能随时间漂移；需依赖作者公开的复现细节。
- **资源报告不完整**：未披露 GPU 型号、数量、具体推理部署参数，仅报告 token 和成本，难以全面评估算力开销。
- **构建环节依赖 LLM 判断**：Reflector/Curator 仍由 LLM 驱动，虽然有多层验证，但其抽取质量和一致性可能受构建模型本身能力上限的影响（AppWorld 中使用最弱构建者已部分缓解该问题，但仍是潜在偏差来源）。
- **适用范围**：方法主要针对可调用函数/API 的应用型计算机使用环境，对于纯文本推理或需要很强物理世界交互的任务，其“函数卡+技能卡”的表示可能不够通用。
