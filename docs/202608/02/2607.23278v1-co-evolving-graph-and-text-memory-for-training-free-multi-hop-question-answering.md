## 摘要
多跳问答需要在推理步骤中协调关系证据和文本证据，这种组合是文本语料库或知识图谱单独无法提供的。先前的工作往往只强调这一循环的一部分：图增强的RAG从预构建或查询更新的图中检索，KGQA系统在主题中心的子图中搜索，而记忆增强代理则维护不断演化的记忆，但不持续地将图记忆与文本语境进行调和。我们提出Co-E，一种围绕同步双向图-文本工作记忆构建的免训练系统。同步周期整合文本记忆，将关系三元组提取到图记忆中，并将图事实注入回生成上下文。由于两种记忆都被维护，它们会影响后续的检索和生成。在六个多跳QA基准上的评估显示，Co-E优于可比的免训练开放骨干基线，并与更大或经过训练的系统具有竞争力。

## Abstract
Multi-hop question answering requires coordinating relational and textual evidence across reasoning steps, a combination neither a text corpus nor a knowledge graph can supply alone. Prior work often emphasizes only part of this loop: graph-augmented RAG retrieves from a pre-built or query-updated graph, KGQA systems search within topic-centered subgraphs, and memory-augmented agents maintain evolving memories without continuously reconciling graph memory with textual context. We propose Co-E, a training-free system built around synchronized bidirectional graph-text working memory. A synchronization cycle consolidates textual memory, extracts relational triples into graph memory, and injects graph facts back into the generation context. Because both memories are maintained, they shape subsequent retrieval and generation. Evaluated on six multi-hop QA benchmarks, Co-E improves over comparable training-free open-backbone baselines and is competitive with larger or trained systems.

# 论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

多跳问答（Multi-hop Question Answering）要求模型在多个推理步骤中同时协调**关系证据**（relational evidence）与**文本证据**（textual evidence），这一需求无法由单一纯文本语料库或知识图谱单独满足。现有工作通常只覆盖这一闭环的局部：

- **图增强 RAG**（如 HypoRAG、C2RAG、EA-GraphRAG）从预构建或查询更新的语料图中检索，但推理过程中无法动态修正其关系状态；
- **KGQA 系统**（如 ToG、MCTS-KBQA、ReKG-MCTS）依赖预存在的知识图谱拓扑，在固定主题中心子图上搜索，没有配对的文本工作记忆；
- **记忆增强代理**（如 HGMem、SubQRAG、SE-Search、A-MEM）能维护演化中的记忆，但通常只维护单一模态（文本笔记或图轨迹），缺少图记忆与文本上下文在**同一推理循环内**的持续相互修订。

论文的核心论断是：多跳推理需要**图与文本记忆的双向、步内协同演化（bidirectional, within-step co-evolution）**——文本证据发现新实体时应扩大图的前沿，图三元组被提取或检索到时应注入文本上下文以影响后续生成。缺少任一方向，系统要么积累需要从头重释的非结构化文本，要么遍历一个其有用事实无法暴露给生成器的静态图。

## 2. 提出的方法论

### 2.1 核心思想：共享图-文本工作记忆

Co-E（Co-Evolving）是一个**免训练（training-free）**多跳 QA 系统，围绕共享记忆对象构建：

```
M(t) = (T(t), G(t))
```

- **T(t)**：文本记忆，存储自包含、与问题相关的片段（检索证据、中间子答案、验证器反馈、图三元组的自然语言陈述）。原始文档从不直接进入记忆，需经提取器过滤为原子片段。
- **G(t)**：图记忆，是有向图，包含两类三元组：KB 模式三元组（从知识库直接检索，规范化）和开放词汇表三元组（从文本记忆提取，自然语言关系标签）。共享实体词典将 T 中的表面提及链接到 G 中的 KB 标识符。

### 2.2 四阶段推理循环

每个推理步骤包含四个阶段：

1. **请求生成（Request Generation）**：从原始问题与当前记忆生成聚焦子查询 q(t)；
2. **双流检索（Dual-Stream Retrieval）**：
   - **语料库检索**：查询生成器将子查询改写为搜索查询，经网络搜索或稠密检索获取文档，再由提取器过滤为片段集 S(t)；
   - **图检索**：实体链接将问题与记忆中的实体映射到 KB 标识符，以当前图记忆中的相关实体扩充种子集，发出 k-hop SPARQL 查询，跨跳重排序并经三元组修剪器过滤，得到三元组 R(t)——图检索因此是**记忆条件化**的，而非固定预计算遍历；
3. **响应生成（Response Generation）**：产生中间答案/推理状态 y(t)；
4. **记忆同步（Memory Synchronization）**：通过双向操作符更新记忆：

```
(T(t+1), G(t+1)) ← Sync(T(t), G(t), S(t), R(t), y(t))
```

### 2.3 双向记忆同步的四个操作

| 操作 | 内容 |
|---|---|
| **文本整合** | 去重重叠片段、合并互补证据、撤回被矛盾的中期预测，防止记忆无限膨胀为噪声上下文 |
| **文本→图传播** | 实体链接器识别实体并映射 KB 标识符，关系提取器从文本提出开放词汇三元组，与 KB 三元组结合、经修剪合并入 G(t)，使新文本证据扩展关系前沿 |
| **图→文本传播** | 将存活的图三元组文本化为显式关系陈述并追加到文本记忆，使生成器直接以自然语言访问图约束 |
| **文本再整合** | 在图派生陈述注入后对文本记忆进行第二次整合，产出下一状态的协调记忆 M(t+1) |

### 2.4 两种推理模式

- **MCTS 模式**：在候选推理轨迹树上搜索，节点类型包括子问题回答、自我修正、综合、问题重述、最终答案生成。选择使用 PUCT 风格分数：

```
S(s, a) = Q̄(s, a) + c · P(s, a) · √(Np(s) + 1) / (1 + N(s, a))
```

其中 Q̄ 为反向传播的平均奖励，P 为节点类型的启发式先验，N 为访问计数。树统计与记忆状态分离（访问与价值保持分支特定，MCTS 发现的证据累积到共享工作记忆）。Rollout 后验证器在三种视图下评分（无检索上下文、文本记忆、图记忆），自然语言评估作为系统预测项加入文本记忆。

- **CoT 模式**：顺序推理链，每步生成并回答问题后应用同一同步操作符，成本更低（避免树搜索与验证器引导的分支选择）。

## 6. 主要结论与发现

1. **SOTA 级别的免训练性能**：Co-E（MCTS，Qwen3-8B）在 2WikiMultiHopQA 达 72.6 EM、Bamboogle 70.0 EM、MuSiQue 52.5 EM、HotpotQA 61.8 EM；KGQA 上 CWQ 达 74.9 Hits@1（超过 PoG 与 iQUEST），WebQSP 达 85.5 Hits@1（与最强开放 7B 训练基线 RoG、GNN-RAG 持平）。

2. **双向同步不可或缺**：移除双向同步使 MCTS EM 从 70.0 降至 61.1，CoT 从 66.4 降至 52.5；仅单向传播（text→graph 或 graph→text）都不足，损失约为双向方案的 6-8 个点。

3. **主动维护优于纯累积**：移除去重/合并/撤回（"−Active maintenance"）导致最大单项退化（MCTS EM 降至 49.5），说明记忆必须选择性演化而非持续堆积。

4. **双模态记忆均必要**：移除图记忆或文本记忆分别使 MCTS EM 降至 54.8 和 55.0，两种记忆互为补充——文本提供 KB 三元组未覆盖的语义基础，图保留文本中隐含的显式实体-关系结构。

5. **协同效应大于组成之和**：检索与提取组件单独移除也已造成大降幅，但完整系统的增益不能由任何单一组件或纯检索替代解释。

6. **主题子图剪枝有帮助，但不是必需的**：Full-Wikidata 下 CWQ 只下降 1.5 个点（74.9→73.4），WebQSP 下降 6.9 个点（85.5→78.6）；在模式不匹配的更大图中，Co-E 仍能保持强组合式 KGQA 性能。

7. **失败主因是证据质量而非记忆机制**：Bamboogle 失败中检索缺口占 44.8%、不完整推理链 20.7%、错误实体链接 13.8%、综合错误 13.8%、表面形式不匹配 6.9%。

## 7. 优点

- **方法创新性**：将多跳推理重构为迭代记忆维护问题，首次在同一推理循环内实现图-文本记忆的双向同步，而非将图作为一次性检索辅助或仅累积文本笔记。
- **免训练架构**：无需微调或强化学习，同一机制适用于文本 QA 与 KGQA 两种设置，具有部署灵活性。
- **主动记忆管理**：不只是"记忆增强"，还包括去重、合并、撤回（回滚矛盾预测）、孤立节点丢弃——体现了记忆的"维护"而非"积累"。
- **双流检索记忆条件化**：图检索的种子集依赖当前图记忆状态，使检索动作本身随推理演化，而非固定预计算遍历。
- **完备的 MCTS 工程**：树统计与共享记忆分离，验证器三视图评分（无上下文/文本/图），反向传播后统一执行同步，兼顾分支探索与记忆清洁。
- **实验严谨性较高**：多指标（EM 与 Acc 双轨）、全 Wikidata 压力测试、失败归因、成本分解、骨干缩小敏感性等，提供的证据链较完整。
- **透明报道成本**：附录 C 明确给出每次 LLM 角色调用数与 token 量，正视了高推理成本问题并给出缓解方向。

## 8. 不足与局限

- **受检索证据质量的天花板限制**：双向同步无法纠正被语料反复支持的错误事实（45% 的失败源于检索缺口），系统虽有协调能力却无溯源核查能力。
- **实体链接准确率是关键瓶颈**：错误

实体链接准确率是关键瓶颈：错误链接会同时污染文本记忆和图记忆，且图→文本传播会将错误三元组文本化为看似合理的"事实"进入上下文，使后续步骤在错误前提上推理，形成错误传播的放大效应。

- **推理成本显著高于纯检索基线**：MCTS 模式在 Bamboogle 上平均每问题 204.1 次 LLM 调用，是 IRCoT 的约 22 倍；即便 CoT 模式也需要 58 次调用（约为基线的 6 倍）。虽然提取器是最大开销来源，但整体 token 消耗仍然高昂，限制了在长查询或大规模批处理场景下的实用部署。

- **免训练架构的天花板**：无需训练带来灵活性，但也意味着系统无法通过数据驱动方式学习"何时该信任图、何时该信任文本"的隐式策略；所有协调规则均需手工设计（如同步操作符的顺序、修剪阈值、验证器提示模板），这些超参数在不同数据分布上可能欠适配。

- **MCTS 模式依赖验证器质量**：验证器的三视图评分对轨迹选择有决定性影响，但验证器本身也是未微调的开源模型；若验证器对错误中间答案给出虚高分数，反向传播后的奖励信号会误导树的扩展方向，系统缺少验证器校准机制。

- **开放词汇三元组的不可靠性**：关系提取器从文本记忆中提取的自然语言关系标签缺少规范化约束，不同语境下同一关系可能被表述为多种表面形式（如 "parent of" 与 "father of"），图记忆中关系的一致性无法保证，弱化了图结构本应提供的跨步稳定性。

- **评估覆盖面的局限**：文本 QA 数据集均为英文维基百科范畴，未覆盖多语言、领域专业（医学、法律）或少资源场景；KGQA 仅涉及 Freebase 与 Wikidata 两个图谱，未在更异质的图（如领域本体）上验证；长链推理（>4 跳）的专门测试也未见系统报道。

## 9. 未来方向与开放问题

- **将主题子图剪枝与记忆同步解耦更彻底**：Full-Wikidata 实验显示主题子图剪枝带来的增益在不同数据集上不一致，识别"剪枝何时有害、何时有益"的条件是值得独立研究的课题。

- **降低推理成本的途径**：论文自身指出 MCTS 的多数 token 消耗在检索侧构造（提取器），这意味着通过蒸馏轻量提取器、缓存实体链接结果或对稳定记忆区域跳过重复同步，都有望在不损失精度的前提下大幅降低开销。

- **跨模态置信度建模**：当前系统隐含假设图三元组与文本片段同等可信，未来可在同步操作符中引入来源置信度与时效性权重，让记忆演化由证据强度驱动而非仅由语义重叠驱动。

- **联合端到端微调的可能性**：虽然 Co-E 免训练，但其四阶段循环与同步操作符的结构可作为可微训练目标（或 RL 奖励信号）的脚手架——例如学习何时触发图检索、何时保留文本片段，可作为后续训练版扩展的探索方向。

## 10. 总体评价

Co-E 的价值在于把"多跳推理"重新定义为一个记忆同步问题：系统的智能不体现在单次问答的生成质量上，而体现在每一步之后记忆状态如何被双向修订、如何在下一次检索中利用更新后的图前沿与文本上下文。这种以记忆演化为推理轴心的视角，使其在方法论上与"一次检索、多次推理"的经典 RAG 流水线、以及与"静态图、固定子图展开"的 KGQA 范式都形成了明确区分。

论文在实验设计上展现了较高的科学自觉：双向同步 vs 单向传播的对照、主动维护 vs 纯累积的消融、以及全 Wikidata 压力测试，都直指方法论的核心机制而非表面调参；失败归因进一步将误差来源从记忆机制中剥离，避免了"系统不好用就说记忆不够大"的空洞论断。

其局限同样清晰：系统性能强烈依赖外部证据质量与实体链接准确率，推理成本在树搜索模式下呈数量级上升，且所有设计决策都建立在免训练假设之上——这既是优点也是约束。整体而言，Co-E 是多跳 QA 记忆增强方向上一次结构完整、证据链充分的方法论贡献，为后续在"图-文本联合工作记忆"框架下的训练化扩展与成本优化留出了明确的生长空间。
