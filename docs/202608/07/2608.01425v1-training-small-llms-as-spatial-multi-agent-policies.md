## 摘要
基于LLM的多智能体系统与多智能体强化学习的训练正迅速受到关注，与此同时，另一条工作路线主张此类系统应依据其行为而非仅依据奖励来评判。我们在空间协作游戏中同时探讨这两条线索。在这些游戏中，使用低级动作提示的小型冻结LLM会完全失败，获得零奖励。在options/半马尔可夫决策过程框架的指导下——并且由于选项执行在智能体间是异步的，我们采用了其在宏动作Dec-POMDP中的多智能体扩展——我们为每个游戏配备了一个符号选项库：由符号规划器执行的类型化、状态可行、短视界行为。每个库由前沿编码模型从游戏源代码中起草；随后，通过廉价的随机策略预热轨迹，机械式地合成过滤每个菜单的可行性守卫——只有当守卫能解释重复的执行失败且不掩盖任何记录到的成功时，该守卫才会被采用——因此没有守卫是手工编写、选择或通过奖励调优的。每个智能体的LLM充当其在选项上的策略，并带有一个私有的每智能体LoRA适配器，由多智能体GRPO的每智能体变体（PA-MAGRPO）训练；这使得冻结的基础模型在三个游戏和四个小型骨干模型上从零奖励提升到胜任的游戏水平。行为审计随后揭示，奖励与协作是解耦的：奖励曲线的上升可能仅仅意味着一个智能体学会了独自完成整个任务，而它的伙伴则在闲置——协作仅在任务需要时才出现。因此，仅凭奖励并不能可靠地反映协作；行为评估必须与之并驾齐驱。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题：** 如何让小型（2–4B参数）LLM成为可训练的空间多智能体强化学习（MARL）策略？

**研究背景：**
- 基于LLM的多智能体系统训练日益流行（MAGRPO、CORY等），但多数工作集中于文本任务；同时已有研究指出，评价多智能体系统应依据行为而非仅有奖励。
- 直接将小型冻结LLM放入2D空间合作游戏并提示其输出低级动作（上下左右、交互），会遭遇两大失败模式：
  1. **空间幻觉（spatial hallucination）**：LLM产生看似合理但未验证前提条件的决策（如不先转向就向北射击）；
  2. **"安全默认"模式坍缩（mode collapse）**：模型集中输出单一语义最"相关"的字母（如`fire_clean`占95.8%），且RL微调反而会加剧这一偏好。
- 此外还面临**时域过长**（数百步稀疏团队奖励）与**角色分工**（共享权重冲突梯度平均化）两大障碍。

**整体含义：** 本文提出一个由"符号选项库 + 每智能体LoRA + 多智能体GRPO"构成的完整配方，使小型LLM能作为空间协作策略被有效训练；同时通过行为审计揭示**奖励与合作解耦**这一重要现象。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 总体框架
将每个智能体的LLM视为**选项（option）空间上的策略**：LLM只负责从状态过滤后的字母化菜单中选择"做什么"，而"怎么做"由符号规划器执行。形式上，单个智能体的决策问题变为半MDP（semi-MDP）；由于选项跨智能体异步启停，团队级问题建模为宏动作Dec-POMDP（macro-action Dec-POMDP）。

### 2.2 符号选项库的构建流水线（4个阶段）

**Stage 1：选项模式起草（唯一的模型步骤）**
- 使用前沿编码模型Claude Opus 4.8读取游戏源代码，生成带四部分契约的类型化选项库：
  - **实例化（instantiation）**：何时在菜单中出现（仅限目标存在性）；
  - **执行器（executor）**：符号扩展为原始动作（BFS最短路径 + INTERACT）；
  - **终止条件（termination）**：队列耗尽；
  - **效果谓词（effect predicate）**：关于状态增量的后置条件，用于判定执行是否兑现选项承诺。

**Stage 2：均匀覆盖预热（burn-in，无LLM）**
- 使用均匀随机菜单策略运行大量 episodes（如Overcooked上用2000次solo + 2000次双人episodes ≈ 55万决策，单CPU核约70秒）。
- 每次选项执行记录"选项、目标、读集特征、结果（成功/效果失败/显式失败原因）"，**以效果谓词而非奖励**判定成败。

**Stage 3：守卫合成与验收证书（无模型、无人工）**
- **显式通道**：类型化失败原因出现≥5次 → 直接成为守卫（如`NoPath` → 实时可达性检查）。
- **推断通道**：所有1–2字面量合取式，若覆盖≥5次失败且覆盖**0次成功**则被采纳（纯度要求即验收证书）。
- 守卫以数据形式存储，不编码任何策略性/环境合法性知识。

**Stage 4：菜单组装**
- 每个目标类实例化一个选项入口（而非仅最近目标）；对每个实例评估所有已采纳合取式守卫，匹配则隐藏该选项；每决策用episode种子随机打乱字母顺序，避免字母位置泄漏身份。

**外层契约修复循环：** 若阶段1的模式有缺陷（如绝对形式效果谓词造成虚假成功、共享状态误归属、最近目标实例化导致不可达），机械内层循环暴露异常，前沿模型修复模式，再重跑Stage 2–3。

### 2.3 每智能体LoRA与PA-MAGRPO训练

- **每智能体私有LoRA适配器** θᵢ 建立在共享冻结基座 f 上：πᵢ( z | o ) = f ∘ θᵢ。共享基座保留共同语言与任务知识，私有适配器为角色分工提供参数空间。
- **PA-MAGRPO算法**（每轮训练过程）：
  1. 收集K条并行联合rollouts（当前联合策略 + 选项菜单接口），每条由团队回报Rₖ（如总苹果数/总交付数）打分；
  2. 计算队列内均值μ、标准差σ，得到**共享的组相对优势** Âₖ = (Rₖ − μ)/σ——同一rollout内对所有智能体相同；
  3. 每个智能体在其**自身决策** {(oᵢ, zᵢ)} 上执行E轮PPO裁剪更新，带KL惩罚；
  4. 仅更新私有LoRA适配器；更新仅在选项边界处进行。

**算法核心创新：** "per-agent"指参数化与更新分离，而非独立奖励——角色分工源于私有适配器在相同团队优势下经历不同观测-动作历史而自发涌现，无需手工角色标签。

## 6. 论文的主要结论与发现

1. **配方有效性**：四个骨干 × 三游戏的冻结基线全部零奖励；完整方法全部获得显著正回报——Cleanup苹果从0到60–105、Overcooked AA交付从0.20±0.51到6.80±1.89（34×提升）、Commons Harvest从0到85–116。
2. **两个成分均不可缺**：
   - 去掉选项菜单（Ablation A）→ 三游戏全部坍缩为零，训练永不产生正checkpoint（原生动作空间随机探索几乎无法产生连贯多步轨迹，GRPO组标准差坍缩，梯度无信号）；
   - 共享LoRA（Ablation B）→ 无法稳定保持角色，Cleanup仅0.10±0.45苹果、Overcooked仅达完整方法的约1/3（对称Harvest因不需要分工而仍可）。
3. **抽象降低决策频率**：选项接口将LLM调用比率从原生动作的1.00降到Cleanup/Harvest约0.40、Overcooked约0.71，每个LLM决策覆盖2–3个环境步。
4. **奖励与合作双向解耦**：
   - **过报**：Overcooked AA高奖励来自"一人干活一人闲置"（agent 0加载洋葱≈69%，agent 1等待≈72%，零交接）；FC中双方单独放置均交付0，说明其高交付仅在有伙伴时成立；
   - **欠报**：Commons Harvest奖励仅从76.73±16.29升到98.29±14.52（看似近持平），但冻结基座约第200步耗尽全部6个补丁，调优模型至第400步仍保持约2.5个存活。
5. **分工涌现的条件**：Cleanup中七个适配器自发分化为3吃/3清/1辅助，无角色标签；共享LoRA无法复制此分化，自由JSON生成（Ablation D）也无法维持分工——约束性菜单选择让每个适配器承诺不同选项分布，梯度才能逐智能体锐化分工。

## 7. 优点

1. **三层分立的设计**（抽象层 + 容量层 + 训练算法层）使归因清晰：抽象解决接地和时域问题，私有容量解决分工问题，组相对优势训练解决信用分配——每层失效时都有各自的实验证据。
2. **机械式守卫合成的价值**：守卫完全由执行数据（效果谓词判断成败）驱动，不引入人工策略先验，且纯度证书（零成功覆盖）天然阻止策略性偏见进入过滤逻辑，消除了手工设计的隐性偏差。
3. **"激励结构决定合作"的行为学洞察**：同一配方在不同激励结构（可选协调的AA vs 强制协调的FC）下产生截然不同的合作行为，用自然的"布局对照"代替了外力干预，结论更可信。
4. **效果谓词设计的工程智慧**：增量形式（delta form）而非绝对形式，绑定到私有状态转换，成功修复两个隐蔽的虚假成功缺陷；过程透明可复现。
5. **成本切实可行**：burn-in阶段纯CPU且极快（70秒/4000 episodes），唯一模型调用是构建期的一次frontier model查询，训练/评估/动作选择全程不依赖外部模型，适合学术预算（academic budget）。
6. **行为审计方法论**：超越奖励的数字，引入solo控制（将FC智能体单独放置→0交付）、补丁存活率、选项分布直方图等行为证据，为多智能体LLM评价树立了示范。

## 8. 不足与局限

1. **覆盖范围窄**：仅限≤4B的小型LLM和三个特定空间游戏；向更大规模模型、非空间任务（如文本/代码协作）的迁移未验证。
2. **选项库非通用**：每个游戏需单独构建库（虽然用同一个frontier模型和非种子化抽样），缺乏选择/搜索选项空间的原理性方法——"选项空间有多大才算合适"没有答案。
3. **前沿模型依赖的隐蔽性**：Stage 1本身的生成质量是凭运气采样的（不可种子化），虽"抽样多种子"缓解，但对库质量的系统性差异、库与任务匹配度的分析缺失；开发中修复了3类契约缺陷，说明此环节仍是隐性人工调优点。
4. **角色审计的种子稀少**：Cleanup角色分化的行为审计仅在单一训练种子下检查，跨种子一致性问题未充分讨论。
5. **无外部基线对比**：与前人工作（Mosquera 2025、Gallego 2026、Piche 2025、Biswas 2026等）无直接数字对比，因为"智能体数、时域、评估指标不同"，这限制了定位本方法在技术前沿中的确切位置。
6. **消融表基于旧接口版本**：作者声明消融使用"手选守卫而非合成守卫"的早期接口，虽论证"消融隔离的是菜单和私有容量价值非守卫来源"，但这破坏了完全同配置的可比性。
7. **奖励信号本身的扁平性**：Commons Harvest的奖励差异几乎不显著，但行为差异巨大——这恰是论文论点，但也意味着如果只按奖励选checkpoint，可能会选中合作度较差的策略；对如何同时优化行为指标未提出算法方案。
8. **理论收紧性**：文中虽以宏动作Dec-POMDP为框架，但更新仅发生在选项边界、采用episodic无折扣回报，严格说来跳过了semi-MDP折扣机制的理论细节，更多是概念映射而非理论创新。
