## 摘要
最近的文本到SQL系统越来越依赖多轮交互、执行反馈和强化学习。然而，大多数现有方法仅将执行正确性作为轨迹级奖励，这为识别导致成功或失败的SQL决策提供的指导有限。我们提出了SERL-SQL，一种用于多轮文本到SQL智能体的选择性执行接地强化学习框架。SERL-SQL对策略内SQL交互轨迹进行采样，并使用仅训练的教师模型通过执行反馈对学生动作重新评分。由此产生的师生似然差距被转换为有界、掩蔽的权重，仅在SQL和工具动作令牌上重新加权GRPO优势。这样，任务奖励保留了优化方向，而执行事后反馈提供了局部信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL取得了具有竞争力的性能，在BIRD-Dev上达到了76.56%的执行准确率，在Spider-Test上达到了89.92%。此外，我们基于奖励的选择策略接近Oracle最佳N上限，并始终优于基于一致性的选择，表明SERL-SQL产生的高质量候选可以通过轻量级执行接地奖励可靠识别。我们的代码将在https://github.com/Ffunkytao/SERL-SQL发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

### 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 现代Text-to-SQL系统已从单次SQL生成转向多轮智能体式数据库交互（如schema grounding、SQL生成、执行、验证、修订等），并越来越多地依赖强化学习（RL）来优化策略。
- 然而，现有方法普遍存在一个关键缺陷：**仅将执行正确性作为轨迹级（trajectory-level）奖励**。这种粗粒度信号能够反映整条轨迹的成功或失败，却无法定位到底是哪一个SQL决策（如选错表、漏掉连接条件、过滤条件错误）导致了最终结果，导致信用分配（credit assignment）稀疏且不精确。
- 部分工作虽然通过搜索、渐进式奖励或步骤级监督来缓解这一问题（如Progress-SQL、FineStep等），但要么未实现真实的数据库交互，要么仍未精确地将执行反馈关联到可执行的SQL动作令牌上。

**核心洞见：**
- 执行反馈（如运行错误、空结果、结果表内容）具有“事后视角”（hindsight），可为训练提供特权信息，帮助判断“哪些SQL令牌本应被鼓励或抑制”。
- 因此，作者提出将执行反馈作为**训练时的特权上下文**，通过训练专用教师策略重新评估学生策略的动作，并将师生似然差转化为有界、掩蔽的权重，仅对SQL相关令牌重加权GRPO优势，实现**局部（token级）信用分配**，同时保留任务奖励确定的优化方向。

### 2. 方法论

SERL-SQL是一个四阶段框架，核心思想是“**任务奖励定方向，执行事后反馈定幅度与局部性**”。

**阶段一：Schema Grounding（模式紧凑化）**
- 离线将数据库各列的代表性取值用嵌入模型编码，构建列感知向量索引。
- 在线时，从问题中抽取关键词与实体提及，通过与向量索引匹配检索相关取值，结合基于推理的schema linking（表/列/连接键/聚合属性）和基于值的linking，输出紧凑的、值感知的grounded schema S'。

**阶段二：Multi-turn SQL Agent Rollout（多轮轨迹采样）**
- 策略πθ按“思考→SQL动作→执行→观察→修订”的过程与数据库交互，每轮动作包含推理片段和SQL动作（中间SQL或最终solution）。
- 对每个输入采样一组N条轨迹{τⁿ}，由分层验证器检查格式有效性，并与金标SQL的执行结果对比，给出稀疏轨迹奖励：
  - Rⁿ = +1（有效且执行正确）；0（有效但不正确）；−1（无效轨迹）。

**阶段三：Selective Execution-Hindsight Teacher（选择性执行事后教师）**
- 维护一个与学生策略周期性同步的教师策略π_T（仅训练时使用，stop-gradient）。
- 对每个学生生成的SQL令牌y_t,i，教师在同一历史但附加执行观察c_ex^t（如结果表、运行错误、解析错误、空结果）的条件下重新评估其对数似然，而学生仅使用决策时可用信息。
- 定义动作掩码m_t,i∈{0,1}，仅对可执行的SQL或工具动作令牌为1，推理与格式令牌为0。

**阶段四：Hindsight-Guided Advantage Reweighting（事后引导的优势重加权）**
- 计算师生对数似然差：Δ_t,i = log π_T(y_t,i | h_t, y_t,<i, c_ex^t) − log π_θ(y_t,i | h_t, y_t,<i)。
- 将其转换为有界、符号感知的权重：w_t,i = clip(exp(sgn(Aⁿ)·sg[Δ_t,i]), w_min, w_max)，其中Aⁿ为轨迹级GRPO优势，sg[·]表示stop-gradient。
- 掩码后有效权重为：w̄_t,i = (1−m_t,i) + m_t,i·w_t,i（非动作令牌权重保持为1）。
- 引入随时间衰减的训练系数α_k，最终令牌级优势为：Ã_t,i = Aⁿ[(1−α_k) + α_k w̄_t,i]。训练早期充分利用事后反馈改善信用分配，后期逐渐回归纯奖励驱动的GRPO。
- 最终目标函数为带KL正则的裁剪GRPO目标：L_SERL-SQL(θ) = −E_τ[Σ ℓ_GRPO(θ; Ã_t,i)] + β·KL(π_θ‖π_ref)。
- 推理时教师被完全移除，学生策略单独部署。

### 6. 主要结论与发现

- SERL-SQL通过将执行反馈转化为有界、选择性、与奖励方向对齐的token级信用信号，显著提升了多轮Text-to-SQL强化学习的性能。
- **主结果**：BIRD-Dev达到76.56%（32B），Spider-Test达到89.92%（14B），Spider-DK达到82.21%（32B），Spider2.0-SQLite达到26.78%（32B），均优于或接近同规模强基线。
- **选择策略**：reward_max（基于执行奖励挑选候选）能紧密接近Oracle Best-of-N上界，且一致优于基于一致性的选择，说明SERL-SQL学习出的候选轨迹质量高、可被轻量执行信号可靠挑出。
- **组件消融**：Schema grounding对性能影响最大（去除后BIRD-Dev降至66.42%）；训练侧各组件均有贡献，其中Execution Hindsight最关键；裁剪、掩码、符号感知、衰减每个环节都不可或缺。
- **反馈来源**：立即执行观察（当前SQL动作的直接结果）是最优的事后信号，完整观察反而带来冗余干扰。
- **错误分析**：剩余错误中Join错误（29.1%）和语义错误（24.6%）占比最高，说明多表连接推理仍是核心瓶颈。
