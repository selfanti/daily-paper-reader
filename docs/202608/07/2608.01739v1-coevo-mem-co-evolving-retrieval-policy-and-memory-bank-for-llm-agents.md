## 摘要
随着记忆在任务和会话中不断积累，长期LLM智能体的性能同时依赖于针对特定查询的检索和持续的记忆优化。然而，现有方法通常要么优化记忆访问（通过迭代查询改写或自适应检索策略），要么优化记忆演化（如结构更新）。这种分离忽视了一个基本的反馈循环：检索决定了哪些记忆获得使用信号，而更新后的记忆库重塑未来的检索。我们提出了\textbf{CoEvo-Mem}，一个用于协同演化检索策略和记忆库的闭环框架。对于每个查询，一个冻结的LLM生成特定路线的查询改写和路由先验，而一个轻量级残差路由器在线纠正这些结果。检索到的上下文充当两个学习过程之间的耦合接口：任务结果将信用分配给路由决策，而基于轨迹的反馈更新记忆值和图关系。这些更新改变了记忆在后续查询中的排序和选择方式，从而闭合了反馈循环。为了减轻耦合引起的非平稳性，CoEvo-Mem在固定记忆库时更新路由器与固定检索策略时演化记忆库之间交替进行。在七个不同的基准测试中，\textbf{CoEvo-Mem}达到了最先进的性能，证明了检索-记忆协同演化的重要性。

## Abstract
As memories accumulate across tasks and sessions, the performance of long-term LLM agents depends jointly on query-specific retrieval and continual memory refinement. However, existing methods typically optimize either memory access, through iterative query refinement or adaptive retrieval policies, or memory evolution such as structural update. This separation overlooks a fundamental feedback loop: retrieval determines which memories receive usage signals, while updated memory bank reshape future retrieval. We propose \textbf{CoEvo-Mem}, a closed-loop framework for co-evolving the retrieval policy and memory bank. For each query, a frozen LLM generates route-specific query rewrites and a routing prior, which a lightweight residual router corrects online. The retrieved context serves as the coupling interface between the two learning processes: task outcomes assign credit to routing decisions, while trajectory-conditioned feedback updates memory values and graph relations. These updates alter how memories are ranked and selected for subsequent queries, thereby closing the feedback loop. To mitigate coupling induced non-stationarity, CoEvo-Mem alternates between updating the router with the memory bank fixed and evolving the memory bank with the retrieval policy fixed. Across seven diverse benchmarks, \textbf{CoEvo-Mem} achieves state-of-the-art performance, demonstrating the importance of retrieval-memory coevolution.

## 1. 核心问题与整体含义（研究动机和背景）

- 长期 LLM 智能体需要在多任务、多会话中持续积累经验，但无法将所有历史信息放入单一上下文，因此必须依赖外部记忆库进行持久化存储和按需检索。
- 现有工作分为两大方向：
  - **记忆访问**：通过 RAG、查询改写、自适应检索策略提升证据召回效率；
  - **记忆演化**：通过价值更新、结构化表示、关系图维护等方式优化记忆本身的组织与质量。
- 已有方法通常将两者分开优化，忽略了它们之间存在的**基本反馈循环**：
  - 检索决定了哪些记忆暴露给模型并接收任务反馈；
  - 记忆库更新又会改变后续检索时的排序和选择结果。
- 单独优化任何一方都会使另一方与更新后的状态失配，限制长期性能。
- 因此，论文提出 **CoEvo-Mem**：将“查询路由策略”和“记忆库演化”建模为耦合学习问题，通过闭环协同优化实现持续改进。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 总体框架

- 同时维护：
  - 一个可学习的**检索策略 π_θ**（Prior-Guided Residual Router）；
  - 一个持久的**类型化关系记忆图 G_t**。
- 回答 LLM `F_ans` 保持冻结，不参与训练。
- 检索结果 `A_t` 是路由器和记忆更新之间的**耦合接口**：既由路由决定，又为生成提供上下文，同时决定哪些记忆获得信用更新。

### 2.2 关键技术组件

1. **自路由查询改写器（SR-QR）**  
   - 冻结 LLM 对每个查询生成：密集查询改写、稀疏查询改写、初始密集/稀疏路由先验 `p_0`、置信度特征 ξ0。
   - 若 LLM 输出无效，则回退到原始查询和均匀先验，保证稳健性。

2. **残差路由器（Residual Router）**  
   - 由可训练查询编码器 φ_ψ 和策略头 f_ω 组成。
   - 输出残差修正量 Δ_t，与原 LLM 先验相加后经 softmax 得到最终路由概率 π_t。
   - f_ω 输出层零初始化，使初始策略正好等于平滑后的 LLM 先验，避免从头学习路由。
   - 路由器训练使用 Beta 分布采样连续混合权重，并采用 score-function 估计器（REINFORCE 风格）结合优势函数和 KL 正则项，防止偏离先验。

3. **Q 加权混合检索器**  
   - 密集检索：基于描述嵌入余弦相似度；稀疏检索：基于 BM25 关键词匹配。
   - 采用加权倒数秩融合（WRRF），综合路由权重、各改写得分和记忆效用价值 Q。
   - 先获得初始 top-k 候选，再通过**时态图扩展**加入候选的时间邻居，重新排序后输出最终 top-k 记忆。

4. **关系记忆图（Typed Relational Memory Graph）**  
   - 节点存储经验内容、密集描述、稀疏关键词、时间元数据、来源轨迹和效用值 Q。
   - 边类型包括 Dense、Sparse、Time，与检索通道一一对应，确保记忆组织与检索操作对齐。
   - 记忆构建基于完整轨迹（含失败轨迹）蒸馏，保留来源信息，不使用金标答案。

5. **TD 式记忆价值更新与关系信用传播**  
   - 对每个暴露记忆 m，计算 TD 残差：`δ_t(m) = R_t * u_t(m) + γ * Q̂_t(m_new) - Q_t(m)`。
   - 新记忆的初始价值继承当前上下文记忆的平均价值。
   - 信用沿图路径传播，路径强度为边衰减系数乘积，取最大路径、多暴露记忆取平均，控制更新尺度。
   - 所有节点价值使用更新前快照同步更新，并进行区间投影。

6. **交替协同演化（Alternating Co-Evolution）**  
   - 一个 Router 阶段：冻结记忆图，仅更新路由器；一个 Memory 阶段：冻结路由器，仅更新记忆图。
   - 每个阶段完整遍历一遍训练数据，反复交替，使每个组件都针对对方最新状态优化。
   - 若记忆图初始为空，则先额外执行一个 Memory 引导阶段。
   - 该交替设计用于缓解耦合更新导致的非平稳性。

### 2.3 主要公式与算法流程

- 路由策略：
  `π_t = softmax(log(平滑先验) + Δ_t)`
- 混合检索得分：
  `S_t(m) = Σ_a w_ta * (1/N_a) Σ_i 1/(η + rank_ta,i(m)) + λ_Q / (η + rank_tQ(m))`
- 记忆更新：
  `Δ_t(v) = δ_t(v)`（若 v 被暴露）；否则为关联记忆残差的加权均值。
  `Q_{t+1}(v) = Π[Qmin,Qmax](Q_t(v) + α_Q Δ_t(v))`
- 训练目标：最大化期望任务奖励 `J = E[平均奖励]`。
- 算法流程：每个训练示例依次执行查询改写 → 路由 → 检索 → 生成 → 评估 → 根据当前阶段更新路由器或记忆图。

## 6. 主要结论与发现

1. **检索与记忆演化之间确实存在增强反馈循环**：路由决定暴露记忆，记忆价值与关系更新又影响后续路由。
2. **协同演化优于任何单侧优化**：CoEvo-Mem 在七个基准上达到 SOTA，提升跨任务类型泛化，非集中于单领域。
3. **残差式路由学习有效**：从冻结 LLM 先验出发，仅学习小型修正，比从头训练更高效稳定。
4. **关系记忆的 TD 式传播显著改善记忆复用**：去除关系传播后，GPQA Diamond 下降 10 点、LiveCodeBench 下降 7.62 点、BFCL thinking 下降 5.94 点。
5. **交替训练是必要的**：同时更新或两阶段训练都导致性能下降，说明分阶段固定一方有助于控制非平稳性。
6. **学习到的检索接口具有跨骨干迁移能力**：固定图形和路由，更换 GPT-4 回答骨干即可提升性能。

## 7. 优点

- **问题提出具有洞察性**：识别出检索与记忆演化之间的反馈循环，并形式化为耦合学习问题。
- **框架设计轻量且务实**：仅训练轻量残差路由器，冻结 LLM，计算开销可控。
- **查询改写与路由先验分离**：充分释放语义和词汇线索，但通过残差机制不偏离 LLM 先验过多。
- **记忆图结构与检索通道对齐**：Dense/Sparse/Time 边类型与检索操作一一对应，实现“检索对齐的关系记忆”。
- **交替训练策略有效缓解非平稳性**：简单但实用，消融实验证明其优于同时更新和两阶段。
- **实验多样性高**：覆盖代码、科学、多模态、函数调用、OS 交互、长程对话，验证通用性。
- **实现细节和失败语义严谨**：附录提供完整接口、超参、协议、失败处理，可复现性强。

## 8. 不足与局限

- **模型角色固定，未系统探索最优配对**：`F_ans` 与 `F_route` 的配对在基准内固定，未比较同质/异质组合的精度-效率权衡。
- **没有理论保证**：交替优化的收敛性、稳定性、路径传播的偏差等均缺乏理论分析。
- **计算资源报告不完整**：没有给出训练时间、单次实验成本或推理开销，难以评估实际部署效率。
- **部分基线非配对重跑**：OpenAI、Full Context 等行来自文献参考值，与 CoEvo-Mem 的评测设置可能不完全一致，轻微影响对比公平性。
- **记忆演化依赖 LLM 辅助**：记忆构建、价值归因、时间分类、元数据修复等步骤均调用冻结 LLM，其错误可能被保守跳过，但整体依然依赖提示质量。
- **多智能体共享和跨智能体信用分配未涉及**：论文仅讨论未来方向，未提供实验验证。
- **评测偏重英文和特定任务形态**：未涉及多语言、真实对话系统部署、长时间在线学习等场景。
- **只冻结回答 LLM，但记忆系统仍依赖外部模型**：当外部 LLM 更新或替换时，记忆质量可能波动，鲁棒性未充分评估。
