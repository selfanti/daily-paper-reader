## 摘要
现有的搜索增强大语言模型智能体使用强化学习进行训练，以提升其推理能力。然而，这些方法主要依赖结果级奖励，对搜索行为几乎不提供监督，并且忽视了智能体正确分解复杂查询的能力。为解决这一问题，我们提出了PROGRESS，它利用教师引导的覆盖奖励来显式塑造策略模型的分解查询生成。在训练期间，使用冻结的教师模型将复杂查询分解为必要的搜索查询。这些必要的搜索查询用于指导策略模型的搜索行为。我们的方法集成到R1风格的训练框架中，在不进行密集过程级监督的情况下，为查询分解决策提供轻量级指导。实验表明，覆盖引导的强化学习提升了整体任务性能，突显了在智能体大语言模型中显式监督搜索策略的重要性。

## Abstract
Existing search-augmented LLM agents are trained using Reinforcement Learning to boost its reasoning capabilities. However, these approaches primarily rely on outcome-level rewards, which provide little supervision over search behavior and overlook agent's ability to decompose complex queries properly. To mitigate this issue, we propose PROGRESS which utilizes teacher-guided coverage reward to explicitly shape decomposed query generation of the policy model. During training, frozen teacher models are used to decompose complex queries into essential search queries. These essential search queries are utilized to guide the search behavior of the policy model. Integrated into an R1-style training framework, our approach provides lightweight guidance over query decomposition decisions without dense process-level supervision. Experiments show that coverage-guided RL improves overall task performance, highlighting the importance of explicitly supervising search strategies in agentic LLMs.

## 二、方法论

### 核心思想
利用**冻结的教师模型**（Qwen2.5-72B-Instruct）离线为每个复杂查询生成一组“必要搜索查询”（essential search queries），作为对策略模型搜索行为的一种**弱监督锚点**。在 RL 训练过程中，通过比较策略模型生成的搜索查询与教师查询之间的语义和粒度重叠程度，构建一个**轨迹级覆盖奖励**，从而引导策略模型朝更优的查询分解方向优化。

### 关键技术细节
1. **教师模型离线生成锚点查询**：对每个训练问题 \(x\)，教师模型 \(\pi_T\) 生成一组关键搜索查询 \(Q_T(x) = \{q^T_1, q^T_2, \dots, q^T_K\}\)，近似表达该问题所需的潜在信息需求集合。
2. **策略模型在线生成搜索轨迹**：策略模型 \(\pi_\theta\) 在环境中执行搜索和推理，生成轨迹 \(y\)，其中提取出策略查询集合 \(Q_P(x, y) = \{q^P_1, q^P_2, \dots, q^P_M\}\)。
3. **查询匹配**：利用 LLM 裁判（Qwen2.5-72B-Instruct）基于**语义等价性**和**粒度一致性**两个标准，识别匹配查询集合 \(I(x, y) = Q_P(x, y) \cap Q_T(x)\)。
4. **覆盖率指标**：计算精确率（Precision）和召回率（Recall）：
   - \(Precision = |I| / |Q_P|\)：惩罚冗余或无关的搜索。
   - \(Recall = |I| / |Q_T|\)：衡量对必要信息需求的覆盖程度。
5. **覆盖奖励**：采用二者的调和平均（F1-score）作为覆盖奖励：\(r_{cov}(x, y) = 2 \cdot Precision \cdot Recall / (Precision + Recall)\)，在完整性和特异性之间取得平衡。
6. **总奖励设计**：最终的轨迹级奖励为：
   \[
   r(x, y) = r_{ans}(x, y) + r_{format}(y) + \lambda_{cov} r_{cov}(x, y)
   \]
   其中 \(r_{ans}\) 为答案精确匹配奖励，\(r_{format}\) 为格式奖励，\(\lambda_{cov}\)（经验值设为 0.2）控制覆盖奖励的权重。
7. **优化方法**：在 **Search-R1** 风格的训练框架下，使用 **PPO（Proximal Policy Optimization）** 优化策略模型，结合检索 token 掩码和 KL 正则化保证训练稳定性。

## 三、实验设计

### 数据集

- 主指标：**Exact Match (EM)** 作为问答准确率。

- **RAG**：单次检索。
- **Prompt-based Agentic RAG**：IRCoT、Search-o1。
- **RL 训练方法**：R1、Zero-search、Search-R1（EM 或 EM+FR）。

### 检索设置
- 知识源：2018 年 Wikipedia dump。
- 检索器：E5。
- 搜索环境：每个查询返回 top-3 段落。

## 六、主要结论与发现

1. **PROGRESS 在多跳 QA 上全面优于基线**：在 6 个数据集的平均得分上超过 Search-R1、Zero-search 等强基线，尤其在 MuSiQue 上带来 2-5% 的绝对 EM 提升（比 Search-R1 高约 5%）。
2. **覆盖奖励显著提升查询分解质量**：在 Completeness（完整性）和 Granularity（粒度）两个维度上均有明显改进，模型更少使用复合查询直接搜索，能更全面地覆盖信息需求。
3. **检索准确率大幅提升**：覆盖引导的查询生成使得检索到的段落中包含正确答案的比例显著提高，在三种多跳数据集上均提升 6% 以上。
4. **仅用多跳数据训练时收益更明显**：当去掉 NQ 等通用 QA 数据、只用 HotpotQA 训练时，PROGRESS 相对于 Search-R1 的优势进一步扩大，说明覆盖奖励与多跳任务高度契合。
5. **模型泛化性良好**：不仅适用于 Qwen2.5-3B，也适用于 Qwen2.5-1.5B，验证了方法的普适性。

## 七、优点

- **轻量级监督**：不需要逐步（step-level）的密集人工标注，而是通过教师模型离线生成锚点 + 在线 LLM 裁判计算覆盖度，实现了“轻量级、轨迹级”的引导。
- **目标明确**：直接针对搜索行为这一核心瓶颈（查询分解质量），弥补了结果级奖励监督不足的关键缺陷。
- **奖励设计合理**：采用 F1-score（Precision 与 Recall 的调和平均），能同时抑制冗余搜索和搜索不足，避免模型走极端。
- **集成经验证框架**：建立在 Search-R1 的稳定训练框架之上（token 掩码 + KL 正则化 + PPO），工程实现成本低，可持续性强。
- **评估多维度**：不仅看答案准确率，还分析查询质量（Completeness/Granularity）和检索准确率，提供了更全面的验证视角。
- **泛化性验证**：在两个不同规模的基座模型上均验证了有效性。

## 八、不足与局限

- **依赖教师模型质量**：教师生成的“必要查询”是否真正完备、均衡，直接决定了覆盖奖励的可靠上限。若教师模型本身分解不充分，策略模型学到的覆盖目标也会存在偏差。
- **依赖 LLM 裁判产生额外成本**：匹配查询集合的判定需要调用 72B 级别的 LLM 裁判来完成，训练阶段的计算开销较大；且裁判判断的准确性（在语义和粒度上存在歧义时）可能引入噪声。
- **缺少关键消融分析**：λ_cov（覆盖奖励权重）仅设定为 0.2，未讨论该超参数的敏感性；未单独验证覆盖奖励相对结果奖励的边际贡献。
- **统计显著性不足**：实验报告中未提供多次独立运行的标准差或置信区间，难以判断 2-5% 的提升是否具有统计显著性。
- **未对比过程级奖励方法**：没有与 HiPRAG 等提供更细粒度过程奖励的方法进行对比，因此无法清晰说明“轨迹级覆盖奖励”与“过程级奖励”之间的优劣关系。
- **局限性说明不足**：论文未充分讨论当教师模型与策略模型规模差距较大、或教师模型自身能力有限时，该框架是否依然有效。
- **对通用 QA 场景贡献有限**：从表 1 可以看出，PROGRESS 在通用 QA（如 NQ、TriviaQA）上的提升幅度相对有限，部分场景下 Zero-search 仍表现出较强竞争力，说明该方法的主要价值集中在多跳推理场景。
