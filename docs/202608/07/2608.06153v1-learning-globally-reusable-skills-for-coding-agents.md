## 摘要
自动化技能进化使大型语言模型（LLM）智能体无需昂贵的重新训练即可持续改进。然而，现有方法通常将技能进化视为一系列局部更新，忽略了技能之间的关系，并常常产生过拟合的技能更新，难以跨任务泛化。我们提出GSE，一种全球化技能进化框架，联合优化技能兼容性和技能泛化能力。为保持技能库的一致性，GSE维护一个技能关系图（SRG），显式建模并共同进化技能间关系。为提高泛化能力，GSE执行基于聚类的技能整合，从局部更新中抽象出可复用能力，并采用基于重放的验证来防止过拟合和行为退化。我们在两个代表性的软件工程任务上评估GSE：缺陷揭示测试生成和误报缺陷报告过滤。在两种最先进的编码智能体OpenHands和mini-SWE-agent上，GSE始终实现最佳精确率、召回率和F1分数。与现有进化技术相比，GSE在测试生成中将精确率和召回率提高了6.1%~34.1%和31.8%~180.0%，在误报过滤中提高了15.4%~96.4%和13.1%~19.8%。在内部工业智能体上的部署进一步使F1分数提高61.4%，证明了GSE在进化有效技能方面的有效性和泛化能力。

## Abstract
Automated skill evolution enables Large Language Model (LLM) agents to continuously improve without expensive retraining. However, existing approaches typically treat skill evolution as a sequence of local updates, overlooking relationships among skills and often producing overfitted skill updates that fail to generalize across tasks. We propose GSE, a globalized skill evolution framework that jointly optimizes skill compatibility and skill generalization. To preserve consistency across the skill bank, GSE maintains a Skill Relation Graph (SRG) that explicitly models and co-evolves inter-skill relationships. To improve generalization, GSE performs cluster-based skill consolidation to abstract reusable capabilities from local updates and employs replay-driven verification to prevent overfitting and behavioral regressions. We evaluate GSE on two representative software engineering tasks: bug-revealing test generation and false-positive bug report filtering. Across two state-of-the-art coding agents, OpenHands and mini-SWE-agent, GSE consistently achieves the best precision, recall, and F1-score. Compared with existing evolution techniques, GSE improves precision and recall by 6.1%~34.1% and 31.8%~180.0% for test generation, and by 15.4%~96.4% and 13.1%~19.8% for false-positive filtering. Deployment on an internal industrial agent further yields a 61.4% improvement in F1-score, demonstrating the effectiveness and generalizability of GSE for evolving effective skills.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有 LLM 编码智能体的技能进化（skill evolution）大多采用“局部更新”策略，即从单条执行轨迹中提取经验并直接更新或新增技能，忽略了技能之间的相互关系。这种局部更新容易导致：  
  - 技能之间产生冲突或兼容性问题（例如一个技能的更新破坏了另一个技能依赖的假设）；  
  - 更新过拟合于特定轨迹、项目或缺陷模式，缺乏跨任务泛化能力；  
  - 随着技能库增长，碎片化、过拟合的技能不断积累，整体技能库质量逐步退化。
- **研究含义**：论文主张将技能进化视为一个全局优化问题，而不仅是一系列独立局部更新。需要同时优化技能之间的兼容性（compatibility）和技能本身的泛化性（generalization），从而构建一个相互关联、可复用的技能库，使编码智能体能够持续、稳定地自我改进。
- **背景**：LLM 智能体在软件工程任务（如测试生成、缺陷分析）中表现优异，但静态的提示、工具策略和人工技能难以适应多样化的项目与任务需求。自动技能进化通过轻量级更新（而非昂贵重训练）使智能体持续适应新场景，已成为重要研究方向。现有代表性方法（如 Live-SWE-agent、Trace2Skill）仍以局部更新为主，缺乏全局视角。

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想
- 提出 **GSE（Globalized Skill Evolution）** 框架，将技能库视为一个**相互连接的整体系统**，通过显式建模技能间关系并抽象泛化局部经验，实现全局一致的技能进化。

### 2.2 关键技术细节

**（1）Trace Collection（轨迹收集）**
- 记录智能体的内部推理、工具调用、命令参数、环境反馈及最终结果。
- 对原始轨迹进行简化，过滤冗长的文件搜索输出、低价值日志，保留命令、路径、关键错误信息与推理块，以提升分析效率。

**（2）Evolution Proposal Generation（进化提案生成）**
- **Failure Diagnosis**：层次化诊断失败原因，区分导航失败（context exploration）、推理失败（reasoning）和执行失败（execution），并归纳为两类技能进化方向：
  - 通用能力增强（general capability enhancement）
  - 可复用问题模式（reusable problem pattern）
- **Skill Relation Graph (SRG)**：有向图 \( G=(V,E) \)，节点为技能，边表示三类关系：
  - **dependency**：技能间存在假设或结果依赖；
  - **co-usage**：技能互补，联合使用效果更好；
  - **conflict**：技能指导不兼容，不应同时激活。
  - 提案更新时，GSE 检索受影响的相邻技能，生成辅助进化提案，**同时进化技能内容与技能间关系**。
- **DSL 结构化的进化提案**：定义标准 schema，包含目标技能（target skill）、操作（operation）、内容（content）、理由（rationale）、预期效果（expected behavior）、关系更新（relationship updates），减少歧义并便于处理。
- **局部验证**：在临时技能库中应用提案，重放触发失败的轨迹；若不能解决原失败则丢弃。

**（3）Skill Generalization（技能泛化）**
- **Cluster-based Skill Consolidation**：
  - 对修改现有技能的提案，按“受影响技能集合”聚类；
  - 对新增技能的提案，按语义相似性（rationale 与预期效果）聚类。
  - 从每个聚类中提取共同能力模式，消除案例特定细节，合并冗余/冲突更新，形成候选技能库。
- **Replay-Driven Validation**：
  - 对修改现有技能的候选技能，重放历史相关案例（这些技能之前被激活的案例）以检测回归；
  - 对新增技能，重放生成该聚类提案的案例。
  - 仅当候选技能库在这些重放案例上保持或提升性能时，才被接受并合并入技能库。

### 2.3 算法流程（文字描述）
1. 收集并简化执行轨迹。
2. 更新代理进行失败诊断，并通过 SRG 识别受影响技能。
3. 生成结构化 DSL 进化提案（单条或附带关系更新的提案）。
4. 在临时技能库中重放原轨迹，进行局部验证，失败则丢弃。
5. 对通过验证的提案进行聚类（已有技能按受影响技能集合；新技能按语义相似性）。
6. 从聚类中提取通用能力模式，构建候选技能库。
7. 在相关历史案例上重放候选技能库，验证是否保持或提升性能。
8. 通过验证的候选技能库合入正式技能库，同时更新 SRG 中的关系。

## 6. 论文的主要结论与发现

- **测试生成任务**：
  - OpenHands 上：GSE 的 Precision/Recall/F1 为 0.35/0.28/0.31，比最强基线 F1（0.22）提升 40.9%。
  - mini-SWE-agent 上：GSE 为 0.55/0.29/0.38，比最强基线（F1 0.29）提升 31.0%。
  - 相比现有进化技术，GSE 在精确率上提升 6.1%~34.1%，召回率提升 31.8%~180.0%。
- **误报过滤任务**：
  - OpenHands 上：GSE 的 Precision/Recall/F1 为 0.55/0.95/0.70，远超最强基线（0.29/0.84/0.43）。
  - mini-SWE-agent 上：GSE 为 0.30/0.97/0.46，优于最强基线（0.26/0.84/0.39）。
  - 精确率提升 15.4%~96.4%，召回率提升 13.1%~19.8%。
- **消融实验**：
  - 移除 SRG 或泛化机制均导致 F1 显著下降（测试生成 F1 从 0.31 降至 0.27；误报过滤从 0.70 降至 0.59/0.54），证明两个组件缺一不可。
- **成本分析**：
  - 进化阶段 GSE 比 Trace2Skill 多消耗 12.28% token；但执行阶段 GSE 的 token 消耗比人类技能、Live-SWE-agent、Trace2Skill 分别低 4.4%、3.3%、4.3%。
- **工业部署**：
  - 内部基座智能体的基础 F1 为 0.43，接入 GSE 后 F1 提升至 0.71，提升 65.1%（相对于基础），相对人工技能提升 61.4%。这证明 GSE 对强基座智能体同样有效。
