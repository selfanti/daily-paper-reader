## 摘要
长周期LLM智能体日益依赖外部执行支持来维护状态、跟踪进度、调用工具、验证结果，并在交互中复用经验。然而，有效使用框架带来了两个相互耦合的挑战：从嘈杂的交互轨迹中形成状态，以及对外部状态访问的运行时控制。现有智能体通常通过提示、启发式规则或领域特定约定来处理这两者，使得外部工作空间及其使用策略被手工设计。为解决这一问题，我们研究了框架策略学习问题，即智能体离线学习框架策略，并在在线运行时任务执行期间部署它们以构建和更新外部框架状态。我们引入了EvoHarness-RL，它将信念、进度和经验（BPE）暴露为面向策略的框架状态。监督式框架微调教会基础智能体框架动作空间以及如何构建有用的外部状态，而成本感知的GRPO则探索协调策略，以便在长周期交互中选择性地读取、更新和整合该状态。在ALFWorld上以Qwen3-8B LLM进行实例化，EvoHarness-RL达到了96.9%的成功率，并揭示了两个关键动态：框架退火，即训练将反复出现的框架使用模式内化为模型策略，使智能体从频繁的框架调用转向选择性的外部状态访问；以及框架演化，即进度更新和经验整合将框架精炼为紧凑、自适应任务的状态基底。这些结果表明，长周期智能体受益于可训练的策略来构建和协调外部框架工作空间，而不仅仅是添加更强的工具或更大的记忆。

## Abstract
Long-horizon LLM agents increasingly rely on external execution support to maintain state, track progress, invoke tools, verify outcomes, and reuse experience across interactions. However, effective harness use raises two coupled challenges: state formation from noisy interaction traces and runtime control over external-state access. Existing agents usually handle both through prompts, heuristics, or domain-specific conventions, leaving the external workspace and its usage policy manually engineered. To address this, we study the problem of harness policy learning, where agents learn harness policies offline and deploy them to construct and update external harness state online during runtime task execution. We introduce EvoHarness-RL, which exposes Belief, Progress, and Experience (BPE) as policy-facing harness state. Supervised harness fine-tuning teaches the base agent the harness action space and how to construct useful external state, while cost-aware GRPO explores coordination policies to selectively read, update, and consolidate that state during long-horizon interaction. Instantiated on ALFWorld with a Qwen3-8B LLM, EvoHarness-RL reaches 96.9% success and reveals two key dynamics: harness annealing, where training internalizes recurring harness-use patterns into the model policy and shifts the agent from frequent harness calls toward selective external-state access, and harness evolution, where progress updates and experience consolidation refine the harness into a compact, task-adaptive state substrate. These results suggest that long-horizon agents benefit from trainable policies for constructing and coordinating with external harness workspaces, beyond simply adding stronger tools or larger memories.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体正被广泛应用于长周期（long-horizon）交互任务中，如具身交互、网页导航、软件工程和工作流自动化。这类任务要求智能体持续维护环境信念、跟踪子目标进度、从失败中恢复、并复用跨回合经验，因此高度依赖外部执行支持（即"外部框架/运行时框架"，external harness），包括记忆、工具、状态跟踪器、验证器、执行日志等组件。
- **核心问题**：尽管外部框架组件日益丰富且被精心设计，但智能体**如何在运行时使用这些框架**——即何时读取、更新、整合外部状态——通常由提示词、启发式规则或固定约定来指定，属于手工工程化的产物，缺乏可学习、可适应的策略。具体而言有两个相互耦合的挑战：(1) 从嘈杂的交互轨迹中形成有用的状态表示；(2) 对外部状态访问的运行时控制（访问有代价，需要权衡）。
- **整体含义**：论文主张将框架使用本身视为一个**可训练的策略决策问题**（harness policy learning），智能体应离线学习框架策略、在线部署以构建和更新外部状态，而非仅仅依赖更强的工具或更大的记忆容量。

## 2. 论文提出的方法论

### 2.1 核心思想
提出 **EvoHarness-RL**，一个可训练的智能体-框架协调层，将异构的外部框架组件抽象为统一的、面向策略的 **BPE（Belief, Progress, Experience）** 工作空间：

- **Belief（信念）**：维护对环境状态的持续估计，如物体状态、位置、关系；
- **Progress（进度）**：记录子目标分解与执行状态，使隐式推理轨迹变为可检查的任务状态；
- **Experience（经验）**：维护跨回合可复用知识，如技能、失败模式、搜索先验等。

### 2.2 关键技术细节：智能体-框架动作协议
定义了 4 种紧凑的框架元动作（meta-actions）：

| 动作 | 功能 | 对应状态 |
|---|---|---|
| `track` | 读取信念状态 | Belief |
| `commit` | 写入子目标/执行更新 | Progress |
| `recall` | 检索可复用经验 | Experience |
| `note` | 记录新见解供后续整合 | Experience |

策略在每步从环境动作与环境动作的并集 A = A_env ∪ A_bpe 中采样，两类动作消耗相同的交互预算，因此需要学习"何时值得访问外部状态"。

### 2.3 两阶段训练流程

**阶段一：监督式框架微调（SFT）**
- 使用教师模型（Claude Opus）在相同 BPE 接口下收集成功轨迹，训练 Qwen3-8B 学习 BPE 动作空间语义以及如何从交互轨迹中外化有用的信念、进度和经验状态。

**阶段二：成本感知的 GRPO 优化**
- 从 SFT 检查点初始化，使用 GRPO 优化策略，奖励函数设计如下：

```
R(τ) = R_succ(τ)          # 任务成功（10分，严格门控）
     + λeff · R_eff(τ)    # 效率奖励（成功时才获得，惩罚冗余查询）
     + λdiv(u) · R_div(τ) # 时变动作多样性奖励（早期鼓励探索，后期退火）
     − λspam · R_spam(τ)  # 重复惩罚
     − λinv · R_inv(τ)    # 格式惩罚
```

其中多样性奖励采用余弦退火课程（λdiv(u) 随训练轮次衰减），防止策略崩溃（忽略框架或陷入循环），并逐步收敛到高效的任务解决策略。

### 2.4 环境适配器（Environment Adapter）
BPE 是功能性接口而非固定模式，通过领域特定的环境适配器将领域信号（观察、动作结果、工具输出等）桥接到统一 BPE 接口。在 ALFWorld 中：
- Belief 用基于规则的解析器维护世界状态存储（不需要 LLM 调用）；
- Progress 用有界子目标状态列表实现；
- Experience 用跨回合技能库实现（分为通用技能、任务特定技能、常见错误、搜索先验四类），通过检索（recall）、写入缓冲（note）、批次后整合（consolidation，包含增/改/删操作）实现演化。

## 3. 实验设计

### 3.1 基准环境与任务
- **环境**：ALFWorld（与 ALFRED 具身 AI 基准对齐的文本游戏），智能体通过文本命令导航房间、操作物体完成多步家务任务。
- **任务族**：6 类——Pick（简单拾取放置）、Look（光照下检查物体）、Clean（清洁后放置）、Heat（加热后放置）、Cool（冷却后放置）、Pick2（放置两个物体）。
- **评估集**：标准 140 任务的 seen 验证集 + unseen 测试集。

### 3.2 对比方法
- **前沿模型**：Claude Opus 4.5、GPT-4.1、GPT-5（标准提示 + EvoHarness-Base 提示框架）；
- **冻结记忆/智能体方法**：ReAct、ExpeL、ReasoningBank、MemP、Dynamic Cheatsheet、ACE、SkillOS-base；
- **可训练方法**：标准 GRPO、SkillOS、SkillRL；
- **自身变体**：EvoHarness-Base（推理时提示框架）、EvoHarness-SFT（监督学习框架调用）、EvoHarness-RL（SFT + GRPO 完整训练）。

### 3.3 主要实验结果
- **Seen 集**：EvoHarness-RL 平均成功率 **96.9%**，相比 ReAct（47.9%）提升 **+49.0**，超越 SkillOS（80.2%）和 SkillRL（89.9%），与 Claude Opus 4.5（96.4%）相当甚至更优。
- **Unseen 集**：EvoHarness-RL 达 **86.6%**，显著高于 ReAct（50.0%）、EvoHarness-Base（77.6%）、EvoHarness-SFT（69.4%）。
- **BPE 组件消融**：分别移除 Belief/Progress/Experience 都会显著降低性能，最低为移除 Experience（48.6%），表明三者协同作用。
- **训练动态分析**：框架退火（harness annealing）——GRPO 训练后期框架调用从频繁下降到每回合约 1 次；框架演化（harness evolution）——技能库先扩张后稳定为紧凑多样状态。

## 6. 论文的主要结论与发现

1. **可训练框架策略有效**：EvoHarness-RL 将框架使用从提示工程转换为学习到的运行时策略决策，使 8B 模型达到 96.9%（seen）/ 86.6%（unseen）的成功率，匹配甚至超越前沿大模型。
2. **BPE 具有普遍增益**：无论基础模型能力强弱，显式外部化信念、进度和经验都能改善长周期任务执行（GPT-4.1 +22.1，GPT-5 +25.7，Claude Opus 4.5 +2.1）。
3. **框架退火（Harness Annealing）**：训练将反复出现的框架使用模式内化为模型策略，使智能体从频繁的"脚手架式"外部调用转向选择性外部状态访问；且不同动作（recall 最持久，commit/note 快速衰减）的衰减速率不同，说明策略学到的是**环境自适应的框架使用分布**。
4. **框架演化（Harness Evolution）**：经验存储在训练中通过积累、整合、遗忘不断精炼，从快速扩张的原始技能库变为紧凑、任务自适应的状态基底，而非被动追加的记忆日志。
5. **两阶段训练有效**：从提示框架（56.4%）→ SFT（68.6%）→ GRPO（96.9%）的递进验证了"先学会构建状态，再学会选择性协调"的训练逻辑。

## 7. 优点

- **概念创新**：提出"框架策略学习"这一新问题视角，将外部框架从环境侧构造提升为"一等公民"的可学习策略决策，衔接了记忆增强与 RL 优化两线研究。
- **抽象设计优雅**：BPE 三态抽象紧凑（仅 4 个元动作）但覆盖面广（环境状态、执行状态、跨回合经验），且通过环境适配器保持领域通用性——策略-框架协调层共享、内部实现可替换。
- **奖励设计精细**：同时考虑任务成功、效率、动作多样性、重复惩罚和格式惩罚，并用余弦退火实现"先探索后收敛"的课程学习，有效防止策略崩溃。
- **训练动态的可解释性分析**：框架退火和框架演化两个概念的提炼，使人们能直观理解 RL 如何将外部脚手架内化为内部策略，以及外部状态如何协同进化。
- **实验对比全面且有说服力**：相对 ReAct 提升 49 个点，超越现有最强 SOTA（SkillRL 89.9%），且对前沿闭源模型也有显著增益，泛化实验也验证了不是过拟合。
