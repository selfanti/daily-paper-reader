## 摘要
大语言模型智能体越来越多地在动态环境中运作，其中工具接口、API和用户需求在部署后发生变化。现有的自进化方法主要遵循两种范式：基于工具（harness-based）的方法，将反馈外化为可编辑的记忆或技能以实现快速适应；以及基于参数的方法，将经验内化为模型参数以实现更深层次的能力提升。然而，单独使用任一机制都会在灵活性和性能之间造成权衡。本文探讨了智能体如何协调两种通道以实现稳健的自进化。我们提出了COVE，一个统一的智能体自进化框架，通过任务感知路由、阶段感知调度和知识优化将基于工具和基于参数的学习相结合。通过这一设计，COVE将自进化视为一种协调过程，而非对经验的无差别积累，该过程将任务和知识类型与合适的学习机制相匹配。跨多个任务类别的实验表明，COVE优于单一通道的进化策略，在动态环境下展现出更稳健和高效的提升。

## Abstract
Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型智能体（LLM Agent）已从被动文本生成器发展为具备规划、调用工具、编写代码、多步推理等能力的交互式系统。然而，外部世界持续变化——API更新、数据库模式改变、新库出现、领域惯例迁移、用户任务超出开发预期，导致已部署的智能体需要频繁重配置或重训练，成本和人工消耗极高。
- **核心问题**：智能体如何通过自我进化（Self-Evolution）在动态环境中持续适应？现有方法分两大范式：
  - **基于工具（Harness-based）的方法**（如Evo-Memory、Reflexion、Voyager）：将反馈外化为可编辑的记忆/技能，检索后注入执行环境。优点是适应快、易修改；缺点是对基础模型能力不足时会产生误导性经验，且记忆累积有限。
  - **基于参数（Parameter-based）的方法**（如WizardLM、Self-Challenging Agent）：通过SFT或RL将经验内化为模型权重。优点是能捕获深层模式；缺点是训练昂贵、适应慢，对表面形式变化（如API改名）脆弱。
- **核心洞见**：单独使用任何一者都会在灵活性和性能之间权衡。论文通过四项诊断实验（MiniF2F定理证明、WikiTableQuestions动态API）证明：任务类型、学习阶段、知识波动性共同决定了应使用哪种进化通道，存在有效协调的必要性和可行性。

### 2. 方法论：核心思想、关键技术细节、公式与算法流程

**2.1 核心思想**

COVE（Channel Orchestrated Volatility-aware Evolution）是一个统一的自进化框架，核心主张是：自进化不应是对经验的无差别积累，而应根据任务类型、学习阶段、知识波动性，将不同经验匹配到合适的存储/学习机制。其核心操作机制包括三大模块：

**2.2 任务公式化（Task Formulation）**

- 智能体由参数化策略模型 π_θ、外部知识库 K={k_j}、执行环境 E 组成。
- 每个任务 τ_i 执行后获得反馈 f_i（可能包括任务奖励、成败标签、错误轨迹、工具调用日志等）。
- 两类更新：工具侧更新 `K ← U_h(K, τ_i, f_i)`（从反馈中提取记忆/技能）和参数侧更新 `θ ← U_θ(θ, D_train, K)`（利用积累的轨迹优化参数）。
- 优化目标为最大化累计任务效用，平衡推理时的token成本与训练时的计算开销：
  `max Σ R_i − α Σ C_tok_i − β Σ C_train_m`

**2.3 任务感知路由（Task-aware Routing）**

- 将路由实例化为**反馈条件化决策策略**，而非手工评分函数。
- 给定任务描述 τ_i 和反馈 f_i，通过受约束的评判器（constrained judge）输出结构化决策记录 d_i = (m_i, s_i, r_i)，其中：
  - m_i：选择的进化通道（harness_only / parametric_candidate / hybrid）
  - s_i：简短自由文本描述符（如 dynamic_tool、logical_rigor）
  - r_i：单句决策理由
- 通道选择逻辑：
  - **harness_only**：失败源于波动性或上下文相关知识，不适合权重更新；
  - **parametric_candidate**：任务奖励可内化的能力，且难以用提示表达；
  - **hybrid**：同时具有两类信号（如形式推理+工具交互）。

**2.4 阶段感知调度（Stage-aware Scheduling）**

- 引入**阶段感知进化触发器（Stage-aware Evolution Trigger）**，动态决定何时切换通道，基于三个可复现条件：
  - **Performance plateau**（性能平台期）：最近 w 个 episode 的成功率/平均奖励提升低于阈值 ε；
  - **DataSufficient**（数据充分）：高质量轨迹数量 |D_q| ≥ N；
  - **ColdStartFailure**（冷启动失败）：任务族前 k 个任务成功率低于阈值 τ_c，工具侧无法自举。
- 触发条件为：`Trigger = Plateau ∨ DataSufficient ∨ ColdStartFailure`
- 常见路径是"工具侧先行探索→平台期/数据充分后参数侧内化"；对冷启动域则相反，先做初步参数更新建立最低能力门槛。

**2.5 知识优化（KnowledgePO：Dual-modal Knowledge Optimization）**

KnowledgePO 是COVE的双模态知识优化模块，解决工具侧记忆与参数侧权重之间如何交换知识的问题，包含两个机制：

- **工具侧辅助参数侧（Memory-aware Rollout）**：
  - 为每条知识条目 k_j 分配波动性标签 ℓ_j ∈ {volatile, stable, strategic}（由受约束评判器判断）。
  - 非波动条目若反复被修订，则自动提升为 volatile（视为依赖变化外部状态的证据）。
  - volatile 条目用 `<volatile>...</volatile>` 显式标记，注入到消息列表中以指导推理。
  - 引入**反背诵奖励（Anti-recitation Reward）**：训练前将 volatile 条目中的名字随机重命名，若模型调用历史中过时或未见过的 volatile 名称，则施加惩罚：
    `R = R_task − λ·I[uses stale or unobserved volatile name]`
    该设计防止模型将接口名到固定动作的映射内化，而促使其"读取当前条目并据此行动"。

- **参数侧辅助工具侧（Memory Release）**：
  - 训练后，对稳定知识执行 A/B 测试（保留 vs 移除检索上下文），若性能下降 Δ_j 低于阈值且此前有正向效用，则该条目被标记为 internalized 并从在线检索集释放（可留档备查）。volatile 记忆永不释放。

**2.6 算法流程**

COVE 的主循环为：检索记忆→工具侧推理→收集反馈→提取带标签候选条目→更新知识库→路由决策→触发判断（循环工具侧探索）→需要时进行参数侧训练（记忆感知 rollout + 反背诵奖励）→评估并释放已内化的稳定记忆→继续工具侧交互。伪代码见论文 Algorithm 1。

### 6. 主要结论与发现

- **单一通道的局限被实证确认**：
  - 工具侧（记忆）在 Lean 定理证明上几乎无效：记忆条目从2增至8，成功率提升不足3%，错误类型无一致下降；
  - 参数侧在动态接口场景下脆弱：API 改名后成功率从40.5%降至16.5%，API调用正确率从96.5%降至54.0%。
- **阶段感知的调度是关键**：平台期触发的参数更新优于持续训练和仅工具侧演化，表明训练时机本身是重要决策。
- **知识波动性是存储机制选择的关键判据**：volatile 知识（如API名）应保留在工具侧并显式防止被内化；stable 知识（如可复用证明策略）适合内化到参数；strategic 知识（如调试计划）需多次稳定证据后才可内化。
- **COVE 整体优于单通道**：在 Lean4、APPS、HotpotQA、MATH 上取得最好成绩，并使用比无差别参数学习少 86% 的训练 tokens；在混合难度子集上优势更明显（24.1% vs 21.3%的最佳单通道）。
- **反背诵机制有效**：在不损害同分布性能的前提下，显著提升了改名场景下的 API 调用正确率（92.5% vs 54.0%），并通过注意力分析验证了模型更关注当前指令而非历史接口名。
