## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题求解能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们引入MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自演化。在执行前，MANTA从先前的结构经验中初始化一个任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保持任务接口和智能体预算不变。我们在五个基准上将MANTA与代表性的单智能体和多智能体基线进行比较，涵盖信息寻求、工具使用、规划、工作流执行和数学推理。MANTA取得了最高的平均分74.0，比最强基线高出5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
MANTA（Multi-Agent Network Topology Adaptation）在推理时对多智能体系统的通信结构进行有界、自演化式的调整。它先将历史结构经验作为初始拓扑，再在协作过程中监控轨迹信号，发现结构性不足时进行局部修复，并将经验跨任务累积。

### 2.2 系统架构
MANTA 分为两个嵌套层级：

- **目标多智能体系统层**：执行推理、工具调用和消息交换。
- **编排层**（orchestration layer）：负责拓扑规划、执行审计、修复控制、记忆学习。由三个 LLM 组件与确定性代码组成：
  - **Topology Planner**：根据任务和长期经验设计初始拓扑；在修复阶段生成有界突变。
  - **Trace Auditor**：扫描协作轨迹中的过程性异常（process anomalies），不判断答案对错。
  - **Skill Reflector**：周期性重写长期剧本中的经验教训，仅基于过程信号。

### 2.3 拓扑表示
- 每个智能体具有**结构角色**（如协调者、工作者、验证者、辩论者、投票者）和**阶段角色**（worker/critic）。
- 智能体可带领域 persona 和允许使用的工具列表。
- 拓扑由**模式组**（pattern group）构成，可嵌套，支持 star、chain、debate、voting 等模式。
- 上下文策略控制消息可见性、传播距离、摘要级别等。
- 确定性代码在运行前验证组归属、附件环、角色和智能体预算，非法提议被拒绝。

### 2.4 编排循环
1. **查询条件化规划**：Planner 接收任务和长期剧本，生成包含交互模式、智能体数量和可选 verifier 的紧凑计划；确定性代码展开并验证。
2. **轮次执行**：智能体通过结构化的中继包交换答案、证据、置信度和未决问题；消息可见性由共享上下文控制器强制执行；工具调用去重；证据账本为 append-only。
3. **轨迹审计与修复**：每轮后 Auditor 扫描结构化工件、工具记录和证据，输出过程风险标志（如过早共识、重复状态变更、工具错误级联等），但不得访问基准答案或 verdict。若有中等/高严重度的可修复标志，则允许一次有界修复和最终轮。
4. **双时间尺度记忆**：

## 6. 论文的主要结论与发现

- **MANTA 在五个基准上平均成绩 74.0，比最强基线（ADAS 68.2）高出 5.8 个百分点，并在 PlanCraft 上取得所有方法中最优结果（76.7）**。同时，MANTA 在信息寻求和工具使用上与最优静态基线相当，在规划任务上优势明显，但在 WorkBench 上不及 ADAS 和 AgentSquare。
- **消融实验显示贡献排序**：初始任务条件化拓扑规划贡献最大（57.5 → 71.7）；执行期拓扑修复次之（60.8 → 71.7）；长期剧本更新与存在提供较小但持续的增益。
- **突变预算分析**：第一次突变机会带来的平均成功增益最大，后续突变增幅递减；预算从 0 增加到 3 时，四个基准的覆盖率均提升。
- **可迁移性**：MANTA 的长期剧本在同域和跨域（PlanCraft↔WorkBench）迁移时均取得正向平均增益（+3.3 分），而 AFlow、AgentSquare、MASS 的离线工作流迁移效果为中性或大幅负向。

## 7. 优点

- **提出新问题层次**：首次系统地将“通信拓扑”作为推理时可演化的对象，定义了“topology-level self-improvement”，与输出、提示、轨迹、记忆等层次区分开。
- **推理时适应性**：无需重新训练模型权重，通过有界、局部、证据驱动的拓扑突变即可实现自适应，符合实际部署需求。
- **过程信号而非正确答案**：Trace Auditor 和长期剧本更新都基于过程性观测，避免利用基准标签，增强了方法的一般性和可信度。
- **结构约束与安全性**：拓扑表示包含确定性校验，修复操作受限且必须通过结构验证，避免无约束地增加智能体或破坏拓扑合法性。
- **高效性**：MANTA 在所比较的多智能体系统中 token 消耗最低，说明自适应拓扑并不以大量额外计算为代价。
- **机制设计细致**：双时间尺度记忆、agent 无状态化、共享只读存储、证据账本和临时候选投票机制，使拓扑突变可以无损失、无迁移成本地发生。

## 8. 不足与局限

- **实验规模偏小**：每个基准只有 30 道题、3 次运行，统计功效有限；许多方法结果的标准差很大，论文未提供显著性测试或置信区间。
- **单一骨干模型**：所有实验仅在 Gemma 4 31B 上完成，未验证在其他规模或厂商模型上的可迁移性和鲁棒性。
- **审计信号本质是代理指标**：过程标志并不等于真实过程缺陷，其精度在不同基准差异巨大（如 WorkBench F1 0.78，而 BrowseComp 仅 0.40，PlanCraft 仅 0.09）；误报率较高，可能会错误触发修复。
- **修复预算限制**：每运行仅允许一次拓扑突变、每次至多 3 个操作，可能不足以修复多个并发或复杂结构性缺陷。
- **跨域迁移实验有限**：仅测试了 PlanCraft↔WorkBench 两个规划/工作流类基准，且迁移增益较小（平均 +3.3），不足以证明长期剧本的广泛泛化能力。
- **应用安全与外部工具风险**：虽然提到了工具去重、串行化等机制，但对于真实环境中状态变更动作的安全性和故障恢复能力缺乏系统评估。
- **未涉及权重级优化**：方法不更新模型权重，在需要深度技能学习的场景下能力上限可能受限于预训练知识。
- **模糊的绝对成本**：虽提供了 token 用量，但没有硬件运行时间、能耗或实际核算成本的说明，难以与其他方法做绝对值比较。
