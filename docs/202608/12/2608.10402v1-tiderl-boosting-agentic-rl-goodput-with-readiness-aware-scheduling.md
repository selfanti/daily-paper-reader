## 摘要
大型语言模型的强化学习正在向多轮智能体工作负载发展，其中回滚任务反复暂停以等待外部环境、以不断增长的上下文恢复，并在高度可变的时间完成。在这种设置下，RL训练有效吞吐量（以训练吞吐量衡量）比原始GPU占用率更重要：GPU等待和重复的预填充重计算纯粹是开销。我们提出了TideRL，一个具有就绪感知的弹性RL系统，包括连续任务批处理、资源感知的Ref-Actor流水线化和弹性资源扩展。CTB保留有用的回滚状态，$\textrm{RA}^2\textrm{P}$根据就绪积压和到达间隔在解耦流式与协同聚合之间进行选择，而ERS利用相同的就绪信号在回滚和训练之间移动rank。在纯文本和多模态智能体工作负载中，TideRL相比同步基线将RL训练有效吞吐量提升了最高5.6倍，相比异步基线提升了超过33%，同时达到相似的任务性能。它还将KV缓存命中率提高了1.58倍，每步训练时间减少了最高44.3%，总等待时间减少了最高77.6%。

## Abstract
Reinforcement learning (RL) for large language models is moving toward multi-turn agentic workloads, where rollout tasks repeatedly pause for external environments, resume with growing contexts, and finish at highly variable times. In this setting, RL training goodput, measured by training throughput, matters more than raw GPU occupancy: GPU waiting and repeated prefill recomputation are pure overhead. We present TideRL, a readiness-aware elastic RL system with Continuous Task Batching, Resource-Aware Ref-Actor Pipelining, and Elastic Resource Scaling. CTB preserves useful rollout state, $\textrm{RA}^2\textrm{P}$ selects between decoupled streaming and colocated aggregation from the ready backlog and arrival interval, and ERS moves ranks between rollout and training using the same readiness signals. Across text-only and multi-modal agentic workloads, TideRL improves RL training goodput by up to 5.6$\times$ over synchronous baselines and over 33% over asynchronous baselines, while reaching similar task performance. It also improves KV cache hit rate by 1.58$\times$, reduces per-step training time by up to 44.3%, and cuts total waiting time by up to 77.6%.

## 1. 核心问题与整体含义

- **研究背景**：大语言模型（LLM）的强化学习（RL）正从单轮推理任务向多轮智能体（Agentic）工作负载演进。在多轮智能体场景中，模型需要与外部环境（如网页浏览器、手机、操作系统等）进行多次交互，每次生成动作后需要等待环境返回结果，导致任务执行轨迹在回合数、上下文长度和墙钟耗时上具有极大的空间和时间维度上的方差。
- **核心问题**：现有的同步 RL 系统（如 VeRL）强制 rollout 与训练阶段之间的屏障，导致训练 GPU 被长尾任务阻塞；而现有的异步 RL 系统（如 AReaL、StreamRL）虽解耦了 rollout 与训练，仍存在三大结构性缺陷：
  1. **C1 — KV Cache 抢占问题**：多轮任务在等待环境反馈时，推理引擎会因持续批处理（continuous batching）而驱逐其 KV Cache，恢复生成时必须重新计算（prefill）不断增长的历史上下文，造成大量冗余计算。实验显示缓存命中率可低至约 12%。
  2. **C2 — 训练端的停滞与抖动**：现有系统在同一组 GPU 上共享 Ref 与 Actor 模型，要么等待完整全局批次导致计算气泡（GPU 空闲高达 81%），要么频繁交替加载两套模型权重导致严重的 I/O 抖动。
  3. **C3 — 静态资源分配的刚性**：任务复杂度随时间剧烈变化，系统瓶颈在 rollout 与训练之间动态迁移，静态 GPU 划分无法适应这种漂移。
- **整体含义**：作者提出以 **训练吞吐量（training throughput，即有效被 Trainer 消耗的 token 数）** 而非原始 GPU 占用率作为 RL goodput 的衡量标准，并围绕"就绪状态（readiness）"这一核心概念设计了统一的弹性调度架构。

## 2. 方法论

论文提出 **TideRL** 系统，包含三个协同设计的核心组件，由就绪信号（RAS 与 TPRM）统一驱动：

### 2.1 Continuous Task Batching (CTB) —— 解决 C1

- **核心思想**：将 rollout 调度从请求级（request-level）提升到任务级（task-level），以任务为粒度管理 KV Cache 的准入、抢占与恢复。
- **Token 感知准入控制**：每个 DP rank 视为一个 token 预算池，通过轻量探测任务估计初始 token 占用，仅在剩余容量足够时准入新任务；同时约束环境并发度、策略陈旧度和任务多样性。
- **语义感知优先级抢占**：任务优先级综合四个因素——评估任务（最高）、GRPO 组完成度、是否正在执行、上下文长度。通过算法循环（Algorithm 1）在超出 token 预算时抢占低优先级任务，在空间恢复时优先恢复已暂停任务，而非引入新任务。
- **Worker 亲和性**：恢复暂停任务时优先放置到最可能保留共享前缀的 rank 上，避免前缀重复计算。
- **效果**：KV 缓存命中率提升 1.58 倍，生成吞吐提升 1.15 倍，步骤耗时降低 15.6%。

### 2.2 Resource-Aware Ref-Actor Pipelining (RA²P) —— 解决 C2

- **两种执行模式**，依据两个就绪信号选择：
  - **RAS（Ready-at-Start）**：训练步骤开始时已有就绪微批次的数量；
  - **TPRM（Time Per Ready Micro-batch）**：后续微批次到达的时间间隔。
- **解耦流式模式（Decoupled Streaming Mode）**：适用于 RAS 大或 TPRM 短的情况。Ref 和 Actor 分布在不同的 GPU 上，形成流式微批次流水线。关键创新是**计算图重构**：将损失计算（含 KL 惩罚）从 Actor 的前向传播推迟到反向传播中，使 Ref 前向、Actor 前向和 Actor 反向三者能够重叠执行，消除同步气泡。
- **优化共置模式（Optimized Colocated Mode）**：适用于 RAS 小且 TPRM 长的情况。Ref 和 Actor 放在同一组 GPU 上，释放更多 GPU 给 Rollout。两个优化：
  1. **就绪批聚合**：多个微批次就绪后才一次性切换模型，摊还模型交替的 I/O 开销；
  2. **零拷贝传输**：同节点内通过 GPU 共享内存传递中间结果，避免网络序列化。
- **微批次调度优化**：早期微批次尽量填满计算能力，最后一个微批次刻意保持最小以缩短流水线排空时间；共置模式采用 zig-zag 分配均衡负载，解耦模式将最短序列放在流水线最后以最小化尾延迟。
- **分析模型**：附录 A 给出了两种模式延迟成本的量化模型（C_dec 与 C_col），用于自动选择模式。

### 2.3 Elastic Resource Scaling (ERS) —— 解决 C3

- **核心思想**：ERS 作为 RA²P 两种模式的运行时调度器，根据全局缓冲区的就绪信号动态迁移 GPU rank：
  - **生成赤字（Generation deficit）**：全局批次小于 B_ideal 且 TPRM 长，表明 rollout 资源不足 → 选择共置模式，将解耦模式的 Ref GPU 释放给 Rollout；
  - **消费赤字（Consumption deficit）**：HoL 延迟超过阈值或 RAS 超过解耦模式盈亏平衡点，表明 Trainer 消费能力不足 → 选择解耦模式，回收 Rollout rank 增加 Ref 容量。
- **无开销弹性**：利用 on-policy RL 每次同步后自然需要刷新 KV Cache 的特性，piggyback 权重迁移到 sync_params 广播的时间窗口内完成角色切换，无需暂停流水线、无需重建 NCCL 通信组、无需迁移 KV Cache。

## 6. 主要结论与发现

- TideRL 在**文本任务**上实现训练吞吐较同步基线 VeRL 提升 **5.6 倍**，较异步基线 AReaL 提升 1.8 倍、较 StreamRL 提升 7 倍以上；
- 在**多模态任务**上实现 6.02 倍（对比 VeRL）和 33% 以上（对比异步基线）的提升，训练时间减少 62.2%，任务性能与基线的差距很小（BoN 奖励差距 ≤0.01，pass rate 差距 ≤0.5%）；
- TideRL 在 100 步文本训练中仅用 VeRL **48.9% 的墙钟时间**达到相近性能；40 步多模态训练仅用 VeRL 37.8% 的时间；
- **CTB** 提升 KV 缓存命中率 1.58 倍、生成吞吐 1.15 倍、步骤耗时降低 15.6%；
- **RA²P** 降低每步训练开销最高 **44.3%**；
- **ERS** 降低 RWT+TWT 总等待时间 68.6–77.6%，结合 RA²P 后（消融表）整体提升 35.7%；
- 后缀解码（SD）在多轮智能体任务中因接受率低（~40%）和接受长度短（~2.8 tokens），验证开销超过投机收益，不适合该工作负载。

## 7. 优点

1. **问题定位精准**：明确区分"原始 GPU 占用率"与"有效训练吞吐"两个概念，瞄准多轮智能体 RL 中特有的三类系统性瓶颈，且每个瓶颈都有实验数据支撑（如图 2、3、4 的动机实验）。
2. **统一就绪信号框架**：RAS 和 TPRM 两个简洁的度量贯穿 CTB→RA²P→ERS 三个层次的决策，形成闭环反馈——"CTB 控制轨迹何时就绪，RA²P 暴露消费就绪流的代价，ERS 移动资源以减少主要等待"，架构逻辑清晰且耦合有序。
3. **计算图重构的巧妙性**：将损失计算延迟到反向传播，打破 Ref → Actor 的依赖链，使 Ref 前向、Actor 前向和 Actor 反向可重叠执行，是教科书中流水线并行思想的创造性变体。
4. **零开销弹性**：利用 on-policy RL 每次同步后 KV Cache 天然失效的特性，将权重迁移隐藏到 sync_params 广播窗口内，避免了传统弹性框架的暂停、重启和通信组重建开销。
5. **兼容性**：系统以模块化设计接入主流训练后端（Megatron、PyTorch FSDP）和推理引擎（vLLM、SGLang），支持多种模型架构，实用性强。
6. **实验剖析深入**：除端到端对比外，还分别针对三个组件设计了隔离实验、微基准实验和消融实验，验证链条完整。

## 8. 不足与局限

1. **实验规模受限**：仅部署在 32 张 H100 的单集群上，每节点 8 卡。论文中提到的生产集群场景（如 Alibaba、Microsoft）通常规模更大，多节点间的网络通信、任务调度、容错等扩展性问题未得到验证。多模态任务中 ERS 的收益较小（33% vs 文本的 80%+），作者解释为"可用迁移的 rank 变少"，这暗示系统在大规模下可能收益递减。
2. **缺乏统计显著性报告**：各组实验的运行次数和方差未报告，无法判断性能差异的统计显著性。
3. **对比基线不完整**：未与 Seer 做定量对比（作者解释为同步架构已被 VeRL 代表以及 SD 开销问题），未与 SGLang HiCache 等层次化缓存方案对比，未与其他异步框架（如 Laminar、AsyncFlow）做端到端比较。基线完整性有所欠缺。
4. **任务性能的异步陈旧度代价**：多模态任务中 TideRL 实际运行在一步策略陈旧度状态，作者坦诚这带来了轻微的性能退化。论文未深入分析陈旧度与吞吐之间的最优权衡。
5. **评估任务的同步冲突**：评估任务需要锚定固定模型版本，与异步训练流水线之间存在结构性冲突。目前通过阻塞连续轨迹流的方式解决，作者承认这会暂时干扰异步流水线动量，并给出 Laminar 集成作为未来方向。
6. **硬件与内存约束环境适应性**：HiCache 等层次化缓存能力被排除，部分原因是 CPU 内存被全局轨迹缓冲区和 Trainer 模型挤占。"多版本模型快照 + 大图像文件 + 参考模型"同时驻留宿主机内存的大规模场景可行性未验证。
7. **时间线可信度的观察（非学术性评价）**：论文标注日期为 2026 年 8 月，且引用中混有大量 2026 年文献，在传统学术验证流程下可获得的实际同行评审与长期验证尚不可知。（待确认真实性）

**总体评价**：TideRL 针对多轮智能体 RL 中独特的系统瓶颈提供了架构性的解决方案，就绪信号统一驱动三个层次的调度决策，设计完整且动机充分、实验较为详实，是 agentic RL 系统研究中一个有分量的工作，但实验规模和统计严谨性方面仍有进一步提升空间。
