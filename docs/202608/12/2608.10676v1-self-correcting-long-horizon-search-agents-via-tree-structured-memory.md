## 摘要
基于大型语言模型（LLM）的搜索智能体通过与外部环境的多步交互来回答问题。然而，将完整的执行轨迹提供给LLM会导致上下文无界增长并引入噪声。现有压缩方法以丢失重要细节为代价来减少上下文，且往往替换错误事实而不修复由这些事实衍生出的下游推理。为解决这一问题，我们提出ReTree，一种用于搜索智能体的自我修正树状记忆机制。ReTree构建有界的逐步推理上下文，同时保留源链接证据。它将搜索建模为证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与早期断言相矛盾时，ReTree回溯到引入该断言的节点，替换过期证据，重新生成摘要，剪除受影响的枝节，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并确保最终声明可追溯到检索到的段落。在四个公开的问答和搜索基准上的实验表明，ReTree始终优于全轨迹ReAct，将答案准确率最多提升25.6个百分点（pp）；全轨迹ReAct每步推理上下文的平均最大值是ReTree的1.27—1.51倍。这些结果确立了ReTree作为长程搜索中一种有效的自我修正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

## 1. 核心问题与研究动机

- **背景**：基于大型语言模型的搜索智能体（Search Agents）通过多步迭代检索与外部环境交互来回答复杂、知识密集型问题。然而，在每一步迭代中，策略模型需要重新阅读所有历史观察、中间结论和来源元数据，导致**上下文随搜索深度无界增长**。
- **核心问题**：现有解决方案（如滚动摘要、报告重构、环境端工作记忆等）虽然在压缩上下文，但存在两个严重缺陷：
  1. **细节丢失**：反复合成压缩状态会损失重要的逐事实溯源信息，使得最终答案无法可靠追溯到具体检索段落。
  2. **错误不可修复**：当新检索证据推翻旧结论时，仅替换错误事实本身并不能使**基于旧错误事实推导出的下游结论**失效，从而造成"错误级联"（error cascade）。
- **研究意义**：论文将问题形式化为一个**结构化的状态修复问题**，强调可靠的搜索记忆不仅要"短"（有界上下文），还必须具备**溯源能力**（claim-to-source provenance）和**依赖一致性修订**（dependency-consistent revision）。这是一个对构建可信赖长程搜索智能体具有重要意义的方向。

## 2. 方法论：ReTree

### 2.1 核心思想

ReTree 将搜索过程建模为**证据树（evidence tree）**，树上每个节点保存有界摘要、局部引入的证据及其来源和修订历史。当新证据与旧事实冲突时，系统回溯到引入该冲突事实的节点，替换证据、重新生成该节点摘要、**剪除所有受影响的子树**，并从修复后的节点恢复搜索。这一操作借鉴了真理维护系统（Truth Maintenance System, Doyle, 1979）的**依赖引导修订**思想，将其实现于 LLM 搜索回路中。

### 2.2 关键技术与算法流程

- **证据树节点结构**：每个节点 n 包含四个字段：
  - `sₙ`：紧凑的任务状态摘要（≤140词），记录请求的答案槽位、已解析的中间槽位、剩余空槽位和未解决的候选。
  - `Eₙ`：本地引入的原子证据集合，每条证据是 (id, 事实声明, 来源URL) 三元组。
  - `Hₙ`：该节点的修订历史（记录旧值→新值的变更）。
  - `pₙ`：父节点指针。
- **有界上下文构建**：策略每次看到的上下文是当前节点摘要与通过词法相关性选出的 top-k（k=5）证据的拼接，即 `C_k(M_t, q) = s_nt ∥ TopK(A(nt), q‖s_nt)`。因此**逐步推理上下文为 O(1)**，不随轨迹长度增长。
- **证据扩展与检索**：
  - 环境返回最多 5 个检索段落，提取器产最多 6 个与问题相关的原子事实。
  - **来源绑定**通过在检索结果的整数索引绑定实现，避免让 LLM 复述 URL，防止不可验证的引用。
  - 新证据若与当前路径兼容，则创建新节点，摘要由父状态+新事实压缩而来。
- **冲突触发回溯（Contradiction-Triggered Backtracking）**：
  - **冲突提议阶段**：仅当新事实与已有事实在**同一实体、属性、作用域和时间**下给出不兼容取值时才提议回溯。不同词义、细化、兼容候选等情况只扩展树。
  - **冲突确认阶段**：第二遍 LLM 调用结合分支摘要、目标证据的修改历史与新证据，仅当冲突同作用域且新证据支持更充分时才执行修复，以减少"来回翻烧饼"式的振荡。
  - **修复操作**：定位引入冲突证据的节点，替换该证据文本与来源并记录修订历史，基于修正后的累积证据重新生成摘要，删除所有后代节点，将当前节点设为修复节点恢复搜索。
- **依赖一致性的形式化保证**：设 `Dep_{t-1}(j)` 为所有直接或传递依赖证据 eⱼ 的状态组件集合，一次依赖一致的更新必须满足 `Dep_{t-1}(j) ⊆ I_t ∪ G_t(e′ⱼ)`，即所有依赖组件要么被无效化，要么在修正后重新生成（Eq. 4）。
- **声明级归因**：最终生成器将答案分解为原子声明，每个声明关联证据 ID；通过两级映射（声明→证据对象→原始段落）实现答案可追溯到具体检索段落，并由独立的 NLI 判官验证段落与声明之间的蕴含关系。
- **剪枝策略**：使用祖先是语义依赖的保守代理，**硬剪枝**所有可能依赖被修订证据的后代节点，偏好修复安全性而非状态复用。

### 3.2 对比方法（Baselines）

- **Full-Trajectory ReAct**（主基线）：完整的 ReAct 协议，保留全部观察轨迹，不做压缩。
- **FlatUpdate**（机制匹配消融）：共享 ReTree 的摘要+top-k证据预算与冲突检测，但证据存储为扁平列表，冲突时原地替换事实，**不进行定位、不重建摘要、不剪枝依赖**。用于隔离结构修复的贡献。
- **ReportMemory**（迭代综合代表）：将每次检索折入单一报告摘要并保留无序 URL 集合，丢弃事实级依赖关系。代表 ReSum、IterResearch 一类方法。

### 3.3 评估指标

- **答案质量**：GPT-5 判官准确率（Judge Accuracy）+ 归一化精确匹配（EM）。
- **溯源质量**：基于 NLI 段落蕴含的 CitePrecision / CiteRecall / CiteF1 / Uncited Rate（在 FRAMES 600 题固定子集上）。
- **上下文与计算**：每次运行中观察到的最大逐步策略上下文（字符数）、总模型调用次数、token 用量。

## 6. 主要结论与发现

- **答案质量**：ReTree 在全部 4 个数据集上优于 Full-Trajectory ReAct，准确率提升 **8.3–25.6 pp**（池化后 +13.9 pp 判官准确率、+7.4 pp EM）。相比 FlatUpdate 在每数据集上提升 2.2–4.7 pp；相比 ReportMemory 在 3 个数据集上提升 1.7–7.2 pp，2Wiki 上仅低 0.3 pp。总体第一（44.0%），比最强基线 ReportMemory 高 3.0 pp。
- **上下文有界性**：Full-Trajectory ReAct 的峰值逐步上下文是 ReTree 的 **1.27–1.51 倍**；随检索步数增加前者无界线性增长（FRAMES 上 4 步后可达 5.6K+ 字符），ReTree 保持窄带稳定。
- **归因质量**：ReTree 的 CitePrecision/CiteRecall（44.5/41.3）显著高于 Full-Trajectory ReAct（37.7/27.1）和 ReportMemory（16.8/21.4）。ReportMemory 未引用率最低（5.9%）但引用段落对声明的支撑度最弱，说明高压缩+无序 URL 袋无法保证可靠归因。
- **整体论断**：搜索智能体的工作记忆在压缩上下文之外还必须保留可修订的依赖结构，"记忆不仅是更短的转录，而是用于起源感知修复的可编辑状态表示"。

## 7. 优点

- **问题定义精准**：将长程搜索中的两个危害（上下文增长与错误级联）统一为一个三重需求问题（有界上下文、溯源、依赖一致修订），形式化清晰（Eq. 1–4）。
- **方法设计有理论根基**：借用真理维护系统的依赖导向回溯思想，并用祖先剪枝实现 LLM 环境下的实用落点，与一般候选树的搜索树语义有清晰区分。
- **来源绑定设计巧妙**：通过段落索引而非要求模型复述 URL 来绑定来源，避免不可验证引用的静默失败。
- **实验控制严谨**：FlatUpdate 与 ReTree 的机制匹配度高，能够独离出结构化修复的增量贡献；报告诊断指标（上下文+归因+计算开销）比只报准确率更全面。
- **诚实的局限分析**：对硬剪枝的过度无效化、计算开销、假阴/假阳冲突判断风险等均予以坦诚讨论。

## 8. 不足与局限

- **硬剪枝过度**：祖先作为语义依赖的保守代理会误判独立事实，导致潜在有用状态被删除，产生冗余检索与再生；选择性失效需要显式依赖追踪，论文未实现。
- **上下文压缩不等于总体计算减少**：单步上下文虽在 O(1) 内，但外部存储仍持续增长，线性词法证据选择在极长轨迹上效率下降；结构修复引入额外的 LLM 调用，ReTree 比 FlatUpdate 多 7–11% 调用和 10–13% token。
- **冲突检测器质量是瓶颈**：假阴性保留污染、假阳性过度剪枝；相同作用域规则和历史一致性检查只能降低不能消除错误。
- **实验覆盖不足**：单一模型（Qwen3-8B）、单一 seed、无多轮重复的标准差统计、部分基准仅用子集；缺少对更大模型和更弱模型的泛化证据。
- **难以扩展到通用记忆**：作者明确表示 ReTree 是搜索场景的**工作记忆机制**而非通用长期记忆，硬剪枝语义不适合需要任意历史陈述回忆的任务。
- **实现细节未充分报道**：未见逐步消融（如去掉冲突确认阶段、不同 k 值、不同摘要长度等超参敏感性分析），也未报告墙钟时间。预算内未完整回答问题的失败案例分析缺失。
