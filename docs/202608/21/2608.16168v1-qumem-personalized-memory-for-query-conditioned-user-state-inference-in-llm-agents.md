## 摘要
大语言模型（LLM）智能体越来越多地使用外部记忆系统，通过利用长期且不断演变的交互历史来支持个性化，其中用户偏好可能分布在不同时间、随情境变化，并与早期证据相冲突。然而，现有系统面临三个局限：基于固定轮次、固定token或会话的边界可能会混杂不相关的对话，或将事件与其原因、决策和结果分离；将同一交互中的多条用户信息存储为单条记忆，会绑定功能不同且应可独立检索的条目；而将当前任务视为单个top-k检索查询，可能返回各自相关但无法共同捕捉偏好演变、时间有效性和上下文适用性的片段。我们提出了QUMem，一个用于查询条件化用户状态推断的结构化记忆框架。QUMem首先根据语义连续性将交互历史分割为可变长度的片段，然后将每个片段分解为可独立检索的事实记忆、偏好记忆和可迁移洞察记忆，同时保留时间位置和来源证据。在推理时，三个顺序智能体识别任务特定的信息需求，规划对类型化记忆存储的多查询检索，并联合推断出在时间和上下文上有效的用户状态，用于下游响应生成。QUMem在PersonaMem和KnowU-Bench上均取得了最先进的性能，证明了查询条件化用户状态推断在长期个性化中的有效性。

## Abstract
Large language model (LLM) agents increasingly use external memory systems to support personalization by drawing on long and evolving interaction histories, in which user preferences may be distributed across time, change with context, and conflict with earlier evidence. However, existing systems face three limitations: fixed-turn, fixed-token, or session-based boundaries can mix unrelated dialogue or split an event from its causes, decisions, and outcomes; storing multiple pieces of user information from the same interaction as a single memory binds together items that serve different functions and should be independently retrievable; and treating the current task as a single top-$k$ retrieval query can return fragments that are individually relevant but fail to jointly capture preference evolution, temporal validity, and contextual applicability. We introduce \textsc{QUMem}, a structured memory framework for query-conditioned user-state inference. \textsc{QUMem} first segments interaction histories into variable-length episodes according to semantic continuity, then decomposes each episode into independently retrievable factual, preference, and transferable insight memories while preserving temporal positions and source evidence. At inference time, three sequential agents identify task-specific information needs, plan multi-query retrieval over the typed memory stores, and jointly infer a temporally and contextually valid user state for downstream response generation. \textsc{QUMem} achieves state-of-the-art performance on both PersonaMem and KnowU-Bench, demonstrating the effectiveness of query-conditioned user-state inference for long-term personalization.

## 1. 论文的核心问题与整体含义

LLM 智能体在长期服务中需要记忆与用户的历史交互，以实现个性化。但随着交互历史不断增长，用户偏好可能随时间演变、随情境变化，甚至与早期证据冲突。现有个性化记忆系统存在三个核心局限：

- **固定边界破坏事件上下文**：基于固定轮次、token 数或会话的切分，可能把无关对话混入同一记忆，也可能把同一事件的原因、决策、结果拆散，导致后续检索无法恢复完整事件逻辑。
- **单条记忆耦合多种用户信息**：同一次交互中往往包含功能不同、应可独立复用的信息（例如“偏好简洁实现”与“当前项目需兼容 Python 3.9”），存储为一条记忆会强制绑定检索，阻碍按需取用。
- **单次 top-k 检索不足以推断用户状态**：直接用当前任务查询做相似性检索，可能返回各自相关但无法整体反映偏好演变、时间有效性和上下文适用性的碎片信息，无法支撑对用户“当前状态”的推断。

论文认为长期个性化的核心不仅是“找到相关记忆”，而是要从历史中推断出“与当前查询相关、有历史证据支持、且在时间与上下文上有效的用户状态”。为此提出了 **QUMem** 框架，将记忆构建与推理显式分离，实现查询条件化的用户状态推断。

## 2. 论文提出的方法论

QUMem 包含三个核心模块：

**（1）动态事件构建（Dynamic Episode Construction）**
- 不再使用固定轮次/ token / 会话边界，而是根据**相邻用户话语之间的语义连续性**动态切分历史。
- 使用一个轻量级二分类连续分类器 fθ（由 Qwen3.5-4B 微调得到），判断当前用户话语是否延续前一话语所属事件（ct=1）还是开启新事件（ct=0）。
- 当连续性中断时，结束当前候选片段；否则继续累积。中间助手回复不参与边界判定，但保留在片段中作为交互上下文。
- 这样可保证同一事件的原因、决策、反馈、结果被放在一起解释。

**（2）类型化记忆分解（Typed Memory Decomposition）**
- 每个事件片段 Ek 被同一个 LLM 分解器 gφ 分别以三种类型调用，提取三类原子记忆：

| 类型 | 含义 | 示例 |
|---|---|---|
| 事实记忆 F | 记录具体经历、行为、状态、事件，不推断趋势 | “用户加入了游泳俱乐部” |
| 偏好记忆 P | 记录对特定对象/情境的选择、倾向、要求、约束及直接理由 | “用户偏好有支持性环境的游泳课” |
| 可迁移洞察记忆 I | 从具体选择与反馈中抽象出的、可泛化到新情境的决策原则 | “用户倾向于低压力的锻炼环境” |

- 每条记忆表示为 (v, d, p, E)，其中 v 为内容，d 为类型，p 为该记忆最新来源回合的时间位置，E 为支撑该记忆的交互回合集合，同时用片段编号 k 保留来源链接。
- 记忆按类型存入三个独立存储 M_F、M_P、M_I，实现“片段保留完整事件上下文、原子记忆支持独立检索、类型存储支持动态路由”。

**（3）查询条件化用户状态推断（Query-Conditioned User-State Inference）**
- 由三个顺序职责分离的智能体完成：
  - **信息需求智能体 A1**：给定当前查询 q 和任务上下文，识别需要从历史中验证的信息及其原因，但不指定具体检索语句或存储类型。
  - **检索规划智能体 A2**：将每条信息需求改写为一个或多个自包含查询 eq_j，并为每个查询选择一种或多种记忆类型 D_j，形成检索计划 P_q = {(eq_j, D_j)}。然后按计划检索、合并、去重，得到候选记忆。
  - **用户状态推断智能体 A3**：基于候选记忆，构建结构化的查询条件化用户状态 Z_q = (F_q, T_q, I_q)，其中 F_q 为按时间组织的事实发展，T_q 为偏好演变轨迹及当前生效偏好，I_q 为可迁移原则在当前任务中的应用方式。
- 最终 Z_q 与 q 一起交给下游响应模型 Ψ 生成个性化回复 bŷ_q = Ψ(q, Z_q)。

整体流程将“需要验证什么”“从哪里取证据”“证据共同支持什么状态”三个决策逐步分离，避免单次相似性检索带来的信息碎片化问题。

## 3. 实验设计

**数据集 / 基准**：
- **PersonaMem**：评估长期对话中的动态用户建模，要求系统回忆用户信息、跟踪偏好演变，并在熟悉/新场景下应用推断出的用户状态生成个性化回复。采用**四选一响应选择**任务，评价指标为**准确率**。
- **KnowU-Bench**：评估个性化移动智能体能否从行为历史中推断用户偏好与约束并转化为具体动作。评价指标为**成功率（SR）、平均分、交互效率（IE）**。

**对比方法**：
- **A-MEM**：基于 Zettelkasten 的结构化记忆，支持动态链接与更新。
- **Mem0**：提取用户信息并执行增、改、删、留操作的持久记忆。
- **Zep**：基于时间感知知识图谱管理事实及有效性。

**主要实验设置**：
- 在 PersonaMem 上使用 GPT-4o-mini 和 Gemini-3.5-flash 两种基础模型，并分别评估 32K、128K、1M token 三种上下文长度下的表现。
- KnowU-Bench 使用 GPT-4o-mini 作为基础模型。
- 检索深度 k = 5。

## 6. 论文的主要结论与发现

- 在 PersonaMem 上，QUMem 显著优于所有基线：GPT-4o-mini 下总体准确率从 52.99% 提升到 **61.02%**；Gemini-3.5-flash 下从 63.29% 提升到 **70.58%**，且效应不依赖特定基础模型。
- 最大提升出现在“跟踪完整偏好演变”“偏好一致推荐”“跨场景泛化”等需要跨时间/跨情境联合解释证据的任务；对“识别最新偏好”的提升较小，说明 QUMem 的核心优势不是简单检索最新陈述，而是对分布式证据的综合推断。
- 随着历史长度从 32K 增至 1M，相对基线的优势扩大，表明结构化记忆与推断流水线在长历史中更有价值。
- 在 KnowU-Bench 上，QUMem 在所有指标上均取得最优，整体成功率比最强基线提高 **4.6 个百分点**，说明方法可推广到个性化任务执行场景。
- 消融实验表明三个组件均有贡献，其中**查询条件化的用户状态重建**贡献最大，事件构建与类型化分解也提供稳定增益；它们的作用随历史长度增加而增强。
- 效率上，QUMem 通过本地连续性分类器减少构建触发次数、且每次构建只用 3 次 LLM 调用，显著降低了调用频次和 token 消耗。
- 不足方面：1M 上下文下绝对性能仍下降，“提出新想法”是相对最弱的类别，提示“推断偏好”与“生成新颖且符合偏好的内容”之间仍有差距；KnowU-Bench 上尤其在硬任务中成功率较低，端到端个性化执行仍然困难。

## 7. 优点

- **问题建模清晰**：明确将长期个性化定义为“查询条件化用户状态推断”，而非单纯的检索增强，切中现有系统的核心痛点。
- **记忆结构设计合理**：事件级切分保留上下文，原子级类型化分解支持独立复用，时间戳与来源链接支持有效性验证与溯源，兼顾整体与细粒度。
- **推理流程职责分离**：信息需求识别、检索规划、状态推断三个智能体逐步细化，避免了“用原始查询做一次 top-k”造成的证据碎片化。
- **成本可控**：用轻量分类器替代大模型频繁做边界判断，避免了“构建次数少但 token 开销高”的陷阱，具备实际部署潜力。
- **验证扎实**：覆盖两种基模、三种上下文长度、两个性质不同的基准，消融与超参数敏感性分析完整，结果一致且可解释。

## 8. 不足与局限

- **算力资源未披露**：没有报告 GPU 硬件、训练时长等具体资源信息，难以评估复现成本。
