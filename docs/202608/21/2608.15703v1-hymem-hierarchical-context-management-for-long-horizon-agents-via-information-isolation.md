## 摘要
大型语言模型（LLM）智能体在复杂的、长时程任务上往往表现不佳，因为它们的上下文会随着时间推移而变得越来越杂乱。随着交互的累积，详细的执行轨迹和中间输出主导了上下文，使得模型难以保留和使用高层规划信息。大多数现有方法通过对单一、扁平的上下文应用压缩或检索来解决这一问题，这不能清晰地区分不同类型的上下文信息，并常常导致推理性能下降。为了应对这一挑战，我们提出了HyMem，一个分层框架，明确地将智能体的上下文划分为不同的功能层。HyMem按功能组织上下文，以将高层规划与执行和复杂分析分离。其隔离推理模块处理复杂的子任务，而不会将中间推理痕迹添加到持续规划上下文中，而其记忆管理模块通过结构化摘要保留跨上下文刷新的任务进度。这些组件减少了冗余上下文累积，保留了任务关键信息，并支持在有限上下文窗口内进行连贯的长时程推理。在GAIA和Browsecomp-plus上的实验表明，使用DeepSeek-V4，HyMem实现了平均Pass@1分数66.7%和61.3%，分别比最强基线高出6.1和4.7个百分点。进一步的分析表明，HyMem有效控制了推理上下文的增长，使模型能够在复杂的长时程任务中保持专注和准确性。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

### 2. 方法论

#### 核心思想
- **类型化上下文隔离（Typed Context Isolation）**：按功能将上下文划分为规划、执行、隔离推理和记忆整合四个独立空间，仅有符合模式约束的消息可跨边界传递。
- 设计原则：防止原始执行痕迹和中间推理token直接进入主规划上下文，同时通过结构化记忆保持任务连续性。

#### 关键技术细节

**Planner（规划层）**：维持主决策上下文，包含系统提示、用户查询、三种记忆（episode memory、working memory、tool memory）以及结构化的历史反馈。可发出四种动作：⟨TASK⟩（任务分派）、⟨ISO REASON⟩（隔离推理请求）、⟨FOLD⟩（记忆压缩触发）和⟨ANSWER⟩（最终回答）。

**Executor（执行层）**：针对工具调用指令创建全新上下文，执行有界工具循环，通过相关性条件蒸馏操作ϕ(·)过滤噪声（如导航文本、重复段落、格式伪影），仅保留命名实体、日期、数值、来源、证据片段和候选答案。最终合成结构化返回R(e)t，执行层原始观察被丢弃。

**Isolated Reasoning（隔离推理模块）**：对需要多跳分析、假设验证或冲突证据协调的子任务创建独立上下文空间，继承部分规划状态，可调用执行层获取额外证据，但中间推理痕迹保持私有，只返回结构化结论（含结论、支持事实、来源、置信度κ和假设）。

**Memory Management（记忆管理模块）**：维护三种可重写记忆——episode memory（已完成里程碑、已验证事实、重要决策）、working memory（当前目标、未解决缺口、下一步计划）和tool memory（有效工具模式、失败查询、工具使用注意事项）。通过折叠操作符Φ(·)重写记忆，采用非对称注入策略（planner注入全部三种记忆，隔离推理注入全部三种，执行层仅注入tool memory的紧凑程序摘要）。

#### 上下文边界机制
- 触发器（Trigger）：当规划上下文token利用率>99%、执行器调用≥5次、连续失败≥3次、规划轮次≥8次或工具调用≥10次时触发折叠。
- 信息流边界：原始观察仅进入执行器并在返回后被删除；中间推理token仅进入隔离推理上下文并在返回后被删除。规划器通过有界类型化返回和重写后的记忆增长，而非工具痕迹的完整长度。

- **HyMem在DeepSeek-V4上显著提升性能**：GAIA平均Pass@1达66.7%（超最强基线ReSum 6.1个百分点），Browsecomp-plus平均Pass@1达61.3%（超ReAct 4.7个百分点）。
- **难度越高，增益越明显**：Browsecomp-plus困难任务Pass@1从14.0%提升至30.0%；GAIA Level 3任务增益最大。符合"类型化上下文隔离在需要持续规划、证据积累和多步验证时最有益"的设计动机。
- **上下文隔离而非简单压缩是有效机制**：HyMem-Total上下文继续增长（执行和隔离推理空间进行工具交互），而规划器上下文增长缓慢，"双曲线分离"表明大多数执行细节保留在临时上下文中，规划器保持聚焦。
- **性能提升不依赖更多资源消耗**：HyMem在获得更高性能的同时，token消耗和工具调用次数与基线相当或更优。
- **两个核心模块缺一不可**：消融显示移除任一模块均导致性能显著下降（隔离推理：-5.0至-18.6个百分点；记忆管理：-9.0至-18.6个百分点），说明类型隔离和连续性保持需协同工作。
- **方法论的核心贡献**：HyMem的机制不是简单地在轨迹变长后进行摘要，而是在整个执行过程中限制哪些信息可以进入决策上下文。

### 7. 优点

- **问题诊断精准**：将"上下文稀释"形式化为信息密度失配问题，提供了清晰的理论框架和实证测量（图1展示了任务关键信息密度下降现象）。
- **方法设计优雅**：提出"类型化上下文隔离"原则，相比简单压缩/检索更从根本上解决信息混合问题。类似操作系统中的权限隔离思想，确保噪声信息无法进入决策空间。
- **训练无关、即插即用**：作为推理时控制器，无需额外训练即可应用于任何冻结的基础LLM，工程实用性高。
- **非对称记忆注入设计**：不同类型上下文接收不同粒度的记忆（planner获得完整结构化记忆，executor仅获得工具摘要），精确匹配信息需求。
- **结构化信息接口**：通过模式约束的返回格式（如RESULTS、RETURN标签）确保信息跨边界传递时的质量和可解析性。
- **实验分析维度全面**：不仅报告最终性能，还从token/工具效率、上下文增长轨迹、消融影响、难度分级表现等多角度验证机制有效性。
- **无偏的资源对比**：明确论证性能提升不是靠消耗更多资源换取的，增强了结论可信度。

### 8. 不足与局限

- **主干模型依赖性**：HyMem依赖模型遵循类型化控制指令并产生可靠结构化返回的能力。Qwen3-32B在Browsecomp-plus上未见提升，说明收益在不同主干间不均匀，泛化性存疑。
- **实验规模有限**：Browsecomp-plus仅采样150题（各难度50题），样本量较小；GAIA仅文本任务，未验证多媒体场景。
- **性能-资源权衡的内在张力**：HyMem引入额外的摘要和信息蒸馏开销（辅助LLM调用），虽然总token消耗与基线相当，但多次蒸馏步骤本身引入潜在信息损失和延迟增加。
- **记忆折叠机制的潜在缺陷**：结构化摘要可能丢失关键细节，且折叠是离散事件，在两次折叠之间规划器仍可能累积噪声。
- **未与其他长上下文方法充分对比**：包括long-context RAGs（如Leng et al. 2024）、AgentFold、MEM1等方法在相关工作中提及但未纳入实验对比。
- **缺少对失败案例的分析**：未详细讨论HyMem无法解决的问题类型，也未分析其在不同规划器自动路由决策（如何时选TASK vs ISO REASON）方面的可靠性。
- **公布的日期与模型状态可能存在潜在信息偏差风险**：论文使用"DeepSeek-V4"和"Qwen3-32B"等模型，但正文中引用DeepSeek-V3.2的相关文献，版本对应关系需进一步确认。
- **辅助LLM一致性**：所有框架的辅助摘要和记忆任务均使用DeepSeek-V4，对Qwen3-32B背骨框架而言可能存在不公平分配（辅助能力过强/不匹配）。
