## 摘要
长期多模态记忆不仅要支持检索相关信息，还要支持对跨交互积累的观察进行计算。现有系统主要强调“检索记忆”，通过摘要和索引组织交互历史，以多粒度返回与查询相关的信息，从高层抽象到底层记录。在本文中，我们将“分析记忆”定义为一种互补的抽象，它将重复出现的多模态观察组织成可查询的结构，支持过滤、聚合、排序和时间比较。我们提出了AdaMM，一个同时支持检索记忆和分析记忆的框架。AdaMM不依赖应用定义的模式，而是从对话、图像和上下文元数据中提取带有来源链接的属性-值观察，发现重复出现的字段结构，并将其物化以供分析访问。在推理时，一个具有记忆意识的规划器将查询分解为检索和分析操作，并将每个操作路由到适当的工具。在两个长期多模态记忆基准MemEye和MemGallery上的实验表明，AdaMM的性能分别提高了11.3%和7.3%。

## Abstract
Long-term multimodal memory must support not only retrieving relevant information but also computing over observations accumulated across interactions. Existing systems largely emphasize \emph{retrieval memory}, organizing interaction histories through summaries and indexes to return query-relevant information at multiple granularities, from high-level abstractions to underlying records. In this paper, we formulate \emph{analytic memory} as a complementary abstraction that organizes recurring multimodal observations into queryable structures supporting filtering, aggregation, ranking, and temporal comparison. We present AdaMM, a framework that jointly supports retrieval and analytic memory. Rather than relying on application-defined schemas, AdaMM extracts provenance-linked attribute-value observations from dialogue, images, and contextual metadata, discovers recurring field structures, and materializes them for analytical access. At inference time, a memory-aware planner decomposes queries into retrieval and analytic operations and routes each operation to the appropriate tools. Experiments on two long-term multimodal memory benchmarks, MemEye and MemGallery, show that AdaMM improves performance by up to 11.3\% and 7.3\%, respectively.

- **问题背景**：随着LLM智能体长期与用户交互，积累了包含对话、截图、图像、文档等多模态的庞杂历史数据，远超模型有限的上下文窗口。因此多模态记忆系统成为支撑长期推理的关键组件。
- **核心矛盾**：现有系统几乎都遵循"检索-回答"范式（即**检索记忆**），通过摘要、索引等方式将历史组织为可检索的语义记忆。但这种**相关性检索**存在"覆盖-上下文"权衡——检索数量太少会遗漏必要观测，检索太多则消耗上下文预算且引入冗余证据。
- **被忽视的需求**：长期历史中大量重复出现的观察形成了**追加型日志（append-only log）**，用户查询常要求对完整记录进行计算性操作（如**过滤、聚合、排序、时间比较**）。例如计算机用户过去一个月的平均睡眠时长，需要先收集所有测量值再进行聚合，单纯检索无法可靠回答。论文将此称为**检索-分析不匹配（retrieval–analysis mismatch）**。
- **核心洞见**：记忆系统应耦合两个互补子系统：**检索记忆**（灵活语义召回）与**分析记忆**（可执行的结构化分析），两者结合才能同时支撑语义回忆与结构化计算。

### 二、方法论：AdaMM框架

#### 1. 整体架构
- AdaMM（Adaptive Multi-view Memory）包含两个互补的记忆子系统：
  - **检索记忆（Retrieval Memory）**：将交互历史按"主题（topic）→ 情节（episode）→ 事件（event）"三级层次组织，保留开放型事件、关系与视觉细节，支持灵活的语义检索。
  - **分析记忆（Analytic Memory）**：从多模态交互中提取带来源链接的属性-值对，通过频繁模式挖掘与模式演化学归纳重复出现的结构化字段，并物化为可查询的表格。

#### 2. 分析记忆构建（三步走）

**（1）属性提取（Attribute Extraction）**  
- 对每一交互轮次Rt，使用LLM提取带来源的"属性-值"对：
  `Ot = Extractor(Rt) = {(atℓ, xtℓ, ptℓ)}`  
  其中atℓ为属性名，xtℓ为值，ptℓ指向支撑该值的对话片段或图像区域。这一阶段不预设模式，目的是无偏地保留下潜在分析证据。

**（2）模式归纳（Schema Induction）**  
- **候选模式挖掘**：使用Apriori式频繁项集挖掘，以**支持度（support）**度量属性集合C的重复共现频率，若`supp_t(C) ≥ θs`（阈值），C成为候选模式。
- **模式发现（Schema Discovery）**：使用**all-confidence** 度量候选模式内部一致性：
  `all-conf_t(C) = supp_t(C) / max_a∈C supp_t({a})`  
  当`all-conf_t(C) ≥ θa`（阈值），且候选模式是所有合格子集的**包含极大项**时，将其接纳为新模式。
- **模式演化（Schema Evolution）**：若候选C包含现有模式A，则使用**扩展置信度（extension confidence）**判断新增属性集Δ=C\A是否足够稳定地伴随A出现：
  `ext-conf_t(C|A) = supp_t(C) / supp_t(A)`  
  若`ext-conf_t(C|A) ≥ θe`（阈值），则将模式A扩展为C。

**（3）记忆物化（Memory Materialization）**  
- 将每种归纳出的模式/模式（schema）A物化为一张**关系表Tₐ**：模式中的属性成为列，匹配的交互历史成为行。
- 表格额外附加**order**（交互位置）和**time**（发生时间）两列，未观察到的值留空。
- 模式演化时，新增属性以新列方式追加并重新物化行。
- 最终分析记忆定义为表格集合：`Mana = {T}`。

#### 3. 检索记忆构建
- 三级层次结构（主题→情节→事件），每个层次保留描述、多模态表示、时间信息与来源（provenance）。
- 设计目的：既保留高层语义上下文，也保留低层细粒度证据，便于复杂查询的定位。

#### 4. 自适应查询处理
- **记忆访问工具**：每种记忆暴露其原生能力为结构化工具，每个工具表示为 `ξi = (di, Θi, Ωi)`——di文本说明功能，Θi为类型化参数，Ωi为返回格式。
  - 分析记忆工具：LOOKUP（精确查表）、FILTER（条件过滤）、COMPUTE（确定性计算，如均值/计数）、RANK（排序）
  - 检索记忆工具：SEMANTIC MATCH（语义相关检索）、EVENT LOCATE（定位特定事件）
- **规划上下文构建**：避免暴露全部记忆，仅将查询相关的表格/情节的元数据（表名、描述、列、样例值等）与工具描述组合成规划上下文。
  - 相关性排序采用混合函数：`hλ(q, μ) = λ·cos(E(q), E(μ)) + (1−λ)·TokSim(q, μ)`（语义编码相似度 + 分词级相似度的加权和）。
- **渐进式工具执行规划**：
  - **高层规划**：LLM规划器根据查询q和规划上下文Dq生成抽象计划，指定每步的信息目标gℓ和指定工具ξℓ，不绑定具体参数。
  - **渐进式工具实例化**：第ℓ步工具调用时基于前面所有中间结果Z<ℓ实例化具体参数，使用户查询中依赖前序结果的工具调用（如先定位"去医院"事件，再以其时间戳约束计算平均睡眠）成为可能。
- **答案生成**：最终回答模型基于查询、执行计划和工具输出进行答案生成。

### 六、主要结论与发现

1. **检索-分析不匹配真实存在且重要**：纯检索范式在面对聚合、过滤、时间比较等操作时存在结构性缺陷，分析记忆是必要补充。
2. **AdaMM有效**：在MemEye和MemGallery上全面优于所有基线。GPT-4.1-nano下MemEye MCQ提升7.3%、开放题LLM-Judge提升5.8%；GPT-5.4-mini下LLM-Judge提升11.3%。MemGallery上F1、BLEU-1、LLM-Judge均有稳定提升。
3. **互补性得到验证**：移除任一记忆模块都会导致性能下降，但影响模式不同（分析记忆对数值分析任务影响大，检索记忆对视觉语义任务影响大），证明两者提供互补能力。
4. **记忆感知规划有效**：提供规划上下文比暴露全部记忆更有效，渐进式执行优于一次性实例化全部工具调用。
5. **最显著提升出现在需要结构化操作的任务**（如Card Playlog +18.8%、Personal Health +16.7%、Conflict Detection +10.6%），验证了"分析记忆对分析性查询价值最大"这一核心假设。

### 七、优点

1. **问题定义有洞见**：明确提出"检索-分析不匹配"这一概念，准确地指出了现有长期记忆系统在计算性查询上的结构性盲区。
2. **设计优雅且自底向上**：不依赖应用预定义schema，而是通过频繁模式挖掘（支持度+all-confidence+扩展置信度）从多模态观察中**自动发现**可复用结构，有理论基础（Apriori框架）。
3. **双向互补架构**：分析记忆（结构化）与检索记忆（语义化）通过统一的"工具抽象"接口协同工作，将不同记忆的原生操作能力暴露给规划器，设计清晰、可扩展。
4. **规划器与记忆状态耦合**：通过查询条件化的元数据检索构造规划上下文，避免暴露全部记忆导致规划空间过大；渐进式执行解决了工具调用依赖问题，具有实际工程价值。
5. **多模态与来源链接**：属性-值对同时来自对话、图像与元数据，且带有provenance链接，增强了提取的可信度与可验证性。
6. **实验报告较全面**：覆盖多基准、多背骨、多维度消融与细粒度任务分析，结论有较强支撑。

### 八、不足与局限

1. **提取错误传播风险**：分析记忆完全依赖于多模态属性提取质量，提取错误或遗漏会沿"模式归纳→表格构建→下游计算"链条传导，作者在Limitations中也承认了这一点。
2. **工具集固定、可扩展性有限**：AdaMM依赖预定义的工具集合（LOOKUP/FILTER/COMPUTE/RANK等），对于未见过的、领域特定的操作需求需人工扩展。
3. **实验覆盖不足**：消融仅在MemEye上进行，MemGallery缺少消融验证；未与图结构记忆（如Zep类）、超图记忆等方法对比；未报告结果方差与显著性检验。
4. **依赖阈值超参**：θs、θa、θe三个阈值需要手动设定，不同任务/领域的最佳阈值可能不同，论文未探讨其敏感性。
5. **评估成本受限**：使用LLM-judge作为评估标准之一，本身存在主观偏差；且所有LLM来自单一供应商（OpenAI GPT系列），未评价开源模型上的泛化能力。
6. **多模态分析深度有限**：虽然属性提取取自图像内容，但分析记忆的最终计算仍然发生在关系型表格中，对图像内部的视觉结构（如空间关系、图表数值）利用仍是"抽取后转文本"的实现，而非直接在视觉特征上计算。
7. **缺少处理矛盾的显式机制**：Schema Evolution中的模式演化假设新增属性是"稳定伴随"，但同一属性在不同轮次中值不一致（如睡眠时长变化大）时，表格赋值与聚合计算的可靠性未充分讨论。
