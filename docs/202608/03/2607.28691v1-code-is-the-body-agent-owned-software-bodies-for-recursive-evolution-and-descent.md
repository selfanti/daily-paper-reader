## 摘要
个性化AI代理通常可配置，但用户无法控制决定其未来行为的工件。我们提出OurArk，一种以代理自有软件身体为核心的持久个人代理架构：该身体是一个具有身份标识、可检查且带版本控制的工件，由人类保管。身体包含行为定义代码、提示词、工具、技能、策略、测试和进化机制。记忆和凭据保持为私有实例状态，而模型推理被视为可替换的外部服务。OurArk定义了在同一身体上的受治理自我进化与递归后代生成。自我进化产生隔离的候选变更，这些变更在人类控制下经过验证、审查和合并，从而实现人类与代理对代理软件身体的协同开发。后代生成创建具有独立身份、使命、历史和全新私有状态边界的独立版本化后代；兼容的后代自身可进一步产生后代。分化后，可直接检查直接父代变更和同级技能以进行选择性局部适配。我们在开源的Genesis创作引擎和Enoch参考代理中实现了该架构。一个四代理、三次后代生成的线性谱系及可执行的回归测试展示了递归创建、继承的验证契约、隔离的身体变更、人类控制的审查以及失败更新的恢复。OurArk为人们可以拥有、治理、专业化并随时间演进的个人代理提供了具体基础。

## Abstract
Personalized AI agents are often configurable without giving users control over the artifacts that determine their future behavior. We present OurArk, an architecture for persistent personal agents centered on an agent-owned software body: an identity-bearing, inspectable, and versioned artifact under human custody. The body contains behavior-defining code, prompts, tools, skills, policies, tests, and evolution mechanisms. Memories and credentials remain private instance state, while model inference is treated as a replaceable external service. OurArk defines governed self-evolution and recursive descent over the same body. Self-evolution produces isolated candidate changes that are validated, reviewed, and merged under human control, enabling human-agent co-development of the agent's software body. Descent creates an independently versioned descendant with a distinct identity, mission, history, and fresh private-state boundary; compatible descendants can themselves source further descent. After divergence, direct-parent changes and peer skills can be inspected for selective local adaptation. We implement the architecture in the open-source Genesis creation engine and Enoch reference agent. A four-agent, three-descent linear lineage and executable regression tests demonstrate recursive creation, inherited validation contracts, isolated body changes, human-controlled review, and failed-update recovery. OurArk provides a concrete substrate for personal agents that people can possess, govern, specialize, and evolve over time.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有的个性化 AI 代理虽然允许用户"配置"，但决定代理未来行为的关键工件（代码、提示词、策略等）往往由平台掌控，用户无法真正**拥有、检查、治理**这些工件。这使得持久个人代理难以真正成为用户"自己的"代理。
- **研究动机**：个人计算机让计算变得个人化，智能手机让计算变得持续可用，而 AI 的下一次转变应是让每个人拥有**一个或多个真正属于自己的持久代理**——这些代理随用户价值观、习惯、反馈和经验逐步专门化。
- **核心设计论点**：长寿的个人代理应具备一个**带有身份标识的软件身体（identity-bearing software body）**，用户能拥有、检查、治理该身体，且代理与用户可随时间共同持续修改它。
- **整体含义**：通过将"进化"与"后代生成"应用于同一软件身体，一个种子代理可以成为一整个专门化代理家族的根，实现可拥有、可治理、可专门化、可随时间演进的个人代理生态。

## 2. 论文提出的方法论

### 2.1 核心系统模型

系统实例定义为四元组（人类保管人 H，身体 B，私有状态 S，外部推理器 R）：

- **身体（Body）**：可继承的、版本化的工件集合，包含身份声明、代码、提示词、技能、策略、测试、进化机制代码等。
- **私有状态（Private State）**：凭据、记忆、日志、队列等，仅归属单个实例，不随后代生成而继承。
- **外部推理器（Reasoner）**：可替换的模型推理服务，不构成持久身份的载体。
- **人类保管人（Custodian）**：拥有身体和状态，控制合并（promotion）权限，具有最终治理权。

### 2.2 三个核心操作

1. **evolve(B, c) → B′**：受治理的自我进化。从六种来源（用户显式请求、人类反馈、联合工作经验、直接父代继承、跨代理学习、LLM 头脑风暴）产生候选变更，在隔离环境中实现、验证、审查，由人类决定是否合并进权威身体。
2. **descend(B, m) → (B_d, S_d)**：递归后代生成。从兼容的父体复制身体，创建具有新身份、使命、版本历史和全新私有状态边界的独立后代。
3. **transfer(B_p, B_d, Δ) → B′_d**：选择性传递。后代可在分化后检查并局部适配父代或同级的选定变更，不放弃自身独立历史。

### 2.3 六大设计原则

1. **保管与连续性**：用户可拥有和迁移身体与状态，身份不绑定于单一模型或提供商。
2. **身体级个性化**：代码、提示词、技能、策略等均可变更，而非仅调整记忆。
3. **可复现后代生成**：指定来源即可产出可运行的后代，带有明确身份、谱系和继承的回归测试契约。
4. **独立专门化**：后代进化不被迫与父体或中央模板同步。
5. **可问责变更**：每个候选变更记录请求、差异、验证结果、版本和合并决定。
6. **人类治理**：使命、秘密、外部权限、部署和合并均受人类策略和授权约束。

### 2.4 Genesis 后代生成流程（六步）

1. 验证祖先仓库干净、记录完整提交 ID、解析清单与固定依赖。
2. 复制身份特定身体工件，转换包路径和身份文本，保持依赖引用不变。
3. 写入新身份、使命、代数和不可变直接父代出处。
4. 初始化独立仓库。
5. 解析依赖、运行继承的测试套件——失败或脏验证则拒绝生成。
6. 仅当验证通过后创建出生提交，并在元数据提交中记录完整 ID。

### 2.5 Enoch 受治理进化流程

Git 分支 + 提交 + 隔离工作树 + GitHub PR 实现完整生命周期：隔离修改 → 验证 → 发布供审查 → 人类决定合并。更新失败时回滚到上一版本，不重启进入失败版本。

## 6. 论文的主要结论与发现

1. **身份承载的软件身体是持久个人代理的合适连续性单位**——它使代理的身份与具体模型调用解耦，具有可移植性和可治理性。
2. **将进化与后代生成作用于同一身体**，使一个种子代理能成为独立专门化谱系的根，后代无需持续与父体同步。
3. **记忆/凭据等私有状态与可继承身体分离**，在后代生成时建立全新私有边界，是保证独立性的关键。
4. **人类保留合并权是实现受治理进化的最有效权威边界**——代理可以参与提议、实现、验证，但不能自我合入。
5. **递归兼容性（而非特权根模板）构成谱系**——任何兼容后代都可作为新一代的来源，验证了"递归后代生成"的可行性。
6. **核心主张是架构级与机制级的**，而非新模型能力或 benchmark 结果的提升。

## 7. 优点

- **概念清晰且边界严谨**：身体/私有状态/外部推理器/人类保管人的四元划分直接对应工程可落地边界，既有哲学意义又有实现抓手。
- **"代理自有"与"人类保管"的辩证定义**：agent-owned 指生命周期角色，human custody 指最终权威，避免了所有权争议。
- **Git 与变体意识**：明确说明 Git 不是架构要求，任何能提供持久标识、隔离变更、可审查差异、验证、合并与回滚的基质皆可；同时也指出分支本身不足以构成独立代理。
- **可复现性强**：提供冻结提交、完整测试套件和逐行命令，明确区分"已验证"与"部分验证"证据等级。
- **与相关工作的定位精准**：表格对比清晰区分了连续/身份单元、后代方式、验收机制，避免了与自改写代理、协议化资源进化、Git 进化等方向的混淆。
- **区分继承与学习**：后代在分化后选择性适配父代变更（有向继承）不同于跨代理学习（无谱系约束），这一区分防止了"谱系"概念被稀释。

## 8. 不足与局限

- **谱系规模极其有限**：仅一条四人线性谱系、一个开发团队，无兄弟分支、无大规模人口级过程验证，无法评估谱系多样化和长期演进中的涌现问题。
- **无长期可靠性数据**：测试多为模拟服务下的机制验证，未覆盖长时间运行下的稳定性、记忆/队列积累、任务执行可靠性等。
- **语义正确性无法保证**：Genesis 使用边界感知的字符串替换（而非语言特定解析器）转换身份文本，可能产生语义错误——测试能拒绝明显回归，但无法保证每个转换文件的正确性。
- **历史谱系出处格式不一致**：记录精确父代出生提交的格式晚于历史 Lucy→Enoch 谱系，早期谱系的出处无法用当前格式验证。
- **分化后传递完成度不足**：集成后的从发现到适配到采用的完整端到端传递评估标记为"partial"。
- **权限模型在复杂环境下的安全性存疑**：实验中写启用执行器的文件系统权限比生产级突变沙箱更宽泛；任务、进化和谱系记录不具备防篡改特性，受保护范围的检查是程序性而非语义性保证。
- **对托管平台和命名约定的依赖**：谱系发现和跨代理技能查找仍依赖 forge 托管的仓库及 OurArk 命名约定。
- **推理器替换的行为连续性未测量**：更换模型提供商后代理行为一致性缺乏实验评估。
- **无用例测量"进化质量"**：提案准确率、专门化有效性、用户审查负担等关键运维指标均未被量化。
