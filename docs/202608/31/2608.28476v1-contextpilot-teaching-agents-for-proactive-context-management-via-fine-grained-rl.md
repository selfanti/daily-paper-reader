## 摘要
长程智能体任务要求大型语言模型（LLMs）在多轮交互中迭代地检索、整合和维护分散的信息，但保留所有交互历史会导致工作上下文持续增长。近期主动上下文管理方法允许模型利用专门工具编辑自身的工作上下文，但仍面临三个关键局限：（1）工具集有限，仅限于搜索、删除和摘要，不支持全局规划、长期记忆和自适应压缩；（2）探索效率低下，将上下文管理动作视为同质处理，忽略了它们对最终结果的不同影响；（3）粗粒度的信用分配，在强化学习中将最终的轨迹级奖励分配给所有中间上下文编辑动作。为弥补这些不足，我们提出ContextPilot，一种面向长程智能体推理的主动上下文管理框架。我们的方法系统性地扩展了工具集，新增规划、长期记忆和软上下文卸载工具。我们进一步提出一种针对上下文管理定制的强化学习方法，利用上下文和熵变化来识别关键编辑决策以进行分支采样，并从所有通过相应上下文编辑动作的分支轨迹中估计动作级优势。在长上下文问答和深度搜索任务上的实验表明，ContextPilot以更紧凑的工作上下文取得更强的性能，在各种基础模型和基准上持续优于现有基线。代码可在https://github.com/Tencent/ContextPilot获取。

## Abstract
Long-horizon agentic tasks require large language models (LLMs) to iteratively retrieve, integrate, and maintain dispersed information across multi-turn interactions, but preserving all interaction histories leads to a continuously growing working context. Recent proactive context management methods allow models to edit their own working context with specialized tools, yet they still face three key limitations: (1) a limited toolset restricted to search, deletion, and summarization, with no support for global planning, long-term memory, and adaptive compression; (2) inefficient exploration that treats context management actions uniformly despite their heterogeneous impacts on final outcomes; and (3) coarse-grained credit assignment that assigns the final trajectory-level reward to all intermediate context editing actions during RL. To bridge these gaps, we introduce ContextPilot, a proactive context management framework for long-horizon agentic reasoning. Our approach systematically augments the toolset with planning, long-term memory, and soft context offloading tools. We further propose an RL method tailored for context management, which uses context and entropy variation to identify critical editing decisions for branch sampling and estimates action-level advantages from all branched trajectories that pass through the corresponding context editing action. Experiments on long-context QA and deep search tasks show that ContextPilot achieves stronger performance with a more compact working context, consistently outperforming existing baselines across various base models and benchmarks. Code is available at https://github.com/Tencent/ContextPilot.

## 1. 核心问题与研究背景

**核心问题**：在长程智能体任务中，LLM 需要多轮迭代地检索、整合和维护大量分散信息。若将所有交互历史（推理、工具调用、环境反馈）全部保留在上下文中，工作上下文会持续增长，导致推理成本增加、注意力分散、甚至超越上下文窗口而失败。

**现有解决方案的不足**：此前已有“主动上下文管理”（如 StateLM、Sculptor、MemAct 等）方法，让模型通过工具自行编辑工作上下文。但作者指出这类方法仍存在三大瓶颈：
1. **工具集过于有限**：仅支持搜索、删除、摘要，缺乏全局规划、长期记忆与自适应压缩能力；
2. **探索效率低**：把不同上下文管理动作视为同质操作，未考虑其对最终结果的异质性影响，统一分配预算导致关键动作探索不足；
3. **信用分配粗糙**：RL 训练时将最终轨迹级稀疏奖励直接复制给所有中间上下文编辑动作，忽略了每个编辑动作的实际贡献差异。

**研究意义**：作者提出 ContextPilot 框架，通过系统化扩展工具集并设计针对上下文管理场景定制化的 RL 训练算法（部分展开 + 细粒度信用分配），让模型真正成为自身工作上下文的主动管理者，在保持更紧凑上下文的同时取得更好的任务性能。该研究对推进长程 agentic 推理与智能记忆架构设计具有直接价值。

## 2. 方法论

### 2.1 工具集扩展（Tool Design）

论文将工具集分为五类，紫色标注为新增工具：

| 类别 | 工具（新增/原有） | 功能 |
|------|-------------------|------|
| 感知与规划 | analyzeText（原）、checkBudget（原）、**plan（新）** | 计算上下文长度、检查剩余预算、生成简洁执行计划 |
| 信息检索 | buildIndex、searchContext、readChunk、readMultiChunks | 建立索引、搜索、读取上下文块 |
| 短期记忆 | note、updateNote、readNote | 记笔记、更新/读取笔记 |
| 长期记忆 | **memorize（新）**、**updateMemory（新）**、**readMemory（新）** | 提取结构化实体/时间戳/事件片段信息，建立跨块关联，支持邻居检索 |
| 上下文卸载（软删除） | deleteContext（原）、summarizeContext（原）、**compressContext（新，基于LLMLingua-2）**、**foldHistory（新）** | 占位符删除、摘要、自动压缩、将历史折叠为带搜索索引的关键词与摘要 |

### 2.2 SFT 数据合成

- 教师模型为 Qwen3.5-397B-A17B，通过一个“上下文管理 harness”提供分步提示与约束（如必须先 search 再 readChunk、上下文超阈值时强制清理等），这些提示仅用于生成阶段，最终从轨迹中剔除。
- 经过三阶段过滤：**结果过滤**（精确匹配，允许两次重试）→ **过程过滤**（GPT-OSS-120B 判断上下文管理行为是否合理）→ **峰值长度过滤**（轨迹峰值不超过 32K token），最终保留 3,068 条合格轨迹，切分为 51,469 个轨迹快照。

### 2.3 RL 训练算法（核心贡献）

**（1）上下文感知部分展开（Context-Aware Partial Rollout）**

针对每个上下文管理动作 acm_t，计算两个指标：
- 上下文变化：ΔC = (len(c_{t+1}) − len(c_t)) / len(c_t)
- 熵变化：ΔH = H_cm_t − H_initial（当前动作后生成 token 的平均熵与轨迹初始熵之差）

敏感度得分：**S(acm_t) = α·ΔC + β·ΔH**（实验中 α=1，β=1）

流程：每个查询先做 8 条轨迹级 rollout，切分出最多 M=64 个快照；若未达到每查询 128 个快照的预算，则按敏感度排序选取关键动作作为分支点补充采样，将探索预算更多分配给影响更大的编辑决策。

**（2）细粒度信用分配（Fine-Grained Credit Assignment）**

- 终态快照奖励：R(SM) = Rout（最终答案匹配）+ Rfmt（输出可解析）+ Rpen（非法工具调用/超长惩罚）
- 中间快照奖励：R(Si) = 对所有以 Si 为前缀的终态轨迹 T(Si) 的奖励取平均（而非只使用包含 Si 的单个终态轨迹）
- 在每个查询分组内对快照奖励做标准化得到优势值，最后用 **GRPO 目标**优化模型，将信用分配粒度从“轨迹级”下降到“快照/动作级”。

**理论依据（附录 A）**：该方法被证明是条件延续值 Q(S)=E[R(T)|S⪯T] 的无偏估计，且当同一快照有多个后续分支（nS>1）时，方差从 σ²(S) 降至 σ²(S)/nS，即严格小于轨迹级信用分配，从而提供更稳定的优势信号。

## 7. 优点与创新点

1. **问题定位准确、动机清晰**：将“主动上下文管理”从“简单工具调用”提升为“需要规划与分配的序列决策问题”，切中长程 agentic 任务的实际痛点。
2. **工具设计系统性较强**：五类工具覆盖感知、检索、短期记忆、长期记忆与卸载，形成了较完整的上下文管理操作原语，尤其是 `memorize/updateMemory/readMemory` 三件套实现了跨块长期记忆，超出此前方法仅做局部摘要的能力。
3. **RL 训练算法有实质贡献**：
   - 部分展开策略利用敏感度指标（上下文长度变化 + 熵变化）引导探索预算分配，缓解了所有动作同质化探索的问题；
   - 细粒度信用分配以前缀平均奖励取代轨迹级奖励，并提供方差缩减的理论证明，使 RL 信号更稳定。
4. **模型通用性好**：在 Qwen3、Gemma4、WebSailor、WebExplorer 等多个开源模型上都验证了有效性，说明方法不依赖特定基座。
5. **评测透明度高**：提供了详细的超参数、工具调用频率分析、token 消耗对比、失败率分析以及多次运行均值/标准差。

## 8. 局限性

1. **算力与超参数调优受限**：作者在附录中承认未对训练超参数进行广泛搜索，敏感度权重固定为 α=β=1，缺乏对 α/β 取值的敏感性分析。
2. **教师模型依赖较大**：SFT 数据依赖 Qwen3.5-397B-A17B 合成，过滤与评测依赖 GPT-OSS-120B，整体流程对闭源/超大模型的依赖较高，可能影响方法在资源受限场景下的可复现性。
3. **部分展开预算未充分验证**：每查询 128 快照、每条轨迹最多 8 快照等超参缺少消融，无法确认其最优性或泛化性。
4. **基准覆盖仍有空白**：未在工具调用型 agent 基准（如 AgentBench、WebArena）上测试，评测集中于 QA 与搜索类任务；同时缺乏对超长记忆保持（如跨会话记忆）的评估。
5. **未与最大规模模型对比**：ContextPilot 最高仅训练到 14B，未验证方法在更大模型（如 70B 以上）上的可扩展性。
6. **长上下文 QA 部分与 StateLM 共享数据管线**，可能在一定程度上削弱了对比的独立性与公平性说服力。

**需谨慎看待之处**：32K 上下文窗口击败 128K 无工具模型的结论虽然在任务准确性上成立，但这本质上是“用管理的紧凑性换取更有效的注意力分配”，其适用范围（如小型模型、长文档场景）仍需进一步界定。另外，论文对 token 成本的计量主要聚焦输入侧，忽略了规划与记忆读写本身的额外输出开销。

**总体打分**：方法创新性 4.5/5，实验充分性 4/5，写作清晰度 4.5/5，可复现性 3.5/5。
