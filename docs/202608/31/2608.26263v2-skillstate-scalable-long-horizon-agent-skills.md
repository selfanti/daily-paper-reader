## 摘要
大型语言模型（LLMs）日益作为自主智能体执行复杂、长期运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理轨迹追加到不断增长的对话历史中来维持执行，这会导致长时程任务中的延迟退化和上下文污染失败。我们提出了SKILL.state，一种运行时架构，用显式的、可变的执行状态取代了仅追加的对话历史。在每个执行步骤中，模型仅接收不可变的技能规范、当前的结构化执行状态和最新的观察结果。中间推理在产生经过验证的状态更新后立即被丢弃，从而防止提示因执行历史而增长。在多样化的数据集、模型和执行环境中，SKILL.state提高了任务准确性，同时大幅减少了累计token消耗。我们的结果表明，显式执行状态是用于可扩展长时程智能体技能的有效且与架构无关的抽象。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL. state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大型语言模型（LLMs）正从被动语言接口演变为可自主执行复杂任务的智能体，能够进行迭代推理、工具调用和外部环境交互，并将这些能力封装为可复用的程序性技能（procedural skills）。
- **核心问题**：现有智能体运行时几乎普遍采用"对话式执行模型"——在每个执行步骤中，模型接收原始技能规范加上不断增长的推理、动作、观察和工具输出记录。这种**仅追加（append-only）的对话历史**机制带来了三个根本性问题：
  1. **提示词大小随执行长度线性增长**，导致token消耗和推理成本持续上升；
  2. **历史观察和过时推理长期驻留上下文**，产生"上下文污染"（context poisoning），模型需不断区分当前事实与历史伪影；
  3. **执行正确性日益依赖于从累积的文本历史中重构状态**，而非直接维护当前世界状态。
- **整体含义**：论文主张将长时程程序性技能的执行从"推理问题"重新定义为"系统问题"，并提出用**显式、可变的结构化执行状态**取代对话历史，从而实现对长时程任务的可持续扩展。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

SKILL.state 将程序性技能执行重塑为**显式状态转换过程**，而非对话历史的累积。在每个执行步骤 t，模型仅接收三部分输入：

```
A_t = (P, Σ_t, O_t)
```

其中：
- **P**：不可变的程序性技能规范；
- **Σ_t**：步骤 t 的结构化执行状态；
- **O_t**：环境返回的最新观察。

模型**永远不会看到**之前的观察、动作或推理轨迹。

### 2.2 执行状态与模式设计

- 执行状态被视为**一等运行时抽象**，仅包含未来执行所需的信息，以领域定义的结构化模式（schema）表示。
- 模式按领域一次性编写而非按任务编写。例如，在 InterCode CTF 的 100 个挑战实例中，复用单个静态 5 字段模式（`discovered_flags`、`tested_hypotheses`、`active_files`、`working_dir`、`cmd_summary`）。

### 2.3 推理与状态转换

给定上下文 `(P, Σ_t, O_t)`，模型生成三重输出：

```
(R_t, ΔΣ_t, a_t)
```

- **R_t**：多步 Chain-of-Thought 推理轨迹（临时计算）；
- **ΔΣ_t**：结构化状态更新（JSON 字典，包含键的变更与删除）；
- **a_t**：要执行的动作。

关键机制：步骤内的多步推理在生成期间完全保留以支持复杂演绎规划，但**状态转换经过验证并应用后，推理轨迹 R_t 被永久丢弃**，绝不进入后续提示词。状态更新遵循：

```
Σ_{t+1} = Σ_t ⊕ ΔΣ_t
```

其中 ⊕ 是运行时实现的字典合并算子，具备 null-删除语义。

### 2.4 算法流程

```
算法 1: SKILL.state 运行时
输入: 程序性规范 P, 初始状态 Σ_0
for t = 0, ..., T do
    接收最新观察 O_t
    构造提示词 (P, Σ_t, O_t)
    使用 LLM 生成 (R_t, ΔΣ_t, a_t)
    验证 ΔΣ_t
    Σ_{t+1} ← Σ_t ⊕ ΔΣ_t
    执行动作 a_t
end for
```

### 2.5 复杂度分析

- **对话式运行时**：提示词长度 |C_t| = O(t)，累积 token 复杂度为 **O(T²)**；
- **SKILL.state**：提示词长度 |P_t| = O(|P| + |Σ| + |O|)，与历史步数 t 无关，累积 token 复杂度为 **O(T)**——严格线性。

## 6. 主要结论与发现

1. **显式执行状态显著提升长时程扩展性**：在 T=100 时，Stateful 基线消耗 1,062,387 tokens，SKILL.state 仅消耗 65,408 tokens（**16.2× 减少**）；T=200 时 SKILL.state 保持 0.94 准确率，消耗 122k tokens，而 Memory 基线膨胀至 6.1M tokens。
2. **噪声鲁棒性大幅增强**：在 50 干扰事件/轮的高噪声水平下，Prompt 运行时从 0.68 跌至 0.53，SKILL.state 维持 ≥0.97——因为干扰在状态生成时即被过滤，绝不进入后续提示词。
3. **零步状态恢复**：面对外部环境漂移，基于历史的基线需 5–8 步才能恢复（因为过时事实压制了矛盾的新观察），SKILL.state 因决策依赖当前结构化状态而**立即（0 步）恢复**。
4. **公共基准上全面领先**：InterCode CTF pass@1 达 54.2%（比最强基线 +7.8 点，比 Stateful +12.4 点），同时总 token 较 ReAct 降低 60.4%；τ-Bench Retail 以 58.3% 通过率取得最低 token 成本；τ-Bench Airline 保持 ~2800 tokens/步的平坦占用并节省 40.5% tokens。
5. **结构化状态优于统计压缩**：预算匹配下，滑动窗口截断降至 0.18，LLMLingua 降至 0.22（因统计熵过滤删除了语义关键但看似冗余的槽位标识符），而 SKILL.state 保持 0.94。
6. **开放权重模型的失败以结构化输出遵从为主**：68% 的错误是过早状态覆写/删除，20% 是模式理解/类型强制问题，12% 是 JSON 语法错误——表明小模型的瓶颈在结构化输出遵从而非推理能力。

## 7. 优点

- **理论复杂度优势明确**：从 O(T²) 到 O(T) 的累积 token 复杂度改善有严格的形式化证明，O(1) 提示词占用使得执行时间不再随历史增长而退化。
- **架构无关性**：在专有模型（Gemini-3-Flash）和两种开放权重模型（Gemma-4-31B、Qwen-3-8B）上均验证了收益，跨模型族保持一致趋势。
- **隔离变量的实验设计**：通过统一技能指令注入、确定性种子、温度 0 解码，确保运行时框架是唯一自变量；第 5 个实验专门做预算匹配控制，排除"仅仅是短提示的好处"这一混淆因素。
- **新颖的诊断基准**：SkillExecBench 提供了可控的确定性环境，精准检验长时程状态维护、噪声过滤和状态恢复等核心机制。
- **关键洞见**：统计压缩（LLMLingua）和窗口滑动的方法在长时程任务中会破坏精确关系依赖，而结构化状态保留这些依赖，这一发现对 prompt 压缩领域具有独立参考价值。
- **实际可行的状态管理模式**：每个能力域只写一次 schema（如 InterCode CTF 全基准复用单一 5 字段 schema），降低了应用门槛。

## 8. 不足与局限

### 8.1 方法层面的固有假设

论文承认其核心假设是**执行状态可以成为未来执行的充分统计量**——所有影响未来行动的历史信息都可以在获知时立即投影到结构化状态中。这一假设在三种场景下失效：

1. **无预知 schema**：当相关状态结构必须在执行过程中动态发现时，无法预先定义固定的结构化状态；
2. **迟到相关性识别**：如果某个早期观察的相关性在首次出现时未被识别、因此从未提交到状态，则该信息永久丢失；
3. **以历史轨迹为目标的场景**：审计、调试溯源、解释过去行为等任务本身以交互历史为输出目标，丢弃历史直接违背任务定义。

- **多智能体场景未经验证**：虽在局限中讨论，但没有实验数据支持。

### 8.3 工程挑战与安全风险

- **状态模式设计的负担**：虽然每域只写一次 schema，但模式设计质量直接决定整个系统的能力上限；设计不佳的 schema 会成为新的表达瓶颈；
- **小模型的 JSON 遵从问题**：实验中开放权重模型的表现暴露出当前方法对小模型不友好，论文提出的补救方案（如文法约束解码）尚未实现和验证；
- **缺乏真实长时程部署验证**：CTF 和 τ-Bench 虽为真实场景，但执行轮次相对有限，真正意义上的"数小时乃至数天"的持续执行尚未测试；
- **确定性验证的局限**：运行时确定性校验虽然防止了畸形输出破坏状态，但当合法格式的 patch 包含语义错误（如误删正确键）时，系统无法自动识别，只能依赖 rollback-retry 循环；
- **单智能体限制**：多智能体并发写入会导致状态合并冲突，需要确定性的冲突解决语义，目前未实现。
