## 摘要
大语言模型已从语言生成器演变为能够完成复杂、长期任务的自主智能体。这一演变催生了多种范式，包括用于激发模型能力的提示工程、用于管理信息访问的上下文工程、用于组织外部工具与资源的工具链工程，以及支持持续反思与自我改进的循环工程。然而，随着任务日益复杂，个体智能面临根本性局限：许多任务需要异构专业知识、相互依赖的子任务、并行执行、独立验证和持久状态，超出任何单一智能体的组织能力。仅增强单个智能体的能力或上下文无法解决这种架构性不匹配；智能必须分布在专业化智能体之间，并在系统层面进行组织。我们称之为系统智能：智能体系统将多个智能组件组织并协调为连贯、自适应整体以追求共同目标的能力。实现系统智能不仅需要增加智能体，更需要显式结构来组织工作、协调异构智能体并维护不断演化的执行状态。我们引入图工程，这是面向下一代智能体系统的新兴范式。与以往主要优化个体交互或智能体层面行为的范式不同，图工程构建显式、动态、演化的图结构，表示任务、智能体和系统状态。这些抽象为组织复杂目标、编排异构智能体、建模系统动态以及实现可扩展的智能体演化提供了统一基础。我们系统综述了LLM智能体的图工程原理、方法与应用。相关论文、开源数据和项目已收集于https://github.com/DEEP-JLU/Awesome-Graph-Engineering。

## Abstract
LLMs have evolved from language generators to autonomous agents capable of complex, long-horizon tasks. This evolution has produced paradigms including Prompt Engineering to elicit model capabilities, Context Engineering to manage information access, Harness Engineering to organize external tools and resources, and Loop Engineering to support continual reflection and self-improvement. Yet as tasks grow more complex, individual intelligence faces a fundamental limit: many tasks require heterogeneous expertise, interdependent subtasks, parallel execution, independent verification, and persistent state, exceeding any single agent's organizational capacity. Augmenting one agent's capabilities or context cannot resolve this architectural mismatch; intelligence must instead be distributed across specialized agents and organized at the system level. We call this System Intelligence: an agent system's ability to organize and coordinate multiple intelligent components into a coherent, adaptive whole pursuing a shared objective. Achieving it requires more than adding agents; it demands explicit structures to organize work, coordinate heterogeneous agents, and maintain evolving execution states. We introduce Graph Engineering, an emerging paradigm for next-generation agent systems. Unlike prior paradigms that mainly optimize individual interactions or agent-level behavior, Graph Engineering constructs explicit, dynamic, evolving graph structures representing tasks, agents, and system states. These abstractions provide a unified foundation for organizing complex objectives, orchestrating heterogeneous agents, modeling system dynamics, and enabling scalable agent evolution. We systematically review the principles, methodologies, and applications of Graph Engineering for LLM agents. Related papers, open-source data, and projects are collected at https://github.com/DEEP-JLU/Awesome-Graph-Engineering.

## 2. 论文提出的方法论

### 2.1 核心思想

图工程将图结构从静态表示转变为组织和管理智能体系统执行的**操作机制**，围绕三个相互耦合的图视图展开：

- **工作组织图**：回答“做什么、如何组织”；
- **智能体团队图**：回答“谁来做、如何协作”；
- **运行时状态管理**：回答“系统当前在哪里、应如何演化”。

### 2.2 智能体的形式化定义

个体智能体可抽象为：

```
Ai = Loop(Fi, Hi; sti)
```

- `Fi`：基础模型（认知核心）；
- `Hi`：智能体工具链（Harness，提供外部资源与可执行能力）；
- `sti`：智能体在时间 t 的局部运行时状态。

智能体系统可表示为：

```
St = {At, Rt, Et, Πt, xt}
```

- `At`：智能体团队；`Rt`：共享资源；`Et`：外部环境；`Πt`：协调机制；`xt`：系统级状态。

### 2.3 关键技术维度（图工程的三大支柱 + 系统演化）

1. **任务组织（Task Organization）**
   - **目标分解**：将高层目标转化为显式子目标图（节点为子任务，边为依赖、前驱、数据或逻辑关系），支持依赖感知调度和动态目标细化（如HuggingGPT、ReWOO、LLMCompiler、TDAG、Flow）。
   - **工作流优化**：将语义子目标编译为可执行算子图（节点为LLM调用、专用智能体、检索模块、工具、验证器等），并可对工作流结构本身进行搜索与优化（如GPTSwarm、AFlow、A2Flow、MermaidFlow），以及运行时自适应调整（如DyFlow、EvoFlow、QualityFlow）。

2. **智能体协调（Agent Coordination）**
   - **能力建模**：用图表示智能体的技能、资源、权限和可靠性，实现能力感知的任务分配与重配置（如DyLAN、MasRouter、SkillGraph、MaAS）。
   - **团队组织**：用图表示角色分配、委派路径、监督和审查关系，支持链式、路由、扇出/扇入和动态团队结构（如MetaGPT、ChatDev、Magentic-One、Mixture-of-Agents、AgentNet）。
   - **多智能体通信**：用动态图建模运行时信息交换与反馈关系，区分团队组织的稳定关系与执行中涌现的通信流（如MAgICoRe、G-Designer、AgentPrune、DyTopo、CARD、QueenBee Plannner）。

3. **运行时状态管理（Runtime State Management）**
   - **状态记录**：将执行证据、来源和版本以结构化、可查询的方式持久化；要求结构化表示、受控更新、作用域可见性和一致性管理（如Magentic-One的Task/Progress Ledgers、Graph of States、PatchBoard、MemTX）。
   - **故障定位**：从执行证据中检测异常、追踪决定性错误、沿依赖关系传导影响、测试假设（如Who & When、MAST、TraceElephant、MAGE）。
   - **失败恢复**：选择恢复边界、重放可恢复计算、补偿外部副作用、分支到替代执行路径（如MAGE、ALAS、AgentGit、Shepherd、SagaLLM、RAC、Atomix）。

4. **系统演化（System Evolution）**
   - 任务组织演化：动态细化任务图与工作流（TDAG、DyFlow、EvoFlow）；
   - 智能体协调演化：适应团队结构与通信模式（SwarmAgentic、AgentNet、Meta-Team、DyTopo）；
   - 状态管理演化：将执行历史蒸馏为可复用经验并控制状态修订（ReCreate、SkillGraph、Swarm Skills、MemTX）。

### 2.4 未来方向：本体工程

## 6. 论文的主要结论与发现

1. **范式演进的必然性**：从模型智能到个体智能再到系统智能，是任务复杂性驱动的必然方向；个体智能的三大局限（串行化并行依赖任务、角色混淆、状态与恢复不可持续）促进图工程的产生。
2. **系统智能的核心不在于“更多智能体”而在于关系组织**：任务、智能体、运行时状态之间的显式结构是系统智能的关键。
3. **图工程的三视图是统一框架**：工作组织图、智能体协调图、运行时状态管理图相互耦合，共同支撑系统的组织、协调、监控、恢复与优化。
4. **系统演化仍不成熟**：现有系统大多在预定义结构内做执行时的动态调整（条件路由、临时委派、恢复），但跨执行的持久化结构演化仍非常少见。
5. **本体工程是下一代系统智能的语义基础**：图工程必须与共享语义、价值对齐和可度量标准相结合，才有望实现可持续、可信的系统智能。
6. **评估体系需要三个层次的区分**：模型智能评估单元是输出，个体智能评估单元是轨迹，系统智能评估单元是组件间关系与结构。现有评估仍碎片化。

## 8. 不足与局限

1. **缺乏第一手经验证据**：综述归纳了图工程的方法论，但未对这些方法做统一基准测试或消融实验，无法回答“图工程相比非图方法在何种条件下有实质增益”这一关键问题。
2. **语义与一致性问题未解决**：论文虽然将本体工程作为未来方向，但承认“显式图结构并不保证系统实体与关系的一致解释”，目标、证据、有效状态的共享语义仍缺失。
3. **跨图演化的治理机制薄弱**：任务图、智能体图、能力图、状态图如何协同演化（避免修改任务图导致团队能力不匹配，替换智能体导致权限失效等）仅被列为开放问题，没有成熟方案。
4. **永久性系统演化仍罕见**：多数系统在执行时动态改变某一次运行的路径，但跨运行持久化并可转移的“自演化图系统”在部署环境中基本缺席。
5. **评估碎片化且测评重叠加**：基准分散在工作组织、协调、状态、演化的不同维度，缺乏统一的结构化评估协议，跨结构效应难以测量。
6. **安全与隐私风险突出但对策有限**：系统智能引入跨组件暴露面，敏感信息可能跨任务泄漏、责任难以追溯；给出的方向（权限、溯源、人工监督）是原则性的，缺乏具体机制。
7. **图工程的实际工程栈碎片化**：训练/服务与智能体运行时语义不统一，智能体框架对任务依赖、能力、通信与状态的表示不兼容，MCP只解决能力接口的互操作而没解决系统组织层面的互操作。
8. **需要跨领域验证**：应用部分（如社会仿真、医疗）中“额外智能体是否真正带来结构价值”仍未与基线模型能力充分剥离；语境中存在过度泛化的风险。

（完）
