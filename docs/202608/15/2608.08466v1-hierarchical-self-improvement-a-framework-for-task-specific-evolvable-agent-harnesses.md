## 摘要
现代LLM智能体通常通过手动修改提示、工具或工作流来改进，而模型周围的可执行脚手架——即\emph{harness}——在部署后通常被视为固定产物。本研究探讨了一种替代方案，其中harness是\emph{任务特定且可持续演化的}：每个任务族维护自己的harness，通过固定的任务注入接口在迭代间热切换，并利用环境反馈进行重写。我们提出了\textbf{层次化自我改进（HSI）}框架，其中单个冻结的LLM $M$ 在三个层次范围内运行：执行任务的任务harness $H$、重写$H$的演化器，以及在冻结的外部锚定下重写演化器策略代码的元演化器。思考开启/关闭设计通过在任务执行期间禁用推理而在自我修改期间启用推理，隔离了harness演化的贡献。HSI受到两个因素的限制：\emph{反馈保真度界限}，因为演化需要信息丰富的奖励信号来指导选择；以及\emph{骨干能力界限}，因为harness重新设计无法克服冻结模型的局限性。在以DeepSeek-V4-Flash-Preview为冻结骨干的BALROG上，HSI在中等难度任务上相对于初始harness持续取得提升（BabyAI上$+39.3$，Crafter上$+33.0$，TextWorld上$+25.0$，MiniHack上$+15.0$，均为原始\%进度），同时在BabaIsAI子套件上获得强大的持有外泛化能力（在$20\%$未见分割上，BreakStop最佳测试为$0.98$，GoTo为$1.00$）。对于超出骨干能力的任务（NLE），harness演化未带来任何改进。这些结果表明，在明确的实证限制下，任务特定harness演化是改进冻结LLM智能体的一个可行方向。代码可在https://github.com/TailinZhou/hsi获取。

## Abstract
Modern LLM agents are often improved by modifying prompts, tools, or workflows manually, while the executable scaffold surrounding the model---the \emph{harness}---is typically treated as a fixed artifact after deployment. This work studies an alternative where the harness is \emph{task-specific and continuously evolvable}: each task family maintains its own harness, which is hot-swapped across iterations through a fixed task-injection seam and rewritten using environment feedback. We introduce \textbf{Hierarchical Self-Improvement (HSI)}, a framework in which a single frozen LLM $M$ operates across three hierarchical scopes: a task harness $H$ that executes tasks, an evolver that rewrites $H$, and a meta-evolver that rewrites the evolver's strategy code under a frozen outer anchor. A thinking-on/off design isolates the contribution of harness evolution by disabling reasoning during task execution while enabling it during self-modification. HSI is bounded by two factors: a \emph{feedback-fidelity bound}, since evolution requires informative reward signals to guide selection, and a \emph{backbone capability bound}, since harness redesign cannot overcome limitations of the frozen model. On BALROG with DeepSeek-V4-Flash-Preview as the frozen backbone, HSI achieves consistent gains over the initial harness on moderate-difficulty tasks ($+39.3$ on BabyAI, $+33.0$ on Crafter, $+25.0$ on TextWorld, and $+15.0$ on MiniHack, all in raw \% Progress), while obtaining strong held-out generalization on BabaIsAI sub-suites ($0.98$ best-test on BreakStop and $1.00$ on GoTo from a $20\%$ unseen split). On tasks beyond the backbone's capability (NLE), harness evolution provides no improvement. These results demonstrate task-specific harness evolution as a viable axis for improving frozen LLM agents under clear empirical limits. Code is available at https://github.com/TailinZhou/hsi.

- **现有方法不足**：

- **核心研究问题**：当底层 LLM 参数完全冻结时，智能体能否通过内生地演化自己的 harness 来提升任务性能？这种提升的最终边界是什么？
- **整体含义**：本文提出一种新范式——任务特定、持续可演化的 harness。每个任务族维护自己的 harness，通过固定接口热切换，并利用环境反馈自动重写；在冻结模型的前提下，通过层次化、有界自修改来系统化地榨取既有模型的额外能力。

## 2. 提出的方法论：核心思想与关键技术细节

### 2.1 核心思想
- **层次化自我改进（Hierarchical Self-Improvement, HSI）**：使用同一个冻结 LLM $M$ 在三个层次范围（scope）中运作：
  1. **任务 harness 层（Task Harness $H$）**：执行具体任务，包含提示词、工具、记忆、状态管理、hooks 和执行策略；
  2. **演化器层（Evolver）**：重写 harness $H$，负责种子选择、主演化、提交选择；
  3. **元演化器层（Meta-Evolver）**：重写演化器策略 $\Sigma$（包括种子生成、演化、提交、最终版本选择等策略）。
- **冻结外部锚（frozen outer anchor）**：元演化器自身的执行逻辑加载自不可变初始化模板，不可被编辑。从而将自修改限制在“有层次、有实证验证”的范围内，避免无限自引用。
- **思考开关设计（thinking-on/off）**：任务执行时禁用扩展推理（thinking disabled），从而固定模型单步能力上限、隔离 inference-time reasoning 对结果的干扰；在自我修改阶段启用思考，以最大化成功重写 harness 的概率。

### 2.2 关键技术细节与流程
- **自决探索-利用（Self-Determined Explore–Exploit）**：框架不预设探索/利用调度，而是由模型自己决定何时检查代码、评估候选、提交修改、记录经验等。框架只提供原子交互原语、演化反馈信号和结构不变量。
- **五阶段演化循环**：
  1. **种子选择（Seed Selection）**：基于累积演化图 $G_t$ 选择祖先版本，生成结构化假设 $h_t$（包含锚定版本、动机、预期改进方向、可证伪标准）；
  2. **主演化（Main Evolution）**：在固定任务注入接口的约束下，直接修改 harness 的提示词、工具、记忆、状态管理、控制逻辑等，生成候选版本集合；
  3. **提交选择（Commit Selection）**：不是只选最高奖励候选，而是维护一个多样化的提交池，保留多个演化方向，供未来种子选择参考；
  4. **元演化（Meta-Evolution）**：修改演化器策略 $\Sigma$，使未来的 harness 搜索策略本身可适应；
  5. **最优版本选择（Best-Version Selection）**：在 $T$ 轮迭代后，以泛化优先原则选择最终部署的 harness，在验证集上评估并导出。
- **关键公式/符号**：
  - 种子选择：$(\hat{H}_t, h_t) = \text{seed\_selection}(G_t, M)$
  - 主演化：$\{V_t^{(k)}\}_{k=1}^{K_t} = \text{main\_evolution}(\hat{H}_t, h_t; M)$
  - 提交选择：$C_t = \text{commit\_selection}(\{V_t^{(k)}\}, G_t; M)$
  - 元演化：$\Sigma_{t+1} = \text{meta\_evolution}(G_t \cup C_t, \Sigma_t; M)$
  - 最终选择：$H^* = \text{best\_version\_selection}(G_T, M, \Sigma)$
- **候选排序奖励**：使用随机下置信界（LCB）奖励：$r = \mu - z \frac{\sigma}{\sqrt{n}}$，其中 $z=0.5$，以降低随机高奖励轨迹的影响。
- **结构不变量**：任务与 harness 之间的外部接口 `using_harness(agent, task)` 固定不变，保证不同版本可公平对比；评估信号和数据划分不受智能体控制。

## 6. 主要结论与发现

- **HSI 带来一致的分布内增益**：在中等难度任务上，相对初始 harness，meta-on 配置的 % Progress 提升为：BabyAI +39.3、Crafter +33.0、TextWorld +25.0、MiniHack +15.0；NLE 无提升。
- **HSI 达到或超过部分前沿系统**：例如 TextWorld 65.0 超过 Grok-4（62.9）和 Claude-Opus-4.5-Thinking（59.0）；Crafter 44.6 超过 DeepSeek-R1（36.4）和 GPT-5-minimal-think（39.1）。
- **元演化带来额外增益**：meta-on 相比 meta-off 在 BabyAI 上提升 4.0、Crafter 上提升 8.2、TextWorld 上提升 19.0、MiniHack 上提升 10.0，表明演化策略本身的可演化性是重要杠杆。
- **存在泛化能力**：在 BabaIsAI 留出测试中，BreakStop 最佳测试 0.98、GoTo 1.00，几乎完美泛化；Make 则仅 0.36，说明复杂多步合成任务仍接近骨干能力边界。
- **两个关键限制**：
  1. **反馈保真度界限**：演化需要信息丰富的奖励信号；NLE 中初始奖励几乎为零，无从指导演化；
  2. **骨干能力界限**：harness 重写只能重组和放大已有模型能力，不能超越冻结模型本身的推理极限。
- **演化动力学**：最大提升通常发生在第一轮迭代，之后为渐进式微调；演化过程非单调，存在回归现象；早期迭代往往发现缺失的任务抽象（如显式奖励信号、库存状态），后期迭代加入结构化算法组件和规则约束。

## 7. 优点

- **明确且干净的贡献隔离**：通过 thinking-on/off 设计，将 harness 演化效果与 inference-time 推理计算解耦，使增益可明确归因于 harness 重写。
- **真正的内生自我改进**：同一个冻结 LLM 同时充当任务执行器、演化器和元演化器，不依赖外部更强的模型或额外参数，展示了“自举”式改进的可行性。
- **层次化自修改边界设计巧妙**：用“任务 harness → 演化器策略 → 冻结外部锚”的分层结构，避免无限自引用，同时保留了演化过程本身的可适应性。
- **任务特定演化视角新颖**：不追求一个通用 harness，而是每个任务族维护自己的演化 harness，并通过留出任务测试泛化，规避了“演化=测试时搜索”的批评。
- **实验基准选择合理**：BALROG 提供自然难度梯度，能够同时展示正结果和负结果，较全面地刻画了方法的有效边界。
- **定性与定量结合**：除指标外，还提供了演化轨迹的逐轮分析，展示了 meta-evolver 如何将局部成功转化为可复用的演化启发式。

## 8. 不足与局限

- **骨干模型单一**：仅验证了 DeepSeek-V4-Flash，未测试 GPT、Claude、Gemini 等不同能力的模型，无法判断 HSI 的普适性和模型依赖度。
- **演化预算较小**：仅 5 轮外层迭代，每轮最多 80 步 react；更大的演化轮数是否带来持续增益未知。
- **评估噪声与统计效力**：部分环境（MiniHack）在最终测试中仅 5 个 episode/任务、3 次重复，标准误较大；NLE 结果接近零分，缺乏 meta-off 对照，结论的统计稳健性有限。
- **与排行榜的对比不对齐**：HSI 与前沿模型的比较混杂了不同骨干、不同推理配置和不同评估设置，只能作为“背景参考”，不能严格说明 harness 演化优于更强模型。
- **领域覆盖有限**：BALROG 均为文本/网格类游戏环境，未涉及真实软件工程、网页导航、工具调用等更实际的应用；BabaIsAI 的 Advanced 子套件因任务数不足被排除，缺乏对更复杂组合任务的验证。
- **未披露算力和成本细节**：未报告 API token 消耗、运行时长或经济成本，复现难度较高。
- **理论基础依赖外部工作**：论文引用了关于自我改进统计极限的已有理论结果（VC 维条件），但未给出 HSI 自身的理论保证，边界分析以经验观察为主。
- **潜在偏差风险**：演化过程中使用 LCB 选择候选，但最终报告的是原始均值；dev 评估与最终测试的 episode 预算不同，可能带来“选择偏置”，尽管留出测试在一定程度上缓解了该问题。
