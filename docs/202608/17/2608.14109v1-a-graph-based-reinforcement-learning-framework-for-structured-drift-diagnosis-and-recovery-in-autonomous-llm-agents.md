## 摘要
自主LLM智能体日益部署于复杂真实工作流中，但仍易遭受运行时行为漂移——一种对原始任务的静默偏离，可能对外部系统造成不可逆的副作用。现有方法在提示层面处理漂移，但缺乏步骤级检测、风险评估和恢复决策的结构化机制。由于主任务执行智能体通常是大型且昂贵的模型，无法在每次部署时重新训练，因此本研究针对即插即用的恢复模块。该模块引入一种基于图的框架，其中单个小型语言模型通过强化学习训练，在恢复图的每个节点上专门化，独立于主智能体。每个节点有明确角色：漂移分类、操作检测、风险评估或最终决策，模型学习生成适应角色的结构化XML格式推理。训练结合基于规则的结构奖励与LLM作为评判者的语义质量信号，使模型既依据其回答方式（模式与长度）又依据其内容进行评分。在公共AppWorld基准上的实验表明，该方法通常能利用疑似漂移起始信息，借助小型语言模型发出正确恢复决策。此外，训练后的小型语言模型可靠遵循规定的输出模式，并根据其分配节点角色在各字段中生成语义恰当的内容。

## Abstract
Autonomous LLM agents are increasingly deployed in complex real-world workflows, yet they remain vulnerable to runtime behavioral drift, a silent deviation from the original task that can lead to irreversible side effects on external systems. Existing approaches address drift at the prompt level but lack structured mechanisms for step-level detection, risk assessment, and recovery decision. Because the main task-executing agent is often a large and expensive model that cannot be re-trained on every deployment, this work targets a plug-and-play recovery module instead. It introduces a graph-based framework in which a single small language model is trained via reinforcement learning to specialize at each node of a recovery graph, external to the main agent. Each node has a precise role\,: drift classification, operation detection, risk evaluation, or final decision and the model learns to produce structured XML-formatted reasoning adapted to that role. Training combines rule-based structural rewards with an LLM-as-judge semantic-quality signal, so that the model is graded both on how it answers (schema and length) and on what it says. Experiments on the public AppWorld benchmark show that the method generally exploits information about the suspected drift onset to issue correct recovery decisions using a small language model. In addition, the trained small language model reliably respects the prescribed output schema and produces semantically appropriate content in each field according to its assigned node role.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体已不再仅回答问题，而是执行真实操作（调用 API、发送邮件、转账、修改数据库）。此类智能体在长轨迹执行中极易发生**行为漂移（Behavioral Drift）**——即偏离原始任务目标的静默偏差，可能由恶意提示注入或模糊子目标过度延伸引发。
- **核心痛点**：
  - 漂移一旦发生，智能体会"自信地"继续执行后续步骤，逐步远离初始目标；
  - 由于智能体现在执行 **写操作**（如转账、删消息、改设置），单纯回滚消息历史无法回滚外部世界状态（"Rolling back the message history does not roll back the world"）；
  - 现有防御研究（提示隔离、指令层级、防火墙）几乎全部聚焦于 **预防**，缺乏漂移发生后的 **结构化恢复机制**。
- **关键约束**：主任务执行智能体通常是大型昂贵模型，无法每次部署都重训练，因此需要一个**即插即用（plug-and-play）的外部恢复模块**。
- **研究意义**：提出了首个将漂移恢复构造为**小型状态机路由遍历**的框架，用单个小型语言模型（SLM）承担完整的漂移诊断与恢复决策链路，兼顾结构化、资源效率和部署可行性。

## 2. 论文提出的方法论

### 2.1 核心思想

将漂移恢复建模为**五节点恢复图（Recovery Graph）**的有向遍历。所有节点共享**同一个策略模型**，但通过角色条件提示（role-conditioned prompts）进行节点特化——即"一个模型、五个角色、共享 GRPO 目标"。

### 2.2 五节点恢复图架构

| 节点 | 角色 | 输出 JSON 键 |
|------|------|-------------|
| **n1 (Classify Drift)** | 给定任务、疑似漂移起始点、单步内容，判定该步是否对齐（Y/N）并给出简短理由 | `{step, is_aligned, why}` |
| **n2 (Detect Operations)** | 在漂移步骤中枚举所有成功执行的**写操作**和**离题读操作**（排除失败写操作和对齐读操作） | `{write_operations, read_operations}` |
| **n3 (Search Documentation)** | 从写操作中提取去重后的应用列表，供文档检索 | `{apps_name}` |
| **n4 (Evaluate Risk)** | 结合 API 文档，将写操作划分为**可逆**与**不可逆** | `{write_reversible, write_not_reversible}` |
| **n5 (Aggregate & Decide)** | 生成最终决策：`rollback_before_drift`（附回滚目标步骤）或 `escalate_human`（附结构化事件报告） | `{action, arguments}` |

### 2.3 结构化 XML 推理格式

- 每个节点强制输出**恰好一个 `<reasoning>` 块** + **恰好一个 `<answer>` 块**（内含节点特定 JSON）。
- 该设计是有意脱离自由形式 CoT：下游节点读取上游输出时无需重新解析自由文本，固定 schema 将每个节点的输出变成"类型化消息"。

### 2.4 向后行走与连续对齐终止（Backward Walk & Aligned-Streak Termination）

- 从外部漂移检测器提供的疑似起始点 `k0` 出发，逐**步向前回溯**；
- 若 n1 判定为漂移（N），则路由到 n2 检测操作；
- 若出现**连续 K 个对齐（Y）判定**，则终止回溯并路由到 n5；
- 单一对齐步骤不足以证明漂移已结束，短连续窗口是稳健且廉价的代理指标。
- 算法伪代码（Algorithm 1）完整定义了该路由控制律。

### 2.5 GRPO 节点特化训练

- **算法**：GRPO（Group Relative Policy Optimization），无需价值网络，在单 GPU 上即可训练；
- **分组采样**：每个训练提示 q 采样 G 个补全，组内相对优势为 $\hat{A}_i = (r_i - \bar{r}) / (\text{std}(r) + \epsilon)$；
- **目标函数**：带 PPO 式裁剪比率的 GRPO 目标 + KL 散度惩罚（保持接近基础模型，防止 schema 能力崩塌）；
- **LoRA 微调**：仅训练低秩适配器，πθ 是对冻结基础模型的微小更新。

### 2.6 复合奖励函数

奖励 $R(o, \nu, q) = \sum_{k=1}^{9} w_k r_k(o, \nu, q)$，共 9 个分量，每个在 [0,1] 内：

| 类别 | 分量 | 作用 |
|------|------|------|
| **格式（节点无关）** | `r_xml-count`, `r_strict`, `r_soft` | 检查 XML 标签数量、严格/宽松顺序 |
| **长度与风格（节点无关）** | `r_reas-len`, `r_tot-len` | 约束推理块和总输出长度的紧凑性 |
| **JSON 有效性与节点 schema（节点特定）** | `r_json-valid`, `r_json-schema`, `r_json-sanity` | 语法合法性、键集合精确匹配（Jaccard 部分分数）、节点特定值检查 |
| **语义质量（LLM-as-judge）** | `r_judge` | 冻结的 14B 推理模型按节点专属 rubrics 评分（1.0=具体/有根据/正确，0.5=笼统但没错，0.0=空/幻觉/矛盾），明确忽略格式问题 |

## 6. 论文的主要结论与发现

1. **节点特化可行**：单个小策略通过 GRPO 可在五个节点角色上实现专门化，无需每节点单独策略或单独奖励。
2. **内在奖励显著提升**：
   - Granite 3.3 2B：复合奖励 3.68 → 5.15，judge 子分数 0.71 → 0.90；
   - Qwen 2.5 1.5B：复合奖励 0.56 → 4.80（**8.6 倍提升**），judge 从 0.47 → 0.66；
   - 100 个保留提示中**每一个**都严格改善（ΔR 严格为正）。
3. **端到端恢复有效（Type I）**：训练的 Granite 恢复 27.5% 聚合任务完成率，达无漂移上限（35.3%）的 **78%**；在 D1 上与 GPT-4o 恢复骨干完全持平（57.1%）；未训练的 Granite 在所有任务上完全失败（0.0%），证明节点特化训练不可或缺。
4. **端到端恢复有效（Type II）**：强主代理（GPT-4o）下，Granite 恢复达 35.0%，接近无漂移基线 42.5%；弱主代理（GPT-4o-mini）下恢复效果显著下降（7.5% vs 20.0% 上限），说明恢复效果受主代理能力制约。
5. **小模型差距可压缩**：1.5B 与 2B 模型训练前的巨大奖励差距（0.56 vs 3.68）在训练后缩小至 0.35（4.80 vs 5.15），即 **8.9 倍压缩**——支撑即插即用、低成本部署的定位。
6. **schema 遵循是主要收益来源**：`json_sch`（Granite: 0.67→0.98；Qwen: 0.08→0.97）和 `json_san` 是最大增益分量，证明 GRPO 将模型特化进各节点 schema。

## 7. 优点

- **问题定位精准**：捕捉到"防御后仍有漏网漂移"的真实部署缺口，聚焦事后恢复而非事前预防，切入点新颖且实用。
- **即插即用设计**：恢复模块独立于主智能体、无需重训大模型、单 GPU 可训练，工程落地性强。
- **结构化输出纪律**：以 `<reasoning> + <answer>` XML 信封替代自由 CoT，将节点输出变成下游可直接读取的"类型化消息"，显著降低级联解析误差。
- **复合奖励设计精巧**：规则奖励保证形式、LLM-as-judge 保证内容，二者通过 GRPO 组归一化自然融合，无需手动平衡权重；非负奖励保证训练初期即使所有样本不佳也能拉动策略。
- **图路由机制简洁有力**：向后行走 + K 步对齐终止规则，以极小代价（短对齐窗口）稳健定位漂移起始点。
- **实验设计控制变量严谨**：base vs. trained、无漂移上界 / 无恢复下界、小模型 vs. 大模型 oracle 等多重对照，能清晰隔离训练带来的增益。

## 8. 不足与局限

- **Type III 未闭环**：框架目前只检测写操作并上报人工，不实际执行逆操作 API 调用；可逆性分类仅作为决策信号而非可执行修正计划。
- **n4（风险评估）提升有限**：Granite 上 judge 子分数仅 0.72 → 0.78，说明通用 judge 难以验证 API 可逆性判断的事实正确性，存在幻觉逆端点风险。
- **依赖外部漂移检测器**：框架需要外部系统提供疑似起始点 k0，自身不执行自主漂移检测，质量受上游信号制约。
- **奖励黑客风险**：模型可能学习 judge 过度偏爱的风格化痕迹（冗长但看似合理的推理、通用因果连接词），而未必提升事实基础；GRPO 能吸收单调偏移但无法纠正 judge 的系统性偏差。
- **假设漂移单调**：明确排除了 Remark 1 中漂移区与对齐区交错出现的真实模式，简化了问题但降低了现实覆盖度。
