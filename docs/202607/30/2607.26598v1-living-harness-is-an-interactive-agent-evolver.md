## 摘要
大型语言模型（LLM）代理可能在一个回合内或在重试后从失败中恢复，但相同的执行失败可能会在后续任务中重现，因为回合后的反馈很少修改指导未来交互的持久框架。静态框架通过固定工具、上下文、记忆和工作流结构提高可靠性，但在部署后保持不变。我们提出$\textbf{活体框架}$（Living-Harness），一种自我进化的代理框架，它将每个完成的轨迹及其评估器信号转换为后验证据，用于受限的框架更新。在领域级$\textbf{进化标准操作程序}$（$\textbf{Evolution-SOP}$）的指导下，活体框架提取回合抽象和结构化更新证据，并写入两种互补的程序性知识：记录触发条件、失败模式和恢复动作的情景记忆，以及记录状态节点、修复边和转换规则的状态图。更新后的框架状态被检索以指导未来交互，而工具和基础上下文保持不变，允许程序性修复在进化周期中累积。在源自$τ^2$-Bench和MultiWOZ-2.4的八个交互环境中，活体框架在最强交互基线之上将平均Pass@1分别提高了10.07和9.91个百分点，并支持跨模型骨干仅通过检索重用进化后的框架状态。

## Abstract
Large language model (LLM) agents may recover from a failure within an episode or after a retry, yet the same execution failure can recur in later tasks because post-episode feedback rarely revises the persistent harness that guides future interactions. Static harnesses improve reliability through fixed tools, context, memory, and workflow structures, but remain unchanged after deployment. We propose $\textbf{Living-Harness}$, a self-evolving agent harness that converts each completed trajectory and its evaluator signals into posterior evidence for bounded harness updates. Guided by a domain-level $\textbf{Evolution-SOP}$ ($\textbf{S}$tandard $\textbf{O}$perating $\textbf{P}$rocedure), Living-Harness extracts an episode abstraction and structured update evidence, and writes two complementary forms of procedural knowledge: episodic memory that records trigger conditions, failure patterns, and recovery actions, and a state graph that records state nodes, repair edges, and transition rules. The updated harness state is retrieved to guide future interactions, while tools and base context remain frozen, allowing procedural repairs to accumulate across evolution cycles. On eight interactive environments derived from $τ^2$-Bench and MultiWOZ-2.4, Living-Harness improves average Pass@1 over the strongest interactive baseline by 10.07 and 9.91 percentage points, respectively, and supports retrieval-only reuse of the evolved harness state across model backbones.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：大型语言模型（LLM）智能体在交互任务中常常重复相同的失败，因为现有的“静态框架”（如固定工具、上下文、记忆和工作流结构）在部署后不会改变。智能体可能从单次失败中通过局部重试恢复，但纠正经验无法持久化，导致后续类似场景下同样错误反复出现。例如，智能体正确识别应转接用户至人工客服，但下次仍需重新学习调用转接工具。
- **背景**：现有方法分为两类：一是通过设计更强的提示、SOP、工具约束或执行结构来构建静态框架（如Meta-Harness、AFlow等），这些结构在部署前固定；二是通过反思和经验记忆保留批判或轨迹摘要供后续使用（如Reflexion、ReasoningBank），但文本性教训缺乏可执行的触发条件和具体工作流转换，无法直接阻止相同失败发生。
- **研究目标**：实现“持久化程序性修复”——将评估器支持的失败证据转换为触发条件、缺失动作和恢复步骤之间可复用的关系，使修复跨回合持久化，同时不改变工具和基础上下文。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想
- **Living-Harness**：一种自我进化的代理框架，将评估后的交互轨迹（含反馈信号）转化为对框架状态进行受限更新的证据。框架状态包含两个互补部分：**情景记忆**（记录触发条件、失败模式、恢复动作）和**状态图**（记录状态节点、修复边、转换规则）。工具和基础上下文保持冻结，仅框架状态进化。
- 使用领域级**进化标准操作程序（Evolution-SOP）** 指导如何解释失败、提取证据并提交更新。

### 关键技术细节
- **框架状态定义**：
  \[
  H_d^{(n)} = \langle C_d^{\text{act}}, \psi_d, S_d^{(n)} \rangle, \quad S_d^{(n)} = \langle R_d^{(n)}, G_d^{(n)} \rangle
  \]
  其中 \(C_d^{\text{act}}\) 是固定执行资源（工具、基础上下文、领域规则），\(\psi_d\) 是固定进化SOP，\(S_d^{(n)}\) 是进化状态（情景记忆 \(R\) 和状态图 \(G\)）。
- **流程**（图2）：
  - **Rollout**：从当前状态 \(S^{(n)}\) 检索相关上下文，代理在固定工具和上下文下与环境交互，生成轨迹 \(\tau_n\)。
  - **Evaluate**：评估器产生信号 \(y_n = E(x_n, \tau_n)\)。
  - **Update**：进化SOP将 \(\tau_n\) 和 \(y_n\) 转换为情节抽象 \(e_n\)，再提取结构化证据 \(u_n = (u_n^R, u_n^G)\)；经门控检查后写入记忆和状态图，得到 \(S^{(n+1)}\)。更新仅在回合后发生，不改变当前回合的轨迹。
- **程序状态POMDP视角**：将框架状态视为程序状态 \(z^{(n)}\)，环境状态 \(s_t\) 在回合内演化，\(z^{(n)}\) 仅在回合间更新。证明程序增强信念可降低最优贝叶斯误差界（Proposition 1）。
- **更新门控**：包括模式门、范围门、证据门、约束门和合并门，确保更新仅针对可重复的失败证据、不覆盖冻结约束、合并相似条目。

### 公式与算法（文字说明）

## 7. 优点

- **创新的持久化机制**：将评估反馈转化为结构化、可检索的程序性知识（记忆+状态图），而非简单存储文本教训。
- **受限更新**：通过门控机制保证进化不违反基础约束，避免过度适应。
- **高效检索**：同任务族优先，语义排序，避免上下文爆炸。
- **跨模型可迁移**：进化状态可冻结后直接用于其他模型，降低重复进化成本。
- **理论支撑**：程序状态POMDP解释和信息论分析，说明为什么增加程序状态能降低误差。
- **实验严谨**：消融、迁移、周期分析、案例研究，证明每个设计选择的有效性。
