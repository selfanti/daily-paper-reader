## 摘要
大型语言模型智能体通常花费大量实际等待时间等待工具调用结果。工具调用推测可以通过预测并预执行智能体的下一个工具调用（如果预测与智能体最终的工具调用匹配）来隐藏这一延迟，但现有的推测器通常是独立的草稿模型或缓存轨迹，与部署的智能体自身行为对齐不良。我们识别了这种推测器-智能体差距，并表明目标智能体本身就是一个强大的下一个调用推测器。这指向了一个更简单的设计：将智能体和推测器统一在同一模型中。在本文中，我们引入了自推测智能体，这是一个单一模型，既以智能体模式完成任务，又以推测器模式从部分轨迹中预测其下一个工具调用，完全重用前缀KV缓存。为了实现这种双模式智能体而不降低性能，我们提出了一种联合智能体-推测器强化学习方法，该方法从智能体自身的推出中推导推测目标，并交替进行智能体和推测器更新。在智能搜索问答和对话式工具使用智能体任务中，我们的方法将Qwen3-4B的平均下一个工具调用Hit@1从44.1提升到61.2，将Qwen3.5-4B从48.9提升到66.3，同时保持了智能体任务的成功率。

## Abstract
Large language model agents often spend substantial wall-clock time waiting for tool call results. Tool-call speculation can hide this latency by predicting and pre-executing an agent's next tool call if the prediction matches the agent's eventual tool call, but existing speculators are typically separate draft models or cached traces that are poorly aligned with the deployed agent's own behavior. We identify this speculator-agent gap and show that the target agent itself is a strong next-call speculator. This points to a simpler design: unifying the agent and speculator within the same model. In this paper, we introduce the self-speculating agent, a single model that both solves tasks in agent mode and predicts its next tool call from partial trajectories in speculator mode, fully reusing prefix KV cache. To enable this dual-mode agent without degrading performance, we propose a joint agent-speculator reinforcement learning method, which derives speculation targets from the agent's own rollouts and alternates agent and speculator updates. Across agentic search QA and conversational tool-use agentic tasks, our method improves average next tool-call Hit@1 from 44.1 to 61.2 for Qwen3-4B and from 48.9 to 66.3 for Qwen3.5-4B, while preserving agent task success.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：大语言模型（LLM）智能体在任务执行中频繁调用外部工具（搜索、API、数据库等），而工具调用通常涉及远程服务或网络I/O，导致大量等待延迟。现有通过**工具调用推测**（tool-call speculation）来隐藏延迟的方法，通常使用一个独立的草稿模型或历史缓存来预测智能体的下一个工具调用。但这类外部推测器与真实部署的智能体之间存在**推测器-智能体差距**（speculator–agent gap）：由于参数、训练数据或推理状态不一致，推测出的调用往往与智能体最终发出的调用不同，导致推测命中率低且浪费计算资源。
- **观察**：作者通过实验发现，目标智能体本身（用提示词让其预测自己的下一个调用）比任何同系列更小的外部草稿模型都更能匹配其自身的工具调用行为。由此提出一个更简单的设计：**将智能体和推测器合并到同一个模型中**，即自推测智能体（self-speculating agent），既能完成任务，又能从部分轨迹中预测下一个工具调用，且完全重用前缀KV缓存。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- 同一条模型参数，通过不同的输入模式区分角色：
  - **智能体模式**：标准交互流程（推理→工具调用→观察→答案）。
  - **推测器模式**：在中间轨迹末尾附加一个固定的推测后缀（固定文本提示），然后模型直接输出下一个结构化的工具调用（工具名+参数）。
- **训练目标**：在不影响智能体任务成功率的前提下，提升推测模式下下一个工具调用的预测准确率（Hit@1）。

### 2.2 关键技术：联合智能体-推测器强化学习（Joint Agent-Speculator RL）
- **奖励设计**：
  - 智能体奖励 $R_{\text{ag}}$：基于最终答案是否正确（环境评判）。
  - 推测奖励 $R_{\text{sp}}$：工具名精确匹配得1，否则0；工具名匹配后，计算参数词典的宏平均 token-F1，最后相乘。
- **训练流程**（算法1）：
  1. 每次迭代采样一批查询，生成 $G_{\text{ag}}=8$ 条智能体轨迹。
  2. 从每条轨迹的每个工具调用点提取前缀 $h_t$ 和实际调用 $a_t$，构造推测样本（$h_t$ + 推测后缀）。
  3. 对每个推测样本，模型生成 $G_{\text{sp}}=8$ 个候选推测调用，按推测奖励计算优势。
  4. 按照固定调度 $m(k)$ 交替执行智能体更新和推测器更新（均为DAPO风格策略优化）。
  5. 更新调度采用 **4:8 模式**：连续4次智能体更新，然后8次推测器更新。

### 2.3 稳定训练的三种技巧
- **SFT预热**：在强化学习前，用成功智能体轨迹和对应的推测示例进行短监督微调，使模型学会两种模式下的基本行为。
- **优化器状态重置**：每次模式切换时重置Adam优化器状态，避免不同目标的动量干扰。
- **交替更新而非混合更新**：证明交替的长块更新（4:8）优于短块或混合更新，因为推测器需要足够连续的信号来跟上当前智能体的行为分布。

## 3. 实验设计：数据集、基准、对比方法

## 6. 主要结论与发现

1. **外部推测器-智能体差距显著**：同系列更小模型（如Qwen3-0.6B）的猜测命中率极低（平均9.1% Hit@1），而直接用目标模型自我推测可达29.1%（Qwen3-4B基础）。
2. **联合RL大幅提升自推测性能**：Qwen3-4B的Hit@1从SFT后的44.1提升至RL后的61.2；Qwen3.5-4B从48.9提升至66.3，提升约17个百分点。
3. **智能体任务成功率保持不变或轻微提升**：平均成功率从26.6→27.7（Qwen3-4B），49.2→50.6（Qwen3.5-4B），证明没有以牺牲任务表现为代价。
4. **跨域泛化部分可行**：在一个域训练的推测能力能部分迁移到另一个域（如SearchQA训练的模型在τ-bench上Hit@1提升），但任务成功率下降，说明领域特定推理仍需域内训练。
5. **稳定训练技巧有效**：SFT预热、优化器重置、交替更新（4:8）均是必要的，缺乏任一技巧都会导致训练不稳定或性能下降。

## 7. 优点

- **方法简洁**：将推测器与智能体合并，无需部署额外的草稿模型或维护历史缓存，降低了部署复杂度和显存占用。
- **创新性**：首次系统性地识别推测器-智能体差距，并证明目标智能体自身是最佳推测器；提出联合RL框架，从智能体自身轨迹中在线学习推测，保持on-policy。
- **训练稳定性机制**：优化器重置和交替更新调度有效解决双模式干扰，是实用的工程贡献。
- **实验全面**：覆盖两种典型agentic任务、两个同系列模型、详细的消融和跨域分析，结论可信度高。

## 8. 不足与局限

- **仅适用于只读工具**：推测执行依赖预执行后不改变环境状态（如搜索、数据库查询）。若工具会改变外部状态（如下订单、发送消息），错误的推测可能造成不可逆后果，需额外防护机制。
- **模型规模有限**：实验仅基于4B参数模型，更大模型（如70B）的推测器-智能体差距及训练动态可能不同，泛化性未验证。
- **任务领域覆盖不全**：只评估了搜索问答和对话工具使用，未涵盖代码执行、web导航、多智能体交互等常见agent场景。
- **训练成本**：200步RL需要8张H100/H200，虽然相对可控，但未与更简单的微调方法（如直接蒸馏外部小模型）对比训练开销。
- **推测后缀固定**：所有实验使用同一段固定文本触发推测模式，未探索不同后缀（或更灵活的切换方式）对性能的影响。
