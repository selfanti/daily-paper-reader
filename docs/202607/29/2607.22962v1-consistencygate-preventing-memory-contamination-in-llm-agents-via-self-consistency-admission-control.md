## 摘要
在多轮交互中运行的LLM代理会将事实累积到外部记忆存储中，并重用它们作为下游推理的前提。因此，某个步骤中产生的幻觉事实会作为虚假前提持续影响后续所有步骤，这种失败模式我们称为记忆污染。现有的记忆管理解决检索和容量问题，但不处理写入时的正确性；这种准入问题无法通过基于效用或最近性的标准解决，而未受控制的污染会在长轨迹中累积。我们提出ConsistencyGate，一种写入时准入门控机制，在将从上下文c中提取的候选事实m提交之前，它会查询LLM K次以获得软支持分数，并且仅当平均分超过阈值时才准入m。该机制与模型无关，无需微调，并且对于延迟敏感型部署可简化为对数概率变体中的单次前向传播。为了衡量对自然数据的影响，我们通过向LoCoMo和MSC的长期对话中植入受控的单细节损坏，构建了两个真实对话基准（LoCoMo-Contam和MSC-Contam），并用一个结构化合成语料库（MemContam）补充它们，该语料库隔离了近似的理论最优上限。在四个LLM骨干网络上，ConsistencyGate在每一个基准上都减少了相对于“写入所有内容”基线的污染，代价集中在源上下文中仅隐含陈述的事实上。我们发布了所有三个基准以及门控机制的实现。

## Abstract
LLM agents that operate over many turns accumulate facts in an external memory store and reuse them as premises for downstream reasoning. A hallucinated fact written at one step therefore persists as a false premise for every subsequent step, a failure mode we call memory contamination. Existing memory management addresses retrieval and capacity but not write-time correctness; this admission problem cannot be solved by utility- or recency-based criteria, and uncontrolled contamination compounds across long trajectories. We propose ConsistencyGate, a write-time admission gate that, before committing a candidate fact m extracted from context c, queries the LLM K times for a soft support score and admits m only when the average exceeds a threshold. The mechanism is model-agnostic, requires no fine-tuning, and reduces to a single forward pass in a log-probability variant for latency-sensitive deployments. To measure the effect on natural data, we construct two real-conversation benchmarks (LoCoMo-Contam and MSC-Contam) by planting controlled single-detail corruptions in long-term conversations from LoCoMo and MSC, and complement them with a structured synthetic corpus (MemContam) that isolates a near-oracle upper bound. Across four LLM backbones, ConsistencyGate reduces contamination on every benchmark relative to a write-everything baseline, with the cost concentrated on facts that are stated only implicitly in the source context. We release all three benchmarks together with the gate implementation.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：LLM Agent在多轮交互中会将事实存入外部记忆，并在后续步骤中重用为推理前提。但LLM在从给定上下文提取时也会产生幻觉（hallucination），导致错误事实被写入记忆，成为后续所有推理的虚假前提。这种失败模式称为 **记忆污染（Memory Contamination）**。
- **现有工作不足**：
  - 现有记忆管理主要聚焦于**检索**（如何找到相关记忆）和**容量控制**（记忆满时驱逐哪些），但忽略了**写入时的正确性**。
  - 基于效用、新颖性、时效性的准入标准（如A-MAC）无法区分正确事实和其幻觉变体（两者效用几乎相同），对污染“结构性失明”。
  - 污染会随交互轨迹长度**级联放大**：一次写入错误会持续影响后续所有检索和推理。
- **意义**：正确性应作为一个独立的准入标准，与效用和容量管理互补。

## 2. 方法论：核心思想、关键技术细节
### 核心思想
在将候选事实写入长期记忆前，通过**自一致性（Self-Consistency）** 验证其是否得到源上下文的支持，仅当支持分数超过阈值时才准入。

### 关键技术细节
1. **软评分机制（Soft Scoring）**：
   - 给定候选事实 \(m\) 和源上下文 \(c\)，构造验证提示，要求LLM输出0~1之间的支持分数 \(s_k\)（0=矛盾，0.5=模糊，1=完全支持）。
   - 重复采样 \(K\) 次（默认 \(K=5\)），计算平均分 \(\hat{p} = \frac{1}{K}\sum s_k\)。
   - 若 \(\hat{p} \ge \tau\)（默认 \(\tau=0.7\)），则准入该事实。

2. **单次前向传播变体（LogProb）**：
   - 将验证提示改为二元“yes/no”形式，从LLM一次前向传播中读取“yes”和“no”的log概率，通过softmax得到支持分数。
   - 适用于结构化源数据（如文档、工具输出），速度提升12-14倍（23-28ms vs 264-363ms）。

3. **自适应阈值**：
   - 若无法针对部署调整 \(\tau\)，则根据记忆占用率动态调整：\(\tau^* = \tau_{\min} + (\tau_{\max} - \tau_{\min}) \cdot |M|/C\)（记忆越满阈值越高）。但固定 \(\tau=0.7\) 效果更好。

4. **算法流程**（Algorithm 1）：
   - 对每个候选事实 \(m\)，循环 \(K\) 次得到损失分数，计算平均分 \(\hat{p}\)。
   - 若 \(\hat{p} \ge \tau^*\)（固定或自适应），则添加到记忆 \(M\)；否则拒绝。

## 3. 实验设计：数据集、基准、对比方法
### 数据集 / 基准
- **MemContam（合成）**：5个固定源上下文（个人传记、图书馆记录等），每个上下文生成40个样本，共200个样本；每个样本5个正确事实 + 5个错误变体（通过数值扰动、否定、专有名词替换、矛盾子句四种策略生成），共1000正确/1000错误事实，污染率50%。
- **LoCoMo-Contam（真实长对话）**：基于LoCoMo-10（10个长对话，400-700轮），选取up to 5个QA对，将答案转为自包含事实并生成一个单细节错误的变体，共50个探针对（50%污染）。通过预注入正确事实使下游QA对门控决策不敏感。
- **MSC-Contam（基于人格的真实对话）**：基于Multi-Session Chat（20个对话，每对话2轮），过滤出具象人格句子，类似方式生成41个探针对，污染率50%。

### 对比方法
- **WriteAll**：所有提取的事实均写入。
- **Random**：以概率p=0.6随机准入（匹配ConsistencyGate的准入率），用于排除“仅减少记忆量”的解释。
- **ConsistencyGate**：默认配置固定τ=0.7, K=5。

### 评估指标
- 污染率ρ（% incorrect among admitted facts，越低越好）。
- 准入精度（1−ρ）和准入召回（正确事实中被准入的比例）。
- 下游QA F1分数（仅在MemContam上敏感，因LoCoMo/MSC已预注入正确事实）。

## 6. 主要结论与发现
1. **MemContam（合成）**：ConsistencyGate将污染率从50.0%降至1.2%（相对降低97.6%），召回100%，下游QA F1从0.474升至0.840，达到近理论最优上限。
2. **LoCoMo-Contam（真实长对话）**：污染率降至34.1%（精度0.659），召回约0.58（因隐含事实难以验证）。
3. **MSC-Contam（真实人格对话）**：污染率降至36.7%（精度0.633），召回0.93（人格事实更显式）。
4. **跨模型泛化**：四种骨干均显著降低污染，Llama-3.3-70B精度最高（0.998），Llama4-Scout最弱（但上调τ后可改善）。
5. **污染级联效应**：污染率和QA F1随交互轮次单调恶化/改善，验证了长轨迹下写时准入的重要性。
6. **效率与权衡**：LogProb变体在结构化上下文上达到完美精度且速度提升14倍，但在对话上下文中不如软评分；推荐固定τ=0.7, K=5。

## 7. 优点：方法或实验设计亮点
- **方法层面**：
  - **模型无关、无需微调**：仅需在写时调用LLM查询，适用于任何现有Agent框架。
  - **软评分与LogProb双模式**：灵活适应不同延迟需求；软评分细粒度，LogProb快速。
  - **自适应阈值调度**：当无法调参时提供零配置回退方案。
  - **问题聚焦明确**：指出记忆污染是写时准入问题，与检索和容量问题正交，填补重要空白。
- **实验设计**：
  - **构建三个互补基准**：合成基准提供近理论最优上界，真实对话基准覆盖不同对话结构（长程隐式 vs 短程显式），便于全面评估。
  - **精确控制污染率（50%）** 使不同基准的污染指标可比。
  - **预注入正确事实设计**避免下游QA干扰门控评估（LoCoMo/MSC）。
  - **Random基线匹配准入率**，排除“减少记忆数量”的干扰解释。
  - **跨四种骨干全面消融**，验证泛化性。

## 8. 不足与局限
- **依赖LLM写时调用**：增加计算开销（K=5时每事实约300ms），LogProb虽快但适用范围有限。
- **一致性代理的固有局限**：一致性并不等同于正确性，无法替代权威事实核查；当事实需要超出源上下文的世界知识时，门控仍可能出错。
- **隐含事实召回低**：在LoCoMo-Contam上需显式支持的隐含事实召回仅约58%，意味着约42%的正确但隐含事实被错误拒绝，这是运营上的永久性代价。
- **评估局限**：
  - 真实对话基准（LoCoMo/MSC）因预注入正确事实而下游QA F1不敏感，主要信号仅为污染率和精度。
  - MemContam使用与验证器同族的模型生成，可能高估性能；作者明确将其视为“内部一致性上界”而非部署数字。
  - 未在更长的实际互动场景（如几十轮以上）中全面评估召回损失的累积影响。
  - 污染级联效应仅在合成基准上量化，真实场景下因缺乏轮次级事实标签而无法复制。
- **应用限制**：最适合文档/工具支撑的记忆写操作；在开放域多轮对话中隐含事实为常见现象，门控的召回损失可能构成严重限制。
