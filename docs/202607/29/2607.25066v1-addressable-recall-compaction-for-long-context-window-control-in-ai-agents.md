## 摘要
长视界LLM代理会累积推理轨迹、动作和工具观测结果，最终可能超出模型的固定上下文窗口。现有压缩方法通过丢弃、总结或检索早期信息来解决这一限制，但可能会删除任务关键细节或无法可靠地恢复它们。我们提出ARC（可寻址召回压缩），一种将存档存储与活动上下文呈现分离的上下文管理框架。ARC将工具观测结果存储在仅追加的、ID可寻址的日志中，并在需要压缩时用紧凑引用替换较旧的观测结果。代理随后可以使用这些标识符请求存储的内容，而无需重新执行相应的工具或仅依赖基于相似性的检索。我们使用Qwen3-8B（16k上下文窗口）和Qwen3-32B（32k上下文窗口）评估ARC。在Needle-in-a-Haystack评估中，ARC的平均精确答案准确率达到99.40%，而评估中表现最佳的基线为88.12%。在我们的硬件成本模型下，ARC还减少了估计的服务时间和HBM流量。在LongBench-v2 Hard子集上，ARC的平均准确率为29.97%，而表现最佳的基线为28.25%。这些结果表明，在测试设置下，相对于评估的上下文管理基线，显式的、基于地址的召回可以改善信息保留和服务效率。

## Abstract
Long-horizon LLM agents accumulate reasoning traces, actions, and tool observations that can eventually exceed a model's fixed context window. Existing compaction methods address this limitation by discarding, summarizing, or retrieving earlier information, but they may remove task-critical details or fail to recover them reliably. We propose ARC (Addressable Recall Compaction), a context-management framework that separates archival storage from active-context presentation. ARC stores tool observations in an append-only, ID-addressable log and replaces older observations with compact citations when compaction is required. The agent can subsequently use these identifiers to request stored content without re-executing the corresponding tools or depending solely on similarity-based retrieval. We evaluate ARC using Qwen3-8B with a 16k context window and Qwen3-32B with a 32k context window. On the Needle-in-a-Haystack evaluation, ARC achieves an average exact-answer accuracy of 99.40%, compared with 88.12% for the best-performing baseline in our evaluation. ARC also reduces estimated serving time and HBM traffic under our hardware-cost model. On the LongBench-v2 Hard subset, ARC obtains an average accuracy of 29.97%, compared with 28.25% for the best-performing baseline. These results indicate that explicit, address-based recall can improve information retention and serving efficiency relative to the evaluated context-management baselines under the tested settings.

- **整体含义**：论文提出，压缩不必然要在“保持上下文窗口有界”与“信息无损保留”之间做取舍。通过分离**存档存储**（永久保留所有历史）与**活动上下文**（有界显示），可以实现**可逆的压缩**，即压缩是可恢复的，且不增加提示长度。

## 2. 论文提出的方法论

### 核心思想
- **分离存储与呈现**：将每个工具观测结果永久存储在外部内容可寻址存储中（Append-only，永不删除），而在活动上下文中只保留紧凑的引用（citation）和最近的内容。
- **可寻址召回**：每个观测具有唯一ID（基于SHA1哈希），压缩后的引用保留ID头尾预览，代理可通过`_recall <id>`动作精确获取原始内容，无需重新执行工具或依赖语义检索。

### 关键技术细节
- **ID生成**：`id = SHA1(signature(A) || 0x1F || O)`，使用前8个十六进制字符，碰撞时延长4位。
- **存储**：`ObsStore[id] = full_content`，只追加，不覆盖。
- **压缩触发器**：当预测到上下文即将溢出时（主动模式）或收到溢出错误后（反应模式）执行压缩。
- **压缩流程**：确定性地执行，不调用LLM；将长观测替换为引用（保留头/尾预览和元数据），保留最近几轮原文，保证活动上下文有界（K ≤ L）。
- **召回限制**：每步最多r次召回；总召回内容有预算，超过后采用LRU驱逐。

### 算法流程（文字说明）
1. 初始化空观测存储`ObsStore`和空引用集`Cited`。
2. 每轮循环：
   - 代理产生思考和动作`A`。
   - 执行`A`，得到观测`O`，计算`id`并存储到`ObsStore`，同时追加到转录`T`。
   - 检查转录长度是否超过预算L：若超过，执行压缩例程——生成确定性摘要（保留系统提示、摘要、最近turns、引用页、召回缓冲），确保总token ≤ K。
3. 如果代理发出`_recall id`，框架拦截后从`ObsStore`中取回原始内容注入上下文，并维护LRU驱逐。
4. 系统保证：任何存储的观测都可被精确恢复（通过分块不超过q payload tokens），且活动提示长度始终≤K。

## 3. 实验设计

### 数据集/场景
- **Needle-in-a-Haystack (NIH)**：1000个合成任务，每个任务在早期插入一个24字符的唯一针（needle），强制压缩后要求代理精确输出该针值。测试精确恢复能力。
- **LongBench-v2 Hard子集**：311个真实世界长文本任务（单文档QA、多文档QA、长文档理解、结构化数据、代码库理解等）。测试多步推理+回忆的综合能力。

### 基准方法（Baselines）
- **Full_context**：不压缩，直接溢出失败。
- **Sliding_window**：仅保留最近N轮，丢弃旧内容。
- **LLM_summary**：用LLM生成历史摘要替换旧内容（有损）。
- **Structured_state**：压缩为固定模式JSON对象（有损）。
- **RAG_memory**：将历史向量化存入外部向量库，通过语义相似度检索（隐式召回）。

- 准确率（Success/Total）

- **系统效率**：压缩例程是确定性的（不调用LLM），因此额外延迟极小；同时活动上下文变短带来了显著的KV缓存收益，从而降低推理成本和带宽。

## 8. 不足与局限

- **模型泛化局限**：仅测试Qwen3-8B/32B，未在Llama、GPT或其他模型上验证。召回动作格式可能不兼容不同模型的指令跟随能力。
- **外存依赖**：ARC需要一个外部存储系统（ObsStore），在分布式场景或极长轨迹下管理开销可能增加。
- **召回预算敏感性**：LongBench上ARC的准确率随召回预算呈倒U型，过大的预算可能引入噪声导致性能下降（而NIH上单调上升）。实际部署需要调参。
- **推理能力瓶颈**：在LongBench上ARC的优势较小（+1.6~2.3pp），说明许多任务失败是由于模型推理能力不足，而非记忆问题。ARC只解决回忆部分。
- **未测试更大上下文窗口**：如128k或更长，可能影响竞争基线的性能对比。
- **系统保证 ≠ 任务成功**：论文明确承认，即使存储可访问，LLM可能不会使用正确的地址或正确推理。因此ARC不能保证端到端成功。
- **Token开销**：每个引用占用的常数token（头/尾预览、元数据）相对于直接丢弃略多，论文未在长轨迹中量化总影响。
