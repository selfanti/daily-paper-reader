## 摘要
企业数据智能体通过多步推理中的多次工具调用来回答业务查询，每次会话通常会积累数十万上下文令牌。现有的压缩策略通常在分配保留预算时不考虑移除单个工具输出的下游后果。因此，激进的压缩可能触发昂贵的工具重新调用，抵消初始节省。我们将此称为压缩-后果差距。为弥补这一差距，我们提出TRACER，将压缩形式化为一个序列化的每工具决策问题。一个轻量级REINFORCE策略仅使用每次压缩事件时可用的信息来分配查询条件保留比率。其后果感知目标共同考虑任务成功率、总令牌消耗和压缩后的工具重新调用。为改进信用分配，TRACER使用学习到的结果模型来比较所选保留比率与完全保留每个工具输出的预测后果。在三个压缩后端的保留生产查询上，相对于保留所有上下文，TRACER将总令牌消耗减少了29-46%，同时保持相当或更高的任务成功率。与工具类型条件的静态策略相比，TRACER额外提供了15-18%的令牌节省。干预式rollout表明，学习到的每工具信用分数与测量到的单工具后果相关。学习到的策略在跨智能体主干和压缩器架构迁移时也产生正向节省，并在五个保留的LOCA-bench环境中将令牌消耗减少18-25%。这些结果证明了后果感知、每工具上下文保留对于提高长时程语言智能体效率的价值。

## Abstract
Enterprise data agents answer business queries by chaining many tool calls over multiple reasoning steps, routinely accumulating hundreds of thousands of context tokens per session. Existing compression strategies typically allocate retention budgets without accounting for the downstream consequences of removing individual tool outputs. Aggressive compression may therefore trigger costly tool re-invocations that offset the initial savings. We call this the compression--consequence gap. To close it, we propose TRACER, which formulates compression as a sequential per-tool decision problem. A lightweight REINFORCE policy assigns query-conditioned retention ratios using only information available at each compression event. Its consequence-aware objective jointly accounts for task success, total token consumption, and post-compression tool re-invocations. To improve credit assignment, TRACER uses a learned outcome model to compare the predicted consequences of the selected retention ratio with those of fully retaining each tool output. On held-out production queries across three compressor backends, TRACER reduces total token consumption by 29--46% relative to keeping all context while maintaining comparable or higher task success. Compared with a tool-type-conditional static policy, TRACER provides an additional 15--18% of token savings. Interventional rollouts show that the learned per-tool credit scores correlate with measured single-tool consequences. The learned policy also yields positive savings when transferred across agent backbones and compressor architectures, and reduces token consumption by 18--25% on five held-out LOCA-bench environments. These results demonstrate the value of consequence-aware, per-tool context retention for improving the efficiency of long-horizon language agents.

- **核心问题**：论文定义了 **压缩–后果差距（compression–consequence gap）**：压缩时节省的 token 可能被随后昂贵的工具重新调用所抵消，甚至净亏。现有方法在固定粒度上统一压缩，忽略了工具输出在下游重要性上的巨大差异。
- **整体含义**：需要一种**查询条件化、按工具粒度的保留策略**，根据每个工具输出的未来效用分配 token 预算，并在奖励中显式惩罚因压缩而引发的重新调用，从而在不损害任务成功率的前提下降低总 token 消耗。

## 2. 提出的方法论

- **核心思想**：TRACER 将上下文压缩建模为**序列化的每工具决策问题**。每次压缩事件发生时，策略网络根据当前上下文特征为每个工具输出实例输出一个保留比例，固定压缩机按比例执行压缩，随后智能体在压缩后的上下文上继续推理。
- **技术细节**：
  - **问题形式化**：一个会话是一个 episode，每次压缩事件是一个决策点；状态 \(s_t\) 编码查询特征、上下文构成、每个工具输出的尺寸、重要度、调用次数等；动作 \(a_t\) 为每个工具输出的保留比例向量。
  - **奖励设计**：目标函数结合三部分：
    - 会话级基础奖励 \(R_{\text{base}} = \text{success} - \lambda_{\text{tok}} \cdot \text{clamp}(T/T_{\text{base}}, 0.2, 2)\)，其中 \(T_{\text{base}}\) 为不压缩时多次运行的平均 token 数。
    - 事件局部召回惩罚 \(P_{\text{recall},t} = \lambda_{\text{recall}} \cdot \text{clamp}((N_{\text{post},t} - N_{\text{pre},t})/N_{\text{pre},t}, 0, 2)\)，通过对比压缩前后同一窗口内的工具调用次数衡量压缩引发的重新调用。
    - 总目标 \(J(\theta) = \mathbb{E}[R_{\text{base}} - \sum_t P_{\text{recall},t}]\)。
  - **策略网络**：两层 MLP，输入 174 维状态特征，输出每个工具输出实例的 Beta 分布均值。保留比例 \(a_i\) 的采样使用 Beta 分布映射到 \([0.05, 1.0]\)，避免截断伪影；评估时使用确定性均值。
  - **训练算法**：使用 REINFORCE，每查询 EMA 基线归一化。策略梯度损失为 \(L(\theta) = -\sum_{i \in \text{active}} \text{coeff}_i \log \pi_\theta(a_i|s)\)。
  - **信用分配（两通道）**：
    - **通道一**：将召回惩罚均匀分配到当前事件的所有工具（模型无关的保底信号）。
    - **通道二**：训练一个轻量 Transformer 结果模型 \(f_\phi\)，预测每个工具的重新调用计数、总 token 数和成功概率；通过单工具反事实比较“按所选比例保留”与“该工具完全保留”的预测下游代价差，得到每工具定向信用。
    - 最终信用系数合并优势、均匀地板与反事实归因，并用 warmup + 退火来控制结果模型信任度。

## 3. 实验设计

- **生产场景**：在某大型电商公司的生产数据分析智能体上评估，后台为 Claude Sonnet 4.6（200K token 窗口），工具包括知识搜索、SQL 执行、权限检查、表查找、日期解析等。
- **数据集**：从生产日志收集 120 条查询，分为三档难度：25 条简单查找、55 条多步查询（模式检索+SQL）、40 条多表权限门控连接；按难度分层分割为 80 训练 / 40 留出。
- **压缩后端**：
  - **Truncation**：均匀截断（无需模型）。
  - **Self-Info**：基于 Qwen-2.5-0.5B 的 self-information 子句级剪枝。
  - **Summarization**：基于 Qwen-3.7-Max 的语义摘要。
  - 另有一个 AGORA 风格子步级压缩器用于跨后端迁移测试。
- **对比基线**：Keep-all（全保留，作为成功率和 token 基线）、Uniform-0.5、Recency（时间近因递减）、Token-proportional（按输出尺寸惩罚）、Tool-type-conditional（每工具类型固定比例，贪心调优）。
- **实验组**：
  - 主对比：三个压缩后端的完整策略比较。
  - 消融：TRACER vs. RL-only（无结果模型，均匀信用）。
  - 干预 rollout：人为改变单个工具保留比例，对比结果模型预测与真实测量。
  - 跨骨干迁移：冻结 Claude 上训练的策略，零样本用于 Qwen-3.7-Max 和 GPT-5.5。
  - AGORA 转移：截断上训练的策略零样本用于 AGORA 风格压缩器，以及直接在该压缩器上训练。
  - LOCA-bench：公开基准的 96K/128K/256K 长上下文设置，10 个环境训练、5 个留出环境评估。

## 6. 主要结论与发现

- TRACER 在三个压缩后端上将总 token 消耗减少 **29–46%**（Truncation 31%、Summarization 46%、Self-Info 29%），同时维持或略高于 Keep-all 的任务成功率。
- 相比 Tool-type-conditional 静态策略，TRACER 额外节省 **15–18%** token，表明查询条件化、每工具差异化保留带来的增益显著。
- 重新调用率 \(p_{\text{recall}}\) 在所有后端均 ≤0.025，说明节省并非通过昂贵的重新调用获得。
- 归因模块（结果模型）在消融中带来成功率提升（+2.2pp 到 +4.8pp）和 token 比率进一步下降，且干预验证显示预测的每工具信用与实际单工具后果有中等强度相关（Spearman ρ≈0.66），方向准确率约 84%。
- 冻结策略零样本迁移到其他智能体骨干（Qwen-3.7-Max、GPT-5.5）仍保持正节省；AGORA 风格压缩器上零样本即可获得 31% 节省，定向训练进一步提升到 34%。
- 在 LOCA-bench 五个留出环境上，TRACER 相比 Keep-all 实现 18–25% 的 token 节省，并在多数情况下成功率更高。

## 7. 优点

- **问题定义清晰**：明确提出“压缩–后果差距”，将压缩建模为包含下游重新调用代价的顺序决策问题，比单纯优化 token 量更贴近实际部署。
- **方法设计精巧**：每工具粒度、Beta 分布参数化避免动作空间截断；两通道信用分配在模型可靠性不确定时仍能提供有意义的梯度；用结果模型做单工具反事实，缓解长 episode 稀疏奖励下的信用分配难题。
- **实验严谨**：除离线指标外，设计了干预性 rollout 验证归因质量；跨骨干、跨压缩器、跨基准的迁移实验提高了结论的外部有效性。
- **部署意识强**：包含成本-收益分析（约 3–6 周回本）、详尽的超参数表和实现细节，便于复现和应用。

## 8. 不足与局限

- **实验覆盖范围有限**：生产评估集中于单一电商数据代理场景，任务类型以 SQL/权限/表格为主；LOCA-bench 虽覆盖更广，但仅使用长上下文窗口设置，且未报告全部 15 个任务的细粒度结果。
- **数据集规模偏小**：生产查询仅 120 条，训练/留出各 80/40 条，可能限制对策略泛化能力的统计置信度。
- **统计报告不完整**：主对比表未提供逐单元格 p 值，部分结论依赖汇总检验；干预验证中的 NMAE、Top-3 overlap 等指标没有说明其实际业务含义。
- **结果模型的可靠性依赖分布匹配**：结果模型是经验预测器，若部署环境和训练分布差异较大，反事实归因可能产生偏差；论文并未提供严格的因果识别保证。
- **忽略部分成本**：成本分析只计算输入 token 节省，未包含摘要模型调用、Self-Info 打分计算、输出 token、延迟、集成维护等；部署成本分析基于假设的每日流量和价格，实际收益可能因环境而异。
- **可复现性边界**：生产代理、原始日志、训练检查点等私有数据未发布，公开的查询文件部分标注缺失，第三方难以完全重跑生产实验。
- **未联合优化智能体策略**：代理和压缩机均固定，TRACER 只优化上下文策略；与端到端联合训练方法相比，理论上可能无法达到全局最优。
